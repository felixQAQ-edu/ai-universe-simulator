# ADR-034 · 多存档:客户端按键存放的存档指针

- **日期**:2026-10-15
- **状态**:**已采纳**(Felix 2026-10-15 定)。实现进度见文末「实现进度」。
- **决策者**:Felix
- **前提**:`main@fb41ff0`。事实与开放问题以 [多存档勘察底稿](../multi-save-survey.md)(下称「底稿」)为准;
  本 ADR 的「已决」只回答底稿 §7 中与客户端指针有关的那几问,其余明确挂账(见「范围外」)。
- **范围**:只改前端 `web/`。服务端、prompt、golden、部署配置一行不改。
- 背景挂账:[future-experience-backlog §2.3](../future-experience-backlog.md)「存档系统只做了一半」三面一体。
  **本 ADR 只解决第 ① 面**(单 saveId 槽 → 开新局即丢旧局指针);② 孤儿档、③ 清理 / TTL 继续挂账。

---

## 背景

今天前端只有一个指针键 `aiuniverse.saveId`(底稿 §1.1),唯一写入点是 `startGame` 成功分支。
开第二局即覆盖第一局的指针;服务端那一局的存档还在 `/data`,但没有任何列出端点(底稿 §2.1),客户端从此找不回来。

另有一条 bug(底稿 §1.4):`resumeGame` 失败时**不论原因**都无条件 `clearSavedId()`。
一次网络抖动就能删掉一个活着的存档的指针;多页签下,它清掉的还可能是别的页签刚写进去的另一局。

## 立字前提

> **saveId 是今天找回一局存档的唯一凭证。** 服务端不删档(底稿 §2.4),但浏览器丢了指针,玩家仍可能再也找不到那一局。

所以本 ADR 的**第一原则**:

> **前端任何路径都不得在玩家不知情的情况下丢弃一个指针。**

以下每一条已决都要能对照这条原则读。

---

## 已决

1. **只在客户端。** 服务端一行不改。服务端今天没有归属键(底稿 §2.5);服务端列表要先有账号,那条线冻结。

2. **存储形态:每个 saveId 一个独立键**,形如 `aiuniverse.save.<saveId>`,值是这一局的摘要 JSON。
   列表 = 枚举所有带该前缀的键后汇集。
   **不用「一个数组存全部」**:两个页签同时「读 → 追加 → 写回」会互相覆盖,而 localStorage 没有跨窗口锁
   (HTML 标准明确提醒不要假设有)。按键存放后,**任何写操作只碰自己那一条 saveId 的键**,两个页签交错开局不会互相抹掉。
   `storage` 事件只用来刷新显示,不承担一致性。

3. **摘要字段**:世界名(`world.title`)、`archetypes`(单体一个,融合为 host 在前的有序对)、回合号、是否已结局、
   **本设备上次游玩时间**(客户端本地时钟;UI 文案写「本设备上次游玩」,不是服务端时间 —— 服务端存档里没有时间戳,底稿 §2.3)、
   可用状态(`available` / `unavailable`)。
   写入时机:
   - 开局成功写一条;
   - 每回合落地后更新回合号与结局状态(并刷新本设备上次游玩时间);
   - 成功续局时用服务端返回的状态校正摘要(世界名、archetypes、回合号、结局、可用状态一并改正)。

4. **上限只管展示,不管保存。** 默认只展示最近 8 条(按本设备上次游玩时间降序),超出部分通过「查看全部」展开。
   **所有指针全部保留,不自动移除任何一条。**

5. **第一版不提供「移除」。** 以后若要做,必须同时提供按 saveId 找回的入口,并在移除前明确提示风险(移除即可能永久找不回)。
   记为挂账。

6. **错误分类**(修掉 `resumeGame` 失败时无条件清指针的 bug,同时不引入新的失档路径):
   - **确认的 `session_not_found`(404)→ 该条标为 `unavailable`**,UI 显示「暂时无法找回」,**不删除**;
     之后仍可点击重试,成功即恢复为 `available` 并按已决 3 校正摘要。
   - **网络错误、503、其他 5xx、超时 → 条目保持不变**,只提示可重试。
   - **本页签世代过期**(玩家已取消或返回)→ **什么都不写**(沿用线 C 的世代守卫)。

   为什么 404 也不删:服务端「内存里没有」在今天的实现下≈盘上也没有,但「≈」不是「=」(重启回载时载不动的档也是 404,
   而那份 JSON 仍在卷上、留了尸检,底稿 §2.4 / ADR-022 刀 2 前置)。删掉指针就关上了将来找回它的唯一的门;
   标 `unavailable` 只是如实告诉玩家「现在找不回」。

   回合路径上 ADR-022 刀 1.5 的 `forgetDeadSave`:**由「清指针」改为「把该条标为 `unavailable`」**;
   刀 1.5 那句文案(「这一局的存档已经找不到了,点『返回』重新开始」)不改;只改这一条与本页签的内存视图,不影响其他条目。
   刀 1.5 当时「比对后清 / 无条件清」两半判据要防的那件事(多页签下误清别人的指针)在按键存放后**从结构上消失**:
   标记只写死档自己那个键,永远碰不到别的局。

7. **迁移旧单槽 `aiuniverse.saveId`。** 首次加载时:
   1. 若新键 `aiuniverse.save.<id>` 不存在,先写入它(摘要只有 saveId 可知,其余字段待首次续局时校正);
      **写入失败就停,不动旧键**;
   2. 写入成功(或新键本来就在)后,**只有当旧键的值仍等于这个 id 时才清旧键**(比对后清)。
   幂等;多页签同时执行也安全(两边写的是同一个键、同一份内容;清旧键前各自比对)。

8. **多页签**:监听 `storage` 事件刷新列表显示。任何写操作只碰自己那一条 saveId 的键(已决 2)。

9. **选择屏**:「我的存档」区块放在原来「继续上局」按钮的位置,静态呈现,不新增动效,动效预算不变;
   不碰融合拖拽入口的冻结构图(ADR-019)。**没有任何条目时,整个区块不渲染**(选择屏 DOM 与改动前逐字节相同)。
   「回看上局」:`capabilities.history` 为 false 时不显示(维持现状);为 true 时**只跟随最近一条**。

   ⚠️ 位置的一处措辞订正:决策原文括注「(世界卡片下方)」,而底稿 §6.1 实测原「继续上局」按钮在**标题区与世界卡片之间**
   (`<header>` 之后、`.cardList` 之前)。以「原来的位置」这一句为准实现,括注不成立,如实记于此;要移到卡片下方是另一个决定。

10. **范围外(挂账)**:孤儿档(`turn == 0`)与服务端清理、跨设备、按 saveId 找回、移除。

## 已知代价

1. **清浏览器数据、无痕窗口、换设备都会丢失全部指针**,本 ADR 不解决(跨设备那条线冻结在账号 + 云存档上)。
   服务端那几局仍在 `/data`,但客户端没有任何找回路径。
2. **localStorage 写入失败(配额满、被禁用、隐私模式)**:一律 best-effort ——
   写不进的那一条在列表里就不出现(或不更新),**UI 不崩、当局照常进行**;
   迁移遇到写入失败则停在原地,旧单槽键保留(已决 7)。读失败按空列表处理。
3. **「本设备上次游玩」是客户端本地时钟**:调过系统时间会让排序看起来不对;它从不进服务端、不参与任何判定。
4. **迁移来的旧指针摘要不全**:只知道 saveId,世界名 / 回合号要等第一次续局成功才校正;在那之前列表里显示占位文案。
5. **解析失败的键**:跳过、不删除,每次枚举汇报一个计数(`skipped`)。坏键会一直留在 localStorage 里 ——
   这是第一原则的直接代价:宁可留一个读不懂的键,也不替玩家删掉一个也许只是版本不同的指针。
6. **条目只增不减**:第一版没有移除,长期使用后列表会变长;展示上限 8 条只解决「看」,不解决「存」。

## 范围外 / 挂账

| 项 | 为什么不在本 ADR | 解冻条件 |
|---|---|---|
| 「移除」一条存档 | 必须先有「按 saveId 找回」入口与风险提示(已决 5) | 找回入口落地时 |
| 按 saveId 找回(手动输入 / 导出) | 需另立产品形态 | Felix 决定 |
| 孤儿档(`turn == 0`)/ 服务端清理 / TTL | backlog §2.3 第 ②③ 面,服务端改动 | 另立 ADR |
| 跨设备 | 压在冻结的账号 + 云存档上 | 账号线解冻 |

## 测试面

- 两个 store 实例共享同一个 storage,交错开局 → 两条都在(**这条是存储形态选择的依据**);
- 超过 8 条时只展示 8 条,但枚举结果是全部,没有任何一条被删除;
- 404 → 标 `unavailable`、不删除;之后重试成功恢复为 `available`;
- 网络错误、503 → 条目保持不变;
- 世代过期 → 什么都不写;
- 迁移:新键写入失败时旧键保留;旧键的值已被别的页签改掉时不清旧键;重复执行幂等;
- 解析失败的键被跳过且不删除;
- 没有条目时选择屏 DOM 与改动前一致;
- `capabilities.history` 为 false 时没有「回看上局」入口;
- 源码级断言:`web/src` 里只有存档指针模块碰存档相关的 localStorage 键。

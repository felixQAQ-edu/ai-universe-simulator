## 名字先说清

沿用简报给的名字。「**纸箱**」是局面名,不是机制名;「**可以被改变的『被留下』**」说的是这个局面相对今天
《动物人生》的唯一增量 —— 今天「被留下」是**世界设定里写死的一句话**(`ArchetypeRegistry.java:574`
「后来它被留下了,没有人解释为什么,直到最后也不会有」),这个局面把它变成**玩家的选择可以改变的结果**。

⚠️ **刻意不叫「事件系统」「局面层」之类的名字**:本 ADR 只锁一个世界里的一个局面,是层 3.1 的
**纵向样本**,不是它的答案(见 §不做)。名字取窄,是为了让后来者不会把它读成一个通用机制。

## 背景

### 为什么是这个局面

- **F-028**(`bakeoff/FINDINGS.md:938`)现行定性:「**内容不足只是表层;根因是引擎不产生事件**」。
  第二局冒烟里,断裂素材已经进了 prompt,世界仍然从头到尾没有发生断裂(ADR-021 §第二局)。
- **ADR-021 解冻条件**(`ADR-021-…md:776`)逐字:「**当『事件推进』这一层有了答案之后再回来。**」
- [层 3.1 勘察底稿](../event-advancement-survey.md) §6 列了 13 个待讨论问题;**本 ADR 不回答那 13 个问题的一般形式**,
  只在一个局面上给出一份可以跑、可以测、可以真机验的具体答案,让那轮讨论有一个实物可以对着说。
- 选这个局面的理由:它正是《动物人生》两局都没发生的那件事(「被丢下的那几天」,今天占时钟表 T15–17),
  而它今天是**模型自觉**的产物 —— 素材给了、转折条件写成可数判据了(`TurnPromptBuilder.java:277-295`),
  模型照样不写。**本局面把「它发生没有」从模型手里拿走,交给引擎。**

### 今天一个《动物人生》回合里谁决定什么(与本 ADR 相关的部分)

- **合法动作**:玩家只能提交当前 `availableActions` 里的 id(`GameSession.hasAction`,`GameSession.java:107`;
  守卫在 controller,`GameController.java:256`)。`availableActions` 由**模型产出**,`validateTurn` 只校
  **2–4 条、每条有 id 与非空 text**(`GameSchemas.java:113-127`),**不校 id 是不是 A/B/C/D**
  (那一条只在骨架文字里,`TurnPromptBuilder.java:125`)。
- **动作语义**:服务端**不知道** A 是什么意思 —— 它只把 `actionText` 原样喂回下一回合 prompt
  (`EventLoopService.java:176-177`)。「玩家选 A 意味着什么」今天完全由模型解释。
- **降级**:流中断 / 无尾巴 / 修复仍败 → `applyNoOp`,`turn++`,**复用上一组动作**(`EventLoopService.java:296-306`)。
- **时钟**:`LifeStageTables.ANIMAL_LIFE`(`LifeStageTables.java:91-116`)纯按回合号给段:
  屋里 T1–14 / 断裂 T15–17 / 外面·早期 T18–27 / 外面·中期 T28–41 / 末段 T42+;**出口五段全 null**。
- **会话层落盘**:`SessionDocument.encode` = `Engine.toPersistedState()` + session 层 `currentActions` / `phaseHint`
  (`SessionDocument.java:34-40`);文件与 DB 两个 store 共用这一份编解码。

### 约束条件

- **引擎对语义无知**(ADR-008)、**golden parity**、**prompt lockstep**、**三视图消毒**(CONTEXT §三.9)、
  **schemaVersion 只接受 {0.2,0.3,0.4}**(`GameSchemas.java:38-42`)—— 见勘察底稿 §5。
- **ADR-022 立字 5**:不引入「必须永不失败的写操作」。
- **ADR-023 / ADR-027**:游标比对「不相等 ∧ 不在途 → `turn_stale`」;「回合已在内存落地 ⇒ 本次 persist 一定被尝试」。
- **F-027**:验证成本由人承担 —— 本 ADR 的真机验证必须短(简报定:两条短局,每条 ≤7 回合)。

## 已定的产品样本(Felix 2026-09-30 拍板,照写,不重新论证)

### 局面状态

- **阶段 s**:1–4,每回合 +1。
- **把握 g**:整数,下限 0。
- **所有条件用「本回合行动之前的 g」判断**;未结算时才应用本回合的 g 增减。

### 外部槽位与内部意图分开

- 协议与历史仍用 **A / B / C**(本世界无出口,**D 不用**)。
- 引擎为当回合保存映射(如 `A→FOLLOW`);**模型只给固定的 A/B/C 槽位写文案**。
- 玩家提交 A 后,服务端**按当回合保存的映射结算,不得在下一回合反查**。

### 积累阶段 1–3(反馈事实由数据表决定,模型只措辞)

| 阶段 | 意图 | g 变化 | 反馈事实 |
|---|---|---|---|
| 1 | FOLLOW | +1 | 孩子蹲下来摸了它一下 |
| 1 | SNIFF_BOX | +1 | 它在纸箱里留下了自己的味道 |
| 1 | OLD_SPOT | 0 | 没有人往它这边看 |
| 2 | FOLLOW | +1 | 孩子叫了它的名字 |
| 2 | GUARD_BOWL | +1 | 有人把它的碗装进了箱子 |
| 2 | UNDER_BED | −1 | 它躲进了床底,没有人弯腰找它 |
| 3 | INTO_BOX(g<2) | +1 | 有人把它从箱子里抱出来,放在了门边 |
| 3 | INTO_BOX(g≥2) | → 结算 R1 | (见 R1) |
| 3 | TO_DOOR | +1 | 搬东西的人跨过它时停了一下 |
| 3 | UNDER_BED | −1 | 它躲进了床底 |

### 阶段 4 按局面状态分叉(征兆与意图都不同)

| 条件 | 征兆 | 意图 → 结果 |
|---|---|---|
| g ≥ 1 | 门口那只手伸了回来,孩子在车里叫它 | TO_HAND → R2 / STAY → R3b / HIDE → R3c |
| g = 0 | 车门已经关上,引擎声盖过了屋里的声音 | CHASE_CAR「追向正在离开的车」→ R3a / STAY → R3b / HIDE → R3c |

### 结算与记忆事实(按路径分别生成,由数据表给出)

| 结果 | 类别 | 记忆事实 |
|---|---|---|
| R1 | 被带走·箱子 | 搬家那天,它自己跳进了正在搬的箱子 |
| R2 | 被带走·手 | 车发动时,它跑向了那只手 |
| R3a | 被留下 | 它追到了门口,但没有跟上 |
| R3b | 被留下 | 车开走时,它待在原地 |
| R3c | 被留下 | 车开走时,它躲着 |

三种被留下的共同兜底事实:「**车开走时,它没有跟上**」。

### 余波

每种结果后接 **3 回合**,征兆与意图由数据表给出:

- **被带走**:新屋子、门声不同、金属声响了门没开、旧碗在陌生角落。
- **被留下**:光在地板 → 光在墙上、叫声没有招来人 → 天黑、门缝有外面的味道。

**被带走的分支成立,不设第二次必然抛弃**;以后是否去外面,由后续局面与玩家选择决定,本 ADR 不展开
(它与今天世界层「它在外面」的假设冲突,口径见 §已决 A:共享中性主干 + 处境薄片段)。

### 推进与公平性口径(照写)

- 积累阶段每阶段**同时提供**提高机会与不提高机会的意图。
- 两类结果在整个局面中都可由玩家选择抵达;但进入阶段 4 后,部分结果可能因先前选择而不可达。
  **引擎必须通过不同的征兆与行动措辞,将这种不可达表现为可感知的世界状态,不得仅依赖隐藏变量判定。**
- 如果玩家在积累阶段始终没有建立「被注意、被带上」的条件,**最后一刻将无法凭单次行动完全逆转结果**。
- **阶段每回合必进,每回合的局面状态必与上一回合不同**(推进的判据是局面状态,不是场景或地点)。
- **期限是上限**:提前满足条件就提前结算(R1 可在第 3 回合结算)。

### 可达性核对(勘察补,不改样本)

- g 在阶段 3 开始前最大为 2(阶段 1、2 各 +1)→ 阶段 3 选 INTO_BOX 即 R1:**R1 可达,且只在阶段 3**。
- g = 0 到达阶段 4 可达(如 OLD_SPOT 0 → UNDER_BED 0(下限)→ UNDER_BED 0):**R3a 可达**。
- g ≥ 1 到达阶段 4 可达:**R2 可达**。R3b / R3c 在两个分叉里都有:**恒可达**。
- 结论:五个结果**全部可由意图序列抵达**,确定性测试据此写(§测试面)。

## 候选方案(只写需要选的地方;样本本身不再比较)

### 状态落点

- **方案 A · 进引擎七字段**:局面状态作为 `state` 的新字段。代价:动 `Engine.apply` / `toPersistedState` /
  `restore`、**升 `schemaVersion`**(校验白名单要加一档)、**重录 golden**;而引擎要么懂局面语义
  (破 ADR-008),要么只是替会话层存一个不透明块(那就没理由放进引擎)。
- **方案 B · 会话层**(与 `currentActions` 同层落盘、不进引擎):`GameSession` 多一个字段,
  `SessionDocument` 多编解码一个键。**引擎一行不动、golden 零动、`schemaVersion` 不动。**

### 调试入口

- **方案 C · 新 HTTP 端点**(「从纸箱局面直接开局」):代价 = 多一扇门。⚠️ 本项目**删过一扇这样的门** ——
  骨架期的 `/api/dev/echo-stream` 不过配额闸,活到线上才被外部审查发现(ROADMAP v5.4,「入口不止你以为的那一个」)。
- **方案 D · 存档夹具 + 既有续局路径**:手写一份「停在第 10 回合」的存档文档,放进**本地**落盘目录,
  走既有 `@PostConstruct reloadFromStore()` + `GET /state` 续局。**零新增生产入口。**

## 最终决策(草稿;校勘倾向已写明,Felix 定的不改)

### 1. 局面状态放在会话层(倾向方案 B)

- 落在 `GameSession`,由 `SessionDocument` 与 `currentActions` 一并编解码;文件与 DB 两个 store 自动一致
  (它们共用这一份编解码,ADR-025 刀 1 抽出的理由正是防两边各写一份)。
- **阶段 s 不存,派生**:`s = engine.turn() + 1 − 局面起始回合`。它因此**不可能与引擎回合号漂移** ——
  ADR-027 刀 1 之后「已落地未送达」的回合照样会 persist,而 s 跟着 `engine.turn()` 走,不需要单独保证。
- **需要存的只有**:g、结果(未结算 / R1 / R2 / R3a / R3b / R3c)、结算回合号、**当回合槽位映射**。
- 理由:(1) 引擎零动 = golden、`schemaVersion`、`EngineGoldenTest` 全部不碰;
  (2) 局面语义留在世界层,引擎继续无知(ADR-008);
  (3) 与 `currentActions` 同性质 —— 都是「这一回合玩家面前摆着什么、选了会怎样」,本来就在会话层。
- ⚠️ **代价**:[CONTEXT §三.17](../CONTEXT.md) 第 (2) 条逐字写着落盘格式 = 「引擎七字段 + session 层
  `currentActions` / `phaseHint`」,多一个会话层键会让这句话不完整 —— **实现那一刀须同步 CONTEXT**
  (本刀 CONTEXT 在黑名单内,只记不改)。旧存档没有这个键 → 回载时视为「局面未开始」;
  已过局面窗口的旧局按今天的行为继续(⚠️ 旧局 T11–17 若恰在窗口内,见已知代价 6)。

### 2. 三视图消毒

| 视图 | 内容 |
|---|---|
| 视图 1(内部全量 / 落盘) | 意图编号、g、映射、结果、结算回合 —— **只在这里** |
| 视图 2(喂模型) | 本回合征兆、上一回合的反馈事实、记忆事实、**每个槽位的意图人话描述**(写文案要用),**不含**意图编号、g、映射、「哪个选项会提高把握」 |
| 视图 3(客户端) | 只有 A/B/C 的 text / hint;局面字段**一个都不下发** |

- ⚠️ 视图 2 这里**不是 `Engine.snapshot()`**:局面在会话层,送达模型的通道是 per-archetype 回合指令槽
  (`TurnPromptBuilder` `%9$s`,ADR-020 §10)。故「进视图 2」= 注入回合指令,不改 `snapshot()`。
- **g 不给模型,是为了让它写不出泄露 g 的 hint**(ADR-011 的 hint 是定性提示,而「选这个会被注意到」恰好就是 g)。
  玩家对 g 的全部感知,来自数据表给的**反馈事实**与**阶段 4 的征兆差异** —— 这就是公平性口径里
  「表现为可感知的世界状态」的落点。
- **记忆事实此后每回合都注入**:`LOG_KEEP = 4` 之后叙事只剩 `[T13选A]`(`Engine.java:39,295-303`),
  不单独保存,几个回合之后模型就不记得这件事发生过 —— 而那正是 F-028 的形状。

### 3. 局面挂在哪几个回合(倾向;时间空档见 §已决 B)

- 现状:屋里 T1–14(一回合数月)、断裂 T15–17(同一天)。
- **倾向**:屋里 **T1–10** / **纸箱 T11–14**(阶段 1–4,时间尺度由局面数据给 —— 不是「一回合数月」)/
  **余波 T15–17**(3 回合,替换「断裂」)。
  理由:被留下余波的三拍(光在地板 → 墙上 → 天黑)**就是今天断裂段的推进语**(`LifeStageTables.java:98-100`),
  位置对得上;前面的 T15–17 不动,外面·早期仍从 T18 开始,**时钟表其余四段与收敛窗口 45–48 一个数都不改**。
  ⚠️ **订正(第二次修订,原句保留)**:T18–41 已由 Felix 改为四段(§已决 C),故「其余四段一个数都不改」不再成立;
  **收敛窗口 45–48 与第 42 回合进末段仍不改**(总长不变,推算不变)。
- **余波段的推进语随结果不同**(被留下 = 同一天光在走;被带走 = 新屋子里的几天),故余波段的
  label / advanceClause 由局面层按结果给,**`LifeStageTable` 本身仍是纯回合号函数**(不让时钟读会话状态)。
- **R1 提前结算留下的空档**(结算 T13、余波 T14–16、T17 空出)由局面层补,**只在 T11–17 窗口内**(§已决 B)。
- `TurnPromptBuilder` 里 `animal_life` 指令第 (8) 条(断裂素材)与局面数据重叠 ——
  **实现时删除或改写,不得两份并存**(纸箱、胶带、那只手现在是阶段 1–3 的征兆来源)。
  `AnimalLifeRuptureDirectiveTest` 随之改。
- **世界背景那句要改**:`ArchetypeRegistry.java:574`「后来它被留下了,没有人解释为什么,直到最后也不会有。」
  在 R1 / R2 存在之后**不再是事实**。改法见 §已决 A 第 5 条(草拟句已记录,**最终文案实现时由 Felix 定稿**)。

### 4. 模型不守约定时

局面回合要求**恰好 A / B / C 三个槽**。模型产出的 `availableActions` 可能过 schema(2–4 条)却不合局面:

1. **槽位检查并入回合校验**:局面回合里,缺槽 / 多槽 / id 不是 A/B/C → 视同校验失败,
   **走既有的那一次修复**(不新增修复发数 —— ADR-024 的「最坏 2 × 20 秒」上界依赖「一次修复」)。
2. **修复仍不合** → 不降级整回合,**按数据表模板文案补齐缺的槽**(多出的 D 丢弃),回合照常落地。
3. **整回合降级**(流中断 / 修复仍败)→ 今天会**复用上一组动作**(`EventLoopService.java:305`),
   ⚠️ 这在局面里是错的(上一组对应上一阶段的映射)。局面回合的降级**改用本阶段模板文案**,
   且**结算照做**:玩家的意图已知,映射已存,结算不依赖模型。

- **回合不卡住**是硬要求;代价见已知代价 1(模板文案读起来是模板)。

### 5. 与既有机制:局面层不得绕过

- **致命轴触底 / 结局极性 gate**:局面层**不写任何数值轴**,不改 `stateUpdate`,不提议 ending。
  身子在局面中途归零 → 引擎照常 `ended`,局面状态随之失去意义(不另作处理)。
- **ADR-023 / ADR-027 游标**:局面状态更新在**同一临界区、`Engine.apply` / `applyNoOp` 之后、
  `sink.delta` 之前** —— 这样「已落地未送达」时 ADR-027 补写盘的那份快照里,局面状态与引擎回合号一致。
  s 由回合号派生(决策 1),本就无法漂移;g / 结果 / 映射由同一次 persist 带走。
  处境状态与 LEAVE_HOME 转移同此口径(§已决 A 第 7 条)。
- **ADR-022 立字 5**:局面状态更新是**临界区内的内存写**,落盘沿用既有 best-effort persist;
  **不引入任何必须永不失败的写**。
- **收束钳制 / F-029**:纸箱窗口 T11–17 远在末段(T42+)之前,钳制不触发;**F-029 不受本 ADR 影响、不修**。
- **校验层**:`TURN_SCHEMA` 一字不动;局面的槽位检查是会话层在校验之后的**附加判定**
  (同 ADR-020 刀 5 出口追加「在校验之后」的做法)。

### 6. 数据表放哪里、怎么 lockstep

- 新建一张 per-world **局面数据表**(Java,`eventloop` 包,形状照 `LifeStageTables`:
  **唯一允许出现本局面字面量的地方**;结算逻辑是纯机制文件,一个字面量都不许有,源码级断言守护)。

### 关键理由

- **引擎保证事件发生,模型只决定它怎么被写出来**(求职线 3.1 原话)在这里落成可测的形状:
  结算、反馈事实、记忆事实全部由表决定、可断言;模型只负责措辞。
- 状态放会话层让这一刀**不碰引擎、不碰 golden、不碰 schemaVersion**;阶段由回合号派生,游标一致性白送。

### 已决 F · 意图池逐回合轮换(Felix 2026-09-30;算式为提案)

NEW_HOME / EMPTY_HOME 的意图池在一个阶段内**按回合号确定性滑动**,相邻回合给出的组合不同。
规则是 `(回合号, 阶段表, 池表)` 的**纯函数**,不读任何会话状态、不用随机数。

**段的划分**(轮换的「阶段」):

- 第 18 回合起:时钟表的段(18–21 / 22–27 / 28–35 / 36–41 / 42 起),段起点 `S` 取时钟表的 `from`;
- 窗口内余波之后到第 17 回合为止的剩余回合(R1 提前结算时即 T17;见 §已决 B)算作**一段**,`S` = 余波结束后的第一个回合。
  (这是局面层给出的段,不改时钟表;时钟仍是纯回合号函数。)

**NEW_HOME**(池 `P`,长度 `n = 6`,数据表里的顺序即基础顺序):

```
o  = (t − S + b[段]) mod n        // b[段] 为数据表里每段的起始偏移,缺省 0
A  = P[o]
B  = P[(o + 1) mod n]
C  = P[(o + 2) mod n]
```

- 相邻回合(同一段内)`o` 差 1:A / B / C **三个槽位都换了意图**,三项集合只换掉一项(n ≥ 4 时)。
- 段起点处偏移重置为 `b[段]`;`b` 让各段第一回合不必都从同一组三项开始(建议按段依次取 0 / 2 / 4 …,由数据表定)。

**EMPTY_HOME**(旧屋池 `Q`,长度 `m`,不含 LEAVE_HOME):

```
o  = (t − S + b[段]) mod m
A  = Q[o]
B  = Q[(o + 1) mod m]
C  = LEAVE_HOME                    // 固定
```

- **LEAVE_HOME 固定在 C 槽**。理由:位置稳定,玩家不必每回合找它;A / B 两个旧屋意图随回合滑动。
  余波第 3 回合(B3)首次提供 LEAVE_HOME 时也放在 C 槽(纸箱数据表按此写),前后一致。
- `m` 须 ≥ 3,相邻回合 A / B 才会不同(`m = 2` 时只是 A / B 互换)。示例池 5 项满足。

**不变的部分**:映射仍按当回合落盘(决策 1),结算不反查;池内每项的「不改变处境」约束不变(§已决 D);
轮换只决定**给哪几个**意图,不决定模型怎么写。

### 已决 G · 引擎给出「它这些天最常做的事」(Felix 2026-09-30;窗口与并列规则为提案)

**目的**:第 28–35 段说明写着「根据玩家此前的选择」,而模型只看得见最近 `LOG_KEEP = 4` 回合(§勘察 · 第二次修订第 3 条)。
NEW_HOME / EMPTY_HOME 下引擎**知道**每回合选的意图,故由引擎从已记录的历史算出一句,注入回合指令。

**记录**(会话层,视图 1,随 `currentActions` 一并落盘):

- 最近 **8** 条 `(回合号, 意图编号)`,有界列表,超出即丢最早一条。
- 记录时机:**回合落地时**(`engine.apply` 或 `applyNoOp` 之后,与处境写入同一位置,§已决 A 第 7 条)。
  降级回合也记 —— 玩家确实选了那个意图,回合也确实落地。未落地的不记。
- **只记当前处境池里的意图**:不记纸箱局面的意图(FOLLOW / INTO_BOX …),不记 LEAVE_HOME(它是转移,不是习惯)。
- 消毒:编号与列表**只在视图 1**;视图 2 只见那一句人话;视图 3 一个字都不下发(§2)。

**算出那一句**(纯函数 `habit(记录, 处境, 回合号) → 句子或空`):

1. 只取记录里**最近 8 个回合号**之内的条目(即 `t − 8 ≤ 回合号 < t`)。
2. 条目少于 **3** 条 → 空(不注入)。
3. 按意图计数;最高计数 **< 2** → 空(没有「最常做的事」)。
4. 最高计数并列 → 取**最近一次被选的**那个。
5. 句子 = 数据表里该意图的**习惯短语**(每个池内意图一条;文案 Felix 定稿)。

**注入**:第 28 回合起、处境为 NEW_HOME 或 EMPTY_HOME 时,每回合注入(回合指令槽 `%9$s`,处境片段之后)。
第 18–27 回合不注入(那两段说明没有要求它;需要时改一个数即可)。

**已知的偏差**(照实写):轮换(§已决 F)让每个意图只在部分回合出现,「最常做」因此**一部分反映的是它最常被摆出来**,
不完全是玩家的偏好。第一版接受;若要校正(例如按出现次数归一),改的只是这个纯函数。

**OUTSIDE 下不注入**(已知代价 11):OUTSIDE 选项自由生成,引擎不知道意图,没有东西可数。
- **避开了的**:NEW_HOME / EMPTY_HOME 下「此前的选择」超出 4 回合窗口、模型结构上评估不了的问题(F-023 同形)。
- **没避开的**:OUTSIDE 下,第 28–35 段的「根据玩家此前的选择」仍只能落在模型看得见的最近 4 回合;
  更早的选择对它只剩 `[T30选B]` 这类字母。是 F-023 那个形状,原样留着。

### 已决 H · 「屋内」的边界(Felix 2026-09-30,照录)

屋内 = 旧家那扇门以内;楼道、门前、楼梯间、楼下以及街道都属于 OUTSIDE。这是「是否仍在旧家里」的边界,不是「头顶有没有屋顶」的边界。

1. EMPTY_HOME → OUTSIDE 只在玩家选择 LEAVE_HOME、成功跨过旧家门槛后发生。
2. OUTSIDE 状态可以回到那栋楼、楼道和旧家门前,这些移动都不改变处境状态。
3. 第一版不存在 OUTSIDE → EMPTY_HOME。它可以走到门前,但不能进入旧屋;模型也不得因为「回到那栋楼」就写成门重新打开或它已经回家。
4. 这条边界只指旧家。NEW_HOME 是另一处独立处境,不受「那扇门再也不会为你开」约束。

与既有条目的关系:末段楼道口、支线「走回那栋楼」都在门外,与「不得回到屋内」不冲突(§勘察 · 第三次修订第 1 条的冲突由此消除)。

- **结局条件**:末段选择返回旧地,并抵达旧家门前。(不写成「返回旧家」或「回到屋里」。)
- outcome 仍为 `neutral`(不改)。

**勘察 · 这条结局的 id 是否固定**(结论:**不固定**,改名不涉及内部 id):

- `endings[].id` 是 world-gen 时由模型产出的 snake_case 字符串(CONTEXT §二)。代码里没有这条结局的 id:
  `WorldGenPromptBuilder` 里《动物人生》的 world-gen 指令(结局池第 5 条,勘察基线 `:309-310`)只给中文名、outcome 与一句说明,
  模型据此每局自己起 id。所以没有「为兼容保留的 id」,改名在构造上碰不到 id。
- **显示名称与描述住在哪里**:每局 world-gen 产出的 `endings[]` 条目的 `title` / `description` / `condition`;
  它们的来源是上面那段 world-gen 指令里的结局池文字。**改文案 = 改那段指令里第 5 条的名称与说明**,实现时一并改。
- **条目必须留在 world-gen**:引擎只接受 `endings[]` 里已有的 id(`Engine.java:305`,§4.4)。所以 §已决 A 第 4 条
  「移到回合侧 OUTSIDE 片段」对这条结局的落法是:**条目(名称、事实、条件)留在 world-gen 结局池**,
  回合侧 OUTSIDE 片段只管「何时可以提议它」。NEW_HOME 局里这条条目也会存在,但条件不成立,不会被提议
  (被提议也只是 neutral,不触发极性 gate;越界属已知代价 8 同类)。
- 引擎的失败结局匹配(`pickFailureEnding`)按条件里的中文轴名找;新条件里没有轴名,且这条是 neutral,不在挑选范围内。
- 这是对 §已决 A 第 4 条的实现说明,不是新的待决。

## 已知代价

1. **确定性边界(照写)**:引擎保证阶段、结算结果、反馈事实、记忆事实、槽位映射、余波意图。
   **模型负责在流式正文里写出征兆与反馈** —— 是否写清楚,第一版靠两条短局人工验证。
   **后端状态推进了,不等于玩家已经看见了事件。**
2. **模板兜底文案读起来是模板**:违约与降级回合会出现数据表的固定措辞;回合不卡住,但那一回合的质感会掉。
3. **反馈事实落在下一回合的正文里**:玩家选完之后,那条事实要等下一回合的叙事来写(本回合叙事在结算之前已开始流)。
   ⚠️ 降级回合没有叙事,那条事实只进视图 2、玩家看不到 —— 由决策 4 的模板兜住选项,但**事实本身会丢一次呈现**。
   ⚠️ **订正(修订轮勘察)**:上句「本回合叙事在结算之前已开始流」不准 —— 意图在请求到达时就已知(映射在上一回合已存),
   结算是纯函数,**可以在建 prompt 之前算出**,故反馈事实可以注入**提交那一回合自己的** prompt(LEAVE_HOME 的
   「过渡回合反馈事实」正是这个形状)。原句保留作记录;实现按「同回合注入」写。降级那半句仍成立:
   降级回合今天**没有任何叙事通道**(`degrade()` 只发 `sink.delta`,`EventLoopService.java:296-306`)。
4. **第一次让服务端知道「A 是什么意思」**:今天动作语义完全在模型;本局面里服务端知道 A→FOLLOW。
   这是有意的(结算不能依赖模型),但它只在这一个局面成立,**不许被读成通用机制**。
5. **与 world-gen 产物的一致性无人保证**:world-gen 开局一次生成的背景 / 结局池可能写死「它被留下」(F-030 那一侧);
   R1 / R2 之后结局池可能没有合适的落点。本 ADR 不修(§不做);world-gen 侧能做的只有「改成中性主干」(§已决 A 第 4 条)。
6. **旧局穿越窗口**:改时钟表之后,一局正停在 T11–17 的旧《动物人生》存档回载时,局面状态为空、时钟段已变 —— 那一局这几回合会不连贯。
   线上《动物人生》当前实现已停止、存档稀少,倾向接受并在实现时记一条日志,不写迁移。
7. **CONTEXT §三.17 落盘格式措辞要跟着改**(决策 1),不改就是一句变得不完整的约定。
8. **引擎保证处境,不保证正文不与空间矛盾**(Felix 2026-09-30):引擎保证处境状态、转移、槽位效果,
   **无任何隐式转移**;**不保证**模型正文不写出与处境矛盾的空间描述(如 EMPTY_HOME 时写成已在街上)。
   第一版靠短局人工阅读发现;不加文本检查。
   NEW_HOME 下同理(§已决 D 两层保证):引擎保证处境不被改成外面,**不能机器证明**模型没把 `INSPECT_ROOM` 一类意图
   写成「跑到街上」;措辞越界记为已知限制,**不得改引擎状态迁就文字**。
9. **旧屋可以待很久**:EMPTY_HOME 下不加食物或房屋压力,玩家可以一直不选 LEAVE_HOME;
   长期停留时回合是否读起来重复,**记为后续产品问题**,本 ADR 不处理(§挂账)。
   NEW_HOME 下同形:意图池确定性按阶段取三项,阶段内选项会原样重复(§勘察 · 第二次修订第 5 条)。
   **补(第三次修订)**:池改为逐回合轮换(§已决 F)。5–6 项的池仍会循环 ——
   **轮换减少的是相邻回合的重复,不是消除重复**;一段超过 `n` 回合就会回到同一组。
10. **四段时钟不是事件保证**(照录):
    > 四段时钟只是比原来更细的节奏提示,可以降低连续多回合处于同一叙事指令下的概率;它不等于引擎已经确定性地保证每回合都有新事件。
    > 第一版的确定性保证仍只覆盖纸箱局面、余波、处境状态和引擎限定的行动意图。
11. **OUTSIDE 下选项与正文都不受引擎约束**(第三次修订):选项自由生成(§已决 E),引擎只保证处境仍是 OUTSIDE、
    没有任何出口;**不保证**模型不写出「回到屋里」一类句子 —— 与已知代价 8 同类,短局人工阅读发现,不加文本检查,
    **不得改引擎状态迁就文字**。同理,OUTSIDE 下没有习惯句(§已决 G),「根据玩家此前的选择」只能落在最近 4 回合。

## 名字先说清

沿用简报给的名字。「**纸箱**」是局面名,不是机制名;「**可以被改变的『被留下』**」说的是这个局面相对今天
《动物人生》的唯一增量 —— 今天「被留下」是**世界设定里写死的一句话**(`ArchetypeRegistry.java:574`
「后来它被留下了,没有人解释为什么,直到最后也不会有」),这个局面把它变成**玩家的选择可以改变的结果**。

⚠️ **刻意不叫「事件系统」「局面层」之类的名字**:本 ADR 只锁一个世界里的一个局面,是层 3.1 的
**纵向样本**,不是它的答案(见 §不做)。名字取窄,是为了让后来者不会把它读成一个通用机制。

## 背景

### 为什么是这个局面

- **F-028**(`bakeoff/FINDINGS.md:938`)现行定性:「**内容不足只是表层;根因是引擎不产生事件**」。
  第二局冒烟里,断裂素材已经进了 prompt,世界仍然从头到尾没有发生断裂(ADR-021 §第二局)。
- **ADR-021 解冻条件**(`ADR-021-…md:776`)逐字:「**当『事件推进』这一层有了答案之后再回来。**」
- [层 3.1 勘察底稿](../event-advancement-survey.md) §6 列了 13 个待讨论问题;**本 ADR 不回答那 13 个问题的一般形式**,
  只在一个局面上给出一份可以跑、可以测、可以真机验的具体答案,让那轮讨论有一个实物可以对着说。
- 选这个局面的理由:它正是《动物人生》两局都没发生的那件事(「被丢下的那几天」,今天占时钟表 T15–17),
  而它今天是**模型自觉**的产物 —— 素材给了、转折条件写成可数判据了(`TurnPromptBuilder.java:277-295`),
  模型照样不写。**本局面把「它发生没有」从模型手里拿走,交给引擎。**

### 今天一个《动物人生》回合里谁决定什么(与本 ADR 相关的部分)

- **合法动作**:玩家只能提交当前 `availableActions` 里的 id(`GameSession.hasAction`,`GameSession.java:107`;
  守卫在 controller,`GameController.java:256`)。`availableActions` 由**模型产出**,`validateTurn` 只校
  **2–4 条、每条有 id 与非空 text**(`GameSchemas.java:113-127`),**不校 id 是不是 A/B/C/D**
  (那一条只在骨架文字里,`TurnPromptBuilder.java:125`)。
- **动作语义**:服务端**不知道** A 是什么意思 —— 它只把 `actionText` 原样喂回下一回合 prompt
  (`EventLoopService.java:176-177`)。「玩家选 A 意味着什么」今天完全由模型解释。
- **降级**:流中断 / 无尾巴 / 修复仍败 → `applyNoOp`,`turn++`,**复用上一组动作**(`EventLoopService.java:296-306`)。
- **时钟**:`LifeStageTables.ANIMAL_LIFE`(`LifeStageTables.java:91-116`)纯按回合号给段:
  屋里 T1–14 / 断裂 T15–17 / 外面·早期 T18–27 / 外面·中期 T28–41 / 末段 T42+;**出口五段全 null**。
- **会话层落盘**:`SessionDocument.encode` = `Engine.toPersistedState()` + session 层 `currentActions` / `phaseHint`
  (`SessionDocument.java:34-40`);文件与 DB 两个 store 共用这一份编解码。

### 约束条件

- **引擎对语义无知**(ADR-008)、**golden parity**、**prompt lockstep**、**三视图消毒**(CONTEXT §三.9)、
  **schemaVersion 只接受 {0.2,0.3,0.4}**(`GameSchemas.java:38-42`)—— 见勘察底稿 §5。
- **ADR-022 立字 5**:不引入「必须永不失败的写操作」。
- **ADR-023 / ADR-027**:游标比对「不相等 ∧ 不在途 → `turn_stale`」;「回合已在内存落地 ⇒ 本次 persist 一定被尝试」。
- **F-027**:验证成本由人承担 —— 本 ADR 的真机验证必须短(简报定:两条短局,每条 ≤7 回合)。

## 已定的产品样本(Felix 2026-09-30 拍板,照写,不重新论证)

### 局面状态

- **阶段 s**:1–4,每回合 +1。
- **把握 g**:整数,下限 0。
- **所有条件用「本回合行动之前的 g」判断**;未结算时才应用本回合的 g 增减。

### 外部槽位与内部意图分开

- 协议与历史仍用 **A / B / C**(本世界无出口,**D 不用**)。
- 引擎为当回合保存映射(如 `A→FOLLOW`);**模型只给固定的 A/B/C 槽位写文案**。
- 玩家提交 A 后,服务端**按当回合保存的映射结算,不得在下一回合反查**。

### 积累阶段 1–3(反馈事实由数据表决定,模型只措辞)

| 阶段 | 意图 | g 变化 | 反馈事实 |
|---|---|---|---|
| 1 | FOLLOW | +1 | 孩子蹲下来摸了它一下 |
| 1 | SNIFF_BOX | +1 | 它在纸箱里留下了自己的味道 |
| 1 | OLD_SPOT | 0 | 没有人往它这边看 |
| 2 | FOLLOW | +1 | 孩子叫了它的名字 |
| 2 | GUARD_BOWL | +1 | 有人把它的碗装进了箱子 |
| 2 | UNDER_BED | −1 | 它躲进了床底,没有人弯腰找它 |
| 3 | INTO_BOX(g<2) | +1 | 有人把它从箱子里抱出来,放在了门边 |
| 3 | INTO_BOX(g≥2) | → 结算 R1 | (见 R1) |
| 3 | TO_DOOR | +1 | 搬东西的人跨过它时停了一下 |
| 3 | UNDER_BED | −1 | 它躲进了床底 |

### 阶段 4 按局面状态分叉(征兆与意图都不同)

| 条件 | 征兆 | 意图 → 结果 |
|---|---|---|
| g ≥ 1 | 门口那只手伸了回来,孩子在车里叫它 | TO_HAND → R2 / STAY → R3b / HIDE → R3c |
| g = 0 | 车门已经关上,引擎声盖过了屋里的声音 | CHASE_CAR「追向正在离开的车」→ R3a / STAY → R3b / HIDE → R3c |

### 结算与记忆事实(按路径分别生成,由数据表给出)

| 结果 | 类别 | 记忆事实 |
|---|---|---|
| R1 | 被带走·箱子 | 门外响着车声时，它自己跳进了那个正被人抱走的箱子。 |
| R2 | 被带走·手 | 车发动时,它跑向了那只手 |
| R3a | 被留下 | 它追到了门口,但没有跟上 |
| R3b | 被留下 | 车开走时,它待在原地 |
| R3c | 被留下 | 车开走时,它躲着 |

三种被留下的共同兜底事实:「**车开走时,它没有跟上**」。

### 余波

每种结果后接 **3 回合**,征兆与意图由数据表给出:

- **被带走**:新屋子、门声不同、金属声响了门没开、旧碗在陌生角落。
- **被留下**:光在地板 → 光在墙上、叫声没有招来人 → 天黑、门缝有外面的味道。

**被带走的分支成立,不设第二次必然抛弃**;以后是否去外面,由后续局面与玩家选择决定,本 ADR 不展开
(它与今天世界层「它在外面」的假设冲突,口径见 §已决 A:共享中性主干 + 处境薄片段)。

### 推进与公平性口径(照写)

- 积累阶段每阶段**同时提供**提高机会与不提高机会的意图。
- 两类结果在整个局面中都可由玩家选择抵达;但进入阶段 4 后,部分结果可能因先前选择而不可达。
  **引擎必须通过不同的征兆与行动措辞,将这种不可达表现为可感知的世界状态,不得仅依赖隐藏变量判定。**
- 如果玩家在积累阶段始终没有建立「被注意、被带上」的条件,**最后一刻将无法凭单次行动完全逆转结果**。
- **阶段每回合必进,每回合的局面状态必与上一回合不同**(推进的判据是局面状态,不是场景或地点)。
- **期限是上限**:提前满足条件就提前结算(R1 可在第 3 回合结算)。

### 可达性核对(勘察补,不改样本)

- g 在阶段 3 开始前最大为 2(阶段 1、2 各 +1)→ 阶段 3 选 INTO_BOX 即 R1:**R1 可达,且只在阶段 3**。
- g = 0 到达阶段 4 可达(如 OLD_SPOT 0 → UNDER_BED 0(下限)→ UNDER_BED 0):**R3a 可达**。
- g ≥ 1 到达阶段 4 可达:**R2 可达**。R3b / R3c 在两个分叉里都有:**恒可达**。
- 结论:五个结果**全部可由意图序列抵达**,确定性测试据此写(§测试面)。

## 候选方案(只写需要选的地方;样本本身不再比较)

### 状态落点

- **方案 A · 进引擎七字段**:局面状态作为 `state` 的新字段。代价:动 `Engine.apply` / `toPersistedState` /
  `restore`、**升 `schemaVersion`**(校验白名单要加一档)、**重录 golden**;而引擎要么懂局面语义
  (破 ADR-008),要么只是替会话层存一个不透明块(那就没理由放进引擎)。
- **方案 B · 会话层**(与 `currentActions` 同层落盘、不进引擎):`GameSession` 多一个字段,
  `SessionDocument` 多编解码一个键。**引擎一行不动、golden 零动、`schemaVersion` 不动。**

### 调试入口

- **方案 C · 新 HTTP 端点**(「从纸箱局面直接开局」):代价 = 多一扇门。⚠️ 本项目**删过一扇这样的门** ——
  骨架期的 `/api/dev/echo-stream` 不过配额闸,活到线上才被外部审查发现(ROADMAP v5.4,「入口不止你以为的那一个」)。
- **方案 D · 存档夹具 + 既有续局路径**:手写一份「停在第 10 回合」的存档文档,放进**本地**落盘目录,
  走既有 `@PostConstruct reloadFromStore()` + `GET /state` 续局。**零新增生产入口。**

## 最终决策(草稿;校勘倾向已写明,Felix 定的不改)

### 1. 局面状态放在会话层(倾向方案 B)

- 落在 `GameSession`,由 `SessionDocument` 与 `currentActions` 一并编解码;文件与 DB 两个 store 自动一致
  (它们共用这一份编解码,ADR-025 刀 1 抽出的理由正是防两边各写一份)。
- **阶段 s 不存,派生**:`s = engine.turn() + 1 − 局面起始回合`。它因此**不可能与引擎回合号漂移** ——
  ADR-027 刀 1 之后「已落地未送达」的回合照样会 persist,而 s 跟着 `engine.turn()` 走,不需要单独保证。
- **需要存的只有**:g、结果(未结算 / R1 / R2 / R3a / R3b / R3c)、结算回合号、**当回合槽位映射**。
- 理由:(1) 引擎零动 = golden、`schemaVersion`、`EngineGoldenTest` 全部不碰;
  (2) 局面语义留在世界层,引擎继续无知(ADR-008);
  (3) 与 `currentActions` 同性质 —— 都是「这一回合玩家面前摆着什么、选了会怎样」,本来就在会话层。
- ⚠️ **代价**:[CONTEXT §三.17](../CONTEXT.md) 第 (2) 条逐字写着落盘格式 = 「引擎七字段 + session 层
  `currentActions` / `phaseHint`」,多一个会话层键会让这句话不完整 —— **实现那一刀须同步 CONTEXT**
  (本刀 CONTEXT 在黑名单内,只记不改)。旧存档没有这个键 → 回载时视为「局面未开始」;
  已过局面窗口的旧局按今天的行为继续(⚠️ 旧局 T11–17 若恰在窗口内,见已知代价 6)。

### 2. 三视图消毒

| 视图 | 内容 |
|---|---|
| 视图 1(内部全量 / 落盘) | 意图编号、g、映射、结果、结算回合 —— **只在这里** |
| 视图 2(喂模型) | 本回合征兆、上一回合的反馈事实、记忆事实、**每个槽位的意图人话描述**(写文案要用),**不含**意图编号、g、映射、「哪个选项会提高把握」 |
| 视图 3(客户端) | 只有 A/B/C 的 text / hint;局面字段**一个都不下发** |

- ⚠️ 视图 2 这里**不是 `Engine.snapshot()`**:局面在会话层,送达模型的通道是 per-archetype 回合指令槽
  (`TurnPromptBuilder` `%9$s`,ADR-020 §10)。故「进视图 2」= 注入回合指令,不改 `snapshot()`。
- **g 不给模型,是为了让它写不出泄露 g 的 hint**(ADR-011 的 hint 是定性提示,而「选这个会被注意到」恰好就是 g)。
  玩家对 g 的全部感知,来自数据表给的**反馈事实**与**阶段 4 的征兆差异** —— 这就是公平性口径里
  「表现为可感知的世界状态」的落点。
- **记忆事实此后每回合都注入**:`LOG_KEEP = 4` 之后叙事只剩 `[T13选A]`(`Engine.java:39,295-303`),
  不单独保存,几个回合之后模型就不记得这件事发生过 —— 而那正是 F-028 的形状。

  **余波 T15–17**(3 回合,替换「断裂」)。
  理由:被留下余波的三拍(光在地板 → 墙上 → 天黑)**就是今天断裂段的推进语**(`LifeStageTables.java:98-100`),
  位置对得上;前面的 T15–17 不动,外面·早期仍从 T18 开始,**时钟表其余四段与收敛窗口 45–48 一个数都不改**。
  ⚠️ **订正(第二次修订,原句保留)**:T18–41 已由 Felix 改为四段(§已决 C),故「其余四段一个数都不改」不再成立;
  **收敛窗口 45–48 与第 42 回合进末段仍不改**(总长不变,推算不变)。

  被留下 R3a / b / c T15–17 → 第三组)。时钟表 15–17 那一格只是占位,**对新局从不渲染**(测试守);旧局不走覆盖。

### 4. 模型不守约定时

局面回合要求**恰好 A / B / C 三个槽**。模型产出的 `availableActions` 可能过 schema(2–4 条)却不合局面:

1. **槽位检查并入回合校验**:局面回合里,缺槽 / 多槽 / id 不是 A/B/C → 视同校验失败,
   **走既有的那一次修复**(不新增修复发数 —— ADR-024 的「最坏 2 × 20 秒」上界依赖「一次修复」)。
2. **修复仍不合** → 不降级整回合,**按数据表模板文案补齐缺的槽**(多出的 D 丢弃),回合照常落地。
3. **整回合降级**(流中断 / 修复仍败)→ 今天会**复用上一组动作**(`EventLoopService.java:305`),
   ⚠️ 这在局面里是错的(上一组对应上一阶段的映射)。局面回合的降级**改用本阶段模板文案**,
   且**结算照做**:玩家的意图已知,映射已存,结算不依赖模型。

- **回合不卡住**是硬要求;代价见已知代价 1(模板文案读起来是模板)。

### 5. 与既有机制:局面层不得绕过

- **致命轴触底 / 结局极性 gate**:局面层**不写任何数值轴**,不改 `stateUpdate`,不提议 ending。
  身子在局面中途归零 → 引擎照常 `ended`,局面状态随之失去意义(不另作处理)。
- **ADR-023 / ADR-027 游标**:局面状态更新在**同一临界区、`Engine.apply` / `applyNoOp` 之后、
  `sink.delta` 之前** —— 这样「已落地未送达」时 ADR-027 补写盘的那份快照里,局面状态与引擎回合号一致。
  s 由回合号派生(决策 1),本就无法漂移;g / 结果 / 映射由同一次 persist 带走。
  处境状态与 LEAVE_HOME 转移同此口径(§已决 A 第 7 条)。
- **ADR-022 立字 5**:局面状态更新是**临界区内的内存写**,落盘沿用既有 best-effort persist;
  **不引入任何必须永不失败的写**。
- **收束钳制 / F-029**:纸箱窗口 T11–17 远在末段(T42+)之前,钳制不触发;**F-029 不受本 ADR 影响、不修**。
- **校验层**:`TURN_SCHEMA` 一字不动;局面的槽位检查是会话层在校验之后的**附加判定**
  (同 ADR-020 刀 5 出口追加「在校验之后」的做法)。

### 6. 数据表放哪里、怎么 lockstep

- 新建一张 per-world **局面数据表**(Java,`eventloop` 包,形状照 `LifeStageTables`:
  **唯一允许出现本局面字面量的地方**;结算逻辑是纯机制文件,一个字面量都不许有,源码级断言守护)。
- **单一真理源**:征兆、反馈事实、记忆事实、模板文案只在数据表里写一次;prompt 从表**渲染**,不另抄。
  故**不需要**「文件 ↔ prompt」两份之间的 lockstep(`prompts/event-loop.md` 本就不含 per-world 指令,已核:
  `prompts/` 下「纸箱 / 断裂」零命中)。
- 需要的守护是**登记面对拍**(照 `LifeStageTables` 的 static 断言):局面表登记的世界必须是已注册 archetype、
  且窗口回合落在该世界时钟表的范围内 —— 挂错 = 加载即抛。
- ⚠️ 若 Felix 希望文案有一份给人读的真理源(同 `world-ordinary-life-writing-standards.md` 先例),
  则回到「文件 → 表」的 lockstep,**不得反向**。倾向:第一版不建,文案只在表里。

### 关键理由

- **引擎保证事件发生,模型只决定它怎么被写出来**(求职线 3.1 原话)在这里落成可测的形状:
  结算、反馈事实、记忆事实全部由表决定、可断言;模型只负责措辞。
- 状态放会话层让这一刀**不碰引擎、不碰 golden、不碰 schemaVersion**;阶段由回合号派生,游标一致性白送。

**7. 转移的落地判据(勘察,对照 ADR-027)**

- 判据用 ADR-027 的「回合已在引擎落地」:`TurnStateMachine` 的 catch 按 `engine.turn()` 变没变区分已落地 /
  未落地,已落地补一次 persist。转移**与落地同一时刻提交**:在 `settle()` 里紧跟 `engine.apply` 之后、
  `degrade()` 里紧跟 `engine.applyNoOp` 之后写入会话层处境,且**在任何 `sink` 写之前**
  (`EventLoopService.java:269-276`、`:296-306`)。这样:
  - 已落地未送达(`sink.delta` 抛出)→ ADR-027 的补写盘带走的快照里已经是 OUTSIDE;
  - 未落地(流中断前抛出、`engine.turn()` 未变)→ 处境仍是 EMPTY_HOME,什么都没写。
- **与代码不冲突**。唯一的实现约束:转移写入必须排在 apply 之后**第一件**会话层写(排在
  `updateActionsFromParsed` 之后也可以,但它和 `sink.delta` 之间不能夹任何可能抛出的东西 —— 否则会出现
  「已落地、处境没写」)。不引入必须永不失败的写(ADR-022 立字 5):仍是临界区内的内存写 + 既有 best-effort persist。
- ⚠️ **勘察补 · 降级回合带上离开反馈的可见载体**:「模板降级也须带上离开反馈事实」—— 但 `degrade()` 今天
  **只发 `sink.delta`,没有叙事通道**(已知代价 3)。离开反馈要让玩家看见,实现须给降级的过渡回合加一个
  可见载体。候选:(i) 降级时先 `sink.narrative` 补一句反馈事实再发 delta(SSE 本就 narrative → delta 顺序);
  (ii) 写进下一组槽位模板文案的 hint。倾向 (i);**这一处新增的 sink 写必须排在处境写入之后**(同上一条约束)。
  另:降级的过渡回合落地后处境已是 OUTSIDE,下一组动作不再由 EMPTY_HOME 池给,需要一组「刚出门」的模板动作
  (今天的降级会复用上一组 —— 那组含 LEAVE_HOME,在 OUTSIDE 下是错的)。
- **已决(校勘处置,Felix 未反对)**:取 (i) —— 降级时**先补一句叙事(即数据表的反馈事实)再发 delta**,
  这句 sink 写排在处境写入之后;另备一组「**刚出门**」模板选项,防止复用含 LEAVE_HOME 的旧选项。模板文案 Felix 定稿。

  不从意图池取;**轮换从第 18 回合开始**。上一句「算作一段」不再适用。

**NEW_HOME**(池 `P`,长度 `n = 6`,数据表里的顺序即基础顺序):

```
o  = (t − S + b[段]) mod n        // b[段] 为数据表里每段的起始偏移,缺省 0
A  = P[o]
B  = P[(o + 1) mod n]
C  = P[(o + 2) mod n]
```

- 相邻回合(同一段内)`o` 差 1:A / B / C **三个槽位都换了意图**,三项集合只换掉一项(n ≥ 4 时)。
- 段起点处偏移重置为 `b[段]`;`b` 让各段第一回合不必都从同一组三项开始(建议按段依次取 0 / 2 / 4 …,由数据表定)。
  ⚠️ **订正(刀 2b,校勘定;原句保留)**:`b[段] = 2 × 段序号`(第 18 回合起的段依次 0 / 2 / 4 / 6 …,步长 2 写在数据表),
  由「提案」改为**已决**。

**EMPTY_HOME**(旧屋池 `Q`,长度 `m`,不含 LEAVE_HOME):

```
o  = (t − S + b[段]) mod m
A  = Q[o]
B  = Q[(o + 1) mod m]
C  = LEAVE_HOME                    // 固定
```

- **LEAVE_HOME 固定在 C 槽**。理由:位置稳定,玩家不必每回合找它;A / B 两个旧屋意图随回合滑动。
  余波第 3 回合(B3)首次提供 LEAVE_HOME 时也放在 C 槽(纸箱数据表按此写),前后一致。
- `m` 须 ≥ 3,相邻回合 A / B 才会不同(`m = 2` 时只是 A / B 互换)。示例池 5 项满足。

**不变的部分**:映射仍按当回合落盘(决策 1),结算不反查;池内每项的「不改变处境」约束不变(§已决 D);
轮换只决定**给哪几个**意图,不决定模型怎么写。

### 已决 J · R1 记忆事实与近人显示(Felix 2026-10-01,照录)

1．修改 R1 记忆事实
原文：

理由：

* 删除动物无法理解的“搬家”概念；
* 只保留它能听见、看见和做出的事情；
* 不使用“被带走”提前解释结果；

其他四条结算记忆不改。
2．【近人】使用中性颜色，不做动态危险变色
【近人】在所有处境下都使用普通非致命轴的中性颜色，不把高位固定显示成红色，也不把低位显示成绿色；第一版同样不根据 `NEW_HOME` / `EMPTY_HOME` / `OUTSIDE` 动态换色。
理由有两层：

1. 同一个数值的后果取决于处境：
   * `NEW_HOME` 中，站得近可能得到食物和触碰；
   * `EMPTY_HOME` 中，没有人可供靠近；
   * `OUTSIDE` 中，站得近才会增加被踢、被砸和被驱赶的风险。
因此任何固定的“高位危险色”都会在新屋分支说假话。
2. 动态进入 `OUTSIDE` 后立刻把轴染红，也会变成系统直接提示“这条规律现在危险了”，与“系统绝不提示规律变了，只让它撞上”的核心机制冲突。

玩家应从档位文字和实际反馈中理解它：

* 躲着人；
* 敢靠近；
* 站得很近。

是否危险由处境片段、事件结果和结局 gate 决定，不由颜色提前宣判。
实现时只调整显示语义，不改变：

* 【近人】的数值；
* 数值增减条件；
* `OUTSIDE` 中高位有害的 prompt 约束；
* 【太近了】的结局条件；
* 已有状态与存档格式。

如果当前颜色直接由 `axisRole` 推导，而修改 `axisRole` 还会影响引擎逻辑，不能为了改颜色顺手改领域语义。应使用显示层的中性覆盖；如果现有结构做不到，停下报告具体耦合点，不自行扩大修改范围。

## 已知代价

1. **确定性边界(照写)**:引擎保证阶段、结算结果、反馈事实、记忆事实、槽位映射、余波意图。
   **模型负责在流式正文里写出征兆与反馈** —— 是否写清楚,第一版靠两条短局人工验证。
   **后端状态推进了,不等于玩家已经看见了事件。**
2. **模板兜底文案读起来是模板**:违约与降级回合会出现数据表的固定措辞;回合不卡住,但那一回合的质感会掉。
3. **反馈事实落在下一回合的正文里**:玩家选完之后,那条事实要等下一回合的叙事来写(本回合叙事在结算之前已开始流)。
   ⚠️ 降级回合没有叙事,那条事实只进视图 2、玩家看不到 —— 由决策 4 的模板兜住选项,但**事实本身会丢一次呈现**。
   ⚠️ **订正(修订轮勘察)**:上句「本回合叙事在结算之前已开始流」不准 —— 意图在请求到达时就已知(映射在上一回合已存),
   结算是纯函数,**可以在建 prompt 之前算出**,故反馈事实可以注入**提交那一回合自己的** prompt(LEAVE_HOME 的
   「过渡回合反馈事实」正是这个形状)。原句保留作记录;实现按「同回合注入」写。降级那半句仍成立:
   降级回合今天**没有任何叙事通道**(`degrade()` 只发 `sink.delta`,`EventLoopService.java:296-306`)。

   这是有意的(结算不能依赖模型),但它只在这一个局面成立,**不许被读成通用机制**。

| 意图 | 正常选项必须表达 | 行动边界 | 降级模板 | 习惯短语 |
|---|---|---|---|---|
| `FOLLOW_CHILD` | 跟着孩子 | 只能跟随孩子在新屋内部移动；不能跟出家门，也不能借孩子开门制造地点转换 | 跟着孩子走 | 这些天，它常跟在孩子身后。 |
| `FIND_SAFE_SPOT` | 寻找可以安心停留的位置 | 只能寻找新屋内的角落、垫子、家具旁或其他休息处；描述的是寻找，不保证已经找到 | 找一个能安心趴下的地方 | 这些天，它常在屋里找能安心趴下的地方。 |
| `WAIT_BY_NEW_DOOR` | 守在新家的门内 | 可以听、闻或观察门外动静，但身体必须留在门内；这不是旧家的那扇门 | 守在新的门边 | 这些天，它常守在新的门边，听门外的动静。 |
| `INSPECT_ROOM` | 查看新屋里还不熟悉的房间 | 只能在新屋内部移动；不得进入楼道、街道、阳台外侧或其他未定义空间 | 去看看还没闻过的房间 | 这些天，它常去闻那些还不熟悉的房间。 |
| `RETURN_TO_BOWL` | 回到从旧家带来的那只碗旁 | 可以靠近、闻、吃喝或在旁边停留；不能把动作改写成回旧家 | 回到旧碗旁边 | 这些天，它常回到那只旧碗旁边。 |
| `TRACE_SOUND` | 寻找新屋内部声音的来源 | 声音来源必须位于新屋内部；如果声音来自门外，只能在门内听，不能追出去 | 去找屋里的声音从哪里传来 | 这些天，它常循着屋里的声音找过去。 |

##### 新屋共同边界

- 六个意图的处境效果全部为 `NONE`，完成后仍是 `NEW_HOME`。
- 模型不得把任何一个意图改写成离开新屋。
- “孩子开门”“门外有声音”“查看房间”都不能成为未经定义的 `NEW_HOME → OUTSIDE`。
- 以后若要离开新屋，必须新增确定性的转换局面，不能复用这六个意图暗中完成。
- 降级模板是最终兜底文字，可以直接显示给玩家。

#### 3．`EMPTY_HOME` 旧屋意图池

##### 池内固定顺序

1. `WAIT_BY_OLD_DOOR`
2. `SEARCH_FOR_FOOD`
3. `CALL_IN_EMPTY_HOME`
4. `RETURN_UNDER_BED`
5. `INSPECT_EMPTY_ROOMS`

每回合由轮换算式从池中取两项，依次放入 A、B；C 始终固定为 `LEAVE_HOME`。

##### 意图定义

| 意图 | 正常选项必须表达 | 行动边界 | 降级模板 | 习惯短语 |
|---|---|---|---|---|
| `WAIT_BY_OLD_DOOR` | 留在旧家门内等待 | 可以听楼道、闻门缝或守着门，但不能跨过门槛 | 守在门边等一会儿 | 这些天，它常守在门边，听楼道里的动静。 |
| `SEARCH_FOR_FOOD` | 在旧屋里寻找还能吃的东西 | 可以查看碗、地面、厨房或家具旁；只保证寻找，不保证找到食物，也不能为了找食物离开旧屋 | 去找还能吃的东西 | 这些天，它常在空下来的屋里找吃的。 |
| `CALL_IN_EMPTY_HOME` | 在空屋里发出叫声 | 可以朝门、房间或过去有人出现的方向叫；不保证有人回应，也不改变处境 | 朝空屋里叫一声 | 这些天，它常朝着没有回应的屋里叫。 |
| `RETURN_UNDER_BED` | 回到熟悉的床底躲藏 | 只能回到旧屋内已经存在的藏身处；不能借躲藏转移到屋外 | 躲回床底 | 这些天，它常躲回床底。 |
| `INSPECT_EMPTY_ROOMS` | 查看已经空下来的房间 | 可以在旧屋各房间之间移动、闻或观察留下的痕迹；不能从窗户、阳台或其他出口离开 | 去看看已经空下来的房间 | 这些天，它常一个房间一个房间地闻过去。 |

##### 固定 C 槽

| 意图 | 正常文字与降级模板 | 状态效果 |
|---|---|---|
| `LEAVE_HOME` | 从门缝钻出去 | 回合成功完成后，由 `EMPTY_HOME` 转为 `OUTSIDE` |

##### 旧屋共同边界

- A、B 两个意图的处境效果全部为 `NONE`。
- 只有 C 槽的 `LEAVE_HOME` 可以越过旧家门槛。
- 模型不得把寻找食物、查看房间或听门外动静写成已经离开旧屋。
- 玩家可以长期不选择 C；不得按停留回合数自动把它搬到外面。
- 如果长期停留产生重复感，应另开局面解决，不能用自由叙事偷偷改变地点。

#### 4．习惯短语的共同口径

习惯短语只描述玩家反复选择过的动作，不宣称动作取得了模型自行决定的结果。

因此：

- 写“寻找能安心趴下的地方”，不写“已经找到了自己的位置”；
- 写“寻找食物”，不写“总能找到食物”；
- 写“循着声音找过去”，不写“认出了每一种声音”；
- 写“朝空屋里叫”，不补写有人回应；
- 不把统计结果说成性格、命运或永久习惯。

注入时直接使用表内完整句子，不再在外层重复拼接“这些天，它常……”。

统计口径维持已定规则：

- 只看最近 8 个已经落地的回合；
- 至少有 3 条可计入记录；
- 最常选择的意图至少出现 2 次；
- 并列时取最近一次选择的那个；
- `LEAVE_HOME` 和纸箱局面内的意图不计入；
- 轮换会影响意图被提供的次数，这个偏差保持如实记录，不把它包装成纯粹的玩家偏好。

习惯短语只供模型承认玩家过去的行动，不新增数值，不改变处境，也不能覆盖当前阶段和处境片段。

### 第二节:背景与选择屏一句话(2b 接入,本刀不改代码)

#### 5．《动物人生》世界背景

它一直生活在一户人家的屋里。它不懂人的话，也不知道搬家、遗弃或收养，只能从反复出现的声音、气味、动作和结果里学习：金属声响过，门会打开；叫一声，脚步会靠近；碗被放下，就有东西可吃。它把这些重复当作世界本来的秩序。
后来，纸箱出现，家具被搬走，那套秩序开始松动。玩家可能让它跟着人进入新家，也可能让它留在空下来的旧屋，并在以后决定是否跨过那扇门。无论到了哪里，过去熟悉的信号都不再可靠；故事应通过它能够直接感知的变化，表现它怎样继续试探、记住回应，并慢慢形成新的生活方式。
不得预先宣布它必然被留下、必然进入外面，也不得替它解释人的理由。正文只能通过具体发生的事表现变化，不要直接复述"规则失效""建立新规律"或"处境改变"等设计语言。

#### 6．选择屏一句话

熟悉的一切变了，你学会的规则还作数吗？

### 第三节:Item 7(误读回收、结局池、rules 形态、近人轴、回合侧裁决与 OUTSIDE 片段;2b 接入,本刀不改代码)

这四块不能只做“把外面改成处境”的文字替换。核心要改成：**旧家的规律在不同处境里得到不同回应；只有 `OUTSIDE` 使用踢、砸、驱赶等重失效。**

#### 7-A．世界生成侧：误读回收与结局池

用以下内容替换现有《动物人生》专属块：

##### 本世界专属 · 误读回收与结局池

- 【核心机制 · 误读回收】第 1–10 回合里，它在旧家学会的规律都是真的；那正是它会相信这些规律的原因。

  纸箱局面开始以后，不再使用“屋里全为真、外面统一变假”的二分法。规律得到什么回应，以会话保存的权威处境为准。纸箱局面和余波期间，以局面数据表给出的征兆、反馈和记忆事实为准。

- 【四条核心对应】

  1. **金属声 = 门要开**

     - `NEW_HOME`：新家的门声已经不同；楼道里的金属声可能来自别人家的门。它仍会抬头，但门不一定为它打开。
     - `EMPTY_HOME`：楼道里仍会有金属声，但旧家的门不会因此打开。
     - `OUTSIDE`：那是别人的钥匙、别人的门，不是它等的那一扇。

     这条规律可以反复失效，但“听见金属声抬头”永远改不掉。它到死都还会抬头，这是这个世界必须保留的记忆点。

  2. **靠近人 = 有吃的、不会出事**

     - `NEW_HOME`：熟悉的人仍可以喂它、摸它；不得为了表现“规则失效”，让新家里的人无故踢它或拿东西砸它。
     - `EMPTY_HOME`：屋里没有可以靠近的人。不得凭空生成人，只为了让这条规律失败。
     - `OUTSIDE`：靠近陌生人可能换来踢、砸、驱赶或追赶；代价落在【身子】与【近人】。

  3. **叫 = 有人来**

     - `NEW_HOME`：叫声仍可能换来孩子、脚步或门内的回应，但不保证每一次都有人立刻出现。
     - `EMPTY_HOME`：叫声没有招来任何人。
     - `OUTSIDE`：叫声可能引来不友善的人、别的动物或其他让处境变糟的东西。

  4. **那个位置 = 安全**

     - `NEW_HOME`：旧位置已经不存在，它必须在陌生房间里重新寻找能停留的地方；这不是惩罚，也不能直接写成受伤。
     - `EMPTY_HOME`：有些旧位置还在，但家具、人和日常声音已经改变，那里不再自动兑现过去的安全。
     - `OUTSIDE`：位置可能已经被别的东西占着；它去了，会被赶开。

- 【不同处境不是同一种失效】

  `NEW_HOME` 与 `EMPTY_HOME` 不得套用 `OUTSIDE` 的踢、砸、驱赶模板。某条规律可以继续成立、只成立一部分、暂时没有适用对象，或者以较轻的方式失效。

  系统绝不告诉玩家“规律变了”，也不把现在和过去拿出来比较；只写这一次具体发生的结果。

- 结局从以下六条里产出。骨架要求 %s 条，因此至少产出其中五条；【熬过去了】与【撞上】必须存在：

  1. **熬过去了**（`outcome=success`）

     身子自然耗尽，而它后来认得的地方还在。

     `condition` 示例：回合走到尽头、【身子】仍在 15 以上且未归零，并且【地面】处于较高位置。

  2. **冬天**（`outcome=neutral`）

     【暖】长期处于低位以后，身子耗尽。

  3. **太近了**（`outcome=failure`）

     只允许在权威处境为 `OUTSIDE` 时提出；【近人】处于高位，而【身子】归零。

     这一条必须存在。它表现的是在外面仍然敢站到陌生人够得着的地方，不能用于惩罚 `NEW_HOME` 中靠近熟悉的人。

  4. **撞上**（`outcome=failure`）

     【身子】在途中归零。它仍是致命轴触底时引擎兜底需要命中的结局。

  5. **走回门前**（`outcome=neutral`）

     只允许在权威处境为 `OUTSIDE`、进入末段并且玩家明确选择返回旧地以后提出。

     它循着残留的气味回到那栋楼，在那扇没有再打开的门前伏下，身体在那里耗尽。

     标为 `neutral`，不标为 `success`。它回到了旧家门前，但没有进入旧屋；这个模糊是故意的。

  6. **没有名字的**（`outcome=failure`）

     只允许在权威处境为 `OUTSIDE` 时提出；【身子】耗尽，而【地面】处于低位。

     结局文字应写它停在没有遮挡的低处，有人从旁边经过，却不知道孩子以前怎样叫它。不得写成“它从来没有名字”，也不得替经过的人解释它从哪里来。

- 【身子归零 = 撞上；老死 = 走完回合表、身子低但未归零】。族级共用片段“活到最后”继续生效。

- 【不解释人的原因】

  可以写纸箱、搬空的家具、车声、伸回来的手和关上的门，但旁白不得说“这是搬家”，不得解释为什么带走或留下，也不得写“他们不要它了”。

  世界生成提示可以知道设计事实；生成给游戏使用的 `background`、`rules`、`openingNarrative` 和任何结局文字，都只能写动物感知得到的东西。

- 【结局文字可以回收一条，且只回收一条】

  回收的是早年在旧家学会的某一条规律，并且必须以“别人不知道”的方式出现：东西还在，人不在了，认得它的只有它和玩家。

  不解释、不点破、不列回收清单；回收不加分、不产生额外标记。

- 【condition 一律使用中文轴名】

  只写【身子】、【暖】、【地面】、【近人】，不得写 `body`、`warmth`、`ground`、`close`。

#### 7-B．世界生成侧：`rules` 形态说明

用以下内容替换现有说明：

> 【动物没有守则。它有的是在旧家学会的规律，而规律会随着处境得到不同回应。】
>
> `rules` 生成 6–8 条“这只动物在旧家学会的规律”。每一条都用它能够感知的东西来写，例如金属声、鞋、腿边、叫声、碗和那个位置；不得写成人类口吻的条款，也不得编号成守则。
>
> 每条规律在第 1–10 回合的旧家里都是真的。不得为了制造反转，把它早年学到的规律写成从一开始就是误会。
>
> 纸箱局面以后，不得把所有规律统一写成“到了外面就变假”：
>
> - `NEW_HOME` 中，有些规律仍然成立，有些只成立一部分，有些需要重新寻找对应的声音或位置；
> - `EMPTY_HOME` 中，有些规律因为人已经不在而没有适用对象；
> - `OUTSIDE` 中，才允许使用踢、砸、驱赶、被占位置等重失效。
>
> `hiddenLogic` 必须写清：
>
> 1. 这条规律在旧家里怎样兑现；
> 2. 它在 `NEW_HOME` 中怎样继续成立或发生偏差；
> 3. 它在 `EMPTY_HOME` 中怎样失去回应或暂时没有适用对象；
> 4. 它在 `OUTSIDE` 中怎样失效，以及代价落在哪条轴上。
>
> 某个处境确实不适用时，明确写“不触发”，不得为了填满四格凭空制造事件。
>
> 不带 `isTrue`。这里不是真假混合的守则墙，而是时间与处境共同决定的变化：旧家里学会时为真，此后是否继续成立，由权威处境和具体事件决定。

---

#### 7-C．【近人】轴说明与档位

用以下内容替换现有说明：

> 【近人】是“敢不敢靠近人”。
>
> 被喂过、被摸过、靠近以后没有出事时上涨；被踢、被砸、被驱赶或被追以后下降。由模型在 `stateUpdate` 中给出新的绝对值。
>
> 同一个数值在不同处境里的含义不同：
>
> - `NEW_HOME`：靠近熟悉的人可以是安全的；高位不自动有害，也不得为了压低数值让家里人无故伤害它。
> - `EMPTY_HOME`：屋里没有人。不能只因为没有人出现就自动修改【近人】，也不能凭空生成人来兑现这条轴。
> - `OUTSIDE`：高位有害。它让动物长时间停在人能够踢到、砸到或赶到的位置；低位不是失败，只是学会先躲开。
>
> 档位：
>
> - `0　躲着人`——听见脚步就先让开。在 `OUTSIDE` 中通常活得更久；即使后来回到旧家门前，那扇门也不会因此打开。
> - `31　敢靠近`——有人蹲下来时，它会先看一会儿，再决定是否走过去。
> - `61　站得很近`——腿边、手边、脚步声所在的一侧；在 `NEW_HOME` 中可能得到食物和触碰，在 `OUTSIDE` 中则一直站在人够得着的地方。
>
> “那扇门不会再打开”只指旧家的门，不得用于新家的门。

#### 7-D．回合侧：共同裁决与 `OUTSIDE` 片段

##### 替换规则（5）

> **（5）【误读回收 · 按权威处境裁决】**
>
> 玩家行动若用到旧家学会的某条规律，按以下顺序决定回应：
>
> - 第 1–10 回合的旧家：规律应当兑现，那正是它被学会的原因；
> - 第 11–17 回合的纸箱局面与余波：以局面数据表给出的征兆、反馈事实、记忆事实和意图边界为准；
> - 此后：以会话保存的 `NEW_HOME`、`EMPTY_HOME` 或 `OUTSIDE` 为准，使用对应处境片段。
>
> 不得根据回合号、模型刚写出的地点或叙事中的一句话反推处境。权威处境没有发生转换时，正文也不得自行转换地点。
>
> 系统绝不提示“规律变了”，也不比较过去和现在；只把这一次具体发生的结果写出来，不加说明。
>
> 有一条永远改不掉：听见金属声抬头。它到死都还在。

##### 规则（6）保持逐字不变

> **（6）【逐字不变的句子 · 硬约束】**
>
> 以下句子每次出现都必须逐字相同，不许改写、不许加字，也不许在后面接任何东西，包括省略号：
>
> 「楼道里有金属碰金属的声音。」
>
> 「你去床脚那块地方趴下。」
>
> 「你抬起头。」
>
> 「是别的门。」
>
> 「你把头放下去。」
>
> 「不是。」
>
> 「你抬了一下头。」
>
> 不得出现“钥匙”，不得出现“多年以后”；“你去床脚那块地方趴下”不得改成“回到”。

##### 将规则（7）移入 `OUTSIDE` 片段

> **（7）【`OUTSIDE` · 接触种类与动词分区】**
>
> 这一条只在权威处境为 `OUTSIDE` 时注入。
>
> 正文与选项中不得出现“推”字。外面是踢、是砸、是驱赶，是手落下来的地方不对；这是另一种接触，不是屋内接触的加强版。
>
> “靠近人”在这里可能换来踢、砸、驱赶或追赶，但不要求每回合都发生伤害，也不得为了证明规则失效连续重复同一种伤害。
>
> 检查条件从“处于外面三段之一”改为“权威处境等于 `OUTSIDE`”。四段生命周期本身不决定这条规则是否生效。

##### 用以下内容替换规则（8）的强制离屋结论

> **（8）【局面与处境不得由时钟代替】**
>
> 第 11–17 回合的纸箱局面和余波，由局面层提供征兆、反馈、记忆与选项意图。
>
> 第 18 回合开始进入共同的四段生命周期，但生命周期只说明变化进行到哪里，不决定动物身在何处。具体地点始终以会话中的权威处境为准：
>
> - `NEW_HOME`：只能使用新屋意图池与新屋片段；
> - `EMPTY_HOME`：只能使用旧屋意图池与旧屋片段，C 槽固定为 `LEAVE_HOME`；
> - `OUTSIDE`：只能使用外面片段。
>
> 不再要求“三个回合结束时动物必须已经不在屋里”，也不得因为到了第 18 回合就自动切换成 `OUTSIDE`。
>
> 空的处境不是上述三种处境中的任何一种；不得替它猜默认值。

##### 将规则（9）移入 `OUTSIDE` 片段

> **（9）【`OUTSIDE` 末段 · 楼道口边界】**
>
> 这一条只在权威处境为 `OUTSIDE` 且已经进入末段时生效。
>
> 最后一个可玩回合的场景必须落在某个楼道口。冷天往背风处钻，因此返回旧地、寻找新的地方或留在附近都可以走到楼道口。
>
> 只有玩家明确选择返回旧地时，这个楼道口才是旧家的那栋楼，并允许提出【走回门前】；其他路径可以落在别的楼道口，不得偷写成已经回到旧家。
>
> 楼道、楼梯间和门前都属于 `OUTSIDE`。它可以走到旧家的门前，但不能进入旧屋；不得写门为它打开，也不得制造 `OUTSIDE → EMPTY_HOME`。

##### 在 `OUTSIDE` 片段增加结局启用条件

> **【`OUTSIDE` 专属结局】**
>
> - 【太近了】：仅当【近人】高位且【身子】归零时允许提出；
> - 【走回门前】：仅在末段、玩家明确选择返回旧地并抵达旧家门前后允许提出；
> - 【没有名字的】：仅当【身子】耗尽且【地面】低位时允许提出。
>
> `NEW_HOME` 与 `EMPTY_HOME` 不得提出这三个结局。结局存在于本局的 `endings[]` 中，不代表当前处境已经允许使用它。
>
> 【没有名字的】不得写成它从来没有名字；只能写经过的人不知道孩子以前怎样叫它。

还有一个必须写进 2b 简报的兼容条件：

> 对没有新局面键、已经标记为旧局的存档，继续使用旧版回合指令；不能把“空处境”送进上述新共同主干后再临时猜一个片段。`ArchetypeRegistry` 中同时用于逐回合提醒的【近人】说明，也必须保留旧局分支，否则“旧局沿用今天行为”并不成立。

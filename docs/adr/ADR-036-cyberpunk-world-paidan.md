# ADR-036 · 新世界《派单》(cyberpunk 占位 id 激活,单体,深界)

- **日期**:2026-11-09
- **状态**:草案(纯文档,零代码;本 ADR 只落勘察与决策方向,**不含实现**。与源码或既有立字冲突的五处标「⚠️ 待 Felix 裁定」,文案类标「待 Felix 定稿」,汇总见文末清单)
- **决策者**:Felix

## 背景

`cyberpunk` 是 CONTEXT §三.4 原 5 枚举里**仅剩的「已知未开放」占位**(`life_sim` 已由 ADR-020《寻常》激活)。
[世界目录](../world-catalog-and-experience-modes.md) 已把它从 B 档挪进 A 档(引擎零改),归属侧当时记为「待定」;
**Felix 2026-11-09 裁定归深界**。

本 ADR 给这个占位一个具体世界:**《派单》**——城中村里的跑腿员,靠一个虚构的派单平台按单计酬、没有底薪。
世界的引擎是一条从不解释的运转规律:**每一次提前送达,系统把这次用时记成你「能做到」的标准,此后时限收紧。**
恐惧不来自怪物,来自「被看见、被学会、被替代」。

**与旧文件的口径差(如实记,不是冲突)**:[世界库扩展 backlog](../world-library-expansion-backlog.md) 第二级那行写的是
「义体 / 信用点 / 网络入侵轴」。本 ADR 不沿用这套轴:义体与刷机降为**物件和选项**,不单独成轴;数值轴改为体力 / 余钱 / 评分 / 画像(决策 3)。
旧文件正文不回改,自本 ADR 起以本 ADR 为准。

约束条件:

1. **单体世界,不是融合组合,也不属一生制族**:ADR-014 的 per-combo 槽和 ADR-021 的族层都不能直接套用(勘察 1)。
2. **引擎 / 校验语义无知不动**(ADR-008):结局判定的语义产出方仍是模型(ADR-010),引擎只读 `outcome` 与致命轴数值。
3. **`schemaVersion` 能不动就不动**(仍 "0.4");要动就另起 ADR 并回写 CONTEXT。
4. **一世界一个一级记忆点**(ADR-017 / AGENTS.md Motion Constraints §1);新增记忆点要写明它替代谁或降级谁(§3)。
5. **深界口径**:不确认超自然、不出现怪物,只写现象,不写解释。
6. **题材贴近现实平台**:要认真防影射(勘察 6)。

### 勘察结论(只读 `main` `8a468f1`,2026-11-09)

#### 勘察 1 · 时间结构(三个夜班 + 收工回合):三套现成时钟都不能直接用;最小改法是加一张单体按回合注入表

| 候选载体 | 能否借用 | 依据 |
|---|---|---|
| 融合 `FusionTurnCopy.turnClock`(ADR-035 决策 4 修订段) | **不能直接借** | 注入点 `TurnPromptBuilder.fusionTurnClock` 第一行就是 `if (!ctx.fused()) return "";`(`TurnPromptBuilder.java:655`),单体局一律空串。它的形状(`IntFunction<String>`,按 `state.turn + 1` 算出一段文字)**恰好是本世界需要的**,只是挂错了层 |
| 一生制 `LifeStageTables` / `LifeStageTable`(ADR-021 刀 2) | **不能借** | ① `LifeStageTables` 在类加载时与 `LifetimeFamily.WORLD_FAMILY` 对拍,不是族成员拿不到表;② 拿到表就会拿到族层四条片段(不显示岁数 / 最后一回合是活着的 / 时钟契约「每往后一个回合都要比上一个更靠近一生的尽头」),语义全错;③ 表自带出口选项 `X`「就到这里」,本世界没有这个出口。把 `cyberpunk` 登进一生制族 = 为借一张时钟表吃下整族语义,否决 |
| 单体 per-archetype 回合指令槽 `TURN_DIRECTIVES`(ADR-020 §10) | **能用,但只能装固定文字** | 非一生制世界登记模板时,代码已留了一条路(`archetypeTurnDirective`:`table == null` → 只喂 `%1$s` 回合号,时钟槽全空)。模板拿得到回合号,却**算不出「本回合属于哪个夜班」**——那要让模型自己按表推,而 ADR-035 已证明模型自己推时段会稳定漂移(第二夜分别拖 15 / 31 回合) |

**最小改法**:在 `TurnPromptBuilder` 加一张**单体**按回合注入表 `Map<String, IntFunction<String>>`(形状照抄 `FusionTurnCopy.turnClock`),
注入位置与 `fusionTurnClock` 相同(「请推进第 n 回合」之前),两者互斥(融合局只走融合那张、单体局只走单体这张)。
**未登记的世界拿到空串 → 既有六个单体世界的回合 prompt 逐字节不变**(parity 线由现有 golden 守)。不动 schema、不动引擎。

**与 brief 的出入(⚠️ 待 Felix 裁定)**:brief 写「每个夜班 8–12 回合」。**按回合号查表只能给出固定长度**;
要让夜班长度在 8–12 之间浮动,必须由某一方在运行时决定「这一班到头了」——
交给模型就回到 ADR-035 的漂移;交给引擎就要在 state 里加一个字段(动 schema)。故本 ADR 的推荐是**每个夜班长度不同,但都写死在表里**
(见决策 2),「8–12」由三班各取一个定值来满足。

**替代简化方案(备选)**:不分夜班,只按回合数推进(如「第 n / 33 单」),收工回合取消。代价:失去「收工睡觉回体力 / 交租前对账」两个节拍,
体力与余钱的恢复只能散落在夜班中间。只在冒烟证明三段结构撑不住时退到这一档。

#### 勘察 2 · 结局「把话传下去」:`discovered` 进得了模型的判断,进不了引擎的判断

- **引擎侧**:`Engine.apply` 收 `discoveredRuleIds` → `markRuleDiscovered` 把 `rules[].discovered` 置 true(`Engine.java:290`、`:442`)。
  结局判定是**模型提议 `ending.id` → 引擎只校验 id 存在 + 极性 gate**(`Engine.java:304–338`)。
  引擎**从不读 `endings[].condition`**,也没有「数 discovered」的逻辑。要引擎据 discovered 判结局 = 让引擎懂结局语义,违反 ADR-008 / ADR-010,否决。
- **模型侧**:回合 prompt 带 `engine.contextJson()` = 视图 2 全量快照,**含每条规则的 `discovered`、`isTrue`、`content`**。
  所以模型**看得见**「哪几条已识破、哪几条是假的」,能按 condition 自己数。
- **两个缺口**:
  1. `discovered` 的语义是「验证真伪 / 看清机制」(`TurnPromptBuilder.java:129`),**真规则也会被标**。「识破假规则」= `discovered:true` 且 `isTrue:false`,
     还得再筛出来源是「群里说」的——来源靠勘察 3 的前缀。
  2. 「并告诉了下一个人」是**叙事事件**,state 里没有任何字段记它,只能靠模型从 `log` / `logSummary` 里认。

**替代判定(推荐)**:condition 写成可判定的中文,**不出现英文字段名**(同 CONTEXT §三.16 (5) 的口径;且 `endings[].condition` 随 init 下发、不剥,
写进字段名等于告诉玩家后台怎么算):
> 「体力大于 0;已识破至少 2 条以『【群里说】』开头、且确实不成立的规则;已在叙事中把其中至少一条当面告诉了另一个跑腿员;余钱 ≥ 50。」

并在回合指令槽里加一条兑现要求:**玩家选了「告诉别人」一类行动时,本回合叙事必须写出对方是谁、听到了哪一条**(给后续回合的模型留下可认的痕迹)。
这条判定**完全依赖模型**,冒烟需专项核(已知代价 2)。

#### 勘察 3 · 规则来源:schema 表达不了;推荐放 `content` 前缀,不加字段

- `GameSchemas.validateWorld` 对 `rules[]` 只校验 `id` / `content` / `isTrue`(可选)/ `hiddenLogic` / `discovered`(`GameSchemas.java:65–76`),**没有来源字段**。
- 校验器**不拒多余字段**,`toClientState` 的消毒是**黑名单**(只剥 `LeakDetector.LEAK_TOKENS`),所以技术上模型多吐一个 `source` 也能过校验、也会下发。
  但按本项目口径,在 state schema 里**正式**加一个字段要升 `schemaVersion`(ADR-010 加 `endings[].outcome` 即 0.3 → 0.4 的先例),
  还要改 CONTEXT §二、前端 `types/schema.ts` 的 `Rule`、校验器(否则「给了不校验」就是一个无人守的字段)。
  **⚠️ 加字段牵涉 `schemaVersion`(→ "0.5"),标出,不推荐。**
- **推荐:`content` 前缀**——「【服务守则】……」/「【群里说】……」。零 schema 变更;玩家本来就该看到来源(它是公开信息,不是隐藏逻辑);
  模型在 contextJson 里按前缀能数(勘察 2)。代价:前缀格式靠提示词守,模型可能写成「群里说:」「〔群里〕」等变体 → world-gen 指令槽写死两个前缀原文,冒烟核格式。

#### 勘察 4 · 记忆点:`signatureAxisKey` 离不开皮肤登记;后端无法确定性地知道「本回合跨档了」

- **前端**:`signatureAxisKey` 是 `WorldSkin` 的字段(`theme/contract.ts:248`),`useSignalCrossing(skin, …)` 在 `skin` 为 null 时恒返回 tick 0。
  而 `WorldSkin` 的必填项包括 `Ambient` / `Stats` / `Actions` 三个组件与四个 class 令牌;`SkinId` 是封闭联合类型(四个基础世界)。
  `skin` 字段同时是 ADR-018 §4.5 的 feature gate,登记了就离开「未登记世界 DOM 对拍」那条护城河。
  **结论:不登记皮肤就用不了**。
- **方向不冲突**:`useSignalCrossing` 只认「档序号变大」;画像是 accumulation 轴,档表升序(生手 → 熟手 → 标杆),
  值涨 = 序号变大 = 触发,画像下降不触发 —— **正好是 brief 要的「上跨才播、下降不播」**。
  末日那段注释(`skins.tsx:79`,「签名机制判的是向上跨档 = 成就」)讲的是**语义**,机制本身只看方向;克苏鲁禁忌知识(perilAtHigh 双刃)已经挂过签名轴,先例在。
- **后端**:跨档发生在本回合的 `stateUpdate` 里,而叙事是**先**流出的;下一回合 prompt 只看得到**当前值**,`log` 不存数值,**拿不到上一回合的档**。
  故后端没有现成的确定性信号,只能让模型在同一次生成里自己协调(它写叙事时已经知道自己要把画像落到多少)。
- **最小落地(两层,分开切)**:
  1. **后端软层(先做)**:回合指令槽写死「若本回合 `stateUpdate` 让画像越过 30 或 60(向上),叙事中头盔逐字播『已为你优化时限。』一次,不解释,只写下一单的时限比上一单短;画像下降或不跨档时绝不出现这句」。
     靠模型守,冒烟核「播了但没跨 / 跨了没播」的比例。
  2. **前端硬层(后做,与卡面 / 顶图同批)**:登记一个 `cyberpunk` 皮肤,`signatureAxisKey: 'profile'`,在跨档那一回合由前端**确定性**渲染头盔原句。
     所需:`SkinId` 加一项 + 一套 `WorldSkin`(可先复用通用组件,`Ambient` 给空实现)+ ADR-017 §5 补一行 + AGENTS.md §1 一级记忆点表补一行 +
     ADR-018 §4.5.1 对拍集合里移除本世界。**「不登记完整皮肤就用信号」需要改 contract(把 `signatureAxisKey` 挪出 `WorldSkin`),那是全局契约变更,不推荐为一个世界做。**

#### 勘察 6 · 雷区:ROADMAP §六 管的是上架资质,题材风险的约束在仓库里找不到出处

**先如实记一个出入**:brief 引用的「不写政治隐喻、不写真实品牌和地名」**在仓库里没有出处**——
`docs/`、`prompts/`、`server/src/main` 全文检索「政治 / 品牌 / 影射」均无此类立字;[ADR-004](ADR-004-content-safety.md) 的程序层只拦**自伤**一条,
其余靠 provider 侧过滤与提示词。**本 ADR 把它作为本世界的硬约束写进决策 9 / 10;是否升为全局约束(进骨架、对所有世界生效)⚠️ 待 Felix 裁定**,挂账。

**ROADMAP §六 逐条**(该清单在路线 B 下已转为「未来补合规时的检查表」):

| §六 条目 | 本世界的风险 | 规避 |
|---|---|---|
| 小程序账号与主体 | 与世界无关 | — |
| 游戏类目与版号 | 与世界无关(不引入虚拟货币;「余钱」是局内数值轴,不可购买) | 不给余钱任何充值 / 兑换口径 |
| 内容安全(生成内容须过审) | **本世界是全库最贴近现实社会议题的一个**,风险从「血腥 / 恐怖」变成「被读成影射 / 社会评论」。程序层(ADR-004)不拦这类内容,只能靠提示词 | 决策 9(禁用词)+ 决策 10(题材边界)写进 world-gen 与回合两个指令槽;冒烟人工通读 |
| 备案(算法 / 大模型) | 本世界的主题**就是**「算法如何管人」;若将来补备案,演示材料里这个世界最容易被追问 | 解冻合规时,对外材料不以本世界为示例;本世界描写的是**虚构平台的虚构规则**,不出现任何监管主体、政策、法规名 |
| 备案措辞(避「游戏」字样) | 与世界无关 | — |

**题材专项(认真写的一项)**:

1. **核心机制本身就贴着一个公共议题。**「提前送达 → 时限被学去 → 时限收紧」与现实中关于外卖配送算法的广泛报道和讨论高度同构。
   **这一点措辞消除不了,因为它就是玩法本身。** 能做的是:不让任何一处文本把它**指认**为现实。
   - 平台名、商家名、小区名、街道名、城市名全部虚构,且**不得与现实平台谐音、拆字、取同色**(例如不用一个字的颜色或动物来指代平台);
   - 跑腿员的制服 / 头盔 / 餐箱**不写颜色**,或只写磨损、反光条等无品牌信息的细节——现实平台靠颜色识别,写颜色等于点名;
   - 不出现任何现实年代刻度、真实新闻事件的变形复述(如某次具体的事故、某篇报道的标题句式);
   - 系统只有一句台词「已为你优化时限。」,**不出现平台方的人格化发言人、公关口吻、致歉信**——那是现实事件的常见形状。
2. **「把话传下去」不能写成组织行动。** 本结局是「一个人把识破的一条经验告诉下一个人」,**不是**联合、串联、罢单、维权、讨薪、投诉、
   上访、集体停工。这类词与情节一律禁(决策 10),也不写「大家一起不接单」这类变体。这是本世界政治敏感度最高的一个口子。
3. **城中村不写成城市治理题材。** 不出现拆迁、清退、整治、驱赶、暂住、户籍、执法人员与城中村居民的冲突;城中村只作为地形(窄巷、握手楼、没电梯的九楼)存在。
4. **刷机改装**:作为虚构世界里的**风险选项**合适,条件是:
   - **只写物件与后果,不写方法**——可以写「改装过的头盔」「群里流传的一个刷法」,不写任何步骤、工具名、固件名、参数;
     这也是 ADR-004 被否决的那一条(「现实可执行的危险指令」)在本世界的提示词侧收口;
   - **永远有被查的代价**(评分重挫),不写成无风险最优解;
   - 它既可以是「群里说」的假规则(刷了也没用,反而被标记),也可以是真规则(确实能把画像压一点)——真假由 world-gen 每局决定,
     但 hiddenLogic 里必须写清被查的条件。
5. **交通违规不得被奖励。** 「一个红灯都等不起」只能作为**压力的描写**;闯红灯、逆行、走机动车道若作为选项出现,必须带代价(摔车 / 体力 / 评分),
   **不写成更快更好**,也不写成玩家被叙事夸奖的行为。
6. **自伤**(ADR-004 程序层唯一拦截项):「倒在楼道里」是体力耗尽的**倒下**,不写死因,不写高处、天台、窗边的意象;
   全局自伤硬禁照常生效。高层、天台在本世界是常见地形,**在体力见底档禁止与「坠」「跳」同句出现**。
7. **惊悚层**(标杆传说 / 系统知道太多 / 夜单):只写现象(工号、时限精确到秒、电梯不停的楼层、在更新的备注),**不给解释,不确认超自然**,
   不写成「平台在用死人跑单」之类可被读成都市传说式指控的定论。

## 候选方案

> 本 ADR 的核心选择在**时间结构**(勘察 1),其余各项都是在既有槽位上填内容,不另列方案。

### 方案 A:模型按表自推时段

在 `TURN_DIRECTIVES` 里写死三班一收工的切分表,让模型按回合号自己判断当前在哪一班。

**优点**:
- 零 Java 改动(只加一段模板文字)。

**缺点**:
- ADR-035 两轮冒烟的实证:时段交给模型推,第二夜分别拖了 15、31 回合,补节奏说明也无效。
- **排除理由**:同一失效形状已经付过一次学费。

### 方案 B:借一生制时钟表

把 `cyberpunk` 登进 `LifetimeFamily`,用 `LifeStageTable` 表达三班。

**优点**:
- 有现成的阶段 / 推进语 / 收敛窗口结构。

**缺点**:
- 带入族层四条片段与出口选项 `X`,语义全错(勘察 1)。
- **排除理由**:为借一张表吃下整族语义。

### 方案 C:引擎记「当前班次」

state 里加一个班次字段,由模型提议「本班结束」、引擎落账,夜班长度可在 8–12 间浮动。

**优点**:
- 夜班长度真的可变。

**缺点**:
- 动 state schema(`schemaVersion` → "0.5")、动 `Engine.apply`、要重录 golden。
- 「本班结束」仍由模型提议,漂移风险只是从叙事移到了字段上。
- **排除理由**:成本高,且没解决根因。

### 方案 D:单体按回合注入表,班次长度写死(本 ADR 采纳)

照抄 `FusionTurnCopy.turnClock` 的形状,给单体世界开一张 `Map<String, IntFunction<String>>`;三个夜班各取一个定长(决策 2)。

**优点**:
- 与 ADR-035 决策 4 修订段**同一机制**,已有冒烟实证(73 回合中 72 回合与注入一致)。
- 不动 schema、不动引擎;未登记世界空串,parity 零回归。

**缺点**:
- 夜班长度不能随局浮动(「8–12」只能由三班各取一个定值满足)。
- 「单体按回合注入」从此是一个通用口子,别的世界可能想挂东西 → 判据写进类注释:只收「叙事推进在冒烟中稳定失效」的时段信息(CONTEXT §三.16 (9) 的口径平移到单体)。

## 最终决策

### 1. 名称与目录(文案待 Felix 定稿)

- archetype id 沿用 `cyberpunk`(不改 `KNOWN`、不改前端联合类型)。
- `displayName`「派单」/ `tagline`「你每快一次,它就记住一次。」/ `vibeTag`「城中村 · 高压」——**三条均待 Felix 定稿**;displayName 口径见勘察 5 ⚠️。
- 归属:**深界**(Felix 2026-11-09 裁定)。归属目前只在世界目录文档里有载体(代码里没有 `experienceMode` 字段),激活批顺手改那一行。
- `rulesCarryTruth = true`。

### 2. 时间结构:三个夜班 + 收工回合,定长写死(方案 D;回合数待 Felix 定稿)

| 段 | 回合 | 说明 |
|---|---|---|
| 第一夜 · 夜班 | 1–9 | 9 回合 |
| 第一夜 · 收工 | 10 | 收工回合:睡觉回体力、对账 |
| 第二夜 · 夜班 | 11–20 | 10 回合 |
| 第二夜 · 收工 | 21 | 同上 |
| 第三夜 · 夜班 | 22–32 | 11 回合 |
| 第三夜 · 收工 | 33 | **结局回合**:按决策 7 的顺序判定,本回合必须给出结局 |
| 之后 | 34+ | 每回合注入「本回合必须给出结局」(同 `yanqiTurnClock` 的兜底形状) |

- 注入文字只写「第几夜 · 夜班 / 收工」与「这是本班第几单」,不写结局条件。
- 第 32 回合注入「本班最后一单」,让第 33 回合的收工自然落地。
- 收工回合的选项**不出现接单**,给的是吃饭、睡觉、换电、修车、在群里说话这类动作。

### 3. 数值轴(0–100;只有体力致命 —— ⚠️ 评分是否致命待裁定,见已知代价 1)

| 轴 | key | 工厂 | 档(由低到高) | 行为提示要点 |
|---|---|---|---|---|
| 体力 | `hp` | `depleting`(lethal) | 0–20 见底「手抖得握不住车把,看路开始重影」/ 21–50 透支「上楼要扶栏杆,接电话先喘一口」/ 51+ 撑得住「一口气上七楼,下楼还能小跑」 | 爬楼、赶时、淋雨、摔车降;歇脚、吃热饭、收工睡觉升。档界 50/20 与全库默认一致 |
| 余钱 | `cash` | `resource`(非致命) | 空「一碗粉也要掂量,换电得先接单」/ 紧「每花一笔都先算一遍交租那天」/ 宽裕「能吃顿热的,车坏了也修得起」 | 100 = 够交房租;完单、打赏升;吃饭、换电、修车、租义体、超时扣款降。**档界数值待定稿**(brief 未给,缺省 50/20) |
| 评分 | `rating` | `resource`(非致命,见 ⚠️) | 观察「只剩远单、夜单、九楼没电梯的单」/ 普通「单照派,都是别人挑剩的」/ 优选「近单好单先推给你」 | 准时、好评、接没人要的单升;超时、差评、拒单、刷机被查降;归零即停派。**档界数值待定稿** |
| 画像 | `profile` | `doubleEdged`(accumulation + perilAtHigh) | 生手 0–29「时限宽,系统还在看你」/ 熟手 30–59「时限按你最快的那几次算」/ 标杆 60+「时限只够一路不停,一个红灯都等不起」 | 每次提前送达、使用联网义体时涨;**不自然回落**;只有超时(代价:评分)或刷机(代价:被查风险)能压一点。唯一越高越糟的轴 |

- 画像档界 30 / 60 与全库 accumulation 默认(31 / 61)差 1,按 brief 取 30 / 60,构造器校验允许。
- 画像初值:待定稿(建议 5–10 的低正值,与「生手」吻合)。体力 / 余钱 / 评分初值同样待定稿。
- severity:体力最低档 danger、次低 caution;画像最高档 danger、次高 caution(perilAtHigh);**余钱与评分是非致命资源轴,severity 全 neutral**——
  「评分 观察档」在前端不会染危险色。若希望它染色,只有改评分为致命轴一条路(已知代价 1)。

### 4. 运转规律与「快不是永远错」

- 每回合叙事**必须交代这一单是提前、卡点还是超时**,并据此落数值:
  提前 → 画像涨、评分可能涨;卡点 → 画像不动;超时 → 评分降、余钱扣、画像可压一点。
- 系统从不解释,只在画像向上跨档时播一句「已为你优化时限。」(决策 8)。
- **防止「卡点」成为免费最优解**:每个夜班至少出现一单「快对某个人真的重要」的单(送药、冷链、门后有人在等)。
  提前送到对那个人是对的,代价是画像被学去。**不得把快写成永远错,也不得把慢写成永远对**;顾客不是道德题里的占位符,要有具体的人和具体的需要。

### 5. 世界边界与赛博物件

塔楼区由无人机配送,人只送城中村和塔楼最后几层。以下物件允许,并尽量接到核心机制上:

- **廉价义体 / 外骨骼**:例,租来的助力膝——爬楼更快,但每一步都上传平台,画像涨得更快。
- **头盔显示屏**:派单音、倒计时、「已为你优化时限。」都在这里出现。
- **刷机改装**:例,改装头盔把用时报慢、骗过画像;可作「群里说」规则(真假由每局决定),也可作风险选项,被查到则评分重挫。措辞约束见勘察 6 第 4 条。
- **霓虹招牌、全息广告、塔楼无人机**:只作场景物件。

没有战斗。一切平台名、地名、人名都虚构。

### 6. 规则

- 每局 6–8 条(骨架已是 6–8),**真 ≥ 3、假 ≥ 2**(比单体骨架的「至少各一条」严,写进 world-gen 指令槽);
- 来源以 `content` 前缀表达:「【服务守则】」(官方条款口吻)与「【群里说】」(口头经验口吻)**各 ≥ 2 条**(勘察 3);
- 至少一条真规则与画像有关;
- 每条假规则在 `hiddenLogic` 里写一个**可识破的迹象**(玩家通过什么现象能发现它不成立)。

### 7. 结局(7 条;判定条件为草案,待 Felix 定稿)

| id(草案) | 标题 | 极性 | condition 草案 |
|---|---|---|---|
| `rent_paid` | 交上了 | success | 第三夜收工时,体力大于 0,余钱 ≥ 80 |
| `kept_the_pace` | 卡点的人 | success | 第三夜收工时,体力大于 0,余钱 ≥ 60 且画像 ≤ 40 |
| `passed_it_on` | 把话传下去 | success | 见勘察 2 推荐写法;余钱 ≥ 50 |
| `collapsed_in_stairwell` | 倒在楼道里 | failure | 体力 ≤ 0(唯一绑致命轴、供引擎兜底命中的失败结局) |
| `dispatch_stopped` | 停派 | failure | 评分 ≤ 0 |
| `became_benchmark` | 成了标杆 | failure | 画像 ≥ 95;最后一句是「已为你优化时限。」推给一个新跑腿员 |
| `almost` | 差一点 | neutral | 三夜走完,以上都不满足 |

**⚠️ 待 Felix 定稿的三处逻辑问题**:
1. **「交上了 ≥ 80」与「100 = 够交房租」矛盾**:按轴定义,80 交不上房租。要么改轴定义(如「80 = 够交房租」),要么改门槛为 100(但 clamp 后 100 是顶格,几乎不可达)。
2. **三个好结局条件重叠**(余钱 85、画像 30 同时满足「交上了」与「卡点的人」)。需要一个优先序写进第 33 回合的注入,建议:把话传下去 > 卡点的人 > 交上了 > 差一点(越难达成的越优先)。
3. **两条坏结局引擎不兜底**:引擎只在**致命轴**归零时强制结束并挑失败结局(CONTEXT §三.8)。评分按 brief 是非致命 → 评分 0 时**引擎不会结束这一局**;
   画像是累积轴 → 引擎永不据它结束。这两条只能靠模型提议(见已知代价 1)。

### 8. 记忆点(唯一)

画像**向上**跨档(30、60)的那一回合,头盔显示屏和派单音**逐字**播「已为你优化时限。」;画像下降时不播。叙事不解释它,只写下一单的时限比上一单短了。

- 落地分两层(勘察 4):后端软层(提示词约束,先做)+ 前端硬层(登记皮肤后由 `signatureAxisKey: 'profile'` 确定性渲染,后做)。
- 预算口径:它是本世界的**一级记忆点**,上架时 AGENTS.md §1 / ADR-017 一级记忆点表补一行;前端硬层属「低频偶发」槽。
  本世界尚无任何动效,故「替代谁 / 降级谁」一句为「新世界首个动效,无可替代」——前端批实施时再按 Motion Constraints §3 正式声明。
- 这句原文同时是结局「成了标杆」的最后一句(决策 7),**全局只有这一句系统台词**。

### 9. 禁用词(三类,写进 world-gen 与回合两个指令槽)

| 类别 | 词 | 理由 |
|---|---|---|
| 题材标签 | 赛博、赛博朋克、反乌托邦、巨型企业 | 风格靠物件呈现;叙事给世界贴标签,读者会跳出世界,而且标签替代了具体描写 |
| 现实批判用语 | 资本、剥削、打工人 | 题材贴近现实平台,这几个词会把叙事从「一个人的一夜」拉成社会评论,正是勘察 6 要防的影射读法 |
| 现实名称与数字 | 现实品牌、平台名、地名;百分比与成功率 | 前者防点名;后者同 ADR-011「hint 不写精确成功率」,本世界的数字只用分钟、秒、楼层、单数、余钱 |

霓虹、酸雨、义体、黑客**允许作为具体物件**出现,**禁止作为笼统的气氛形容**。另,勘察 6 第 2、3 条列出的组织行动与城市治理类词,并入本表一同注入。

### 10. 惊悚层(三条均待 Felix 定稿)

1. **「标杆」传说**:群里流传一个工号,所有人的时限都照他算,没人见过他收工。
2. **系统知道得太多**:还没决定的路线已被「规划」,时限精确到喘气的秒数。
3. **夜单**:凌晨的单送往电梯不停的楼层,门后无人应答,备注却在更新。

约束:不确认超自然,不出现怪物,只写现象不写解释;恐惧来自被看见、被学会、被替代。勘察 6 第 7 条一并适用。

### 11. 写作风格(进回合指令槽)

冷、准、短,第二人称;情绪交给分钟数、楼层和备注。先写能看见、听见、摸到的变化,再写系统字段。赛博元素一律写成具体物件。示例(进提示词,作正反对照):

- 这样写:「楼下的霓虹招牌坏了半截,只剩一个『药』字在闪。」/ 不要这样写:「霓虹在酸雨里闪烁,城市沉入赛博的夜。」
- 这样写:「助力膝在第六层发出一声短促的提示音,头盔角落的时限跟着少了四十秒。」/ 不要这样写:「冰冷的义体吞噬了他的人性。」

(注:第二条反例里的「他」与第二人称要求不一致,是反例本身的一部分,保留。)

### 12. 视觉(只写方向,本 ADR 不实施)

湿柏油的蓝黑作底、钠灯琥珀、手机屏冷白,加霓虹招牌的残光。卡面与顶图以后照《寻常》流程单独做(先验玩法再投视觉,ADR-020 裁定一的顺序)。
⚠️ 与勘察 6 第 1 条的交叉:钠灯琥珀只用于**环境光**,不得落在跑腿员的衣物 / 餐箱上形成「一种颜色的骑手」。

### 关键理由

1. **时钟走已验证的路**:单体按回合注入与 ADR-035 决策 4 修订段同一机制,不新造判定、不动 schema。
2. **来源用前缀不用字段**:来源是公开信息,不值得为它升 `schemaVersion`。
3. **结局判定留在模型侧**:与全库一致(ADR-010),引擎不为一个世界学会数 discovered。
4. **记忆点先软后硬**:先用提示词验证「跨档那一回合播一句」在叙事上成立,再投前端皮肤,与《寻常》「先验玩法再投视觉」同序。

## 已知代价

1. **两条坏结局没有引擎兜底**(决策 7 ⚠️ 3):评分 0 时局不会被强制结束,模型若不提议「停派」,玩家会在 0 评分下继续接单;画像 ≥ 95 同理。
   **缓解方式**:回合指令槽写成硬约束(「评分落到 0 的那一回合必须提议停派」);冒烟专项核。
   **另一条路(⚠️ 待 Felix 裁定)**:把评分改为致命轴(`depleting`)。好处是归零由引擎强制结束、`pickFailureEnding` 按中文名「评分」命中停派、
   低档前端染危险色;代价是与 brief「只有体力致命」相反,且评分 ≤ 10 时结局极性 gate 会拒绝所有成功结局(「评分快没了还交上了房租」会被改判)。
2. **「把话传下去」完全依赖模型**:识破的计数靠模型读 contextJson,「告诉了下一个人」靠模型读 log。**缓解方式**:回合槽兑现要求(勘察 2);冒烟专项核。
3. **记忆点后端层不确定**:模型可能播了但没跨档,或跨了没播。前端硬层做完之前,这是一个软记忆点。
4. **影射风险无法被措辞消除**(勘察 6 第 1 条):核心机制本身就是一个公共议题的形状。措辞约束只能保证「不指认」,不能保证「不被联想」。
   这是本世界被接受的风险,也是我认为本 ADR 最大的风险(见文末)。
5. **33 回合比全库其他单体世界长**:成本按回合线性涨(ADR-016 成本闸门按局 / 按日计,单局变长会更早触顶)。冒烟时记单局 token。
6. **单体按回合注入成为通用口子**:收什么由判据守(方案 D 缺点),判据只在类注释与本 ADR 里,不是代码检查。
7. **「已知未开放」分支失去真实成员**(勘察 5):选 (a) 后,这条分支只有测试里的假占位在跑。
8. **禁用词靠提示词**:程序层没有任何拦截(ADR-004 只拦自伤)。高频字(「资本」在「资本金」里等)机械 grep 会误报,只能人工读。

## 重新审视的触发条件

- 冒烟中,第 33 回合不出结局、或模型在夜班中途自行「收工」的局 ≥ 2 → 重审注入措辞;若仍失效,考虑方案 C(动 schema,另立 ADR)。
- 「评分 0 未提议停派」在冒烟中出现 → 直接触发已知代价 1 的另一条路(评分改致命)的复议。
- 记忆点软层的「播了没跨 / 跨了没播」占跨档回合的比例明显偏高 → 前端硬层提前。
- 第二个单体世界也需要按回合注入时段 → 单体表与融合表合并为一个「按回合注入」接缝(那时才是通用需求)。
- 任何一局叙事出现现实平台名、现实地名、或勘察 6 第 2 / 3 条所列组织行动 / 城市治理情节 → 停止对外开放本世界,先补约束。

## 背景

`cyberpunk` 是 CONTEXT §三.4 原 5 枚举里**仅剩的「已知未开放」占位**(`life_sim` 已由 ADR-020《寻常》激活)。
[世界目录](../world-catalog-and-experience-modes.md) 已把它从 B 档挪进 A 档(引擎零改),归属侧当时记为「待定」;
**Felix 2026-11-09 裁定归深界**。

本 ADR 给这个占位一个具体世界:**《派单》**——城中村里的跑腿员,靠一个虚构的派单平台按单计酬、没有底薪。
世界的引擎是一条从不解释的运转规律:**每一次提前送达,系统把这次用时记成你「能做到」的标准,此后时限收紧。**
恐惧不来自怪物,来自「被看见、被学会、被替代」。

**与旧文件的口径差(如实记,不是冲突)**:[世界库扩展 backlog](../world-library-expansion-backlog.md) 第二级那行写的是
「义体 / 信用点 / 网络入侵轴」。本 ADR 不沿用这套轴:义体与刷机降为**物件和选项**,不单独成轴;数值轴改为体力 / 余钱 / 评分 / 画像(决策 3)。
旧文件正文不回改,自本 ADR 起以本 ADR 为准。

约束条件:

1. **单体世界,不是融合组合,也不属一生制族**:ADR-014 的 per-combo 槽和 ADR-021 的族层都不能直接套用(勘察 1)。
2. **引擎 / 校验语义无知不动**(ADR-008):结局判定的语义产出方仍是模型(ADR-010),引擎只读 `outcome` 与致命轴数值。
3. **`schemaVersion` 能不动就不动**(仍 "0.4");要动就另起 ADR 并回写 CONTEXT。
4. **一世界一个一级记忆点**(ADR-017 / AGENTS.md Motion Constraints §1);新增记忆点要写明它替代谁或降级谁(§3)。
5. **深界口径**:不确认超自然、不出现怪物,只写现象,不写解释。
6. **题材贴近现实平台**:要认真防影射(勘察 6)。

### 勘察结论(只读 `main` `8a468f1`,2026-11-09)

#### 勘察 1 · 时间结构(三个夜班 + 收工回合):三套现成时钟都不能直接用;最小改法是加一张单体按回合注入表

| 候选载体 | 能否借用 | 依据 |
|---|---|---|
| 融合 `FusionTurnCopy.turnClock`(ADR-035 决策 4 修订段) | **不能直接借** | 注入点 `TurnPromptBuilder.fusionTurnClock` 第一行就是 `if (!ctx.fused()) return "";`(`TurnPromptBuilder.java:655`),单体局一律空串。它的形状(`IntFunction<String>`,按 `state.turn + 1` 算出一段文字)**恰好是本世界需要的**,只是挂错了层 |
| 一生制 `LifeStageTables` / `LifeStageTable`(ADR-021 刀 2) | **不能借** | ① `LifeStageTables` 在类加载时与 `LifetimeFamily.WORLD_FAMILY` 对拍,不是族成员拿不到表;② 拿到表就会拿到族层四条片段(不显示岁数 / 最后一回合是活着的 / 时钟契约「每往后一个回合都要比上一个更靠近一生的尽头」),语义全错;③ 表自带出口选项 `X`「就到这里」,本世界没有这个出口。把 `cyberpunk` 登进一生制族 = 为借一张时钟表吃下整族语义,否决 |
| 单体 per-archetype 回合指令槽 `TURN_DIRECTIVES`(ADR-020 §10) | **能用,但只能装固定文字** | 非一生制世界登记模板时,代码已留了一条路(`archetypeTurnDirective`:`table == null` → 只喂 `%1$s` 回合号,时钟槽全空)。模板拿得到回合号,却**算不出「本回合属于哪个夜班」**——那要让模型自己按表推,而 ADR-035 已证明模型自己推时段会稳定漂移(第二夜分别拖 15 / 31 回合) |

**最小改法**:在 `TurnPromptBuilder` 加一张**单体**按回合注入表 `Map<String, IntFunction<String>>`(形状照抄 `FusionTurnCopy.turnClock`),
注入位置与 `fusionTurnClock` 相同(「请推进第 n 回合」之前),两者互斥(融合局只走融合那张、单体局只走单体这张)。
**未登记的世界拿到空串 → 既有六个单体世界的回合 prompt 逐字节不变**(parity 线由现有 golden 守)。不动 schema、不动引擎。

**与 brief 的出入(草案时 ⚠️ 待裁定;已定,见下)**:brief 写「每个夜班 8–12 回合」。**按回合号查表只能给出固定长度**;
要让夜班长度在 8–12 之间浮动,必须由某一方在运行时决定「这一班到头了」——
交给模型就回到 ADR-035 的漂移;交给引擎就要在 state 里加一个字段(动 schema)。故本 ADR 的推荐是**每个夜班长度不同,但都写死在表里**
(见决策 2),「8–12」由三班各取一个定值来满足。

> **已定(Felix 2026-11-10)**:定长写死,改为 **7 / 8 / 9 回合各加 1 个收工回合,共 27 回合**(不再追求落在 8–12 区间)。见决策 2。

**替代简化方案(备选)**:不分夜班,只按回合数推进(如「第 n / 27 单」),收工回合取消。代价:失去「收工睡觉回体力 / 交租前对账」两个节拍,
体力与余钱的恢复只能散落在夜班中间。只在冒烟证明三段结构撑不住时退到这一档。

#### 勘察 2 · 结局「把话传下去」:`discovered` 进得了模型的判断,进不了引擎的判断

- **引擎侧**:`Engine.apply` 收 `discoveredRuleIds` → `markRuleDiscovered` 把 `rules[].discovered` 置 true(`Engine.java:290`、`:442`)。
  结局判定是**模型提议 `ending.id` → 引擎只校验 id 存在 + 极性 gate**(`Engine.java:304–338`)。
  引擎**从不读 `endings[].condition`**,也没有「数 discovered」的逻辑。要引擎据 discovered 判结局 = 让引擎懂结局语义,违反 ADR-008 / ADR-010,否决。
- **模型侧**:回合 prompt 带 `engine.contextJson()` = 视图 2 全量快照,**含每条规则的 `discovered`、`isTrue`、`content`**。
  所以模型**看得见**「哪几条已识破、哪几条是假的」,能按 condition 自己数。
- **两个缺口**:
  1. `discovered` 的语义是「验证真伪 / 看清机制」(`TurnPromptBuilder.java:129`),**真规则也会被标**。「识破假规则」= `discovered:true` 且 `isTrue:false`,
     还得再筛出来源是「群里说」的——来源靠勘察 3 的前缀。
  2. 「并告诉了下一个人」是**叙事事件**,state 里没有任何字段记它,只能靠模型从 `log` / `logSummary` 里认。

**替代判定(推荐)**:condition 写成可判定的中文,**不出现英文字段名**(同 CONTEXT §三.16 (5) 的口径;且 `endings[].condition` 随 init 下发、不剥,
写进字段名等于告诉玩家后台怎么算):
> 「体力大于 0;已识破至少 2 条以『【群里说】』开头、且确实不成立的规则;已在叙事中把其中至少一条当面告诉了另一个跑腿员;余钱 ≥ 50。」

并在回合指令槽里加一条兑现要求:**玩家选了「告诉别人」一类行动时,本回合叙事必须写出对方是谁、听到了哪一条**(给后续回合的模型留下可认的痕迹)。
这条判定**完全依赖模型**,冒烟需专项核(已知代价 2)。

#### 勘察 3 · 规则来源:schema 表达不了;推荐放 `content` 前缀,不加字段

- `GameSchemas.validateWorld` 对 `rules[]` 只校验 `id` / `content` / `isTrue`(可选)/ `hiddenLogic` / `discovered`(`GameSchemas.java:65–76`),**没有来源字段**。
- 校验器**不拒多余字段**,`toClientState` 的消毒是**黑名单**(只剥 `LeakDetector.LEAK_TOKENS`),所以技术上模型多吐一个 `source` 也能过校验、也会下发。
  但按本项目口径,在 state schema 里**正式**加一个字段要升 `schemaVersion`(ADR-010 加 `endings[].outcome` 即 0.3 → 0.4 的先例),
  还要改 CONTEXT §二、前端 `types/schema.ts` 的 `Rule`、校验器(否则「给了不校验」就是一个无人守的字段)。
  **⚠️ 加字段牵涉 `schemaVersion`(→ "0.5"),标出,不推荐。**
- **推荐:`content` 前缀**——「【服务守则】……」/「【群里说】……」。零 schema 变更;玩家本来就该看到来源(它是公开信息,不是隐藏逻辑);
  模型在 contextJson 里按前缀能数(勘察 2)。代价:前缀格式靠提示词守,模型可能写成「群里说:」「〔群里〕」等变体 → world-gen 指令槽写死两个前缀原文,冒烟核格式。

#### 勘察 4 · 记忆点:`signatureAxisKey` 离不开皮肤登记;后端无法确定性地知道「本回合跨档了」

- **前端**:`signatureAxisKey` 是 `WorldSkin` 的字段(`theme/contract.ts:248`),`useSignalCrossing(skin, …)` 在 `skin` 为 null 时恒返回 tick 0。
  而 `WorldSkin` 的必填项包括 `Ambient` / `Stats` / `Actions` 三个组件与四个 class 令牌;`SkinId` 是封闭联合类型(四个基础世界)。
  `skin` 字段同时是 ADR-018 §4.5 的 feature gate,登记了就离开「未登记世界 DOM 对拍」那条护城河。
  **结论:不登记皮肤就用不了**。
- **方向不冲突**:`useSignalCrossing` 只认「档序号变大」;画像是 accumulation 轴,档表升序(生手 → 熟手 → 标杆),
  值涨 = 序号变大 = 触发,画像下降不触发 —— **正好是 brief 要的「上跨才播、下降不播」**。
  末日那段注释(`skins.tsx:79`,「签名机制判的是向上跨档 = 成就」)讲的是**语义**,机制本身只看方向;克苏鲁禁忌知识(perilAtHigh 双刃)已经挂过签名轴,先例在。
- **后端**:跨档发生在本回合的 `stateUpdate` 里,而叙事是**先**流出的;下一回合 prompt 只看得到**当前值**,`log` 不存数值,**拿不到上一回合的档**。
  故后端没有现成的确定性信号,只能让模型在同一次生成里自己协调(它写叙事时已经知道自己要把画像落到多少)。
- **最小落地(两层,分开切)**:
  1. **后端软层(先做)**:回合指令槽写死「若本回合 `stateUpdate` 让画像越过 30 或 60(向上),叙事中头盔逐字播『已为你优化时限。』一次,不解释,只写下一单的时限比上一单短;画像下降或不跨档时绝不出现这句」。
     靠模型守,冒烟核「播了但没跨 / 跨了没播」的比例。
  2. **前端硬层(后做,与卡面 / 顶图同批)**:登记一个 `cyberpunk` 皮肤,`signatureAxisKey: 'profile'`,在跨档那一回合由前端**确定性**渲染头盔原句。
     所需:`SkinId` 加一项 + 一套 `WorldSkin`(可先复用通用组件,`Ambient` 给空实现)+ ADR-017 §5 补一行 + AGENTS.md §1 一级记忆点表补一行 +
     ADR-018 §4.5.1 对拍集合里移除本世界。**「不登记完整皮肤就用信号」需要改 contract(把 `signatureAxisKey` 挪出 `WorldSkin`),那是全局契约变更,不推荐为一个世界做。**

**补记(定稿勘察,`main` `8a468f1`,2026-11-10):《寻常》是怎么把世界名固定下来的 —— 答案是没有固定。**

| 环节 | 《寻常》实际做了什么 | 依据 |
|---|---|---|
| world-gen 骨架 | `world.title` 只要求「用中文」,**不给定值**;单体骨架对所有世界一样 | `WorldGenPromptBuilder.java:62`(「world:{ title, background, tone 用中文 … }」) |
| worldview 注入块 | 以「《寻常》——一个普通人的一辈子:…」开头,**这是唯一出现世界名的地方**,作为世界观描述喂进去,不是对 `title` 的指令 | `ArchetypeRegistry.java:744` |
| 种子池 | 四条种子(1985 北方工业城 / 1992 南方县城 / …)**都不含「寻常」**。ADR-020 裁定三写的「进 `world.title` 与种子池」与源码不符 | `WorldGenPromptBuilder.java:230–238` |
| 本世界指令槽 | `WORLD_GEN_DIRECTIVES["life_sim"]` 只讲结局池与早逝,**不提 `title`** | `WorldGenPromptBuilder.java:348–370` |
| 服务端后处理 | 没有任何代码改写 `world.title`;模型产出什么就落盘、下发什么 | 全仓 `server/src/main` 无对 `world.title` 的写入 |
| 前端 | 局内标题栏直接显示 `world.world.title`;存档指针也存它 | `GameScreen.tsx:200`、`state/savePointers.ts:26` |

**结论**:《寻常》的「世界名」是**软的**——靠 worldview 开头那个书名号让模型倾向于这么起名,没有约束,也没有校验。
同为「先例」的《动物人生》已有反证:真 key 冒烟时 world-gen 产出的世界名是「屋里的灯」(`bakeoff/FINDINGS.md:1052`)。
测试里写的 `"title", "寻常"`(`LifeExitActionTest.java:76` 等)是夹具手填,不说明线上产出。

**① 定稿后新发现(草案定稿时如实记,未自行调和)**:Felix 第一轮裁定是「游戏内世界名**固定**为《派单》,机制照《寻常》的先例」。
照先例 = 软约束,达不到「固定」。当时列出三档:

1. **照先例(软)**:worldview 以「《派单》——」开头,不加别的。零改动;世界名会漂(《动物人生》已证)。
2. **软 + 指令**:在 `WORLD_GEN_DIRECTIVES["cyberpunk"]` 加一句「`world.title` 必须恰为『派单』」。仍是提示词。
3. **硬**:world-gen 校验通过后由服务端把 `world.title` 覆写为「派单」(per-archetype 一个可空的固定世界名)。

> **已定(Felix 2026-11-10 第二轮)**:**采用 (3) 服务端覆写,并保留 (2) 的提示词行**。

>   未登记(`null`)的世界不覆写,行为逐字节不变。《派单》登记「派单」。实现位置与边界见决策 1、落地切分 Slice A2。

**② 定稿后新发现(草案定稿时如实记)**:卡面 `displayName` 不只出现在选择屏卡上,**还会注入两份提示词**:

#### 勘察 6 · 雷区:ROADMAP §六 管的是上架资质,题材风险的约束在仓库里找不到出处

**先如实记一个出入**:brief 引用的「不写政治隐喻、不写真实品牌和地名」**在仓库里没有出处**——
`docs/`、`prompts/`、`server/src/main` 全文检索「政治 / 品牌 / 影射」均无此类立字;[ADR-004](ADR-004-content-safety.md) 的程序层只拦**自伤**一条,
其余靠 provider 侧过滤与提示词。**本 ADR 把它作为本世界的硬约束写进决策 9 / 10;是否升为全局约束(进骨架、对所有世界生效)草案时待裁定**。

> **已定(Felix 2026-11-10)**:这次**只对本世界生效**。提升为全局约束记进待办,**另开一刀**(不在本 ADR 的任何 Slice 里)。

**ROADMAP §六 逐条**(该清单在路线 B 下已转为「未来补合规时的检查表」):

| §六 条目 | 本世界的风险 | 规避 |
|---|---|---|
| 小程序账号与主体 | 与世界无关 | — |
| 游戏类目与版号 | 与世界无关(不引入虚拟货币;「余钱」是局内数值轴,不可购买) | 不给余钱任何充值 / 兑换口径 |
| 内容安全(生成内容须过审) | **本世界是全库最贴近现实社会议题的一个**,风险从「血腥 / 恐怖」变成「被读成影射 / 社会评论」。程序层(ADR-004)不拦这类内容,只能靠提示词 | 决策 9(禁用词)+ 决策 10(题材边界)写进 world-gen 与回合两个指令槽;冒烟人工通读 |
| 备案(算法 / 大模型) | 本世界的主题**就是**「算法如何管人」;若将来补备案,演示材料里这个世界最容易被追问 | 解冻合规时,对外材料不以本世界为示例;本世界描写的是**虚构平台的虚构规则**,不出现任何监管主体、政策、法规名 |
| 备案措辞(避「游戏」字样) | 与世界无关 | — |

**题材专项(认真写的一项)**:

1. **核心机制本身就贴着一个公共议题。**「提前送达 → 时限被学去 → 时限收紧」与现实中关于外卖配送算法的广泛报道和讨论高度同构。
   **这一点措辞消除不了,因为它就是玩法本身。** 能做的是:不让任何一处文本把它**指认**为现实。
   - 平台名、商家名、小区名、街道名、城市名全部虚构,且**不得与现实平台谐音、拆字、取同色**(例如不用一个字的颜色或动物来指代平台);
   - 跑腿员的制服 / 头盔 / 餐箱**不写颜色**,或只写磨损、反光条等无品牌信息的细节——现实平台靠颜色识别,写颜色等于点名;
   - 不出现任何现实年代刻度、真实新闻事件的变形复述(如某次具体的事故、某篇报道的标题句式);
   - 系统只有一句台词「已为你优化时限。」,**不出现平台方的人格化发言人、公关口吻、致歉信**——那是现实事件的常见形状。
2. **「把话传下去」不能写成组织行动。** 本结局是「一个人把识破的一条经验告诉下一个人」,**不是**联合、串联、罢单、维权、讨薪、投诉、
   上访、集体停工。这类词与情节一律禁(决策 10),也不写「大家一起不接单」这类变体。这是本世界政治敏感度最高的一个口子。
3. **城中村不写成城市治理题材。** 不出现拆迁、清退、整治、驱赶、暂住、户籍、执法人员与城中村居民的冲突;城中村只作为地形(窄巷、握手楼、没电梯的九楼)存在。
4. **刷机改装**:作为虚构世界里的**风险选项**合适,条件是:
   - **只写物件与后果,不写方法**——可以写「改装过的头盔」「群里流传的一个刷法」,不写任何步骤、工具名、固件名、参数;
     这也是 ADR-004 被否决的那一条(「现实可执行的危险指令」)在本世界的提示词侧收口;
   - **永远有被查的代价**(评分重挫),不写成无风险最优解;
   - 它既可以是「群里说」的假规则(刷了也没用,反而被标记),也可以是真规则(确实能把画像压一点)——真假由 world-gen 每局决定,
     但 hiddenLogic 里必须写清被查的条件。
5. **交通违规不得被奖励。** 「一个红灯都等不起」只能作为**压力的描写**;闯红灯、逆行、走机动车道若作为选项出现,必须带代价(摔车 / 体力 / 评分),
   **不写成更快更好**,也不写成玩家被叙事夸奖的行为。
6. **自伤**(ADR-004 程序层唯一拦截项):「倒在楼道里」是体力耗尽的**倒下**,不写死因,不写高处、天台、窗边的意象;
   全局自伤硬禁照常生效。高层、天台在本世界是常见地形,**在体力见底档禁止与「坠」「跳」同句出现**。
7. **惊悚层**(标杆传说 / 系统知道太多 / 夜单):只写现象(工号、时限精确到秒、电梯不停的楼层、在更新的备注),**不给解释,不确认超自然**,
   不写成「平台在用死人跑单」之类可被读成都市传说式指控的定论。

## 候选方案

> 本 ADR 的核心选择在**时间结构**(勘察 1),其余各项都是在既有槽位上填内容,不另列方案。

### 方案 A:模型按表自推时段

在 `TURN_DIRECTIVES` 里写死三班一收工的切分表,让模型按回合号自己判断当前在哪一班。

**优点**:
- 零 Java 改动(只加一段模板文字)。

**缺点**:
- ADR-035 两轮冒烟的实证:时段交给模型推,第二夜分别拖了 15、31 回合,补节奏说明也无效。
- **排除理由**:同一失效形状已经付过一次学费。

### 方案 B:借一生制时钟表

把 `cyberpunk` 登进 `LifetimeFamily`,用 `LifeStageTable` 表达三班。

**优点**:
- 有现成的阶段 / 推进语 / 收敛窗口结构。

**缺点**:
- 带入族层四条片段与出口选项 `X`,语义全错(勘察 1)。
- **排除理由**:为借一张表吃下整族语义。

### 方案 C:引擎记「当前班次」

state 里加一个班次字段,由模型提议「本班结束」、引擎落账,夜班长度可在 8–12 间浮动。

**优点**:
- 夜班长度真的可变。

**缺点**:
- 动 state schema(`schemaVersion` → "0.5")、动 `Engine.apply`、要重录 golden。
- 「本班结束」仍由模型提议,漂移风险只是从叙事移到了字段上。
- **排除理由**:成本高,且没解决根因。

### 方案 D:单体按回合注入表,班次长度写死(本 ADR 采纳)

照抄 `FusionTurnCopy.turnClock` 的形状,给单体世界开一张 `Map<String, IntFunction<String>>`;三个夜班各取一个定长(决策 2)。

**优点**:
- 与 ADR-035 决策 4 修订段**同一机制**,已有冒烟实证(73 回合中 72 回合与注入一致)。
- 不动 schema、不动引擎;未登记世界空串,parity 零回归。

**缺点**:
- 夜班长度不能随局浮动(定稿取 7 / 8 / 9,Felix 2026-11-10)。
- 「单体按回合注入」从此是一个通用口子,别的世界可能想挂东西 → 判据写进类注释:只收「叙事推进在冒烟中稳定失效」的时段信息(CONTEXT §三.16 (9) 的口径平移到单体)。

- 归属:**深界**(Felix 2026-11-09 裁定)。归属目前只在世界目录文档里有载体(代码里没有 `experienceMode` 字段),激活批顺手改那一行。

### 4. 运转规律与「快不是永远错」

- 每回合叙事**必须交代这一单是提前、卡点还是超时**,并据此落数值:
  提前 → 画像涨、评分可能涨;卡点 → 画像不动;超时 → 评分降、余钱扣、画像可压一点。
- 系统从不解释,只在画像向上跨档时播一句「已为你优化时限。」(决策 8)。
- **防止「卡点」成为免费最优解**:每个夜班至少出现一单「快对某个人真的重要」的单(送药、冷链、门后有人在等)。
  提前送到对那个人是对的,代价是画像被学去。**不得把快写成永远错,也不得把慢写成永远对**;顾客不是道德题里的占位符,要有具体的人和具体的需要。

### 5. 世界边界与赛博物件

## 已知代价

1. **「成了标杆」没有引擎兜底**(决策 7 第 3 条):画像是累积轴,引擎永不据它结束;画像 ≥ 95 时模型若不提议「成了标杆」,玩家会在标杆档里继续接单。
   **缓解方式**:回合指令槽写成硬约束(「画像落到 95 及以上的那一回合必须提议成了标杆」);冒烟专项核。
   ⚠️ 已由「[订正(2026-11-10 二):结局核对、经济数字、腿况注入](#订正2026-11-10-二结局核对经济数字腿况注入)」订正 1 缓解:画像 ≥ 95 时服务端直接给出「成了标杆」(仍不是引擎兜底,在落账前改写模型提议)。
   (草案时这一条还包括「停派」;Felix 2026-11-10 裁定评分改致命轴后,停派由引擎兜底,本条只剩画像。
   随之接受的副作用:评分 ≤ 10 时极性 gate 拒绝所有成功结局,见决策 3。)
2. **「把话传下去」完全依赖模型**:识破的计数靠模型读 contextJson,「告诉了下一个人」靠模型读 log。**缓解方式**:回合槽兑现要求(勘察 2);冒烟专项核。
   ⚠️ 识破计数与余钱条件已由「[订正(2026-11-10 二):结局核对、经济数字、腿况注入](#订正2026-11-10-二结局核对经济数字腿况注入)」订正 1 改为服务端核对;「告诉了下一个人」仍靠模型。
3. **记忆点后端层不确定**:模型可能播了但没跨档,或跨了没播。前端硬层做完之前,这是一个软记忆点。
4. **影射风险无法被措辞消除**(勘察 6 第 1 条):核心机制本身就是一个公共议题的形状。措辞约束只能保证「不指认」,不能保证「不被联想」。
   **Felix 2026-11-10 已明确接受这一风险。** 接受的是「被联想」这一层;「不指认」那一层(勘察 6 题材专项 1–7、决策 9 / 10)照样是硬约束,
   冒烟与上线后的抽检照旧(重新审视的触发条件第 5 条:一旦出现指认即停止对外开放)。
5. **27 回合的单局成本**:成本按回合线性涨(ADR-016 成本闸门按局 / 按日计,单局变长会更早触顶)。定稿由 33 回合缩到 27 回合,压力比草案小;冒烟时仍记单局 token。
6. **单体按回合注入成为通用口子**:收什么由判据守(方案 D 缺点),判据只在类注释与本 ADR 里,不是代码检查。
7. **「已知未开放」分支失去真实成员**(勘察 5):选 (a) 后,这条分支只有测试里的假占位在跑。
8. **禁用词靠提示词**:程序层没有任何拦截(ADR-004 只拦自伤)。高频字(「资本」在「资本金」里等)机械 grep 会误报,只能人工读。
   「赛博朋克」同时是提示词里的模式标签,模型每回合都会读到它(决策 9 与卡面名的关系),漏出风险比表里其他词高;冒烟专项核。
9. **`fixedWorldTitle` 是只为一个世界开的口子**:目前只有《派单》登记。它只覆写 `world.title` 一个字段,`background` 与开场叙事里模型自己写的称呼
   不受它管(靠保留的提示词行)。**缓解方式**:字段可空、缺省不覆写,六个既有世界逐字节不变;要不要推广到《寻常》《动物人生》另记待办。

## 订正(2026-11-10):赛博朋克底色

> 本节取代决策 2(收工回合的选项)、决策 3(余钱 / 评分 / 画像的行为提示)、决策 5、决策 8(出现位置)、决策 10、决策 11(示例)里的对应文字,
> 并补充决策 12。旧文字原样保留,被取代处已就地加 ⚠️ 标注并指回本节。决策 1、4、6、7、9 不变。

**为什么订正**:Felix 冒烟一局后的反馈是「有送外卖模拟器的感觉,没有赛博朋克的味道」。原因在定位:底色写成了今天的城中村,
高科技只是零星物件(租来的助力膝、头盔显示屏、改装头盔)。物件少,而且每一件都是今天已经有的东西的小幅加强,读者自然读成今天。

**新定位**:赛博朋克世界里最底层的一个跑腿员。核心是「高科技、低生活」——**主角的身体本身就是那件高科技,而且是分期付的**。
平台的压迫不靠旁白讲,落在这个人的腿、眼和脑子上。

**本次只改提示词与 ADR,不动引擎,`schemaVersion` 仍 "0.4"**;四轴的 key、角色、致命性、档界、档名与档描述都不变。

### 订正 1 · 身体:平台分期的机械腿(取代「租来的助力膝」)

- 跑腿员的一双机械腿是平台入职方案装的义体,按月分期。**余钱的定义改为「80 = 够交房租和这期义体月供」**(取代决策 3「80 = 够交房租」)。
- **腿记录每一步,画像就长在腿上**。画像上涨的来源改为:提前送达、开启腿的超频(取代「使用联网义体」)。
- **欠费的后果落在身体上**:余钱不够交这期月供时(余钱落进「空」档,20 及以下),腿被平台远程降速 —— 体力掉得更快,爬楼要靠手撑栏杆。
  ⚠️ 降速是否生效改由服务端每回合注入【腿况】一行告诉模型,见「[订正(2026-11-10 二):结局核对、经济数字、腿况注入](#订正2026-11-10-二结局核对经济数字腿况注入)」订正 4。
  降速只是叙事与体力落点的提示,引擎不认识它(同 behaviorHint,ADR-008)。
- **新的两难**:收工回合可以把神经接口的算力租给平台过夜,换余钱;代价是睡不安稳,体力回不满。它是收工回合的一个选项(补充决策 2 收工回合的选项表)。
- 理由:「交上了」的门槛仍是 80,但 80 现在同时压着房租和月供 —— 钱的压力和身体直接连起来;降速让「钱不够」第一次有了体力层面的后果,而不只是一个数。

### 订正 2 · 感知:义眼和神经接口(取代头盔显示屏)

- 订单、倒计时、路线投在义眼里;派单音直接响在脑子里。
- 记忆点原句「已为你优化时限。」改为**浮在眼前**;触发条件不变(画像向上越过 30 / 60 的那一回合,下降、持平、没跨过不出现)。决策 8 的其余部分(唯一系统台词、前端硬层后做)不变。
  ⚠️ 跨没跨档改由服务端判、下一回合注入【记忆点】,见「[订正(2026-11-10 三):记忆点服务端注入 + 丢尾巴勘察](#订正2026-11-10-三记忆点服务端注入--丢尾巴勘察)」订正 1。
- 理由:头盔是可以摘下来的东西;义眼和脑子里的派单音摘不下来,「被看见」从此是身体内部的事。

### 订正 3 · 人物与底色

- **开局熟人默认是巷子里黑诊所的义体医生**:能帮你解锁降速的腿,也能帮你刷机,都有代价;**只写后果,不写方法**。他说的跑单经验仍然有真有假。
  ⚠️「能帮你解锁降速的腿」已由「[订正(2026-11-10 二):结局核对、经济数字、腿况注入](#订正2026-11-10-二结局核对经济数字腿况注入)」订正 4 取代:医生解不开远程降速,只能修磕坏的腿、能刷机。
- **worldview 加一段近未来底色**:塔楼和空中连廊悬在头顶,城中村挤在下面;无人机和飞行车只在高处掠过;塔楼的全息广告夜里投在城中村的墙上;
  每个人眼前叠着一层信息,门上浮着这户的评分,巷口浮着路况;招牌上混着几种文字;路边摊和自动售卖机挨在一起;
  送货机器人在垃圾和电线之间穿行;雨、雾、蒸汽几乎不停。
- **每回合的硬要求**:叙事里至少出现一个今天还不存在的物件或现象,而且必须和这一单有关(这一单的路、门、顾客、货、时限),不能只是背景。

- **惊悚层改为更赛博的版本**(取代决策 10 三条):
  1. 「标杆」工号背后可能根本没有人,只是一个一直在跑的账号(仍须作一条「【群里说】」,真假由每局决定);

  3. 凌晨的单,门后是一个还在替某人点餐的语音助手,而那个人很久没出现了。
  仍然只写现象,不写解释,不确认超自然。
- **种子池按新底色改写**,仍是新号 / 老号各 3 条。
- 理由:味道要靠物件和处境出来(决策 9 不允许贴标签),所以物件必须多、必须是今天没有的、必须和这一单有关 —— 只当背景的物件读者会跳过。

## 订正(2026-11-10 二):结局核对、经济数字、腿况注入

> 本节取代决策 7 的「结局判定留在模型侧」(仅对本世界)、已知代价 1 / 2 里「完全依赖模型」的部分,
> 以及「订正(2026-11-10)」订正 1 的降速触发方式与订正 3 里黑诊所「能解锁被降速的腿」一句。旧文字原样保留,被取代处就地加 ⚠️ 标注指回本节。

**为什么订正**:Felix 冒烟两局新版,暴露四个问题 ——
1. 两局结局都与条件不符:「交上了」时余钱 22;「把话传下去」时余钱 2、只识破 1 条假规则。
2. 完单几乎不加余钱,两局余钱最高 44 —— 「交上了 ≥ 80」实际上够不着。
3. 余钱 26–36 时叙事就写腿被降速(降速线是 20)。
4. 3 局里 2 局 world-gen 的规则全部缺 `isTrue`(校验器按 ADR-009 视 `isTrue` 为可选,照单全收)。

共同的原因:这几件事都只写在提示词里,模型每回合要自己从 state 里算出来,算错了没有任何东西兜底。
本订正把「能用数值判定的」挪到服务端,把「只能靠叙事的」留给模型并把数字写死。

### 勘察结论(只读 `main` `c9318bf`)

1. **结局核对有挂接点,不必改 Engine**:`EventLoopService.landSettled` 在 `engine.apply` 之前已有一处服务端改写 `parsed`
   的先例 —— `clampClosingVigorFloor`(《寻常》收束气力下限,ADR-020 §8),同样只对特定世界生效、其余世界原路径。
   结局核对放在它旁边:按本回合 `stateUpdate` 自己算一遍落账后的数值(与 `Engine.apply` 相同的口径:缺省取当前值、clamp 0–100),
   改写 `parsed.ending` 后再交给 `engine.apply`。Engine 一行不动,`EngineGoldenTest` 直喂 Engine 不经本服务,golden parity 不受影响。
   ADR-031 档 1 回放与 settle 共用 `landSettled`,回放会重现同一改判(核对只读引擎状态与 `parsed`,确定性)。
   结局经 `buildDelta` / `buildEnding` 从引擎读,改判后的结局就是下发给玩家的结局。
2. **isTrue 校验可以只对本世界生效**:`WorldGenService.tryParse` 在通用 `GameSchemas.validateWorld` 之后返回;
   在那里按 archetype 追加一条本世界专属检查(任一规则缺布尔 `isTrue` → 记一条错误),错误进同一张列表,走现有的一次修复。
   通用校验器一字不改,其他世界不走这条检查(ADR-009「isTrue 可选」口径不变)。
3. **腿况注入与时段注入同位**:`TurnPromptBuilder.singleTurnClock` 已在「请推进第 n 回合」之前注入时段;腿况按本回合开始时
   (即 `engine.attributes()` 里、本回合 `apply` 之前)的余钱算,紧接在时段之后注入。未登记的世界为空串,回合提示词逐字节不变。

### 订正 1 · 结局核对(服务端,仅《派单》)

- **本节对简报未写明的两处口径**(**已定,Felix 2026-11-10:两处都认可**):
  ① #1 里模型提议的结局被去掉、由引擎兜底挑(简报写「沿用引擎现有的触底兜底,不动」;不去掉的话,模型提议的 neutral / failure 结局会被引擎直接接受,兜底不会触发);

  ⚠️ **① 已订正(Felix 2026-11-10,同分支补一刀)**:触底不再交引擎兜底,核对直接写 —— **体力 ≤ 0 → `collapsed_in_stairwell`;否则评分 ≤ 0 → `dispatch_stopped`**(任一回合)。

  · 第 27 回合及以后判出 success 但体力 ≤ 10 → `collapsed_in_stairwell`;否则评分 ≤ 10 → `dispatch_stopped`(两条都 ≤ 10 时固定取体力,理由同上);
  · 第 27 回合之前,体力或评分 ≤ 10 时「把话传下去」不收(本回合继续),免得被 gate 改判成失败、提前结束这一局;
  · 第 27 回合判定表在「体力或评分归零」之后加一行:「体力或评分 ≤ 10:好结局都不成立;体力 ≤ 10 写倒在楼道里,否则写停派。」
    ⚠️ 这一行已改为「……否则写停派;差一点不受影响。」,见「[订正(2026-11-11 四):结局核对只降级好结局 + 体力数字](#订正2026-11-11-四结局核对只降级好结局--体力数字)」。
- 第 27 回合的时段注入里加上这张判定表,并写明:「先落本回合 stateUpdate,再按表判定;余钱不到 80 不得写成交上了,叙事要和结局一致。」

### 订正 2 · world-gen:《派单》规则必须带 isTrue

《派单》任一规则缺布尔 `isTrue`,按校验失败处理,走现有的一次修复(修复提示里带上这条错误);修复后仍缺 → 与其他校验失败一样整局 ERROR。
通用校验器不改,其他世界不受影响(ADR-009 口径不变)。

### 订正 4 · 腿况注入(仅《派单》,和时段注入同一机制)

每回合按本回合开始时的余钱,在【本回合时段】之后注入一行:
- 余钱 ≤ 20 →「【腿况】这期月供不够,腿处于远程降速:体力掉得更快,爬楼要手撑栏杆。」

worldview、world-gen 指令(开局熟人那条)、回合指令「月供与降速」同步改。

### 已知风险

1. **改判时已经流出的叙事可能和结局不一致**:叙事是逐字流的(ADR-006),核对发生在流完之后、落账之前。
   模型若在叙事里写了「交上了」而核对改判成「差一点」,玩家会先读到前者、再看到后者的结局卡。
   **缓解**:第 27 回合注入判定表,让模型先按表判;改判时记 INFO + issue,冒烟时数改判率。改判率高 → 重审注入措辞,或考虑在第 27 回合前一回合就把判定结果注入。
2. 「把话传下去」的「当面告诉」一项仍只认模型提议,数值核对只能挡住余钱 / 识破数不够的情况。
3. 结局 id 必须与 world-gen 产出的 id 一致(决策 7 的 7 个 id);若某局 world-gen 改了 id,核对给出的 id 不存在,引擎按原规则不收 ——
   核对此时记 WARN,结局退回到引擎原有行为。
4. 经济数字、腿况都只是提示词与注入,引擎不认识它们;余钱的实际涨落仍由模型在 stateUpdate 里落。

## 订正(2026-11-10 三):记忆点服务端注入 + 丢尾巴勘察

> 本节取代决策 8「后端软层(提示词约束)」里「让模型自己判断跨档」的做法,以及「订正(2026-11-10)」订正 2 里同一条的出现方式;
> 触发条件(画像向上越过 30 / 60)不变。旧文字原样保留,被取代处就地加 ⚠️ 标注指回本节。

**为什么订正**:Felix 冒烟两局 ——
1. 快跑局第 4 回合画像 59 → 68 跨过 60,叙事没出「已为你优化时限。」;旧版则几乎每回合都出。跨没跨档要模型自己拿两个数比,两头都会错。
2. 正常局的 `world.tone`(标题下那一行)里出现了这句话 —— 它本该是全局唯一的系统台词,只在跨档回合和「成了标杆」里出现。
3. 《派单》120 回合里有 4 回合 `no_structured_tail` 降级(《验讫》204 回合 0 次)。

### 勘察结论(只读 `main` `843cf2e`)

1. **上一回合的画像推不出来**:存档里 `log` 只有叙事与玩家动作,不带数值;`issues` 只记跳变 > 40 的轴。所以「上一回合跨没跨档」不能事后从已落盘数据算。
2. **不新增落盘字段、不改 Engine 的落点**:跨档发生在落账那一刻(`EventLoopService.landSettled`,`engine.apply` 前后各有画像值)。
   在那里用已有的 `Engine.recordIssue` 记一行「T{n} 画像向上跨档 a→b」(`issues` 本来就落盘、随存档回载;订正二的结局核对与《寻常》收束下限钳制都用它),
   下一回合渲染提示词时读「`issues` 里有没有上一回合的这一行」。
   - 不用会话层的内存标记:它不在轨迹的 `pre` 里,ADR-031 的提示词哈希复核(由 `pre` + `actionId` 重渲染)会对不上;重启也会丢。
   - 不新增 session 层落盘键(那需要停下汇报)。
   - 代价:`issues` 原是遥测清单,这里第一次被提示词读取。只读这一种前缀、只对《派单》生效;`issues` 不进喂模型的 `snapshot()`,模型看不到它本身。
3. **注入位置**:与【腿况】同一机制(`TurnPromptBuilder.SINGLE_TURN_STATUS`),紧接在【腿况】之后。未登记世界为空串,回合提示词逐字节不变。
4. **world-gen 的世界专属检查**:订正二加的 `WorldGenService.worldSpecificErrors` 可直接扩展,走现有一次修复。

### 订正 1 · 记忆点服务端注入(仅《派单》)

- 落账后,画像从 < 30 到 ≥ 30,或从 < 60 到 ≥ 60,记一行 issue「T{n} 画像向上跨档 {旧}→{新}」;一回合连跨 30 和 60 也只记一行。下降、持平、没跨过不记。降级回合不落账,不记。
- 下一回合在【腿况】后注入一行:
  - 有标记 →「【记忆点】本回合叙事开头逐字浮出一次「已为你优化时限。」,不解释,只写这一单的时限比上一单短。」
  - 无标记 →「【记忆点】本回合不得出现「已为你优化时限。」这句话。」
- 回合指令里原来让模型自己判断跨档的那一条,改为「以每回合注入的【记忆点】为准」。
- 成了标杆的结局文字不受这条注入约束(结局由服务端核对给出,description 由 world-gen 写好)。

### 订正 2 · world-gen:系统台词只留在「成了标杆」

「已为你优化时限。」只允许出现在 `became_benchmark` 的 `description` 里。world-gen 指令写明这一条;
`worldSpecificErrors` 加校验:`world.title / background / tone`、每条 `rules[].content`、`openingNarrative`、每个 `availableActions[].text / hint`,
以及其他结局的 `title / condition / description`(和「成了标杆」的 `title / condition`)出现这句话 → 校验失败,走现有一次修复。
`hiddenLogic` 不查(玩家不可见,规则的真实判定可能需要提到它)。

### 订正 3 · 丢尾巴(只勘察,不改;结论挂账)

**现象**(本地轨迹 `server/data/traces/`):四个降级回合 a8aa0275 T20 / T21、bf2de3f5 T13、1c3645fa T3,主调用 `completionTokens` 123 / 146 / 146 / 144;
同局落地回合中位数 325–377。流出的叙事 163–192 字,与落地回合的叙事中位数(159–209 字)相当,而且都是完整收尾的句子 ——
**模型写完叙事就结束了这次输出,没有哨兵、没有尾巴**,不是被截断。

**为什么没走修复**:`EventLoopService.execute` 里「叙事空 / 没见到哨兵 / 尾巴空」直接 `degrade(DEGRADE_NO_TAIL)`(规格 §6.6:叙事已流出、无尾可修)。
修复(`repairOnce`)只处理「有尾巴但没过校验」;没有尾巴时没有可修的输入,这是设计如此,不是漏接。

**《派单》与《验讫》的提示词差别**(两者都把世界专属指令拼在骨架「输出格式 · 严格遵守」与尾巴字段说明**之后**):
- 《派单》单体指令槽约 2700 字符,全部是叙事与裁决要求,**一句都没提哨兵或尾巴**;其后又是三到四段按回合注入(时段 / 腿况 / 第 27 回合判定表 / 本订正的记忆点),
  最后一句是「请推进第 n 回合」。离输出格式说明最远的地方,全是「怎么写叙事」。
- 《验讫》的融合裁决段约 780 字符,其中第 (3) 条写「每回合给出**结构化尾巴**前,对照 endings……」,在指令末段把尾巴重新点了一次。
- 《派单》写作风格要求「冷、准、短」,叙事写完就像一回合说完了;这一条与丢尾巴的关系只是推测,轨迹里没有 `finish_reason`,无法区分。

**候选改法(不实施,待裁定)**:
1. **提示词侧(只动《派单》,便宜)**:在《派单》按回合注入的最后一段(紧挨「请推进第 n 回合」之前)加一句固定提醒:
   「叙事写完后另起一行输出哨兵和结构化尾巴 JSON;缺了尾巴,本回合作废。」—— 让离输出最近的文字指向尾巴。其他世界逐字节不变。
2. **服务端侧(动共享路径,需另立决策)**:没见到哨兵但叙事非空时,补一次「只要尾巴」的调用(复用修复提示「只回结构化尾巴 JSON」,把已流出叙事作为上下文)。
   能把这类回合从降级救回来,但对所有世界生效、每次多一发调用,且要守 ADR-024「最坏 2 × 20 秒」;改之前还应先在 usage 里记下 `finish_reason`,确认确实是 `stop`。

### 勘察结论(只读 `main` `fe7121f`)

**1. 皮肤契约(`theme/contract.ts` `WorldSkin`)**
- 必填:`id`、`hasIntro`、`valueRoll`、`screenClass`、`pausedClass`、`bannerImgClass`、`backClass` 与三个组件槽 `Ambient` / `Stats` / `Actions`。
- 可缺省:`signatureAxisKey`(缺省 = 不盯轴,`signatureTick` 恒 0)、`backPressDurMs`、`Interlude`(间奏槽)、`Prose`(正文形态槽)。
- 三个组件槽都没法直接复用通用组件:`Stats` 的旧形态 `LegacyStats` 未导出,且它的进度条**按轴 key 硬编码配色**
  (`barClass`,ADR-018 §4.2 要被 severity 取代的那条老路),登记皮肤的世界不该再走它。
- 现有四套里**最小的是规则怪谈**:3 个组件(Ambient 204 行 / Stats 63 行 / Actions 33 行,共 300 行)、CSS 444 行、
  测试 1 个文件 20 例(296 行)。对照:修仙 484 / 781 / 37 例,末日 706 / 479 / 32 例,克苏鲁 1114 / 451 / 63 例。
- **《派单》最小皮肤需要**:`theme/paidan/` 下 `PaidanAmbient`(宿主:持续环境动效 + 记忆点浮字)、`PaidanStats`、`PaidanActions`、
  `paidan.module.css`(主题根 token + reduced-motion)、`paidanSkin.test.tsx`;`skins.tsx` 加一条;`registry.ts` 的 `SkinId` 加
  `'cyberpunk'`、`WORLDS.cyberpunk.skin` 改为 `'cyberpunk'`;注册表测试随之改(「有图有卡不登记皮肤」那条换成登记)。
  不开 `Interlude` / `Prose` 槽。量级预估与规则怪谈相当。

**2. 前端「跨档」的触发时机(`useSignalCrossing`),与服务端订正三差一回合**
- 前端判定读的是**引擎落账值**:`gameStore` 在回合流的 `onDelta`(叙事流完、结构化尾巴到达)那一刻写入 `attributeValues`,
  `useSignalCrossing` 在同一次渲染里比较档序号,向上则 `tick + 1`。所以前端硬层发生在**第 N 回合叙事播完、选项刚出现**的那一刻。
- 服务端(订正三)在第 N 回合落账时记 issue,第 **N+1** 回合的回合提示词才注入「本回合叙事开头逐字浮出一次」—— 文字出现在
  **第 N+1 回合叙事的开头**,即玩家选完下一个动作之后。两者相差一回合,中间隔着玩家的一次选择。
- 两边判据一致:画像档表 0 / 30 / 60 升序,前端「档序号变大」与服务端「从 < 30 到 ≥ 30 或 < 60 到 ≥ 60」等价;一回合连跨两档两边都只算一次;
  下降不算;降级回合不落账,两边都不触发。差异:**续局首次装载前端不触发**(规矩 ②),服务端照常按存档里的 issue 注入。
- ⚠️ **位置问题**:前端 tick 发生时玩家通常已经滚到正文末尾 / 选项处,**顶图不在视口里**。浮字若挂在顶图上,大多数情况下玩家看不见。
  推荐挂在视口固定层(见设计 2)。
- 签名机制判的是「向上跨档」。画像是越高越糟的轴,但我们要的触发正好就是「向上」,**机制不用扩**(末日那条「不为方向扩机制」的理由不受影响)。

**3. AGENTS.md Motion Constraints 对本世界的约束**
- §2 预算:同屏最多 1 持续环境 + 1 低频偶发 + 1 用户触发。《派单》目前一个动效都没有(决策 8 已记「新世界首个动效,无可替代」)。
  本刀计划:持续 = 设计 3 的一处;低频 = 记忆点浮字(一次性演出,不循环);用户触发 = 通用层已有的数值滚动 + 选项按压。不加入场序列(`hasIntro: false`)。
- §3「替代谁 / 降级谁」:局内两处都是本世界首个,声明为「新世界首个,无可替代」;卡面粒子是本卡首个 `::after`,同样声明。实现说明里逐条写这一句。
- §4 正文即禁区:持续动效不得落在正文上;粒子进正文区前必须淡出。
- §5 清理与 reduced-motion:定时器 / timeline 登记到 `SkinRuntime`;reduce 下持续动效停在静帧、浮字直接显示后消失(不位移不淡入)。
- §6 性能:只动 `transform` / `opacity`。现有四张卡的 `::after` 都在动 `background-position`(不合 §6 的优先项),本卡改用 `transform`,不照抄。
- §1 一级记忆点「一个世界只准一个」:《派单》的唯一一级 = 「已为你优化时限。」;积水反光 / 雨丝是氛围,不是第二个记忆点。

  - **A. 两层都留(推荐)**:前端在**第 N 回合**落账那一刻浮字(系统的声音,确定、准时);

    理由:后端零改动;两次出现隔着玩家的一次选择,且分别是「系统在改你的时限」和「新一单的时限真的变短了」,读起来是因果,不是复读;
    全局只有这一句系统台词,重复一次反而加重「它记住了你」。代价:同一句话两回合内出现两次,Felix 若觉得重复,可退到 B。

**3. 局内持续环境动效(全屏只允许一处)**

  (只动 `opacity` / `transform`,周期约 6–9 秒)。理由:① 顶图里就有积水和倒影,动的是画里本来有的东西;
  ② 只在顶图上,天然不落正文;③ 和卡面的雨丝分开,卡面 = 下着雨、局内 = 雨后的地面,两处不重样;

- **不用霓虹闪烁**:灯闪是规则怪谈的一级记忆点,撞车;也正是「霓虹渐变堆砌」最容易滑进去的方向。

**4. 卡面粒子(`.cardPaidan::after`)**

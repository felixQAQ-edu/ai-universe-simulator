### 勘察结论(只读 `main` `de89ba6`,2026-11-21)

**a. 删除指针的现状。** `web/src/state/savePointers.ts` 头注释立着第一原则,模块确实**没有删除条目的函数**;
唯一的 `removeItem` 在 `migrateLegacy` 里「比对后清」旧单槽键(那时新键已写好)。`gameStore` 持有 `pointers` 实例(闭包私有),
组件拿不到;存档相关的写入只经 `gameStore` 的 `recordFromWorld` / `patch` 两类路径。源码级断言(`savePointers.test.ts` 末段)现锁两件事:
存档键字面量只出现在 `savePointers.ts`;调用 `localStorage` 的只有 `savePointers.ts` / `api/deviceId.ts` / `state/lobbyPrefs.ts`。
**没有**任何断言约束「谁能删」——今天靠「没有删除函数」守。

**b. 服务端。** 没有删除端点;服务端也从不按客户端指针做任何事。移除只动本机 `localStorage` 里那一条 `aiuniverse.save.<saveId>` 键,
服务端那一局原样留在 `/data`(与 ADR-034 已知代价 1 同一形状:客户端此后没有找回路径)。

**c. 「能找回」何时得知。** `availability` 只在两处被改成 `unavailable`:续局拿到确认的 `session_not_found`(`resumeGame` 的 catch)、
回合流拿到 `session_not_found`(`forgetDeadSave`)。**没有任何主动探测**:一个服务端已经没有的档,在玩家点它之前一直是 `available`。
续局成功即改回 `available`(`recordFromWorld`)。「没结局」= 摘要的 `ended === false`(开局写 false、`onEnding` 改 true、续局按服务端
`state.status === 'ended'` 校正)。迁移来的旧指针 `ended: false`、`title: ''`、`archetypes: []`。
多页签:`onSavePointersChanged` 只在**别的**页签写存档键时触发(`storage` 事件本页签收不到),回调只做 `refreshSaves()` 重读。

**d. 屏幕切换。** 全靠 store 状态,**整个 `web/src` 没有一处 `pushState` / `popstate` / `history.back`**。`GameScreen` 的分派:
`status === 'idle'` 时 `historyStore.viewing !== null` → `HistoryScreen`,否则 `ArchetypeSelect`;其余状态各有一屏。
所以今天**任何一屏按浏览器 / 手机返回键都直接离开整站**(浏览器历史里只有进站那一条)。历史页的「返回」= `historyStore.close()`,回大厅;
游戏屏的「返回」= `gameStore.reset()`,回大厅。

**e. 「回看上局」。** 大厅 effect 以 `saves[0].saveId`(按本设备上次游玩降序的第一条,不论是否结局、是否可用)调 `historyStore.probe`;
`capabilities.history` 为 false 时不探测;探测去重与「只记『是』、失败不记」都在 `historyStore`。入口是一个 0.4s 一次性淡入
(`historyFadeIn`,`prefers-reduced-motion` 下关掉),不预留空位。

**f. 撤销条可复用的东西。** 仓库里**没有** toast / 撤销组件。可复用的范式:ADR-041 的播报区「始终在场、只由一个函数写」;
`theme/cthu/useAnomaly.ts` 的 `visibilitychange` 处理与清理写法;`theme/paidan/PaidanAmbient.tsx` 的 `role="status"`。

**g. 与本 ADR 相干、但 brief 没点到的一处耦合。** ADR-041 的「已发现」= 浏览器记录 ∪ **存档推导**(`lobby.ts` `discoveredFusions`:
`saves` 里 `archetypes.length === 2` 的组合)。存档推导出来的组合**不写回**浏览器记录(`addDiscovered` 只在拖拽合成成功时调用)。
所以:**移除一局融合存档,可能让渗界里那张卡消失;若那是唯一的已发现组合,渗界标签也会消失**,上次停在渗界的玩家下次进门落回浮世
(`initialZone`)。见决策 7 / 待审 6。

## 候选方案

### 删除时机 · 方案 A:点「移除」立即删,「撤销」时把指针写回

**优点**:实现最短;撤销 = 用内存里那份摘要重写一次。
**缺点**:**5 秒内关页 / 切后台被杀 = 指针已经没了**,正好违反 Felix 定的「5 秒内离开 → 不删」;撤销靠写入,而写入在配额满 / 隐私模式下会失败
(ADR-034 已知代价 2),撤销就成了一句假话。排除。

### 删除时机 · 方案 B:先只在画面上藏起来,窗口走完才删(本 ADR 采纳)

**优点**:任何提前结束(关页、切后台、离开存档页、组件卸载、计时器被浏览器冻结)都自然落在「不删」一侧;撤销只是把行放回画面,不需要写存储。
**缺点**:要自己维护「待删」集合与计时;5 秒内另一个页签看到的仍是全部存档(对它来说还没删,这其实是对的)。

### 连续移除 · 方案 B1:前一条立即提交,新一条另起窗口

**缺点**:前一条的撤销窗口被截短,违反改写后的第一原则(「撤销窗口走完时才删」)。排除。

### 连续移除 · 方案 B2:并入同一个窗口,计时从头再走 5 秒(本 ADR 采纳)

**优点**:任何一条被删之前,玩家都至少看到过 5 秒完整的撤销条,且撤销条上说的永远是「接下来要删的全部」;往安全的方向偏(可能晚删,不会早删)。
**缺点**:一次撤销会把这一批全部放回,不能只撤其中一条;并批后的撤销条要一句新文案(待审 1)。

### 连续移除 · 方案 B3:每条各自一个窗口,撤销条只显示最新一条

**缺点**:旧的那几条在看不见撤销入口的情况下继续倒数、到点被删 —— 等于「玩家不知情地丢指针」换了个形状。排除。

### 返回键 · 方案 R1:不接浏览器历史(现状)

**缺点**:存档页按手机返回键直接离开整站,brief 明确不接受。排除。

### 返回键 · 方案 R2:进存档页时压一条浏览器历史,`popstate` 关页(本 ADR 采纳)

**优点**:地址不变、不引路由库;只在玩家**点进**存档页(及从那里点进历史页)时压历史,其余屏的行为一字不变。
**缺点**:这是 `web/src` 第一次碰 `window.history`,要守 ADR-003 平台边界(决策 5);刷新页面后浏览器里会留一条「死」的历史(已知代价 4)。

### 返回键 · 方案 R3:hash 路由(`#/saves`)

**缺点**:地址栏变了、刷新落点要定、可被分享和收藏,牵出「直接打开存档页」这一新入口;范围远超本 ADR。排除。

## 最终决策

**删除时机 B + 连续移除 B2 + 返回键 R2。** 服务端一行不改;前端改动限于存档区本身、`savePointers` / `gameStore` 的删除接缝、
一个导航适配器,以及大厅里被替换的那一块。

### 2. 删除接缝与源码级锁

- `savePointers.ts` 加**唯一一个**删除函数:`removeIfUnchanged(expected: SaveSummary): boolean`。
  读出当前键 → `parseSummary` → **七个字段与 `expected` 全等才 `removeItem`**,否则什么都不做、返回 false。
  理由:撤销窗口那 5 秒里,另一个页签可能刚续了这一局(`lastPlayedAt` / `turn` 变了)—— 那时删掉的就是玩家刚在玩的一局。
  「比对后删」与 `migrateLegacy` 的「比对后清」同一形状。解析失败的键(`parseSummary` 为 null)不删(与 ADR-034 已知代价 5 一致)。
- `gameStore` 加一个动作 `commitSaveRemoval(entries: SaveSummary[])`:逐条 `removeIfUnchanged`,然后 `refreshSaves()`。
  组件不直接拿 `pointers`(现状不变)。
- `savePointers.ts` 头注释改写:第一原则照决策 1 的新句,「本模块没有删除条目的函数」改为「只有一个删除函数,只在撤销窗口走完时由存档页调用」。
- **源码级断言**(加在 `savePointers.test.ts` 末段,同一个 `import.meta.glob` 源码集):
  1. `savePointers.ts` 里 `removeItem(` 恰好出现 **2** 次(迁移清旧键 + `removeIfUnchanged`);
  2. 非测试源码里出现 `removeIfUnchanged` 的文件恰好是 `savePointers.ts`(定义)与 `gameStore.ts`(`commitSaveRemoval` 里一次);
  3. 非测试源码里出现 `commitSaveRemoval` 的文件恰好是 `gameStore.ts`(定义)与存档页撤销窗口所在的那一个模块
     (暂定 `features/game/saves/useRemovalWindow.ts`),且在后者里**只出现一次**(到点提交那一处);
  4. 先证明遍历到了这几个文件(同现有「空集上的断言是假绿灯」那条)。

### 3. 撤销窗口

存档页内的一个 hook(暂定 `useRemovalWindow`)持有本页的「待删批」:`{ entries: SaveSummary[]; kind: 'one' | 'endedAll' | 'mixed' }`。

| 事件 | 行为 |
|---|---|
| 点某行「移除」 | 该行加入待删批,画面上立刻不显示;计时**从头**设为 5000ms(B2);撤销条出现或改字 |
| 点「全部移除」 | 当时「已结局」组里显示着的全部行加入待删批(含暂时无法找回的已结局行);同上 |
| 点「撤销」 | 待删批整批作废,行按原排序回到画面;撤销条消失;**不写存储** |
| 计时到点 | `commitSaveRemoval(entries)`;撤销条消失 |
| `visibilitychange` → hidden、`pagehide` | 待删批作废(同撤销),**不删**。回到可见时行已在原位、没有撤销条 |
| 离开存档页(返回、点开一行续局、点进「回看上局」)、组件卸载 | 卸载清理里作废待删批、清计时器,**不删** |
| 别的页签改了存档键(`storage` 事件) | 照旧 `refreshSaves()`;待删批不动 —— 到点时由 `removeIfUnchanged` 比对,变过的那条不删 |

- **不写任何「关页前赶紧删」的逻辑**(没有 `beforeunload` / `pagehide` 里的提交):删除只可能发生在计时器回调里,
  所有提前结束都天然落在「不删」。`visibilitychange` 必须显式处理,因为后台页签的计时器只是被节流、仍会到点。
- **暂停**:指针悬停在撤销条上、或焦点在撤销条内时暂停计时(细线同步 `animation-play-state: paused`);离开后按**剩余时间**继续,不从头。
  页面 hidden 不走暂停而是作废(Felix 定的「切后台 → 不删」)。
- **撤销条文案**:
  - 待删批只有一条:「已从这台设备移除《X》」,X = `title`;`title` 为空(迁移来的旧指针)时见待审 2;
  - 待删批恰好是一次「全部移除」:「已从这台设备移除 N 局已结局的存档」;
  - 其余(两条以上单删、或单删与全部移除混在一批):**样张没有这一句** —— 提议「已从这台设备移除 N 局存档」,待审 1。
- 计时用注入的时钟与计时器(同 `gameStore` 的 `now` 注入),测试里推进假时钟。StrictMode 下:计时器只在点击处理里起,不在 effect 里起;
  effect 只负责卸载清理与 `visibilitychange` 订阅。

### 4. 「继续」取哪一条

- 纯函数 `pickContinue(saves)`:`saves`(已按本设备上次游玩降序)里第一条 `ended === false && availability === 'available'` 的。
- **「能找回」只是「上次知道时能找回」**(勘察 c):一个服务端已经没有的档仍可能被选成「继续」。点它 → 404 → 标 `unavailable` → 列表刷新,
  「继续」**换成下一条候选**(或消失)。今天 404 不给 `saveNotice`(条目上的「暂时无法找回」就是说明),但继续条会跳过它,玩家只看到
  「点了一下、换了一局」—— 需要一句提示,见待审 3。网络 / 5xx 照旧 `SAVE_RETRY_NOTICE`,条目不变。
- **提示放哪**:大厅 = 继续条下面一行(与现在 `.savesNotice` 同字号同色);存档页 = 说明句下面一行。
- 副标题 = 现有 `describeSave`(含「本设备上次游玩」,Felix 补裁 6);世界名为空时沿用「上一局(续上后显示世界名)」。
- **区块的三种形态**:`saves.length === 0` → 整块不渲染;有存档但没有候选(全部已结局或都暂时无法找回)→ **只剩「全部存档(N)」一行**(待审 4);
  有候选 → 继续条 + 链接。
- **N = `saves.length`**:全部可解析的指针,含暂时无法找回的,不含解析失败被跳过的键(样张 16 = 进行中 5 + 已结局 11,含一条暂时无法找回)。
- 多页签:大厅现有的 `onSavePointersChanged(refreshSaves)` 不变,继续条与 N 随之重算;存档页挂同一个订阅。

### 6. 「回看上局」移进存档页

- **探测语义不变**(ADR-034 已决 9「只跟随最近一条」):目标仍是「最近一条」,触发、去重、能力位、失败不记全部照旧。
  探测**仍从大厅发起**(大厅 effect 不删,只删入口的渲染),所以多数情况下进存档页时探测早已有结果;存档页也调一次 `probe`(被 `historyStore` 去重)。

  理由:玩家刚把最近一局移掉,入口不该还指着一行看不见的存档;窗口作废时它指回原来那条。
- 位置在说明句下、「进行中」组上(样张);小字改为「看看最近这一局已经发生过什么」(Felix 补裁 7)。
  入口出现时沿用 `historyFadeIn`(0.4s 一次性;reduced-motion 关)—— 这是从大厅搬过来的,不是新增。
- 已知:探测晚到时,入口出现会把下面的行整体往下推一行(已知代价 5)。

### 10. 无障碍

- **播报区**:撤销条里放消息文字的那一格是 `role="status"`(隐含 `aria-live="polite"`),**始终在 DOM 里**(没有待删时是空的、视觉上不占位)——
  播报区须先于内容存在(ADR-041 的教训)。「撤销」按钮在播报区**外面**(同一个视觉条里),免得每次改字都把「撤销」念一遍。
- **WCAG 2.2.1(可调整时限)**:5 秒对读屏与键盘用户太短。做法:
  1. 焦点在撤销条内、或指针悬停其上时**暂停**,离开后按剩余时间继续(决策 3);
  2. **键盘 / 读屏触发的移除**(`click` 事件 `detail === 0`)→ 焦点直接移到「撤销」。焦点在那里计时就停,时限实际由玩家控制

  3. **指针触发的移除**(`detail > 0`)→ 焦点不跳,留给同组下一行的「移除」(没有下一行 → 上一行;组空了 → 该组组头,`tabIndex={-1}`)。
  这条分流是提议(待审 8)。
- **「撤销」之后**:焦点到被放回的那一行的打开按钮(多条时放回的第一条)。**「全部移除」之后**:键盘触发 → 「撤销」;指针触发 → 「已结局」组头。

- 继续条整行一个 `<button>`,可访问名 = 「继续 + 世界名 + 副标题」(`›` `aria-hidden`);「全部存档(N)」是按钮不是链接(不换地址)。

### 关键理由

1. **删除只能发生在一个地方**:计时器回调 → `commitSaveRemoval` → `removeIfUnchanged`。其余一切提前结束都不需要「记得别删」,它们本来就删不了。
   这比「在每条离开路径上写一句别删」可靠,也是源码级断言能锁住的形状。
2. **比对后删**复用 ADR-034 已有的「比对后清」:多页签下的风险从结构上关掉,而不是靠时序。
3. **撤销不写存储**:撤销在配额满 / 隐私模式下也成立,不会变成一句假话。
4. **返回键只在新加的两条路径上接历史**:游戏屏、大厅、初始化、错误屏的行为一字不变。
5. **样张为准,但不替 Felix 圆**:并批文案、空世界名、404 提示、只剩链接的形态、渗界耦合、动效记账、焦点分流这几处样张或 brief 没答,全部列为待审。

## 已知代价

1. **移除后客户端没有任何找回路径**:服务端那一局还在,但本机不再知道它的 saveId。缓解:5 秒撤销、常驻说明句;按 saveId 找回仍挂账(ADR-034 已决 5 补充块)。
2. **「继续」可能指向一个已经死掉的档**:能否找回只有点了才知道(勘察 c)。缓解:点了之后标记并换下一条,配一句提示(待审 3)。
3. **并批撤销是整批**:连续移除了三条,想只撤第二条做不到,只能全撤再重删。
4. **刷新页面后留一条死历史**:在存档页刷新,浏览器历史里多出一条本站条目,回到大厅后再按一次返回只是「吃掉」它、没有可见变化,第二次才离开整站。
   缓解:启动时若 `history.state` 是本站压的标记,`replaceState` 清掉标记(条目本身删不掉)。
5. **「回看上局」晚到会推动下面的行**:玩家可能正要点下面某行的「移除」。缓解:探测从大厅提前发出;误点了还有 5 秒撤销。
6. **撤销条遮住页面底部**:固定在底部 5 秒,列表最后一两行在那期间被盖住。缓解:有撤销条时列表底部留出等高内边距。
7. **游戏屏按手机返回键仍直接离开整站**:本 ADR 只修存档页与从它进入的历史页。
8. **决策 7 采纳时,「已发现」只增不减**:玩家把所有融合存档都移掉,渗界仍在 —— 这是有意的(移除说的是存档,不是分区)。

## 重新审视的触发条件

- 有了账号 / 云存档(跨设备那条线解冻)→ 移除要不要同步到服务端、要不要真的删服务端档,另立 ADR。

6. **决策 7**:移除一局融合存档前把它的组合落进「已发现」(提议),还是接受渗界卡随存档一起消失?

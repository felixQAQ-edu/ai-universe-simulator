# ADR-022 · 回合线程池准入与拒绝语义:让「此刻太挤」成为一个有名字的拒绝

- **日期**:2026-08-31
- **状态**:已采纳(七项待裁定项 2026-08-31 Felix 全裁通过;实现分三刀,见实施步骤)
- **决策者**:Felix

## 背景

[工程债清单 §1.1](../backlog-engineering-debt.md)(2026-08-06 外部代码审查,第 1 层「会宕机」)记着一条:
`GameController.turnExecutor` 是 `Executors.newCachedThreadPool()`(`server/.../web/GameController.java:47`),
池上限 `Integer.MAX_VALUE`,而 SSE 回合是**阻塞长连接**——每个在途回合占住一个线程直到模型吐完
(线上实测回合 ~15s)。两个放大器叠在一起:模型变慢 = 在途连接数翻倍 = 线程数翻倍,**没有任何东西会说不**;
[ADR-016](ADR-016-cost-gate.md) 的软闸是**日次数**闸(init 10 / 回合 300),**不是并发闸**——
一个脚本在一秒内打满当天额度,配额账面上完全合规,而线程池已经炸了。512MB 的 Fly 单机上,
这条路通向 `OutOfMemoryError: unable to create native thread` 而不是优雅降级。

**本刀是什么**:给回合路径装一道**并发准入**,让「此刻太挤」成为一个**有名字、有文案、有日志、玩家看得懂**的拒绝。

**本刀不是什么**(逐条,因为每一条都曾被当成「顺手一起做」):

- **不是换一行 `Executors.*`**。换池不解决问题:上限设成 N,一批必然被拒的请求照样能各占一个名额跑到被拒为止。
  **准入必须在领线程之前发生**,而不是在领到之后才发现没位子。
- **不是排队**(见立字 2)。
- **不治超时**:`SseEmitter` 120s 到期不中断 worker(`GameController.java:104`);
  `OpenAiCompatLlmClient:36-37` 的 `CONNECT_TIMEOUT=10s` / `REQUEST_TIMEOUT=60s` 约束的是「拿到响应」,
  **流体阶段(逐 token 读)没有上界**。已知,另刀 —— 但它与本刀的关系被写进已知代价 3,不是无关。
- **不治 init 路径占 Tomcat 线程**([ADR-015](ADR-015-overseas-deployment-form-factor.md) 已知代价 2,预登记出口),另刀。

### 勘察复核:两处读数订正(以现测为准,如实记)

沿本项目「与既有读数不符时以现测为准并如实记」的惯例(v5.4 外部审查那批同形):

1. 口径写「`submitAction` **三个**签名」——现测 `TurnStateMachine` 有 **两个** `submitAction` 重载
   (`:53` 三参 / `:63` 四参);**三个的是构造器**(`:36` / `:41` / `:46`)。守卫搬家牵动的契约面因此是
   **2 个重载 + 3 个构造器**,不是三个签名。
2. 口径写「**12 处**测试调用点」——现测 **13 处**(`TurnStateMachineTest` 9 + `SessionPersistenceWiringTest` 4)。

两处都不改变任何裁定,只影响刀 2 的工作量估算与逐条处置清单的行数。

### 约束条件

1. **单副本**([ADR-015](ADR-015-overseas-deployment-form-factor.md) 硬约束,`fly.toml` `min_machines_running = 1`):
   准入计数可以是纯内存的,与 ADR-016 日计数同一口径;多副本时同时失效。
2. **512MB / shared-cpu-1x**(`fly.toml`),且 `Dockerfile:37` 的 `ENTRYPOINT ["java","-jar","app.jar"]`
   **没有 `-Xmx`、没有 `-XX:MaxRAMPercentage`** —— 堆按 JVM 容器默认推导,**线程栈在堆外**。
3. **[ADR-016](ADR-016-cost-gate.md) 一字不动**:本 ADR 只划出它管不到的地方,不修订它(见立字 1)。
4. **[ADR-003](ADR-003-frontend-stack-and-taro-boundary.md) 接口纪律不动**:平台 IO 仍只在 `web/src/api/`,
   逻辑层仍只见 `TurnStream` 四类语义事件。
5. **引擎 / 校验 / golden / prompt lockstep / `schemaVersion`(保 "0.4")零动** —— 本刀不碰 `server/.../engine`
   与任何提示词。

## 候选方案

### 方案 A:换有界线程池 + 拒绝策略(`ThreadPoolExecutor` + `AbortPolicy`)

`new ThreadPoolExecutor(N, N, 0, MS, new SynchronousQueue<>(), new AbortPolicy())`:
队列容量为零(满足立字 2),满则 `execute()` 抛 `RejectedExecutionException`。

**优点**:
- **归还在结构上不可遗忘**——占用的开始与结束都由池自己管,没有任何「记得释放」的步骤。这是它最强的一点,如实记。
- 实现量最小,一行构造 + 一处 catch。

**缺点**:
- ⚠️ **决定性的一条:它没有名额可漏,但它的在途数只能靠手工维护一个计数器。**
  池自带的读数只有 `getActiveCount()`,而它的 javadoc **自陈 "approximate"** ——
  §C 已立字「在途数漏减是硬故障、且是最阴的一种(骗我们说『好了』)」,
  **一个自陈近似的读数不能拿来在冒烟上签字说「机制生效了」**。
  于是要拿到可签字的读数,就得在池旁边再挂一个 `AtomicInteger` ——
  **那正好同时踩中硬要求 C(漏减让日志撒谎)与 §三.5(两份计数会漂移)**。
  换句话说:方案 A 用「归还不会漏」换来了「读数会撒谎」,而这一刀的全部价值就建立在那个读数上。
- **拒绝决定藏在异常里**:我们要的是「先判断,再决定要不要开工」,而这个形态是「先开工,被弹回来」。
  日志、拒绝文案、在途数三样都得挂在 `catch (RejectedExecutionException)` 上。
- **N 同时是两件事**(池大小 = 准入上限)。以后想让它们不同(例如留一个线程做收尾)就要重构。
- 与立字 3(准入 = 占位,配额在名额之内跑)、立字 7(准入发生在容器线程、在合法性之后)在形状上对不上。

### 方案 B:有界池 + 有界队列(先收下,排队等位)

**优点**:
- 突发流量不掉请求,体感上「慢但没失败」。

**缺点**:
- **违立字 2**。排队意味着一个玩家的请求可能在队里躺 30s 再开始跑,而 `SseEmitter` 的 120s 已经在走;
  真正过载时队列只是把失败推迟并放大。**任何带缓冲队列的形态都不属于本刀**。

### 方案 C:准入信号量 + 容器线程前置拒绝(本 ADR 采纳)

在领线程**之前**用一个容量 N 的准入原语占位;占不到 → 直接返 HTTP 拒绝,**一个池线程都不领**。
占到 → 提交任务,任务体跑完(含配额、忙态、整个回合)后归还。

**优点**:
- ⚠️ **决定性的一条:它让「在途数」这个最容易撒谎的读数失去了撒谎的能力。**
  在途数不是一个被维护的东西,而是准入决定本身的投影(`capacity - availablePermits()`)——
  它没有一条可以漏掉的更新路径,因为它**根本没有更新路径**。
- **准入是一次判断,不是一次异常**:拒绝路径与正常路径在同一层、同一处代码里读得出来。
- 与既有守卫链形状一致(ADR-016 的「拦截在入口、拒绝成本 ≈0」肌肉记忆原样复用)。

**缺点**:
- **归还需要被设计成不可遗忘**,不像方案 A 那样白送。本 ADR 用「调用方拿不到那个名额」的结构解决(§4)。
  ⚠️ **这不是「C 在补 A 的短」** —— 两个方案各有一处会漏的地方,选 C 是因为**它漏的那一处可以被结构消灭
  (调用方拿不到名额),而 A 漏的那一处不能**(读数的近似性写在 JDK 的 javadoc 里,不是我们能封装掉的)。
  写清这一条是为了防止将来读这份 ADR 的人以为我们明知次优还选了它。

### 方案 D:不做准入,把 ADR-016 的软闸调紧

**优点**:
- 零新机制。

**缺点**:
- **日次数闸不是并发闸**(工程债 §1.1 已立字)。把回合日限从 300 调到 30,一个脚本仍能在一秒内发 30 个并发请求
  ——账面完全合规,线程池照炸。**这两个闸测的根本不是同一个量**。

## 最终决策

**方案 C — 准入信号量 + 容器线程前置拒绝。**

### 1. 十一条立字(已裁,不得自行调和)

1. **「此刻太挤」不归 ADR-016「排队不做」管辖。** ADR-016 已知代价 4 逐字是
   「**闸门触发**即拒绝,不做『排队等额度』…拒绝文案已给玩家明确预期(**明天再来**)」——
   它的主语是闸门触发,理由挂在「明天再来」上,**管的是日级状态**。
   「太挤」是**秒级**的:下一次点击就可能成功。
   ⚠️ **这不是推翻 ADR-016** —— 它在自己的管辖范围内一字不动,本刀只划出它管不到的地方。
   ⚠️ **本刀不触发 ADR-016 §重新审视条件末条**(「出现『排队等额度』的真实用户诉求且量级支撑 → 解冻已知代价 4」)
   —— 本刀**不排队**,也**不是等额度**。这句写在这里是为了防后来者把本 ADR 读成那条的解冻。
2. **不排队 = 队列容量为零。** 准入满即拒,不做「先收下再等」。任何带缓冲队列的形态都不属于本刀。
3. **准入不是判断,是占位。** 通过 = 占住一个名额,归还在任务收尾;**配额在名额之内跑**。
4. **池准入在前,配额在后。** 被池拒绝的玩家不该掉额度——他什么都没得到,秒级重试就能成功,扣额度是双重惩罚。
   「配额耗尽的请求流仍要各领线程」这个担心不成立:准入在前之后,那些请求已被限在 N 之内,
   **攻击面从无限线程降到 N 个线程**。
5. **守卫 1(合法性)前移到 controller;守卫 0(配额)与守卫 2(忙态 CAS)留原地。**
   守卫 2 前移要在准入路径上引入一个**必须永不失败的写操作**:CAS 成功后若被拒,相位停在 `GENERATING` 且无人放回,
   **该存档永久 busy,只有进程重启才解开**;而收益只是「连点第二下不吃线程」——连点本来就被准入挡着。
   守卫 1 零副作用零代价,前移干净。
6. **接受 ADR-016 守卫顺序反转,并写成显式立字。** 守卫 1 上移后合法性跑在配额之前;
   连带:**非法动作不再消耗配额额度**(今天会)。理由与立字 4 同源——玩家什么都没得到就不该掉额度;
   而 ADR-016 把配额排最前的理由「被刷时单次拒绝成本 ≈0」在合法性守卫上**同样成立**(零 LLM 调用、O(1) 内存判断)。
   ⚠️ 这条必须是**明写的裁定**,不许是搬家的静默副产品。
7. **容器线程上的顺序:合法性在前,准入在后。** 合法性零副作用、不占名额、不需要归还;
   让一个必然被拒的请求先占一个名额再还回来,是白白让真玩家少一个位子。
8. **拒绝走 HTTP,不走 SSE error 事件。** SSE 路线的代价不可修:**必须先领一个线程才能说这句话**,
   而线程正是要省的东西——为一句话付一个线程,在「太挤」这个场景下正好是反的。
   HTTP 路线的「文案能力为零」不是路线缺陷,是 `web/src/api/sse.ts:140-144` 那个映射的缺陷
   (不读 body、直接拼 `http_${status}`),**本来就该修**。
9. **语义映射落 `h5GameApi.ts`,让 `sse.ts` 回到它自己声明的边界。** `sse.ts:8` 文件头自陈
   「本模块只做『字节流 → (event,data) 帧』的**纯传输解析**;**语义映射在 h5GameApi.ts**」,
   而 `h5GameApi.ts:133 onError` 现在是直通转发——那里本来就该做这事。
10. **顺带清掉 `sse.ts:142` 的死映射 `409 → busy`。** 已复核:`grep -rn "409\|CONFLICT" server/src/main/java` **零命中**,
    服务端从不返回 409。这不是「顺手清理」,是同一处代码被重写时的必然产物。
11. **错误 body 里 `message` 何时出现,是一条规则、不是两个特例**(闸 A,刀 2 勘察时发现,2026-09-03):

    > **状态码本身就能说清的情形,文案归前端兜底表;只有服务端知道的细节,文案归服务端。**

    - **404**「这个档没了」——状态就能知道 → **前端**(刀 1.5 那句被真机<b>逐字证伪一次之后</b>才定下来,
      且它引用的是<b>前端控件名</b>「返回」;服务端没有理由知道那个按钮叫什么)→ body **只带 code**。
    - **`server_at_capacity`**「此刻挤 / 过几秒」、**`quota_exceeded`**(知道具体额度)、
      **`illegal_action`**(知道是哪个动作)——只有服务端知道 → **服务端**发文案。

    ⚠️ **它防的是一次「看不见的撤销」**:刀 1 的链是 `err?.message ?? fallback.message`,而 §2 拒绝链
    又要求刀 2 给 404 补结构化 body。**两条各自正确的规定撞在一起** —— 若那个 body 带上 message,
    它会**压过兜底表**,把刀 1.5 花一整刀定下来的那句话换掉,而**前端测试全绿**。
    ⚠️ **「一种形状、三个状态」不因此破**:形状是 `{error:{code, message?}}`,`message` 何时出现由本条规则决定;
    **写进立字它就是契约,不是特例**。

    **否决「服务端也发同一句、加一条 lockstep 钉住两处」**(刀 2 勘察时的初始建议,Felix 推翻):
    它会引入**本仓第一条 server 测试读 `web/` 源文件**的架构耦合方向。既有跨目录 lockstep
    (`LifetimeFamilyLockstepTest` 读 `../docs`、两条 fusion lockstep 读 `../prompts`)守的都是
    **运行时真依赖**(`prompts/` 是 Java 运行时真去读的东西);而那条要守的是**一份没有任何运行时关系的、
    拷贝的拷贝**。**为一个字符串开一道新的架构耦合方向,不划算。**

### 2. 拒绝链(立字 7 的落地形态)

```
POST /api/game/{saveId}/turn
  ├─ session == null            → 404 {error:{code:"session_not_found", …}}   ← 本刀补 body(今天是 .build())
  ├─ 守卫 1 合法性(容器线程)  → 400 {error:{code:"illegal_action", …}}      ← 由 TurnStateMachine 前移而来
  ├─ 准入 tryAcquire()(容器线程)→ 503 {error:{code:"server_at_capacity", …}} + WARN  ← 本刀新增,零线程
  ├────────────────【交接:提交到池;此后在池线程上】────────────────
  ├─ 守卫 0 配额                → SSE event:error code=quota_exceeded         ← 留原地,相位零触碰
  ├─ 守卫 2 忙态 CAS            → SSE event:error code=busy                   ← 留原地
  └─ TurnExecutor 跑整回合      → SSE narrative/delta/ending
```

⚠️ **两条边界读法**,写在这里免得日后读错:
- 一个**被准入拒绝**的请求不掉配额(立字 4);一个**通过准入但被配额拒绝**的请求**占了一个名额**
  (μs 级,配额判断是内存操作)。这是刻意的:配额在名额之内跑(立字 3)。
- 准入拒绝**不触碰会话相位**——它发生在 CAS 之前、甚至在池线程之前,服务端从头到尾没碰过这局。
  这与 ADR-016 守卫 0「相位零触碰」是同一条性质,只是发生得更早。

### 3. 准入原语与在途数是**同一个东西**(§三.5 的答复)

**单一真相源:在途数是准入决定的一个投影,不是一份被维护的计数。**

```java
// 建议形态(刀 2 实现细节可调,语义不可调)
final class TurnAdmission {
    private final Semaphore permits;      // 容量 N
    private final ExecutorService executor; // 归它所有(见 §5),生产构造自建、测试构造可注入
    private final int capacity;

    /** 在途数 = 已发出的名额数。它就是准入决定本身,不可能与之漂移。 */
    int inFlight() { return capacity - permits.availablePermits(); }
}
```

否决「`Semaphore` + 一个独立 `AtomicInteger` 供观测」:那是两份计数,它们**会漂移,然后日志开始撒谎**
(ADR-018 §4.1 那一族)。否决方案 A 的 `getActiveCount()`:它的 javadoc 自陈 **approximate**,
而 §C 已立字「漏减是硬故障、且是最阴的一种(骗我们说『好了』)」——
**一个自陈近似的读数不能用来签字说机制生效**。`Semaphore.availablePermits()` 返回的是同步器状态本身,
是精确快照(允许并发下过时,不允许错)。

### 4. 归还在结构上不可遗忘(§四.A 的落地)

⚠️ §四.A 明确禁止「记得在 `finally` 里归还」这种约束——**那是备忘录不是机制**。
落地形态:**调用方永远拿不到那个名额**。准入对象**同时拥有获取与提交**,只暴露一个方法:

```java
/** 占到名额 → 提交并返 true;占不到 → 返 false,一个线程都不领。 */
boolean submit(String saveId, Runnable work);
```

内部:`tryAcquire()` 失败即 `return false`;成功后把 `work` 包进 `try { work.run(); } finally { release(); }`
再交给 `executor.execute(...)`;`execute` 本身抛出时在容器线程上 `release()` 后重抛。

由此三件事同时成立:
- **「忘记归还」无法被写出来**——`GameController` 手上根本没有那个东西可忘。
- **归还的 `finally` 在包装层、不在业务 lambda 里**,故它套住的是整个任务体
  ——包括 `emitter.completeWithError(e)` 自己再抛的那条路径(§C 点名要验的那条:
  emitter 已因 120s 超时完成时,`completeWithError` 会抛)。
  ⚠️ 如果归还写在 `GameController` 的 lambda 里,它就成了调用点每次都要写对的一件事;
  由准入对象包装,它套住的是**调用方传进来的任何东西**。
- **池的归属随之改变** —— 见下一节。⚠️ 本 ADR 初稿在这里写过「`@PreDestroy` 一字不动」,**那句是错的**,
  已按 §5 改正(订正过程连同否决的三种形态一并留在 §5,不删)。

### 5. 池的归属与 `@PreDestroy` 形态(原口径「若被迫改则停下报告」——**这里就是那次报告**)

**结论:删掉 `GameController` 的池字段与 `@PreDestroy`,由准入对象自持池并自带 `@PreDestroy`。**

⚠️ **先记订正**:本 ADR 初稿称「准入对象只收一个 `Executor`、不持有其生命周期,故 `@PreDestroy` 一字不动」。
那个形态**字面上确实做得到**(池仍是 controller 的字段,只是传给准入对象用)——
**而它一字不动这件事本身,正是不选它的理由**:`turnExecutor` 这个字段的含义已经从
「controller 的工作池」变成「controller 只为关它而持有、由别人使用的池」,**而那一行看起来毫无变化**。
这正是 `GameController.java:46` 那句 `StreamController` 孤儿注释**形成的前一步**:
**立字失去宿主不是一次断裂,是一次「看起来没变」。**

**四种形态,逐条裁**:

| 形态 | 判断 |
|------|------|
| (a) `GameController` 保留 `@PreDestroy`,body 改成 `admission.shutdown()` | **否**。controller 变成「负责关一个它自己不使用的东西」,职责错位;而且它仍握着一条通往池的引用,已知代价 2 那件「手边就有的东西」没被拿掉。 |
| (b) 池仍是 controller 的字段,只传引用给准入对象(初稿形态) | **否**,理由如上:**「一字不动」在这里不是优点,是症状**。⚠️ 本 ADR 初稿在这一格还挂了第二条反对(「准入对象无法表达『我不再受理』」)——**该条已删**:它挂在一个本刀明确不做的功能上(见下「关闭期语义」),**拿一个不存在的未来功能去否决一个方案是不诚实的**。第一条足够。 |
| (c) 准入对象取名 `turnExecutor` 并暴露 `shutdown()` | **否,且最危险**(Felix 判)。行一样、含义已搬走 —— 与 (b) 同病,但更隐蔽:连字段名都在骗人。 |
| **(d) 池归准入对象,准入对象是 bean 并自带 `@PreDestroy`** | **采纳**。**生命周期跟着所有权走**:谁使用它、谁在它上面挂了不变量(名额与任务一一对应),谁负责关。⚠️ 仅此而已 —— **关闭语义原样承继,见下**。 |

**(d) 的连带收益**:`GameController` 里**不再有 `ExecutorService` 字段** ——
已知代价 2 的缓解从「一条源码级断言拦着别绕过准入」升级为「**手边根本没有那个东西可绕**」,
与 §4「让『忘记归还』无法被写出来」是同一种手法(**取消那个步骤本身,不是更小心地执行它**)。
源码级断言随之改写为更强的一条:**`GameController` 不得出现 `ExecutorService` / `Executors.`**。

**(d) 的代价,如实记**:准入对象因此**必须是 Spring bean**(否则 `@PreDestroy` 不会被调用),
这比一个纯 POJO 多一分容器耦合;测试仍可用「构造器注入 `Executor`」的便捷构造直接 new
(照 `TurnStateMachine` 三构造器的既有先例),不经容器,故可测性不受影响。

#### 5.1 关闭语义原样承继:`@PreDestroy` 的 body 就是 `pool.shutdown()` 一行

**本刀改的是「谁拥有这个池」,不是「它怎么关」。** 逐条钉死:

- **`@PreDestroy` 的 body = `pool.shutdown()`,与今天 `GameController.shutdown()` 逐字等价**,只是换了个宿主。
  ⚠️ **不做「停止受理」**:本 ADR 初稿在 (d) 那格写过「关闭顺序由它自己决定(先停止受理,再关池)」——
  **那句已删**。它是一句**暗示未来会加**的话,而**暗示会被后来者当成已决**。
- ⚠️ **不 `awaitTermination`,在途回合由进程退出硬掐** —— 这条**今天就是这样**(`GameController.shutdown()` 只调 `shutdown()`),
  本刀**原样承继、不顺手修**。玩家体感 = 那一回合丢了、盘上停在上一个完整回合,
  与 [ADR-015](ADR-015-overseas-deployment-form-factor.md) 已知代价 1(崩溃回滚一回合是特性非 bug)**同一族**。
  ⚠️ **池换了所有者之后,「顺手把它修好」会非常顺手 —— 不许。** 那是另一刀,缺口仍挂账。
- **那么关闭窗口里到达的请求穿谁的衣服?** 答:**不穿 `server_at_capacity` 的衣服**。
  池关掉之后名额仍然是空的,故 `tryAcquire()` **会成功**;失败发生在下一步 `execute()`
  ——它抛 `RejectedExecutionException`,走 §6 那条**提交失败 → 容器线程归还名额 → 重抛**的路径,
  最终落进**一个通用的非 2xx 兜底桶**(即已知代价 7 里那族「请求失败(HTTP …)」;
  ⚠️ **具体状态码取决于 Spring 默认 `/error` 的内容协商** —— 请求带 `Accept: text/event-stream`,
  可能落成 406 而不是 5xx,见已知代价 8,那块地已经被圈住)。
  **难看,但诚实**:滚动部署时「过几秒再点一次」恰恰是**错的**建议,而这个兜底桶不给建议。
- ⚠️ **由此立一条禁令,因为这正是日后最顺手的一次「改进」**:
  **不许把 `RejectedExecutionException` 映射成 `server_at_capacity`。**
  两者是**完全不同的情形**(一个是「此刻太挤,过几秒再来」,一个是「服务器正在关,过几秒也没用」),
  共用一个码比 `busy` / `server_busy` 那种「会被看错」更糟 —— **它连看错的机会都不给**(裁定 3 同源)。
  关闭期若要有自己的拒绝语义,**它需要自己的码与自己的文案,那是另一刀**;本刀只在已知代价 10 登记这个缺口。

### 6. 归还责任的交接点(§四.B 的落地,须画出来)

准入发生在**容器线程**,工作发生在**池线程**,中间有一个窗口:名额已占、任务尚未提交成功。

> **立字:`execute()` 正常返回**之前**,归还责任在容器线程(准入对象内的 catch);
> `execute()` 正常返回即交接给池线程的 `finally`。**

这个交接点**各有一条测试**(见 §测试面)。它不是理论风险:`execute` 在池 `shutdown()` 之后
(`@PreDestroy` 已跑、容器正在停)会抛 `RejectedExecutionException`,那一刻若不归还,名额永久丢失。

### 7. 前端语义映射搬家(立字 8/9/10 的落地)

- `sse.ts`:**不得再把 HTTP 状态翻译成业务 code**。把**状态码与 body 原文**交给上层即可
  (契约形态见实施步骤刀 1;`httpErrorCode` 整个函数连同 `409 → busy` 死映射一并消失)。
- `h5GameApi.ts` 的 `onError`:搬既有口径,**不发明新的** —— 仓库里已经有一份现成的、
  而且形状正是我们要的:`resumeGame` 的 `:80-87`
  「`err?.code ?? (resp.status === 404 ? 'session_not_found' : 'resume_failed')`」——
  **body 有 code 则优先取,否则按状态码兜底**;`safeJson` 也是现成的。
- ⚠️ **状态 → code 的兜底表必须保留**:`turn` 的 404 今天是 `ResponseEntity.status(404).build()`,**没有 body**。
  而刀 1(纯前端)会先于刀 2 上线 —— 那段时间里 404 只能靠兜底表认出来。
  **这条不是历史包袱,它正是刀 1 能独立上线的原因。**

### 关键理由

1. **准入必须在领线程之前** —— 这是本刀与「换个池」的全部区别。方案 A/D 都在「领到之后」或「另一个量」上做文章。
2. **复用已建立的肌肉记忆**:ADR-016 的「拦截在入口、LLM 零调用、拒绝成本 ≈0、相位零触碰」四条口径,
   在准入上逐条成立且更早生效;`QuotaGate` 那次「接缝照抄 `SessionStore.NOOP` 模式、既有测试调用点零改」的经验也在(见 §三.7 的答复)。
3. **正确避开的陷阱**:两份计数漂移(ADR-018 §4.1)、近似读数当证据(§4.13/§4.14)、
   守卫 2 前移导致存档永久 busy(立字 5)、以及「为一句拒绝付一个线程」(立字 8)。
4. **保留的演进路径**:准入不依赖池的**具体实现**(它只需要一个 `Executor` 的行为,生产自建、测试可注入),
   换有界池、加超时、把 init 路径也纳入同一道准入,都不必回本 ADR 的结构。

### 七项裁定(2026-08-31 Felix 全裁通过;推导原样留档,便于日后重估时知道当初据什么定的)

#### 裁定 1 · N 的量级与推导

**假想敌**(照 ADR-016「假想敌是脚本刷不是真人玩」的形状写一句):
> **假想敌不是高 QPS,是一个 15 秒不还的线程。** 放大器是**延迟**不是请求率,
> 故闸装在「同时占用」上,而不是「每秒请求」上。

**可查事实**:
- 单副本、512MB、shared-cpu-1x(`fly.toml`);`java -jar` 无 `-Xmx` 无 `MaxRAMPercentage`(`Dockerfile:37`)
  → 堆按 JVM 容器默认推导,**线程栈在堆外**(x86_64 Linux 默认约 1MB/线程,惰性提交)。
- 线上实测:回合 ~15s(工程债 §1.1 与 ROADMAP 同一读数)。
- ⚠️ **量级旁证,不是推导支点**:v5.8 Felix 亲手取的线上读数(上线两周余,`/data` 18 档、约 13 个回合)。
  它说明的是「这个产品现在几乎没人玩」这个**量级**,**对「同一秒有几局在跑」严格来说什么都没说**
  ——18 是累计量。下面的推导不架在它上面。
- ADR-016 日闸 ¥6 ÷ 单回合 ≈¥0.0035 ≈ **1700 回合/日**;按 15s 串行 ≈ 7.1 小时线程时/日
  —— **日预算本身已经是一道吞吐上界**。

**定案 N = 8**。承重的是下面两条(第三条是软的,单列并标明):
- **上界(内存,承重)**:8 × ~1MB 栈 ≈ 8MB 堆外 —— 对 512MB 可忽略。**N 的上界从来不是栈内存**,
  真正的限制是同时 8 条上游流 + 8 份 prompt 构建/JSON 解析跑在 shared-cpu-1x 上时的延迟劣化。
- **成本关系(承重,可数)**:N=8 满负荷 ≈ 32 回合/分 ≈ ¥0.11/分 → 日闸 ¥6 约 55 分钟打满。
  即 **N=8 时先撞到的仍是 ADR-016 的真闸**。这正是我们要的关系:
  ⚠️ **并发闸只负责 turn 路径上的「不死」,成本仍归 ADR-016**,两道闸不互相替代。
- **下界(不得误伤真人,软):** 一小撮朋友同时试 ≈ 3–5,8 留了余量。
  ⚠️ 这条**没有实测支撑**(见上「量级旁证」那条:累计量答不了并发问题),故它只是取值时的一个方向,
  不是论据;真被证伪的信号写在重新审视条件第一条。

⚠️ **「只负责不死」必须限定到 turn 路径,不得当成全站承诺** ——
`POST /api/game/init` 仍是**阻塞占 Tomcat 线程**(world-gen 线上实测首局 ~120s),
容器线程池上限是 Spring Boot 默认 **200**(`application.yml` 未配),**本刀完全没管它**
([ADR-015](ADR-015-overseas-deployment-form-factor.md) 已知代价 2,预登记出口,另刀)。
**不限定就是超卖,而超卖的立字迟早会被人当承诺引用。**

⚠️ **N 必须可 env 覆盖**(照 ADR-016 四阈值:`aiuniverse.turn.max-concurrent` / `AIUNIVERSE_TURN_MAX_CONCURRENT`)。
这不是为了调参方便,而是**刀 3 冒烟唯一能确定性触发拒绝的手段**——压到 1 再手工连点两次,
同 ADR-016 冒烟压低 `INIT=2/TURNS=3` 的做法。
⚠️ 堆的具体默认值我**没有实测**(无法在本机跑该容器),故上面只用了「栈在堆外」这条不依赖堆大小的事实;
若要把堆数字写进结论,须在刀 2/3 用启动日志或 `/actuator` 取一次真值。

#### 裁定 2 · 拒绝的 HTTP 状态码

| 候选 | 判断 |
|------|------|
| `429` | **否**。本仓库里 429 已被 `quota_exceeded` 占着语义(`GameController.java:66`);且 429 语义是「你问得太频繁」(per-client),而这是「服务器满了」(全局)。共用会让前端的状态兜底表当场二义。 |
| `409` | **否**。语义是冲突;而且它正是立字 10 要删的那条死映射,复活它是反向。 |
| **`503`** | **采纳**。RFC 9110 逐条对上:服务器因**临时过载**当前无法处理,且**是临时的**。 |

**`Retry-After`:不带(裁定)。** 理由不是懒:带上它等于给客户端一张「N 秒后自动重试」的许可证,
而**按 `Retry-After` 齐步重试正是过载时最坏的形态**(同步化的重试潮)。我们的前端不自动重试
——重试是玩家手点的,**秒级预期由玩家可见文案给,不由头给**。

#### 裁定 3 · 拒绝的 code 命名

⚠️ **不得复用 `busy`**:那个码现在的意思是「**这一局**的上一回合仍在结算」(per-save,`TurnStateMachine.java:77`),
两件不同的事共用一个码,玩家会有一半时间收到错的解释。

| 候选 | 判断 |
|------|------|
| `server_busy` | 与 `busy` 只差一个前缀,**日志里扫过去会看错**——而这两个码的区别恰恰是本条要保住的东西。 |
| `capacity_exceeded` | 与 `quota_exceeded` 同族后缀,读起来像一道配额 —— 而立字 1 的全部工作就是把它和配额分开。 |
| **`server_at_capacity`** | **采纳**。与 `busy` 不可能看错,与 `quota_exceeded` 不同族,「谁满了」一目了然。 |

⚠️ **刀 1 顺带定的第二个码:`service_unavailable`**(Felix 2026-08-31 追加裁定,见实施步骤刀 1 §5)。
它是**前端的状态兜底**(`status >= 500` 且 body 里没有 code),**不是任何一处后端主动发的码** ——
覆盖反代 502/504、容器启动窗口、Spring 默认 `/error` 那族**裸 5xx**。

| | `server_at_capacity` | `service_unavailable` |
|---|---|---|
| 谁发的 | 后端准入**主动**发(刀 2:503 + 结构化 body) | 前端**状态兜底**(5xx 且 body 无 code) |
| 情形 | **满了** —— 名额被占完,服务本身是好的 | **坏了 / 正在部署** —— 服务这会儿不在 |
| 玩家下一步 | **过几秒**再点一次(秒级,我们确实知道) | 稍后再试(**时长不知道,故不给数字**) |

⚠️ **不许把这两个合并成一个码。** 形状同本裁定开头那条(`busy` 不得复用):
「满了」与「坏了」给玩家的**下一步动作不同**,而合并之后
**连「玩家收到了错的解释」这件事都观察不到** —— 它连看错的机会都不给。

⚠️ **由此再立一条禁令,因为它是日后最顺手的一次「简化」**:
**不许在状态兜底层写 `503 → server_at_capacity`。** 那条规则会把 **Fly 网关的 503**
(与准入毫无关系)也贴上「此刻同时进行的回合太多,请过几秒再点一次」——
一句**在那个情形下确凿是错的**建议。准入拒绝之所以能被认出来,靠的是它**自己带 body**,
不是靠状态码;**「body 优先压过状态兜底」这条链序是它的唯一保障**(刀 1 有变异验证钉住)。
与 §5.1 那条「不许把 `RejectedExecutionException` 映射成 `server_at_capacity`」**同族同源**。

#### 裁定 4 · 玩家可见文案与呈现形态

**文案定稿:「此刻同时进行的回合太多,请过几秒再点一次」**
- 「过几秒」= 秒级预期 ✅;⚠️ 全句**不出现**「明天」「今日」「名额」「已满」任何一个日级词
  (「名额」已被 `quota_exceeded` 的「今日名额已满」占着)。
- 「再点一次」= 明确的下一步动作,并且和「决策圈还在」这个事实一致。
- 与 `busy` 的「上一回合仍在结算,请稍候」**可区分**:一个说「**你的**上一回合」,一个说「**此刻同时**进行的回合」。

**呈现形态(定死)**:
- **`notice` 黄条**(`web/src/features/game/game.module.css:396`,`#f6e7c8` / `#7a5a13`),不弹窗、不占正文。
- **决策圈保留可点**:`status` 回 `awaiting`、`availableActions` 不变 —— 玩家原地再点一次即可。
- **会话相位零触碰**:服务端停在 `AWAITING_ACTION`(准入拒绝发生在池线程之前)。
- 落地 = 把新 code 加进 `web/src/state/gameStore.ts:152` 的 `RECOVERABLE_TURN_ERRORS`。
  ⚠️ **诚实记**:今天该集合的两个分支可见行为几乎相同(`:321-326` 都回 `awaiting` + notice,
  差别只在 message 为空时的兜底文案),故「加进集合」主要是**声明意图**而非改变行为。
  仍然要加——那个集合是这类错误的**清单**,漏登记会让下一个读它的人以为这个 code 不可恢复。

**刀 1 追加的两条兜底文案**(同走 `notice` 黄条 + 决策圈保留可点,呈现形态与上面一致):

- **`service_unavailable`:「服务暂时不可用,请稍后再试」**
  ⚠️ **不写「过几秒」** —— 部署窗口与网关故障的时长**不是一个量级**,
  **给错的时间预期比不给更糟**。「过几秒」是 `server_at_capacity` 的专属,
  因为**只有那一条我们确实知道它是秒级的**。
- **`session_not_found`:「这一局的存档已经找不到了,点『返回』重新开始」**
  ⚠️ 文案里的动作**必须是玩家真做得到的**,已核对:「返回」= `BackButton`
  (`web/src/features/game/BackButton.tsx:43`,按钮上的字就是「返回」)经 `SceneBanner`
  渲染在游戏屏顶部(`GameScreen.tsx:192` 传 `onBack={reset}`);**回合屏上没有第二个出口**
  (「重新生成」只在 initError 屏、「取消」只在 loading 屏)。
  ⚠️ **不写「回首页」** —— 按钮上没有这三个字,让玩家找一个不存在的标签比不给指引更糟。
  ⚠️ 这条文案在刀 2 给 404 补了结构化 body 之后**仍然有用**:兜底表是常驻设施,不是过渡物。

  > **订正(刀 1.5,2026-09-01):原措辞「会话已失效,返回后点『继续上局』可接续」作废。**
  > 它在真机冒烟里**逐字被证伪** —— 照它去点「继续上局」,`GET .../state` 回 404,
  > 按钮**直接消失、玩家零提示**。根因是**两条各自正确的决定撞在一起**:
  > (a) `gameStore.ts:290-292` 立字「续局失败(404/损坏/网络)→ 静默清 saveId,不弹错误挡路」
  > (ADR-015 Slice 2);(b) 回合 404 本身就意味着这个存档**已经回不来了**
  > —— `GameSessionManager` 的 `@PostConstruct reloadFromStore()` 启动时把盘上所有档载进内存,
  > 故「内存里没有」基本等价于「盘上也没有或载不动」。
  > 两条一合并 = **我们让玩家去点一个必然失败、且失败后连句话都没有的按钮**;
  > 且按上述推理,**几乎不存在这句话能成立的场景**。
  > **错的不是刀 1 的机制**(映射链 / body 优先 / 状态兜底 / 渲染全部验通),**是那句话的内容**
  > —— 故是刀 1.5,不是回炉刀 1。修法两条见下面的「刀 1.5」小节。
  > ⚠️ **否决候选 B**(「…… 再点也不会有反应,请点『返回』另选一个世界」):
  > 「再点也不会有反应」**本身不够准** —— 再点会得到同一条黄条,那也是反应;
  > **修一句不准的话时不该引入另一句不准的话**。

#### 刀 1.5 · 让文案不再指向一个做不到的动作

**改文案只是一半,根治是第二条。**

1. **404 文案不再指路**(上面的订正块)。
2. **回合拿到 `session_not_found` → 清掉 localStorage 的 saveId** —— **这条才是根治**。
   否则玩家返回后,选择屏**还在拿一个已经死掉的存档招手**;那个按钮本身就是个谎,
   再好的文案也解释不了点了为什么没用。清掉之后:返回即无「继续上局」,
   文案不需要替系统道歉。
   ⚠️ **这不是新规矩** —— `resumeGame:290-291` 今天就在做「404 → 清指针」,
   ADR-015 Slice 2 的既有规则本就是**「存档确认不可用即清」**;本刀只是让**另一个同样确凿的
   死亡信号**(回合 404)也走这条既有规则。它与线 C 立字「退出不弃局」**不打架**:
   那条管的是**玩家主动返回**(触发者是人),这条管的是**服务端说这个档没了**(触发者是事实)。
   ⚠️ **落点在 `gameStore` 的 `chooseAction` → `stream.onError`**:`SAVE_ID_KEY` 与三个 helper
   是 ADR-015 Slice 2 立在 store 里的既定单点,**不新立抽象、不让 `h5GameApi` 碰 localStorage**。
   `RECOVERABLE_TURN_ERRORS` 成员**不动**(行为仍是 `awaiting` + notice)。

**⚠️ 必须比对后清,不能无条件清**(勘察发现,brief 里没有):

`session_not_found` 在回合路径上**只有一个来源** —— `statusFallback(404)`
(服务端 SSE error 帧只发 `quota_exceeded` / `illegal_action` / `busy` / `internal_error`,
`TurnStateMachine.java:67/72/77/89`;`GameController.java:101` 的 turn 404 今天是**裸的** `.build()`。
`GameController.java:91` 那个 `session_not_found` 是 `GET /state`,走 `resumeGame` → `GameApiError`,
**与回合流是两条不相交的路**)。**但来源单一不等于可以无条件清**:

> **多页签**:页签 1 在玩存档 A,页签 2 开了新局 B → localStorage 已是 B;
> 页签 1 的 store 里仍是 A,它点选项拿到 404 → **无条件清档会抹掉活着的 B 的指针**。

这正是 `resumeGame:287-288` 那段注释**已经写着**的形状(「玩家可能已经开了新局,这时清的是那一局的指针
—— **拿一次过期失败去删一个跟它无关的存档**」)。**这条规矩不是本刀发明的,是本刀找到了它已经写在旁边**。

**⚠️ 两半的判据刻意不同**(实现时才看清,勘察那版误把它们当成一件事、写作「同条件」,**该措辞作废**):

| | 作用域 | 判据 |
|---|---|---|
| `localStorage` | **跨页签共享** | **比对后清** —— 仅当 `readSavedId() === ` 这次报错所用的 `saveId`;它可能已经是别人的档 |
| `resumableSaveId` | **本页签自己的内存快照** | **无条件清** —— 这个页签正在玩的就是刚死掉的那个 A,清的就是 A 本身 |

**两个变量的作用域不同,判据当然不该相同。**

**附带收益(将来修那个旧洞时的入口)**:内存那半清掉之后,页签 1 返回时**根本不会出现「继续上局」**,
于是不会去点它、也就**不会触发 `resumeGame` catch 里那处无条件 `clearSavedId`** 把页签 2 的 B 抹掉。
⚠️ **那个旧洞本刀不修**(范围外),但**这条路径不再喂它** —— 记在这里,因为它是修那个洞时的起点:
`resumeGame` 的清档同样该比对,只是那要动 ADR-015 Slice 2 的静默失败语义,**须另开口径**。

⚠️ 对应的守护测试是**本刀的承重件不是补充用例** —— 它保护的是一个「代码看起来更对、行为却更坏」的方向,
故变异验证**须覆盖比对条件本身**(摘掉比对 → 该用例变红),不只验「摘掉清档 → 变红」。
**且必须是「② 单独红、① 仍绿」** —— 两条一起红只能说明 ② 搭了 ① 的便车,**比对那件事根本没被独立守着**。

**残余风险(如实记)**:若 404 来自路由/代理错配而非死档,指针仍会被误清。定性 = **实际损失接近零**
(那种情形下所有存档都进不去),⚠️ **写「接近零」不写「为零」** —— 盘上的档还在、丢的是指针,
说「为零」就轻了一档。

**挂账(本刀不做、不预拍)**:拿到 `session_not_found` 之后**决策圈仍可点**,再点仍会 404。
候选修法是该 code 下禁用决策圈,但那要动 `RECOVERABLE_TURN_ERRORS` 分支的**行为语义**
—— 属行为层,**不该用文案去糊**(这也是否决候选 B 的同一条理由)。

**⚠️ 一笔记账:那道文案回归闸不是全覆盖**(Felix 审阅时点明)。
`h5GameApi.test.ts` 的 `expect(message).not.toContain('继续上局')` 是个好闸,
**但它守的是这一句** —— 将来若有人在**别处**写出一句新的指路文案(另一个 code 的兜底、
某个组件里的提示),它**抓不到**。真正守住这件事的是 `gameStore` 那三条用例:
**那个按钮压根不该在**。闸是对的,只是别把它当成全覆盖 ——
**「有一条断言在守它」与「这件事被守住了」是两回事**(同 ADR-018 §4.13:绿有两种解释)。

#### 裁定 5 · 准入原语与在途数是不是同一个东西

**是,单一真相源。** 详见最终决策 §3(含否决两份计数与 `getActiveCount()` 的理由)。

#### 裁定 6 · 刀的切分

采纳 Felix 的建议三刀,顺序**不可换**(理由见实施步骤)。

#### 裁定 7 · 要不要新建接缝接口

**裁定:不新建。** 先说清现有这一层为什么够,再谈加层——

`QuotaGate` 之所以是接口 + `NOOP`,有两个具体理由:(a) 它有**真实的「关掉」形态**
(mock 豁免 / 既有 15 个测试调用点零改需要一个不做事的实现);(b) 它有**状态与配置**、且有**多个消费方**
(init 与 turn 两条路径)。准入这两条**都不成立**:
- 它没有「关掉」的产品形态 —— 关掉就等于回到今天的无上限,那不是一个我们想让人能配出来的状态;
- 它只有**一个消费方**(`GameController.turn`)与**一个实现**。加接口 = 加一个只有一个实现、
  一个消费方的抽象,而 ADR-018 §4.1 那一族的教训正是「多一层就多一处会漂移的判定」。

所需的**可测性**由**构造器注入 `Executor`** 达成(要测「提交失败路径归还名额」,注入一个必抛的 `Executor` 即可),
这不需要接口。

## 已知代价

1. **N 是拍在软启动量级上的数**:真实并发涨上来会误伤真人,而误伤的表现是一次**成功的点击变成一次拒绝**。
   缓解:env 可覆盖(无需改码)、拒绝有 WARN(误伤看得见)、并已挂进重新审视触发条件。
2. **`newCachedThreadPool` 仍在代码里,只是变得不可达**。准入在前之后它的「无上限」永远够不着,
   但**它还在**——日后有人在准入之外另起一条提交路径就回到今天。
   缓解**两层**:(i) 形态 (d) 把池移进准入对象,`GameController` **手边根本没有那个东西可绕**
   (同 §4「让忘记归还无法被写出来」的手法);(ii) 一条**源码级断言**
   (ADR-021 刀 2 用过同一手法:行为等价时行为测试抓不到,源码级断言抓得到)。真换池是另一刀。
   ⚠️ **该断言的两个洞必须在写它的时候就堵上**(见测试面):**作用域**要写死、**目标存在**要先断言。
3. ⚠️ **本刀最尖锐的一条:准入把「无限线程」换成了「有限名额」,而「名额被长期占用」没有被治。**
   一条卡死的 LLM 流会长期占住一个名额;N 条卡死 = **全站拒绝**。
   ⚠️ **且这个占用没有时间上界**:名额跟着 **worker** 走、不跟着 emitter 走 ——
   worker 不结束,`finally` 不跑,名额不还;而 emitter 120s 到期**不中断 worker**、
   流体阶段本身也**没有上界**(见背景「不治超时」)。
   **本条最坏情况不是「120s 后自愈」,是不会自愈。**
   ⚠️ 这句必须写死:按「最多卡 120s」估容量,会把这条代价**低估一个量级**。
   缓解 —— 也是这条代价的另一面:**名额有限反而让这个故障第一次变得可见**(WARN 会响),
   而今天它是**不可见的**(线程只是静静地涨)。**本刀因此为「超时那一刀」提供了开刀信号,而不是掩盖它。**
4. **守卫顺序反转的连带(立字 6)**:非法动作不再消耗配额额度 —— 对被刷场景是**放宽**。
   接受:它零 LLM 调用、零成本,真闸(¥)完全不受影响。
   ⚠️ 但如实记另一半:**非法动作的拒绝仍占一个 Tomcat 容器线程**(Spring Boot 默认 200,`application.yml` 未配),
   本刀不治容器线程,这条与 ADR-015 已知代价 2 是同一片地。
5. **拒绝不排队**:真正过载时玩家可能连点几次都被拒。接受,理由 = 立字 2。
6. **准入是 per-instance 的**:多副本时每个实例各有 N,与 ADR-016 内存日计数**同一条约束、同一条失效条件**。
7. **前端映射搬家的代价**:`sse.ts` 变薄(回到它自陈的边界),`h5GameApi.ts` 变厚一段;
   `http_${status}` 那族兜底仍在(且必须在,见最终决策 §7)。
   ⚠️ **订正(刀 1 追加 5xx 与 404 两条兜底文案之后,2026-08-31)**:原措辞
   「兜底那族**本刀不会变干净** —— 部署与反代层的裸状态码(502/504…)仍会以
   『请求失败(HTTP 5xx)』的形态出现,只是不再是**唯一**的形态」**已不成立**,
   原措辞留此备查、不并存两个口径。刀 1 之后:**5xx 那一族与 404 都说人话**
   (`service_unavailable` / `session_not_found`),`http_${status}` 退居**最后兜底**;
   真正还裸着的是**非 404 的 4xx 与其他杂状态**——尤其是已知代价 8 那个内容协商可能返的 **406**。
8. **`POST /api/game/{saveId}/turn` 的返回类型要从 `ResponseEntity<SseEmitter>` 放宽到 `ResponseEntity<?>`**,
   以便同一端点既能返 SSE 又能返 JSON 错误体。
   ⚠️ **实施注意(必须由断言钉住,不许留给冒烟发现)**:前端请求头带 `Accept: text/event-stream`(`sse.ts:62`),
   错误响应若不**显式** `.contentType(MediaType.APPLICATION_JSON)`,内容协商有返 **406** 的风险
   ——那会让玩家看到的不是我们写的文案,而是一个空壳错误。
   ⚠️ **而这件事比「本刀引入的风险」更早**:全仓**没有任何 `@ControllerAdvice` / `@ExceptionHandler`**
   (2026-08-31 复核,零命中),故今天 `@Valid @NotBlank actionId` 的 400 **已经**走 Spring 默认 `/error` 做内容协商,
   而那个请求只带 `Accept: text/event-stream`。**本刀不是把这个洞打开,是第一次让它被断言看着。**
9. **`@PreDestroy` 被迫改**(形态 (d),最终决策 §5;原口径「若被迫改则停下报告」已履行):
   池的所有权从 `GameController` 搬到准入对象,连带**准入对象必须是 Spring bean**(否则 `@PreDestroy` 不触发)。
   接受:这换来的是「controller 手边没有池可绕」与「关闭顺序归使用者自己决定」。
   ⚠️ 被否决的三种形态(委托 / 只传引用 / 同名暴露 `shutdown()`)**逐条留在 §5 不删**——
   其中「只传引用」那种**字面上可以一字不动**,而**那正是不选它的理由**。
   ⚠️ **关闭语义本身原样承继、一个字不改**(§5.1):不 `awaitTermination`、在途回合由进程退出硬掐,
   与 ADR-015 已知代价 1 同族,**仍挂账**。池换了所有者不构成修它的理由。
10. **关闭期没有自己的拒绝语义**(§5.1 登记的缺口):`@PreDestroy` 跑过之后到进程退出之前到达的请求,
    落进通用兜底桶(状态码取决于默认 `/error` 的内容协商,见已知代价 8),**没有一句为「服务器正在关」写的话**。接受:滚动部署窗口以秒计、软启动量级几乎撞不到,
    且**通用兜底不给错建议**好过借用一个说「过几秒再点一次」的码。
    ⚠️ 缓解不是「以后顺手映射过去」——那条路已被 §5.1 明令禁止;要治就得给它自己的码与文案,那是另一刀。

## 挂账

### 准入容量的**现值**不可观测(刀 3 冒烟当场冒出来的缺口,2026-09-04)

**它补的是哪一种不可观测,写清楚**:不是「拒绝没被记录」——拒绝那一刻的 WARN 已经有了;
缺的是**配置的现值**。观测面**只在拒绝那一刻说话,平时一声不吭**,于是:

> **我们能证明「压低生效了」,证明不了「还原生效了」。**

刀 3 靠 `inFlight=1/1` 的**分母**证明了 `AIUNIVERSE_TURN_MAX_CONCURRENT=1` 真被绑进来;
而 `unset` 之后 N 是不是回到 8,**只能信 `fly secrets unset` 的回执** ——
现值没有任何一处会说出来,除非再制造一次拒绝(而那要再占满名额)。
⚠️ **这是不对称的**:让它变严有读数,让它变松没读数,**而变松才是危险的那个方向**。

**补法形状 = 刀 2 前置那条启动汇总 INFO 的同一招**:启动时打一条
`[turn-admission] 准入容量 N=8`。**开机就说清当前配置**,压低与还原都变成可核对的读数
(同 `[session-store] 启动回载:载入 N / 跳过 M / 拒载 K` ——
那条也是「把一个只在出事时才现形的东西,变成一个平时就能读的数字」)。

⚠️ **不在刀 3 做**(冒烟已通过、不在其范围;且改的是观测面而非机制)。
**解冻条件**:下一次要动 `TurnProperties` 或准入观测面时**顺手做掉**——
它是一行 `log.info`,不值得单开一刀,但值得在这里记着**它补的是什么**,
免得下次被写成「加个日志」而丢掉判据。

### 落盘目录分家(本刀记账,刀 2 前置的另一半)

**由来**:刀 2 的观测面是「拒绝时打一条 WARN」(§实施步骤 刀 2 第 4 点)。开工前勘察发现,
每次启动都稳定出现一条 `[session-store] 存档回载失败……quota-2026-07.json — 未指定 archetype`
——**行为本身是对的**(单档容错 = 跳过 + 保留原文件留尸检,ADR-015 立字),
**错的是它每次启动都出现**:`FileSessionStore.loadAll` 只按 `.endsWith(".json")` 收,
而 [ADR-016:114](ADR-016-cost-gate.md) 明写月账 `quota-YYYY-MM.json`「**与会话同目录**」,
且月账**一月一个、永不删除** → 线上已有 2026-07 / 08 两份,**一年之后是 12 条**。
稳定出现的 WARN 会把人训练成自动跳过 WARN,**而那正是刀 2 要往里加信号的那条通道** ——
故:**先清噪音,再加信号**。⚠️ 这不是可选的清洁工作,是刀 2 的前置。

**已落地的是症状层修法(2026-09-03,刀 2 前置)**:`FileSessionStore.loadOne` 按**文档形状**三分
(无 `world` 对象节点 → DEBUG 静默跳过 / 有 `world` 但载不动 → **WARN + 留尸检,口径逐字不变** /
连 JSON 都解析不了 → 也走 WARN,无从判断、保守叫出声),外加一条启动汇总 INFO
「载入 N / 跳过 M / 拒载 K」。**判据不看文件名** —— `SAFE_SAVE_ID` 是 `[A-Za-z0-9-]+`,
`quota-2026-07` 同样匹配它,另立第二条 UUID 正则等于两处「什么是合法 saveId」并存。

**⚠️ 它治的是症状,不是根**:根是「两个模块共用一个目录命名空间而没人划界」。

**被推迟的选项 B · 分目录**(存档进 `<dir>/sessions/`,或月账进 `<dir>/quota/`):

- **形态**:两个租户各占一个子目录,扫描面天然不重叠,**不需要任何文件名或文档形状判据**;
  真坏档仍叫得出声(`sessions/` 下任何 `.json` 失败照旧 WARN,留尸检一字未改)。
- **代价 1**:**要改 ADR-016 的明文口径** —— [ADR-016:114](ADR-016-cost-gate.md) 逐字写着「与会话同目录」,
  那是写进 ADR 的决策,**位置本身就是决策,不是实现细节**。⚠️ 循本项目惯例
  **不回改 ADR-016**,由做 B 的那一刀新立划界(旧 ADR 不动)。
- **代价 2**:**线上卷 `/data` 上有真存档要迁移**,而迁移**本身需要一条判据**(哪些文件该搬)——
  判据要么退回「按 UUID 文件名」那条被否决的路,要么落进一条 Felix 亲手的一次性 `fly ssh` 命令。
- **代价 3**:**迁移遗漏 = 所有存档静默消失**,是「吵变哑」的最坏形态(且是全量);
  要补一条启动护栏(顶层仍有 UUID 形 `.json` → ERROR),而那条护栏又要用回代价 2 那个判据。

**解冻条件(写死,不留模糊)**:**第三个模块也往这个目录写文件时。**
判据取「租户数」而不是「觉得该整理一下了」——**两个租户可以靠认自己东西共存,三个租户才值得分家**;
门槛可数,否则每次看到这个目录都会有人想顺手分家一次。

**⚠️ 已落地那条修法自带一个洞,已由汇总 INFO 挂住**:分流判据是「有没有 `world` 对象节点」,
若将来有人重构持久化文档结构(把 `world` 改名或挪层),**全部存档会被静默跳过** ——
汇总 INFO 就是它唯一的现形处(读到 `载入 0 档,跳过 12 个非存档文件` 即当场暴露)。
故那条 INFO **是修法能成立的前提、不是装饰**,连同它的计数一起有守护测试钉着。
另:该判据在 `Engine.restore` 有一份同判据的合法性闸门,两处**互相指认、必须一致**(改一处必须看另一处)。

## 重新审视的触发条件

### 刀 1 · 前端语义映射(纯前端,零后端风险,可独立冒烟)

1. `sse.ts`:删 `httpErrorCode`(连同 `409 → busy` 死映射,立字 10);非 2xx 时把**状态码与 body 原文**
   交给上层。`sse.ts` 自此不认识任何**由 HTTP 状态翻译而来**的业务 code。

   **契约定稿(Felix 2026-08-31 审过)**:`onError` 收一个**判别联合** `SseFailure`,
   `http` 分支**没有任何 code 字段**——sse.ts 拿不到一个地方去写业务码,这是**构造保证不是纪律**:

   ```ts
   export type SseFailure =
     | { kind: 'http'; status: number; body: string }                       // 非 2xx:状态 + body 原文
     | { kind: 'transport'; reason: 'network' | 'no_body'; message: string }; // 传输事实
   ```

   ⚠️ **`network` / `no_body` 留在 sse.ts(裁定,不是遗漏)**:立字 10 逐字是「不得再把 HTTP **状态**
   翻译成业务 code」,这两条**不是状态翻译**——它们是传输事实,且 `network` 这个词
   `h5GameApi.ts:27/54/78` 自己就在用,是**共享的传输词汇**。行为逐字不变。
   ⚠️ 类型落 `sse.ts` 自身,**不进 `contract.ts` 也不进 `index.ts`**:那是 ADR-003 的
   provider-agnostic 边界,让它学会 HTTP 状态与 body 原文等于把传输细节顶穿到边界上。
2. `h5GameApi.ts` 的 `onError`:搬 `resumeGame:80-87` 的现成口径(**body 有 code 优先取,否则状态兜底**),
   `code` 与 `message` **各自独立兜底**(故「code 取自 body、message 取自状态兜底」是允许的混合)。
   优先级链**写死**:

   ```
   transport                  → { code: reason, message }        ← 与刀 1 之前逐字相同
   http 且 body 有 error.code → 取 body 的 code(message 同取,缺则退该状态的兜底文案)
   http 且 status === 404     → session_not_found  「这一局的存档已经找不到了,点『返回』重新开始」
   http 且 status >= 500      → service_unavailable「服务暂时不可用,请稍后再试」
   http 其他                  → http_${status}     「请求失败(HTTP ${status})」  ← 最后兜底,保留
   ```

   ⚠️ **`status >= 500` 不枚举** 500/502/503/504(枚举会留缝)。
   ⚠️ **body 优先永远压过状态兜底**,链序不可反:503 带 `server_at_capacity` body → 得
   `server_at_capacity`(刀 2 的准入拒绝);503 裸 → 得 `service_unavailable`(网关/默认 `/error`)。
   **同一个状态两种读法,各有一条测试**(裁定 3 那条「不许在状态兜底层写 `503 → server_at_capacity`」
   的落地保障就是这条链序)。
   ⚠️ **解析 body 原文用 `safeParse(text)`,`safeJson(resp)` 一个字不改**:后者入参是 `Response`、
   字符串路径用不上,而把它改成 `safeParse(await resp.text())` 会让 init/resume **全部现有测试桩当场失效**
   (那些桩只有 `json:`,没有 `text:`)。两个函数**各写一行互相指认的注释**说清为什么是两个 ——
   它们吃的是**不同类型的输入**,不是同一个判断的两份拷贝(非 ADR-018 §4.1 的两份真相)。
3. `gameStore.ts:152`:`RECOVERABLE_TURN_ERRORS` 加 **`server_at_capacity`** 与 **`service_unavailable`**

5. `GameController.java:46` 那句「同 `StreamController` 骨架口径」**一并重写**

**三处自己抓到的假探针(都是被变异抓出来的,不是读代码读出来的)**

1. **两条准入用例用「收下但不跑」的停车执行器 → M1 下照样绿**:任务不跑,配额与相位本就不会动,
   那两条断言测不出「被准入挡住」与「跑进去了」的差别。改真并发(第一发卡在任务体里占住名额)。
2. **回合配额闸的宿主是 `TurnStateMachine`,不是 controller**(controller 的 `quota` 只服务 init)——
   原先把 `CountingQuota` 只传给 controller,计数**恒 0**,「零配额调用」在任何实现下都通过。
   已装进状态机,并各加一句**控制组**断言(合法动作确实消耗一次配额),否则「0」永远可能只是闸没接上。
3. **配额断言是竞态绿**:配额在异步线程里查,而断言紧跟 `turn()` 返回 —— M1b 下线程还没起来,故仍绿。
   主判据改用**同步的提交计数**(在调用线程上加)。

**量具自身的两条**(§4.14 同族,记着免得下次重踩):变异脚本在 glob 失败处提前退出、**把变异留在了工作区**
(已加 `trap … EXIT` 复原);`mv .bak` 复原保留旧 mtime 会让 Maven 增量编译跑**陈旧 class**(一律 `touch`)。

**审阅抓到的两条,连在一起(Felix,2026-09-03)**

1. **`catch (RuntimeException)` 比它自己的 javadoc 窄 —— 真洞,已改 `catch (Throwable)`。**
   `newCachedThreadPool` 起不出线程时抛的是 `OutOfMemoryError: unable to create native thread`,
   那是 `Error`;**而它正是本 ADR 背景里那个场景**(512MB、线程栈在堆外)。
   ⚠️ **后果不是崩溃,是慢性失血**:它**不一定杀死 JVM**(堆可能完全健康、进程继续跑),
   于是每漏一次名额上限就少一个,直到 **N=0 = 全站永久 503**。
2. **拒绝 WARN 里的分子是同义反复,原注释那句「此时必然 = capacity」是过头话。**
   `tryAcquire()` 返 false 当且仅当那一刻可用名额为 0,故随后再读一次 `inFlight()`:
   要么读回 `capacity`(**把「被拒了」重说一遍**),要么读回更小的数(**就是否决闸 B 时用的那个竞态,
   只是窗口短得多**)。→ **这条 WARN 里真正带信息的是分母**(当时生效的 N),不是分子。

> ⚠️ **两条是连着的:第一条是唯一能让第二条那个同义反复变成谎话的路径。**
> 名额一漏,`8/8` 就从「恒真」变成「在说一件假事」,**而它与真实饱和在日志上长得一模一样**。

顺带修一处 `application.yml` 的**段落头串位**(ADR-016 那三行头下面跟成了 `turn:` 块,
`quota:` 被推到后面)——**段落头不再头它自己的段落**,同「文档会骗人」那族。

### 刀 3 · 真机冒烟

⚠️ **必须用两个存档,不能单存档连点。** 单存档的第二次点击**先撞忙态守卫**(per-save CAS,守卫 2),
你会拿到 `busy` 然后以为准入验过了 —— **那是 ADR-018 §4.18「观测指标要与被测对象匹配」的原样重演**
(热区先测四角那次:形态没错,是指标问错了问题)。

1. 冒烟前置照 [runbook §3.1.5](../phase3-fly-deploy-runbook.md):`curl /actuator/info` 比对 commit SHA。
   ⚠️ 这一步在本刀有具体后果:**压低 env 之后「没被拦」也可能只是部署陈旧**
   ——那个坑摔过(ADR-016 冒烟首轮把部署陈旧误判成注入 bug)。**先证明线上跑的是这次的镜像,再验功能。**
2. 临时 env 压 `AIUNIVERSE_TURN_MAX_CONCURRENT=1`;**开两局**(两个 saveId),
   在 A 局回合跑着时(~15s 窗口)对 **B 局**发回合请求 → 必被拒,且拿到的是 `server_at_capacity` **不是 `busy`**
   (拿到 `busy` = 验错了对象,回去看你是不是在同一局上点了两下)。
3. B 局看到 **notice 黄条 + 秒级文案 + 决策圈仍可点**,几秒后重点即成功(会话未受损)。
4. 服务端 `fly logs` 见 `[turn-admission] … 拒绝 inFlight=1/1` 一条 WARN。
   ⚠️ **判据是「WARN 出现了」+「分母是 1」,不是分子**(刀 2 审阅立字):
   **分母证明 env 覆盖真的生效了**(线上默认 8,读到 `/1` 才说明压低的那个值被吃进去了,
   同 §3.1.5「先证明环境是你以为的那个」);而**分子是同义反复** ——
   `tryAcquire` 失败当且仅当那一刻名额为 0,它只是把「被拒了」重说一遍。
   **别对着分子找意义。**
5. 撤 env 恢复 N,复验正常路径不受影响。

**冒烟结果(2026-09-04,Felix 亲手,线上真机):通过。** 四条实证逐条记,**不写「通过」了事**:

```
03:38:39  WARN [nio-8080-exec-9]  [turn-admission] save=5e27944c… 拒绝 inFlight=1/1
03:38:40  INFO [pool-2-thread-1]  [event-loop] save=a4c2fa24… T1 action=A 落账
```

1. **分母 = 1** —— 压低的 env 真被绑进了 `aiuniverse.turn.max-concurrent`(判据本身,见上一条)。
2. ⚠️ **拒绝发生在 `nio-8080-exec-9`,那是 Tomcat 容器线程,不是 `pool-2-thread-*`** ——
   **这是「准入在领线程之前」最直接的一条实证**:被拒的请求从头到尾**没碰过池**。
   **整刀的核心主张(它与「换个池」的全部区别)被一个线程名证掉了。**
   这条比黄条更有力:黄条只说明玩家收到了拒绝,线程名说明**那次拒绝没花掉我们要省的东西**。
3. **两个不同的 saveId**(`5e27944c` 被拒 / `a4c2fa24` 在跑)—— 确实是两局,
   **没撞忙态守卫、没验错对象**(那正是本节开头那条「必须两个存档」要防的事)。
4. **立字 3「准入拒绝相位零触碰」在真机上成立** —— 两张截图里 **A 局已是「第 1 回合」、
   B 局仍停在「第 0 回合」**:被拒那一局**回合数没动、配额没扣、相位没碰**。
   ⚠️ 这条是冒烟时**自己冒出来的**、不在验收清单里 —— 记下来,因为它是单元测试
   (`admissionRejectionLeavesPhaseUntouched`)在真机上的对照证据。

玩家侧:B 局黄条「此刻同时进行的回合太多,请过几秒再点一次」+ 控制台 `503 (Service Unavailable)`;
env 已 `unset` 还原(⚠️ **还原本身不可核对,见 §挂账「准入容量的现值不可观测」**)。

## 测试面

⚠️ **起点是零**:`POST /api/game/{saveId}/turn` **服务端没有任何测试**(`server/.../web/` 下只有
`ArchetypeControllerTest` 与 `GameControllerQuotaTest`,后者两个用例都是 init 的)。
准入要落进的是一个**当前无覆盖的类**。

**必须建**(清单,实现留刀 2):

- 404 / 合法性拒绝 / 准入拒绝,**各自的结构化 body 形态**(沿用 init 的 `{error:{code,message}}` **一种形状、三个状态**),
  含 **Content-Type 断言**(已知代价 8)。
- 准入通过后**配额拒绝仍走 SSE**(守卫 0 留在原地的证据)。
- **池拒绝时配额零调用**(立字 4 的可验证形态)。
- **池拒绝时相位零触碰**(守卫 2 在池线程里,自动成立 —— 但要有断言在看)。
- **在途数进出配对**;**提交失败路径归还名额**(§四.B 交接点,注入必抛的 `Executor`)。
- **任务体抛出时仍归还**(§C 点名那条:`completeWithError` 在 emitter 已超时完成时自己会再抛)。
- **源码级断言**(已知代价 2 的缓解 (ii)),⚠️ **两个洞在写的时候就要堵上**:
  1. **作用域写死**:扫描范围 = `server/.../web/` 包(或就 `GameController.java` 一个文件),
     断言其中不得出现 `ExecutorService` / `Executors.`;
     **准入类显式排除并在测试里注明理由**——它**必须**持有池,那是形态 (d) 的全部内容。
     ⚠️ 不写作用域 = 全仓扫描 = **打到准入类自己,断言当场自相矛盾**。
  2. **先断言目标文件存在**:源码扫描类断言的经典死法是「文件改名 / 移动 → 扫描零命中 → 绿灯」——
     ADR-018 §4.14 那族的原样重演,也与「遍历清单的守护、清单本身没人守」是同一个洞
     (ADR-021 刀 2 那次:片段被从清单里删掉,所有 lockstep 照样绿)。
     **先断言目标文件读得到,再断言它的内容。**
- ⚠️ **冒烟的可信度也要有断言在看**:一条「**单存档第二次提交拿到的是 `busy` 而不是 `server_at_capacity`**」的用例
  —— 它钉住的不是产品行为,而是**刀 3 那条「必须用两个存档」的理由**;
  没有它,那句话只是清单里的一行叮嘱(ADR-018 §4.18)。

**变异验证**(ADR-018 §4.13;写进清单的探针,先问「**谁在自动看它**」):

- 摘掉 `finally` 里的归还 → 测试必须变红;
- 摘掉提交失败路径的归还 → 第 N+1 次请求必被拒 → 测试必须变红;
- `completeWithError` 再抛那条路径 → 断言在途数归零(摘掉包装即变红);
- 把守卫 1 塞回 `TurnStateMachine`(退回今天)→ controller 侧新测试必须变红;
- 把池退回 `GameController` 的字段(退回形态 (b))→ 源码级断言必须变红;
- ⚠️ **把被扫描的目标文件改名 / 移走 → 断言必须变红,而不是照常通过**
  ——这一条验的不是产品行为,是**那条断言本身有没有在看东西**(§4.14)。

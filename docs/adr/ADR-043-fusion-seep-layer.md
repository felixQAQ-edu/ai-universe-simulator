## 背景

融合局在游戏内一直走「纯 host 呈现」:`registry.ts` 的 `FUSIONS` 只登记封面与卡皮肤,局内皮肤一律取 host 的
(ADR-018 §5 Q2;ADR-019 §4 立了「安全渗漏签名」六条约束,但「本轮只立字、不实现」,至今没有实现)。
《验讫》(cultivation × cthulhu,ADR-035)在局内看起来就是一局修仙:克苏鲁那一半只剩两根换皮轴的名字(清明 / 窥天)。

Felix 2026-11-21 定了**方向乙**:融合局照旧用宿主皮肤,外来世界只「渗」进一两样东西;做成通用机制 ——
每个融合组合在登记表里登记自己的渗入项,没登记的组合(识海遗蜕、缺页的人防工程)逐字节不变。第一个登记《验讫》。

### 勘察结论(只读 `main` `b161da0`,2026-11-21)

**a. 融合局怎么取宿主皮肤。** `resolveWorldTheme`(`web/src/features/game/theme/registry.ts:166`)是全项目唯一的世界判定入口:
融合局 `key = host×foreign`,`FUSIONS`(`registry.ts:139`)命中 → 封面与卡皮肤取融合登记,`skin` 取 host 的;没登记的组合回落 host 单体登记。
`GameScreen.PlayingScreen` 拿 `theme.skin` 查 `SKINS` 得到一套 `WorldSkin`(`contract.ts:256`),再按槽分发:`Ambient` / `Stats`(经通用 `StatsPanel`)/
`Prose?`(可选,缺省通用 `Prose`)/ `Interlude?` / `Actions`。**没有任何「融合局专属」的局内入口**;`WorldTheme` 也没有可挂渗入项的字段。

**b. 信号来源。** 通用层只为**一根**轴算信号:`useSignalCrossing(skin, axes, values)`(`theme/useSignalCrossing.ts`)按 `skin.signatureAxisKey`
取那根轴的档序号(`index`)、向上跨档计数(`tick`)与当前档 severity;皮肤组件只收 `signatureTick`(Ambient)/ `signatureSeverity`(Prose)/
`AxisView.signature`(Stats),**不许读 key**(ADR-018 §4.2、§5 Q5)。修仙 `signatureAxisKey = 'realm'`,所以在《验讫》里:
- 压印要的「境界向上跨档」= 现成的 `signature.tick`;「境界当前档 > 0」= 现成的 `signature.index`。**都不必另起检测**。
- 墨洇要的「窥天档序号」、字洇要的「清明 severity」**今天没人算** —— 需要通用层按渗入登记的 key 另算(同 `useSignalCrossing` 的取法)。
  《验讫》的轴(ADR-035):`knowledge` = 窥天(未觉 / 见格 / 知渔,累积,`perilAtHigh`),`san` = 清明(澄澈 / 起雾 / 将失,致命损耗);
  severity 由服务端派生、随 bands 下发,前端只读。

**c. 境界「只升不降」引擎不保证。** `realm` 是 accumulation 轴,但「只涨或持平、不无故回落」只写在 behaviorHint 里(`ArchetypeRegistry.java` `realm` 一条),
是**提示词约束**;`Engine` 只把累积轴用于「≤0 不致死」,不拦回落;修仙规则的 `hiddenLogic` 明写可带「境界后果」。
初值「10–25」同样只是提示词。故:境界可能跌回初境;开局可能已在小成。→ Felix 补裁 7。

**d. 境界印的版式。** `XianStats`(`theme/xian/XianStats.tsx:59`)渲染 `.lingmai`(flex,`space-around`)里四根灵脉 + 一方境界印(`RealmSeal`,签名轴);
`.seal` 带八角 `clip-path`、`.sealFace` 带 `overflow: hidden` + `clip-path`(`xian.module.css:486` 起),**印放进 `.seal` 里会被切掉**。
样张把印放在数值区里绝对定位:`left: calc(50% + 18px); top: 86px` —— 成立只因境界在五根轴里排第三(气血 / 灵力 / 境界 / 清明 / 窥天)、
宽度对称时恰好居中。样张实测(375 宽):境界印 70×70,印的中心落在境界印框的 **(97%, 69%)**。
现成的 `--seal-x/--seal-y` 是**视口坐标**、滚动时下一帧(rAF)才更新,给常驻元素定位会在滚动时与印错开。→ Felix 补裁 8。

**e. 正文。** 修仙没配 `Prose` 槽,走通用 `Prose`(`game.module.css:230` `.prose`,无 `position`)。克苏鲁的文字异常靠 `Prose` 槽(`CthuProse` +
`useAnomaly`):分片 span + 命令式改字 + `data-orig` 回写 + 换行守卫 + `paused` 停表 + 持锁兜底放锁(§4.11)。
字洇只变颜色、不换字、不改字宽,**不需要命令式改 DOM**(见决策 5)。生命周期:`useSkinRuntime(skinKey, turn)` 在换皮肤 / 换回合 / 卸载时走同一个
`teardown()`;`runtime.setTimeout` 自带世代号核对;F-041 的教训是「revert 不等于回调不会再来,回调里写 state 先查 `runtime.alive(token)`」。

**f. 墨渍压字(样张实测,motion 样张 375 宽,对 path 的填充区逐像素采样)。** 墨渍的上色区与文字行框相交:

| 窥天档 | 数值区左下 | 数值区右下 | 正文左上 | 正文右下 |
|---|---|---|---|---|
| 未觉 | 「气血亏损」两行的 11% / 48% | — | — | — |
| 见格 | 同上 | 「见格」18% | 0 | — |
| 知渔 | 「气血亏损」68% / 100%、「灵力见底」4% | 「见格」81%、「41」1% | 首行 2% | 0(**随正文末行长短而变**) |

(只采了水渍主体 path;墨点、水线外缘没计,实际只多不少。)数值区四角**文字之外只剩约 10px 的内边距**(`.lingmai` padding 10 / 9 + 1px 边;
最左一列的档名贴着左下角)——样张尺寸的墨渍**放在原位不可能不压字**。手算对比度(`--muted` #475454,底按 `.lingmai` 渐变合成,未计顶图):
常态 6.1;墨渍下 5.17 / 4.74 / 4.26(三档);压在水线上 4.18 / 3.45 / 2.82。→ Felix 补裁 9。

**g. 动效预算(宿主修仙,`xian.module.css` 头注释):1 + 0 + 1。** 持续 1 = 天穹层(流云 + 微粒同层);**低频 0(收敛批腾空)**;
用户触发 1 = 玉简签按压 + 钟鸣 + 数值滚动 + 灵脉亮芯(同一玩家动作的回应)。钟鸣时间轴(`XianAmbient.tsx` 头注释):跨档成立 +0 → +300 收住 →
**+550 鸣** → +1100 数值起滚(`ceremonyDelayMs`)。钟鸣持 `runtime.tryLock()` 到 +2600;reduced-motion 下不鸣。

**h. 登记形状的先例。** `WorldSkin` 的可选项一律「不登记就不出现」(`Interlude?` / `Prose?` / `statsTimeline?: true` / `StatsProps.timeLabel?`),
通用层只在登记时才把键放进 props;`WorldTheme.scenePosition?` 只在登记了的世界才出现在解析结果里。本 ADR 照这一形状加字段。

**i. ⚠️ 与 ADR-019 §2 / §4 不一致(brief 没点到;本 ADR 按 Felix 2026-11-21 所定写,冲突逐条列出,待审 1)。**
ADR-019 为局内渗漏立的模型是「**每个基础世界维护一套可复用的渗漏签名,六对组合自动覆盖**」,并给了六条约束。本 ADR 与其中四处不同:

| ADR-019 原文 | 本 ADR | 性质 |
|---|---|---|
| §2「四个基础世界各维护一套可复用资产,六对组合自动覆盖」「局内侧 = 安全渗漏签名」 | **每个组合登记自己的渗入项**;没登记的组合纯 host | 模型改变(按组合,不按外来世界) |
| §4 第 2 条「只能作用于通用表面…**不得要求 host 提供特定组件**」 | 验讫印要宿主 `Stats` 支持「签名轴挂件」(Felix 补裁 8 许可改 `XianStats`) | 放开一条禁令 |
| §4 第 4 条「**不挂业务轴**…渗漏是氛围信号,不假装成机制」 | 三项都读轴:墨洇读窥天档、字洇读清明 severity、压印读境界跨档 | 放开一条禁令(仍不改数值 / 选择 / 叙事结果) |
| §4 第 5 条「默认统一渗漏权重,偏离必须记账」 | 每个组合自带权重(颜色、档、时长、频率) | 照记账要求在登记表里逐项写明 |

§4 第 1 条(「与一级记忆点同源,但不是缩小播放」「文字异变渗进别人的正文直接撞原则 ①」)本 ADR **不违反但贴着边**:字洇来自克苏鲁文字异常,
但不换字、不改字形、不改布局,只改颜色,且一屏最多一个(决策 5);第 3 条(与 host 低频共享槽、代码保证互斥)、第 6 条(缺失即纯 host)照守(决策 8 / 决策 1)。
**若审定维持本 ADR,则本 ADR 修订 ADR-019 §2(局内侧)与 §4 第 2、4、5 条**(补充块文字见决策 10);若不维持,本草案作废重写。

## 候选方案

### 挂载 · 方案 S1:渗入项写成宿主皮肤的配置项

`WorldSkin` 加 `seep?`,融合局解析时把组合的渗入项塞进 host 皮肤的一份副本。
**缺点**:皮肤表(`SKINS`)是按世界的,组合的东西混进去,单体局与融合局共用一份 `WorldSkin` 的假设破掉;「没登记就逐字节不变」要靠副本逻辑保证,不是构造保证。排除。

### 挂载 · 方案 S2:独立的渗入登记表 + 通用层三个可选挂点(本 ADR 采纳)

`FUSIONS` 每项可选登记一个 `seep` id → 查 `SEEPS` 表得到一份渗入配置;通用层在三处可选地叠上去(数值区外包一层、Stats 的签名轴挂件、正文形态)。
**优点**:宿主皮肤一字不动(除补裁 8 许可的挂点);没登记 → `theme` 里没有这个键 → 三处挂点一律不渲染,是构造保证。
**缺点**:通用层多三处「有渗入才做」的分支(同 `Interlude?` / `Prose?` 的先例)。

### 墨渍避让 · 方案 M1:压字,实测对比度 ≥ 4.5

**Felix 已否**(补裁 9;勘察 f:知渔档压字 4.26、水线上 2.82)。

### 墨渍避让 · 方案 M2:墨渍挪到框外,只让边缘洇进内边距

**优点**:不读任何文字几何,纯静态。
**缺点**:数值区四角文字之外只剩约 10px(勘察 f),墨渍得主体悬在框外的页边 / 块间距里,**长得和样张不一样**(样张是洇在框里的)。

### 墨渍避让 · 方案 M3:墨渍照样张画,用遮罩把文字行框挖掉(本 ADR 采纳,待审 3)

每个承载框一块覆盖整框的 SVG 层,墨渍画在里面,`<mask>` 挖掉框内每个文字行框(外扩 2px)。
**优点**:形状、位置、档位与样张一致;字底下始终是宿主原来的底色,对比度 = 宿主已测读数,不必另测压字对比度。
**缺点**:要读框内文字的行框几何。正文框是渗入层自己渲染的(决策 5),读自己的 DOM 不越界;**数值区的字是 `XianStats` 的**,
外包层读它的文字行框 = 读别的组件的布局(只读、不改,不依赖它的类名与结构,只取文本节点的 `getClientRects()`)。
ADR-018 §4.2 / `AmbientProps.rootRef` 头注释禁的是「query 别的组件的 DOM」,本方案在这一条上要 Felix 裁(待审 3)。

### 字洇载体 · 方案 B1:照克苏鲁命令式改 DOM

**缺点**:命令式改动要 `data-orig` 回写、换行守卫、文本不稳定期停表 —— 这一整套是为「换字」付的;字洇不换字,付这套是纯债。排除。

### 字洇载体 · 方案 B2:声明式 —— 正文按「前段 + 那一个字 + 后段」渲染(本 ADR 采纳)

渗入层的正文形态持有 `bleed: { offset } | null` 状态;有值时把正文渲染成三段,中间那个字包一层 `<span>` 挂晕开 class;没有时就是一段文本。
**优点**:React 自己管 DOM,不会被重渲染冲掉,也不会把「洇着的字」当原文记下;拆三段不改任何字、不改字宽,布局不变。
**缺点**:每次字洇触发三次重渲染(开、收、复原)—— 正文一屏几百字,代价可忽略。

## 最终决策

**方案 S2 + M3 + B2。** 分条如下。

### 1. 登记表与解析

- `registry.ts` 的 `FUSIONS` 项类型加可选 `seep?: SeepId`;本 ADR 只给 `'cultivation×cthulhu'` 登记 `seep: 'yanqi'`。
- `WorldTheme` 加可选 `seep?: SeepId`:**只在登记了的组合才出现这个键**(同 `scenePosition`);单体世界、识海遗蜕、人防工程的解析结果与今天逐键相同。
- 新文件 `theme/seep/registry.ts`:`SEEPS: Partial<Record<SeepId, SeepEntry>>`(形状见决策 9)。
- `GameScreen.PlayingScreen` 在唯一的世界判定点多一行:`const seep = theme.seep ? SEEPS[theme.seep] ?? null : null`,
  并要求 `seep.hostSkin === theme.skin`,不等即当作没登记(防登记表与皮肤表对不上;同 `SKINS` 是 `Partial`「对不上只降级、不崩」)。
- **feature gate**:删掉 `FUSIONS` 那一项的 `seep`,《验讫》立刻回到纯 host 呈现,不回滚任何基建(同 ADR-018 §4.5)。

### 2. 信号(通用层算,皮肤与渗入组件不读 key)

- 新 hook `useSeepSignals(seep, axes, values)`(放 `theme/seep/`,与 `useSignalCrossing` 同一取法:`resolveBandIndex` / `resolveSeverity`,
  跟**引擎落账的目标值**走,不跟屏幕上插值中的显示值):
  - `stainLevel: number | null` = 登记的 `stain.axisKey`(《验讫》`knowledge`)的当前档序号;无档表 / 找不到轴 → null → **不画任何墨渍**。
  - `bleedSeverity: AxisSeverity | null` = 登记的 `bleed.axisKey`(《验讫》`san`)的当前档 severity;null → 按 neutral(不出现)。
- 压印**不另算**:直接用 host 的 `signature.tick`(向上跨档)与 `signature.index`(当前档序号)。渗入配置里写的是
  `stamp: { on: 'hostSignature' }`,不写 `realm` —— 「哪根轴」仍只锁在宿主皮肤的 `signatureAxisKey` 里(ADR-018 §5 Q5)。
- 「哪根轴」对墨洇 / 字洇锁在 `SEEPS` 里(按 key 配置,同 `signatureAxisKey` 的先例);渗入组件只收档序号与 severity。

### 3. 墨洇(数值区与正文框)

- **数值区**:`StatsPanel` 在有渗入时把宿主形态组件包一层 `<div class={seep.statsHost}>`(`position: relative`,不加 margin / padding / 尺寸),
  外包层里叠一块覆盖整框的 `aria-hidden` SVG 层(`pointer-events: none`),画该档该出现的墨渍。**没渗入时不包**(输出与今天逐字节相同)。
- **正文框**:墨渍画在渗入层自己的正文形态里(决策 5),同一种 SVG 层。
- 墨渍形状取样张 path 与三个墨点原样(`viewBox 0 0 100 100`、`preserveAspectRatio="none"`、四角靠 `scaleX(-1)` / `scaleY(-1)` 翻转),
  位置贴角(`left/right/top/bottom: 0`),尺寸与不透明度按上表三档。档序号 → 档:0 → 未觉、1 → 见格、≥ 2 → 知渔(登记表按序号给三档参数)。
- **过渡**:档变了(上或下)→ fill / stroke 不透明度与显隐(`opacity`)走 2400ms `ease`;尺寸变化(知渔变大)同 2400ms,
  用 `transform: scale()` 做,不动画化 `width/height`(Motion Constraints §6;样张直接改了宽高,实现改成同终态的缩放,终态逐像素一致,见验证 F)。
  **首次装载与续局不走过渡**,直接到位(挂载那一帧带 `no-transition` class,下一帧摘掉)。
- **避让(方案 M3)**:见决策 6。

### 4. 验讫印(Stats 签名轴挂件)

**契约**(`contract.ts`):
- `WorldSkin` 加 `signatureAccessory?: true`:皮肤声明「我的数值形态能在签名轴旁挂件」(同 `statsTimeline?: true` 的形状)。本 ADR 只给修仙加。
- `StatsProps` 加 `signatureAccessory?: ReactNode`:**只在有渗入登记了印、且宿主声明了 `signatureAccessory` 时**由 `StatsPanel` 放进 props;
  其余一律不出现这个键(调用逐键不变)。

**`XianStats`(补裁 8 许可的唯一改动)**:
- 收到 `signatureAccessory` 时,`RealmSeal` 外多包一层 `<div class={styles.sealHost}>`(`position: relative`;承接 `.seal` 原有的 flex 子项属性
  `flex: 0 0 auto; align-self: center`,`.seal` 自己的 `margin-top: 6px` 改在外层不塌陷的前提下保持 —— **境界印的几何必须与不包时逐像素相同**,见验证 B),
  紧跟 `.seal` 之后渲染一个 `<div class={styles.sealAnchor} aria-hidden="true">`:与 `.seal` 同位同大(`position: absolute; inset: 0`,
  从 `.sealHost` 的内容框算)、**不带 `clip-path` / `overflow`**,挂件放进去。
- 没收到时,`RealmSeal` 的输出与今天逐字节相同(不包、不渲染挂点)。新增的两个 class 只在有挂件时被引用。

**印的定位(不依赖像素)**:印相对挂点(= 境界印框)定位,中心在 **(97%, 69%)**(勘察 d 实测):
`left: calc(97% - 15px); top: calc(69% - 15px)`(15px = 印边长 30px 的一半;`transform` 只留给样张的 `rotate(-9deg) scale(…)`,
关键帧与样张一字不差)。境界印换位置(轴序、轴数、宽屏)时印跟着走,因为它就挂在境界印上。

**显示与动画(Felix 补裁 7)**:
- **印在不在** = `signature.index > 0`,纯推导,不记状态。跌回初境 → 不在;首次装载 / 续局 / 开局就在小成 → 直接在,不播。
- **播压印**:`signature.tick` 加一(向上跨档;通用层已保证首次装载不加、跨多档只加一)且新档序号 > 0 →
  印先藏起(`pending`),**跨档成立后 +1650ms**(= 钟鸣 +550ms 鸣、再 1100ms;待审 4)播样张关键帧 260ms,播完即常显。
  每次向上跨档都重压一次(小成 → 高深时印先藏、再落下),同样张 `bell()` 的行为(待审 5)。
- 计时走 `runtime.setTimeout`(世代号核对,换回合 / 卸载自动作废);`runtime.onTeardown` 登记「把 `pending` 清掉」——
  **回调写 state 前先查 `runtime.alive(token)`**(F-041)。被打断的结果是「印直接常显、不补播」,同钟鸣「不补播」的口径。
- **不持锁**:压印是钟鸣的第二拍,与钟鸣同一个用户触发事件;钟鸣自己持锁,压印不另抢(抢了会在 +1650ms 被钟鸣的锁拒掉)。
- 钟鸣被抑制(reduced-motion / 忙态 / 主题根未挂载)时:reduced-motion 下印直接出现(决策 8);其余两种抑制极少发生,印照常按 +1650ms 压
  —— 压印锚在「跨档成立」上,不读 `XianAmbient` 的内部状态(读了就是捅穿组件边界)。

### 5. 字洇成墨(正文形态)

- `SeepEntry` 可选 `Prose` 能力:**只在宿主没有 `Prose` 槽时生效**(修仙没有);宿主有 `Prose` 槽 + 登记了字洇 → 登记表测试红(不许两套正文形态打架)。
  `GameScreen` 的正文分派改为 `skin.Prose ?? (seep?.bleed ? SeepProse : null) ?? Prose`。
- `SeepProse` 复用通用 `.prose` 容器 class(同 `CthuProse` 的做法),多挂一个渗入 class(`position: relative; isolation: isolate`,
  让字后那团淡墨的 `z-index: -1` 落在正文底色之上、字之下 —— 样张靠 `.yqProse` 的 `position: relative`,实现要实测墨团确实可见)。
  墨洇的正文两角也画在这里(决策 3)。
- **载体(方案 B2)**:`bleed: { offset } | null`;有值时渲染 `前段 + <span class=bleed>字</span> + 后段`。`.bleed` 只改 `color` 与 `::before`
  (`transform: scale(0.35 → 1)` + `opacity`),**不改字、不改字宽、不加 aria**,复制 / 选择 / 读屏连续。
- **时序**:晕开 400ms(`.on`)→ 停 600ms → 收回 500ms(`.off`)→ 复原为一段文本。三段都用 `runtime.setTimeout`;回调写 state 前查 `runtime.alive(token)`。
- **调度**(待审 6 定数):
  - neutral / null → 不调度;
  - caution → 指数分布,均值 75s,截断 [30s, 150s];danger → 均值 40s,截断 [20s, 90s](理由同 `anomalySchedule.ts`:无记忆、学不成节拍);
  - 每回合正文稳定后(`paused` 变 false)才开始计时,首次至少 20s;`paused` 一变 true(开始生成)→ 在途的一次**立即撤销**(复原、清计时);
  - 一屏最多一个:状态只有一个 `bleed` 槽,在途时不起第二次。
- **选字**:正文中的汉字(`\p{Script=Han}`,不含标点、数字、拉丁),优先落在当前视口内的(读自己组件的行框,不越界),不连续两次选同一字位。
- **只在正文逐字结束后**:`paused`(= generating 或开场 reveal 未完)期间不调度、不在途。

### 6. 墨渍避让(Felix 补裁 9;方案 M3)

**规则(等式,不是体感)**:任一时刻、任一档、任一宽度,墨渍的**上色区域**(水渍 path 的填充与水线描边、全部墨点)与所在框内**任何文字行框外扩 2px** 的交集为空;
验讫印同理(不得压境界印自己的字,也不得压相邻灵脉的字)。

**做法**:每个承载框(数值区外包层 / 正文框)的 SVG 层带一个 `<mask>`:白底 + 框内每个文字行框(`Range.getClientRects()`,换算到框坐标,外扩 2px)一块黑矩形。
- 行框几何在 `ResizeObserver`(框尺寸)+ 正文文本变化 + 字体加载完成(`document.fonts.ready`)时重取,rAF 合并,一帧最多一次;
  墨渍与印、`aria-hidden` 元素、渗入层自己的节点不计入行框。
- 数值区的行框取自外包层子树里宿主组件的文本节点 —— 待审 3(读别人组件的布局)。若不批,退回方案 M2(墨渍挪框外,形状另出样张)。
- 字底下始终是宿主原底色 → 文字对比度 = 宿主已测读数(修仙 `--muted` 等),不另测压字对比度;**仍要实测「挖空后」边缘处**(见验证 D)。

**实测方法**(实现刀交付时给读数):
1. 用桩后端续一局《验讫》,分别把窥天拨到 12 / 41 / 76(未觉 / 见格 / 知渔),每档在 320 / 375 / 414 / 480 四种宽度下:
2. 对每块可见墨渍,用 `SVGGeometryElement.isPointInFill` / `isPointInStroke`(path 与 circle,经 `getScreenCTM().inverse()` 换算、并按 mask 扣掉挖空区)
   在每个文字行框外扩 2px 的区域里逐像素采样 → **命中数必须为 0**;印用其旋转后的四边形对同一组行框求交 → 必须为 0;
3. 正文按两段长度各测一次(末行长 / 末行短),因为正文右下墨渍是否压字随末行长短而变(勘察 f);
4. 变异:去掉 mask → 第 2 步必须变红(证明采样能测出压字,§4.13 / §4.14)。

### 7. reduced-motion

| 项 | `prefers-reduced-motion: reduce` 下 |
|---|---|
| 墨洇 | 直接到位,不走 2400ms 过渡 |
| 验讫印 | 档序号 > 0 即直接出现,不播落下(钟鸣此时本就不鸣) |
| 字洇 | **不出现**(提议,待审 7)。直接换色也是正文里一次无预告的变化;关了动效的人要的是正文安静。备选:直接换色、停 600ms、直接复原 |

### 8. 动效预算(Motion Constraints §1 / §2 / §3;ADR-019 §4 第 3 条)

《验讫》一屏,宿主修仙 1 + 0 + 1 → 渗入后 **1 + 1 + 1**(未超):

| 槽 | 宿主修仙 | 渗入层 | 记账 |
|---|---|---|---|
| 持续 | 天穹层(流云 + 微粒) | — (墨渍平时静止) | 不变 |
| 低频 | 0(收敛批腾空) | **字洇** | **新增、不替代**:填的是收敛批腾出来的空槽,宿主没有低频效果可与之互斥;ADR-019 §4 第 3 条「与 host 低频共槽、代码互斥」在本组合**按构造成立**(宿主低频 0)。通用规则:字洇只许登记在低频槽为空的宿主上(决策 9 校验);宿主将来若加低频效果,须先另立 ADR 定共锁 |
| 用户触发 | 玉简签按压 + 钟鸣 + 数值滚动 + 灵脉亮芯 | **验讫印(钟鸣第二拍)+ 墨洇加深** | 并入同一槽:都是「这次选择落账」的回应,同修仙收敛批「槽位管同时运行的效果数」的记账口径(待审 8) |

- **记忆点唯一**:《验讫》的一级记忆点仍是修仙的**钟鸣**;验讫印是钟鸣的第二拍,不另立、不占名额(AGENTS.md §1「融合世界不新立一级记忆点」)。
- **§3 加法要付账**:字洇是新增、不替代(上表);压印与墨洇加深并入钟鸣所在的用户触发事件,不另开槽。
- **正文即禁区**:字洇是一次性的「进入 → 停 → 退出」,做完即止,不循环;墨渍挖空文字(决策 6),绝不压在字上;正文墨渍的 2400ms 过渡只在跨档那一回合发生一次。
- **字洇不持宿主的锁**:宿主的忙态锁同时管钟鸣;字洇若抢锁,在 `/state` 同步(409 `turn_stale`)这类非生成期落账的路径上会把钟鸣挤掉。
  字洇只用自己的在途槽;它与钟鸣分属低频 / 用户触发两槽,同时出现不超预算。

### 9. 以后别的组合怎么登记(本 ADR 只登记《验讫》)

```ts
type SeepId = 'yanqi';

interface SeepEntry {
  id: SeepId;
  /** 必须等于该组合解析出的宿主皮肤 id;不等即当作没登记。 */
  hostSkin: SkinId;
  /** 墨洇:按某根轴的当前档序号画角落水渍。 */
  stain?: {
    axisKey: string;                       // 《验讫》'knowledge'
    color: string;                         // '#184034'
    transitionMs: number;                  // 2400
    /** 按档序号给(0 起),超出取最后一档。 */
    levels: ReadonlyArray<{
      fillOpacity: number; strokeOpacity: number;
      corners: ReadonlyArray<{ host: 'stats' | 'prose'; corner: 'tl' | 'tr' | 'bl' | 'br'; w: number; h: number }>;
    }>;
  };
  /** 压印:挂在宿主签名轴上(宿主须声明 signatureAccessory)。 */
  stamp?: {
    on: 'hostSignature';
    text: string;                          // '验讫'(玩家可见文案)
    afterCrossingMs: number;               // 1650(待审 4)
    pressMs: number; fromScale: number;    // 260 / 1.35
    center: { x: string; y: string };      // '97%' / '69%'(相对签名轴挂点)
  };
  /** 字洇:正文里一个字晕开(宿主不得有 Prose 槽、低频槽须为空)。 */
  bleed?: {
    axisKey: string;                       // 《验讫》'san'
    color: string;
    inMs: number; holdMs: number; outMs: number;   // 400 / 600 / 500
    /** severity → 指数分布均值与截断;不给的档 = 不出现。 */
    schedule: Partial<Record<'caution' | 'danger', { meanMs: number; minMs: number; maxMs: number }>>;
  };
}
```

- **三种原语是通用的,组合只登记数据**(颜色、档、文案、时长、频率)—— ADR-019 §2「不为任何一对组合编写专属流程」在原语这一层仍成立;
  加第四种原语须另立 ADR。
- **登记表测试**(`theme/seep/registry.test.ts`)钉住:`hostSkin` 存在于 `SKINS`;登了 `stamp` 的宿主声明了 `signatureAccessory`;
  登了 `bleed` 的宿主没有 `Prose` 槽、且宿主皮肤头注释记的低频槽为空(以一张显式白名单表达,改宿主低频时这张表必须一起改);
  `stain.levels` 非空、不透明度在 [0, 1];每个 `FUSIONS[*].seep` 都在 `SEEPS` 里。
- 各组合的权重(颜色、档、频率)写在登记项里 —— 这就是 ADR-019 §4 第 5 条要求的「偏离必须记账」。

### 关键理由

1. **没登记就逐字节不变是构造保证**:`seep` 键只在登记了的组合出现;三处挂点都以它为前提;挂件 prop 不登记就不出现。不是「没写错就不会变」。
2. **信号仍只在通用层算**:皮肤与渗入组件不读 key、不判档;「哪根轴」锁在登记表里(压印连轴都不登记,直接跟宿主签名轴)。
3. **印挂在境界印上而不是数值区坐标上**:轴序、轴数、宽屏变了,印跟着境界印走;不依赖样张那个「恰好居中」。
4. **字洇不碰 DOM**:只改颜色的效果用声明式渲染,省掉克苏鲁为「换字」付的那一整套守卫。
5. **避让是等式**:命中数为 0 才算过,并配变异证明采样有效。

## 已知代价

1. **印跟着境界当前档走(Felix 补裁 7)**:
   - **境界跌回初境 → 印消失**。印说的是「验讫」,这一局的「被验过」并不会撤销;但引擎不保证境界只升不降(勘察 c),印只能跟着当前档。
     再升回小成时钟鸣照响、印重压一次。
   - **开局就在小成(或更高)→ 印直接在,没有钟声在前**。此时印不是「钟鸣的第二拍」,玩家第一眼就看见一方没来由的印。
     初值约束「10–25」只是提示词,模型偶尔会给到 31 以上。
2. **读宿主数值区的文字几何(若待审 3 批 M3)**:外包层依赖「宿主数值区里的字是文本节点」这一点;宿主改成画布或图片字时避让静默失效。
   缓解:验证 C 的采样测试放进组件测试(jsdom 无布局,只能钉「行框被读到、mask 有对应矩形」;真几何靠实现刀的浏览器实测)。
3. **墨渍挖空后有「绕字」的形状**:字周围 2px 留着宿主底色,知渔档墨渍大时,「气血亏损」一圈会读成墨被字推开。这是 M3 的固有样子,样张里没有,真机由 Felix 判。
4. **字洇频率是提议数**(均值 75s / 40s):Felix 只给了「偶尔 / 较常」;调过才知道。
5. **宿主将来加低频效果,字洇就不能留在本组合**,除非另立 ADR 定共锁(决策 8)。
6. **ADR-019 的组合模型被改掉一半**(若待审 1 维持):局内渗漏从「每个外来世界一套、自动覆盖」变成「每个组合各登一份」。没登记的组合永远是纯 host —— 识海遗蜕、人防工程今天就是。
7. **压印锚在跨档上而不是钟声上**:钟鸣因忙态被抑制时(极少),印仍按时落下,那一回合只有第二拍没有第一拍。

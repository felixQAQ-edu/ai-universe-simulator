# ADR-004 · 内容安全:主防线在生成之前(prompt 硬禁),检测器只做事后遥测

- **日期**:2026-09-06
- **状态**:已采纳。**刀 1(撤 `moderation` 包)/ 刀 2(骨架硬禁 + lockstep + parity 阳性对照)
  / 刀 3(扫描器落测试,不接线)均已落地 2026-09-07**;
  **刀 4(真机冒烟)已跑完 2026-09-08,四刀走完,本 ADR 收口** —— 读数与三条口径见实施步骤刀 4。
  > ⚠️ **收口 ≠「内容安全做完了」。** 做完的是**这一版的形态**;
  > **已知代价 1 逐字写着「这条代价是真的敞着,不是有兜底所以还好」,那条不因收口而变小**,
  > 它的两条触发条件仍然挂着、仍然有认领人。
- **决策者**:Felix

## 背景

② 内容安全是软启动开闸前的最后一环([phase3-launch-plan.md §四腿②](../phase3-launch-plan.md)),
也是[工程债清单 §1.2](../backlog-engineering-debt.md) 第 1 层仅剩的一条
(第 1 层另一条并发可用性已由 [ADR-022](ADR-022-turn-admission-and-rejection-semantics.md) 三刀走完)。
**§1.2 的正文不在本 ADR 复述,只指过去**(指针纪律)。

### 一 · 它的三条理由,今天只剩一条

合规在 2026-07-16 定路线 B 时就已被**显式降级**——[工程债 §1.2](../backlog-engineering-debt.md) 结尾逐字写着,
路线 B 下本条理由「已从『境内合规硬要求』改为:防模型输出伤玩家 / 防滥用刷成本 / 为未来补合规预留可插拔接缝」。

本刀勘察的第一件事就是逐条核这三条**今天**还成不成立:

| 原理由 | 今天的状态 |
|---|---|
| 防滥用刷成本 | ⚠️ **已被 [ADR-016](ADR-016-cost-gate.md) 解决** —— 双层闸门 2026-07-22 上线并冒烟全过(全局 ¥ 日 6 / 月 175 真闸 + 单 IP/设备日次数软闸),`init` 与回合守卫 0 两处都在。**这条理由过期,不是仍然成立。** |
| 为未来补合规预留可插拔接缝 | ⚠️ **「预留」这件事本身没做完** —— `moderation.review(...)` 四个调用点**全部在 `GameInitService`**(`openingNarrative` / `world.title` / `world.background` / 各条 `rules[].content`),`eventloop` 包命中数 **= 0**。而 `init` 在一局里只发生**一次**,回合叙事发生几十上百次。 |
| **防模型输出伤玩家** | **唯一还活着的。** 本 ADR 只为它而写。 |

> 三条里两条已经不是理由了。**若不先核这一步,这一刀会照着一份三年前的动机去设计一套两倍大的机制。**

### 二 · 威胁面盘点(勘察实测,非推断)

服务端全部入口 **= 4 个**(`grep` 全仓 `@*Mapping`,骨架期那个 `POST /api/dev/echo-stream`
已于 2026-08-06 删除,见[工程债第 0 层](../backlog-engineering-debt.md)):

| 入口 | 玩家能送进来的东西 | 约束 |
|---|---|---|
| `GET /api/archetypes` | 无 | — |
| `POST /api/game/init` | `archetype` / `archetypes` 字符串 | `GameInitService` 校验 `KNOWN` + 已激活 + 融合组合已登记,否则 400 |
| `GET /api/game/{saveId}/state` | `saveId` | 内存 map 查,查不到 404 |
| `POST /api/game/{saveId}/turn` | `actionId` | 守卫 1 `GameSession.hasAction` 要求与 `currentActions[].id` **精确相等** |

**结论:没有提示词注入面,也没有用户生成内容。**
一般内容安全方案里有一半篇幅在讲输入侧审核、注入防护、UGC 过滤——**在这个项目上那半篇幅全是空转**。
本 ADR 把这一点写明,是为了让后来者**不要照搬一套用不上的机制**:不是我们忽略了输入侧,是输入侧是空集。

### 三 · ⚠️ 一处措辞订正:「玩家输入不进模型」作废

本刀开工时的口径(Felix 在 brief 里给的)是「**玩家输入不进模型**」。**这句话是假的,就地作废。**

实测:`Engine.apply` 把 `actionId` 写进 `log[].playerAction`,`log` 进 `snapshot()`,
`snapshot()` 经 `contextJson()` 成为视图 2 喂给模型。**玩家选的 id 确实会进模型。**

**订正后的准确措辞**:

> **玩家无法把任意字节送进模型。**
> 进去的那个 `actionId` 不是自由文本,而是**服务端闭集里的一个元素**——
> 守卫 1 要求它与 `currentActions[].id` 精确相等,而那个集合是模型自己上一回合产的。

结论不变(仍然没有注入面),**但理由完全不同:稳在闭集,不稳在「没进去」。**
原措辞一读 `Engine.apply` 那行就被推翻,而**一句不准的安全论断比没有论断更危险,因为它会被当成前提往下建**。
两个口径不并存,作废的那句留在本节备查。

### 四 · 恐怖题材本身不是威胁

克苏鲁 / 规则怪谈 / 末日生存的内容会令人不适——**那是产品本身,玩家是自己点进去的**。

> **判据不是「内容吓不吓人」,是「玩家没有选择的那部分伤害」。**

这条判据同时决定了下面范围裁定里为什么只剩一条。

## 候选方案

### 方案 A · 接外部审核 API + 流式分句缓冲 —— 否决

按句/按段缓冲送审、边审边放。
**否决理由**:它要付的代价是 [ADR-006](ADR-006-event-loop-streaming-wire-protocol.md) 的核心体验——
回合叙事是**逐字流**给玩家的,缓冲送审等于把它变回一段一段蹦。
为一条「防玩家没选择的伤害」的辅助措施,去换掉整个产品的阅读手感,不成比例;
且它引入一个会挂的外部依赖,连带 fail-open / fail-closed、超时、跨境延迟一整套问题
([launch-plan §九](../phase3-launch-plan.md) 第 1、3、4 条记的正是这些)。

### 方案 B · 接外部审核 API + 流完再判 —— 否决

整段叙事生成完再送审。
**否决理由**:审得准,**但玩家已经读完了**。在一个逐字流的产品里,「流完再判」不是拦截,是延迟报告——
它能提供的东西和方案 C 的事后遥测完全一样,却额外背上一个外部服务的全部代价。
**同样的产出,更贵的形态。**

### 方案 C · prompt 硬禁(生成之前)+ 流末扫描遥测(生成之后)—— 采纳

见下。

## 最终决策

### 一 · 范围:只拦一条,其余三条各自留档

| # | 候选 | 裁定 | 理由 |
|---|---|---|---|
| ① | **自伤 / 自杀相关** | ✅ **拦** | 唯一一条「玩家没选、且真的会伤到人」的。且判据最窄:**具体方法出现即命中**,不需要判断「够不够吓人」——**是可写成测试的形状**。 |
| ② | 现实可执行的危险指令 | ❌ **不拦** | 要拦它得先判断「现实可执行性」,⚠️ **那是个无法验收的判据**。而这个项目最不该造的就是没有验收判据的安全机制——一个没人能判断它有没有生效的防线,和没有防线的区别只在心理上。 |
| ③ | 仇恨内容 | ❌ **不建** | provider 侧既有过滤已覆盖,本层边际价值接近零。⚠️ **取证边界如实记:这是依据,不是实测——我们没有测过 DeepSeek 的过滤边界**;写进 ADR 是为了让后人知道**这条是被想过并放弃的,不是漏了**。 |
| ④ | 未成年玩家 | ⚠️ **移出本 ADR** | 无年龄门、无登录、公网链接谁都能开——**这是产品门禁不是内容审核**,混进来会让这一刀变形。单列挂账,见[工程债清单](../backlog-engineering-debt.md)。 |

### 二 · 形态:照抄本项目对 `hiddenLogic` 泄露已经立过的那套

**不新建一套审核 API 调用。** [CONTEXT §三.9](../CONTEXT.md) 立过字,`LeakDetector` 的类 javadoc 也逐字自陈:
**实时防护 = 提示词硬禁 + 结构层消毒;检测器在流式路径里是事后遥测,不是实时拦截。**

本 ADR 把同一套形态用在自伤上:

- **主防线 = prompt 侧硬禁**(生成之前)
- **辅助 = 流末扫描 + 命中记一笔**(生成之后,**遥测不拦截**)

⚠️ **勘察订正一处本刀的自我认知**:「流末扫描 + WARN」这条链**今天已经完整存在并在跑**——
`Engine.apply` 调 `LeakDetector.detect` 并**返回**命中列表,`EventLoopService.settle` 收到后打 WARN。
**故辅助这一半不是新增机制,是给一条既有链加一张词表。** 本 ADR 的实现量因此比立项时估的小。

#### 连带的两个结论(本形态最大的收益)

**(1) 流式不必缓冲——[launch-plan §九](../phase3-launch-plan.md) 第 3 条那个死结整个被绕过去。**
那条待答问题的形状是「流完再判牺牲 vibe / 分句缓冲实现复杂」,**两难成立的前提是「审输出」**。
主防线一旦挪到生成**之前**,输出侧就不需要拦截,自然也不需要缓冲。
**这不是在两难里选了一边,是那个两难不再存在。**

**(2) fail-open / fail-closed 问题不成立——本形态下没有会挂的外部服务。**
⚠️ 但要写明:**若将来接了外部审核器,这个问题会原样回来**,触发条件见「重新审视」节。

### 三 · 撤掉 `moderation` 包(含解冻条件)

**删除 `ModerationGateway` 接口、`NoopModerationGateway` 实现,以及 `GameInitService` 里的四个调用点。**

理由三条:

1. **本形态下没有任何东西会来替换它。** 主防线在 prompt,辅助在既有的 `LeakDetector` 那条链——
   两个位置都有宿主,`ModerationGateway` 不在其中任何一个上。
2. **它今天只覆盖 init,而 init 在一局里只发生一次。** 一道覆盖不到 1% 文本量的关,不是接缝,是装饰。
3. **它的 javadoc 逐字写着「由尚未撰写的 ADR-004 决定」。**
   ADR-004 一旦落档而它还在,**那句注释当场变成假话**——而这个项目上一刀刚为一句 javadoc 里的过期枚举动过手
   (`ArchetypeRegistry`,2026-09-04)。**留一个永远 no-op 的接缝也是一种撒谎。**

#### ⚠️ 解冻条件(撤选项必须写,否则「撤掉」和「忘了」日后读起来一样)

出现下列任一条 → **重建这道接缝,并且要重新划它的位置**(不保证还是今天这四个调用点):

- **(a) 出现真正的自由文本输入面** —— 玩家自定义世界描述 / 自定义行动文本 / 昵称 / 分享文案。
  今天「输入侧是空集」这个结论是**当前接口形态的性质,不是永久属性**。
- **(b) 路线 B 解冻**(回国 / 进微信生态 / 开始收费)—— 境内合规会把「境内审核 API」重新变成硬要求。
- **(c) 换 provider** 到一个上游过滤未知或更弱的模型 —— 范围裁定 ③ 的依据随之失效。

### 四 · prompt 硬禁写在骨架层

判据直接套 [ADR-021](ADR-021-lifetime-family-layer-and-animal-life.md) 立字二:
**一条指令若对族内每个世界都成立,它属族层;只对一个世界成立,属世界层。**
自伤禁令对**所有**世界成立——不止一个族——故归**骨架**,
亦即 [ADR-008](ADR-008-multi-mode-extension-architecture.md)「多个世界共用的一律回骨架」。

落点:`TurnPromptBuilder.SKELETON` 与 `WorldGenPromptBuilder` 的 `SKELETON` / `FUSION_SKELETON`,
各加一个 `【…】` 段;与 `prompts/event-loop.md` / `prompts/world-gen.md` **lockstep**
(形态照 `ActionHintPromptLockstepTest` 那套,**四处扩为五处**,见下)。

**不进族级、不进世界级、不做 per-archetype 开关**——一条对所有世界都成立的安全约束若可以被单个世界关掉,
它就不是约束。

#### ⚠️ 编辑点是五个不是四个(刀 2 勘察订正)

本节原措辞「两个 builder 的骨架」读起来像两处,**实测是三个常量**:
`WorldGenPromptBuilder` 的 `SKELETON`(单体)与 `FUSION_SKELETON`(融合)是**两份独立骨架**,
各自持一份 `【泄露硬约束】` 拷贝——那正是既有先例。加上两份 `.md`,**编辑点五个**。

> **⚠️ 漏改 `FUSION_SKELETON` 的失败方式,比漏改本身更值得记**:
> 它不会让 parity 变红,只会把 16 处变成 **14 处**;
> 而阳性对照跑出「大部分都变了」时,**没有人会去数那两个**。
> **parity 只报变没变,不报该不该变。** 这一条是**勘察**抓住的,不是 parity 抓住的。
>
> 处置:`FUSION_SKELETON` 在 lockstep 里有**独立断言**,且变异时必须**单独变红**
> (只摘掉它 → 只有融合那条红,其余四条仍绿;一起红说明它们搭了便车)。

`.md` 侧按 `【泄露硬约束】` 的既有惯例**只写一次**(融合段声明「输出格式骨架与上文单体完全相同」),
运行时三份都要有。

#### 三条设计判据(为什么是这个形状,不只是贴一段文案)

1. **并入「怎么写」这一族,不作孤立安全条款。**
   两个骨架里已有的硬约束**全是「怎么写」的约束**(叙事清洁度 / 长度上限 / 贴合状态档 / 输出格式),
   而这是第一条「**不许写什么**」的内容约束——**形制不同会被模型当成孤立例外条款,权重被隔离**。
   回合侧接在「叙事须贴合当前状态档」之后,是同一件事的延续:**绝望是要写的,方法不写**。
   ⚠️ world-gen 侧**没有对应的「怎么写」族**,落点取「紧贴 `openingNarrative`、在 `【泄露硬约束】` 之前」——
   **这是最接近的落点,不是等价落点**,是判读不是推导,标出来比抹平好。
2. **「这不是让你把绝望写轻」是承重句,不是补充说明。**
   没有它,模型会用**降低强度**来满足禁令——**而那正好把这段话变成「把世界写坏」的原因**,
   也正是刀 4 冒烟要验的那件事。**禁令必须自带反向配平。**
3. **「虚构世界内部的主动代价」是显式许可,不是「别误伤」。**
   修仙的自爆金丹 / 散功 / 兵解、克苏鲁的主动凝视与接触禁忌,**是这几个世界核心张力的所在**。
   显式写出来 ≠ 靠模型推断:**前者是许可,后者是赌它想得到。**

#### world-gen 那份逐字照抄而不是改写(刀 2 裁定)

曾考虑为 world-gen 改写一版(理由:回合叙事是散文、world-gen 产的是 JSON,「把镜头停在哪个景别」
可能落不到实处)。**两条勘察事实推翻了它**:

- **world-gen 不是「只产 JSON」,它产的 JSON 里装着散文**——`openingNarrative` 骨架逐字写着
  「开场散文整段」,且它是 init **一次性下发、玩家最先读到的那段字**;另有 `background` /
  `rules[].content` / `endings[].description` / `hint`。**这是最该管的地方,不是勉强适用的地方。**
- **改写会亲手制造判据 1 要防的东西**:两份措辞一旦不同,world-gen 那份就成了
  「**为这一侧单独写的安全条款**」——正是「孤立例外、权重被隔离」的形状。

附带收益:逐字相同 → lockstep 可以**整段对拍**而不是挑短语,是本刀能拿到的最强守护形态。

**不加作用域到「玩家可见字段」**:`hiddenLogic` 会随 `state` 回喂模型、是后续回合叙事的**上游**,
不是「引擎侧所以无所谓」。

#### 两条格式判断

- **`.md` 侧不加 markdown 加粗**,整段与三个运行时常量**逐字节相同**。
  加粗会把 lockstep 退回短语级;不加粗则四面同串。
- **`⚠️` 进骨架是首例,但不是首次进 prompt**:实测 `prompts/*.md` 与两个 `SKELETON` 常量里
  ⚠️ 计数为 **0**,而 `TurnPromptBuilder` 的 per-archetype 指令槽内已有 **12 处**在 prompt 文本里
  (ADR-020 / ADR-021 那批)。⚠️ **这个区分要写清楚**——否则下一个人只会看到「先例有 12 处」,
  读不出「它第一次进入四世界共用的骨架与人类可读资产」。

### 五 · 流末扫描:判据 / 宿主 / 命中动作

**判据形状**:一张**多字方法词表**,对**玩家可见文本**(`narrative` + `availableActions[].text` / `.hint`)
做字面匹配,命中即记。~~它与 `LeakDetector.LEAK_TOKENS`(那就是一张 4 条的字面词表)**完全同构**,
故宿主现成、实现量接近零。~~

> #### ⚠️ 订正(刀 3 勘察,2026-09-07):删线那句只看了形状,没看消费方
>
> **形状同构成立**(字面表 + 静态纯函数 + 返回命中列表),**但「宿主现成」不成立**:
>
> **`LEAK_TOKENS` 不只是一张检测词表,它同时是 `Engine.toClientState()` 的递归剥除清单**
> (`Engine.java:408`)。两个消费方、两种语义。
>
> 失效方式很具体:**下一个人把新表也接进 `toClientState()`** ——
> 而「把『割腕』当字段名从 JSON 里剥掉」是荒谬的,**且那种剥除是静默的**。
> 另一条:`LeakDetector` 的 javadoc 立的字是「**只抓两类逐字泄露**」(对齐 CONTEXT §三.9),
> 加第三类进去,那句 javadoc 当场变成假话 —— 与刀 1 抓到的「javadoc 现写现留假话」同族。
>
> **落点改为**:`SelfHarmScanner` 新类,与 `LeakDetector` **同包(`engine`)并列**,`LeakDetector` 一字不动。
> 同包的理由不只是「未来接线时两处都在 engine」——**两个检测器住一起本身就是可读的信号**;
> 而新起一个 `safety` 包会让人以为它是一层机制,**⚠️ 它不是,它是一个纯函数**。
>
> 实现量接近零那半仍然成立(主类 30 行)。**旧措辞留档,两个口径不并存。**

**⚠️ 顺带记一条既有缺口(刀 3 勘察发现,不在本刀范围,未修)**:
`LeakDetector` 今天**只扫 `narrative`**(`Engine.java:294`),**不扫 `availableActions[].text` / `.hint`** ——
而选项文本同样是玩家可见的。`SelfHarmScanner.scan()` 设计成**吃字符串**的纯函数(调用方决定喂哪几段),
接线时两侧都能喂;但 `LeakDetector` 那半边的缺口仍在。

> **⚠️ 这条不是孤零零挂着的,它绑在 WARN 接线那个决策上**:
> 接线时**必须同时回答「新扫描器喂不喂选项文本」** —— 而那个答案一旦是「喂」,
> 就会立刻显出**同一段文本上两个检测器覆盖面不一致**(泄露只看叙事、自伤看叙事 + 选项)。
> **两者要么一起改,要么把不一致写明**;此刻单独修 `LeakDetector` 是在没有接线决策的情况下先动它,
> 顺序反了。故:**本条随 §挂账「流末扫描的 WARN 接线」一并解冻,不单独排期。**

**为什么判据必须窄到「具体方法」**——一个正面例子胜过十条误报候选:
[ADR-010](ADR-010-ending-outcome-polarity-gate.md) 真 key 冒烟里,AI 自己给过一个选项「**闭目等死**」。
它**没有方法**,按本判据**正确地不命中**。

> **判据窄在了对的地方:它要抓的不是「角色死了」,也不是「角色想死」,是「文本里出现了一个可以照做的方法」。**

**命中动作 = 打一条 WARN,不进 `issues`。**
`Engine.recordIssue` 的 javadoc 明文写着「**本方法不是通用日志后门,不得这么用**」,
`issues` 的语义被限定为「引擎侧的**数值异常**记录」(跳变过大 / 结局极性 gate 改判 / 收束下限钳制),
并要求新增调用方须在 ADR 里说明它为何属于数值异常。
**自伤命中不是数值异常** → 不进 `issues`。而同类的泄露遥测走的正是 WARN——**先例现成,照抄即可**。

WARN 要能回答「谁读它、读了做什么决定」(这是 [ADR-022 刀 2 前置](ADR-022-turn-admission-and-rejection-semantics.md) 立的规矩):
读者 = 冒烟后的 Felix;决定 = **「这条方法词该不该进 prompt 硬禁的负面清单」**。
即**流末扫描的产出直接回喂主防线——这是它唯一的用途,也是它值得存在的唯一理由。**

#### ⚠️ 本刀不接 WARN 线:扫描器停在测试里

裁定原文是「**先量后接**」——理由是 ADR-022 刀 2 前置刚为噪音清过一次场,
不能转头自己造一条(「在一条已被训练成背景音的通道里加信号等于没加」)。
误报**不是理论风险**:四个已上线世界是恐怖 / 末日 / 克苏鲁 / 修仙,
而例如修仙的「自爆金丹」是正经设定用语(⚠️ **取证边界:在 authored 内容里 grep 零命中,这是可能而非已观测**)。

**而本刀实测把「先量」这一步的前提推翻了:那份语料不存在,也无法从磁盘重建。**

| 实测 | 读数 |
|---|---|
| 本地 `server/data/` | **10 档**(第 11 个文件是 `quota-2026-07.json`——正是刀 2 前置教我们别数进来的那份月账) |
| 档的世界分布 | **全部 `rules_creepy`** |

> **对叙事文本不成立**。线上那 53 档也救不了:结构上限 53×4 ≈ 212 条,且全是各局**最后四回合**(分布偏结局段)。

**故按「先量后接」的字面执行:量不到 → 不接。**
扫描器(词表 + 纯函数 + 用例)落进代码与测试,**但不接进 `settle` 打 WARN**。

> ~~「**词表还不存在,无从数误报**」(词表是刀 3 的产出)。~~
>
> **⚠️ 再订正(刀 3 落地,2026-09-07)**:词表已存在(5 条),误报也已在基线语料上数过 ——

> 那 0 命中**只证明「这批基线语料在这张词表下不产生噪音」**,

| | |
|---|---|
| **来源** | **实施步骤刀 4 冒烟那四局的完整叙事** —— 四世界各一整局,逐回合。 |

**产出** —— 四局 × 四回合 + 四发 init,见 [ADR-004 基线语料](ADR-004-baseline-corpus.md)。

## 已知代价

1. **⚠️ 主防线是软的,而且这次没有硬兜底。**
   prompt 硬禁靠模型遵守,没有引擎级保证。这与本项目反复吃过的亏同族——
   而 [ADR-020](ADR-020-lifetime-world-family-and-ordinary-life.md) 刀 8 那批立过字
   ([F-021](../../bakeoff/FINDINGS.md) 收口时同步):「**『软的够不够』不是二值问题,要看它差多少;
   凡有硬阈值的立字,『指令 + 兜底』是正解,不是二选一**」。
   **但那条在这里用不上**:自伤不是一根轴上的数值,写不出钳制,没有阈值可兜。
   唯一存在的硬兜底形态是「**缓冲 + 命中即拦**」,而那**正是本刀为保住逐字流明确放弃的**(候选方案 A/B)。
   **这条代价是真的敞着,不是「有兜底所以还好」。** 本 ADR 不粉饰它 ——
   **一份写着「有兜底所以还好」而其实没有的 ADR,正是这个项目一路在抓的那类谎。**

   > ⚠️ **本条配两个重新审视触发条件(见下节 ①②),写死是为了让它保持是一个「被裁定接受的代价」,
   > 而不会慢慢被读成一个「没人管的洞」。** 敞着可以,无人认领不行。
   >
   > **⚠️ 刀 4 之后本条一个字不改。** 那四局四个面全 0 命中 → 触发条件 ① **未触发**;
   > 而「未触发」的含义只有一个:**这四局没有立刻炸**。
   > 它不构成「主防线其实是硬的」的任何证据 —— **这条代价的大小,从来不由「炸没炸过」决定,
   > 而由「炸了有没有东西接得住」决定,而那个东西今天仍然不存在**。
   > 四刀走完、本 ADR 收口,**②(受众面扩大)照旧挂着,①照旧只需要一次**。
2. **检测器抓不到改写式表达** —— 直接继承 `LeakDetector` 的已知局限([工程债 §1.2](../backlog-engineering-debt.md) 已立字)。
   ⚠️ 词表是**中文字面匹配**:变体 / 谐音 / 拼音 / 繁体 / 拆字一律绕过。
   在遥测语境下可接受(**它本来就不是防线**),但**不得被当成防线引用**。
3. **骨架加字有成本(刀 2 已实测,不再是估计)** —— prompt 变长、其余指令权重被稀释,
   而 [ADR-007](ADR-007-world-gen-wire-protocol.md) 立过字 world-gen JSON 首过失败是头号失败模式。
   定稿 **217 字符 / 8 行**,三个骨架常量:回合 1837 → 2056(**+11.9%**)、
   world-gen 单体 1987 → 2206(**+11.0%**)、world-gen 融合 2626 → 2845(**+8.3%**);
   16 处渲染后合计 59,875 → 63,379(**+5.9%**),单份最高 `wg-rules_creepy` **+10.2%**。
   > ⚠️ **给刀 4 的验收口径**:这段话**不占叙事长度预算,但在同一份 prompt 里与 A-1 抢权重**,
   > 而**回合骨架涨 11.9% 是三处里最高的、回合侧恰恰是 A-1 生效的地方**。
   > 故刀 4 对照基线时,「**叙事变长 / 变短**」要与「**叙事质感退化**」分开读,别混成一条结论。
   >
   > **⚠️ 刀 4 实测(2026-09-08)—— 这条代价的账,三笔分开记,不合并成一句「代价付得起」**:
   >
   > | 这条代价预期打到的地方 | 实测 | 与预期 |
   > |---|---|---|
   > | **world-gen JSON 首过失败**(ADR-007 的头号失败模式,本条最担心的那个) | **0 次 / 4 局**,无一发「触发一次结构化修复」 | **比预期好**。⚠️ 但**没有基线**(过程指标 HAR 不承载),故它证明的是「**没有立刻炸**」,不是「首过率没降」 |
   > | **A-1 长度**(回合侧 +11.9% 抢权重) | 超 280 的 **1/16**(317 字);基线 0/16 | **代价现形了一次**,已裁定可接受,定性见实施步骤刀 4 口径三 |
   > | **回合 no-op 降级** | **2/16**(基线 0/16),复现批零降级 → 判**偶发** | ⚠️ **未复现 ≠ 与本条无关**:16 发对 16 发答不了归因,**这一格是敞着的**,见刀 4 口径一 |
   >
   > **⚠️ 三笔里只有第一笔是「好于预期」,另两笔各自留着一个没答完的问题。**
   > 把它们并成一句「代价付得起」,恰好会把那两个问题一起抹掉。
4. **撤掉接缝 = 未来重建时要重新划边界。** 已用解冻条件对冲(§三),但不等于零成本。
5. **未成年门禁不在本 ADR 范围** —— 一个 13 岁的玩家今天能打开这个链接玩克苏鲁,**这条本 ADR 不解决**,
   它被移出去了,不是被处理了。
6. **范围裁定 ③ 建立在一个未实测的依据上** —— provider 侧过滤覆盖仇恨内容。若该依据不成立,这一层是空的。

7. **⚠️ world-gen 的一次修复路径绕过这段话(刀 2 勘察发现,本刀不修)** ——
   `WorldGenPromptBuilder.buildRepairPrompt` **不含骨架**
   (只有 `REPAIR_HEAD` + 校验错误 + 上次失败的 raw),故 world-gen 校验失败后那一发**看不到这段禁令**。
   回合侧的 `REPAIR_SYSTEM` 明写「不含 narrative、不要叙事」,**不受影响**。
   > **这是一条真实的绕过路径,不是「风险低所以没事」。** 说它今天可接受的依据只有两条,
   > 都不是保证:修复那一发拿的是**已在约束下产出的 raw**、去改字段而非重写世界;
   > `REPAIR_HEAD` 已写「字段与约束同前」。**两条都靠模型的连贯性,不靠结构。**
   >
   > **⚠️ 触发条件(这条代价的认领人)**:① **修复路径的产出第一次被观察到与首发实质不同**
   > (不只是修字段,而是重写了 `openingNarrative` / `background`);
   > ② **刀 3 的扫描器接线之后,命中 WARN 出现在一发修复产出上**——
   > 命中哪条路径是可读的,那一刻这条代价就从「敞着」变成「有读数」。
   > 任一条命中 → 把 `REPAIR_HEAD` 补上这段话(成本是一行常量拼接)。

  故两种**合法**产出都会打出空串:**`ending` 字段整个缺失**(`path()` 给 MissingNode,`isNull()` 是 **false**,
  于是走 else 分支)、或 `ending: {}` / 只有 `reached` 没有 `id`。
  > ⚠️ **这条订正了「可能是日志截断」那个猜测的顺位**:截断在原理上仍可能(`ending={}` 恰在行尾),
  > 但既然存在一条**只靠代码本身就能解释**的路径,截断就不再是最可能的那个。
  > **两者在这一行上读起来完全一样** —— 要分清得看别的(例如同一行 `attrs=` 是否完整)。
  >
  > **为什么值得记而不是顺手修**:今天 `ending=null`(模型明确说没有结局)与 `ending=`
  > (模型没提这个字段 / 提了没给 id)**是两件不同的事,而日志把后两者合并成同一个空串**。
  > 它现在没有伤到任何人 —— 但**per-turn INFO 是这个项目冒烟排查的主要读数来源**
  > (ADR-014 E'' 顺带落的那条,逐字写着「冒烟排查不再解剖 heap」),
  > **一个读数分不清两种状态,就是下一次排查会踩的坑**。
  > 修法是一行三元改成三分(`null` / 缺失 / 无 id),**顺手做,不单开一刀**。
- **未成年门禁**:已移出本 ADR,单列进[工程债清单](../backlog-engineering-debt.md);
  ⚠️ 该条目注明**这是产品门禁不是内容审核,别并回 §1.2**。

### 刀 1 · 撤掉 `moderation` 包

**已落地(2026-09-07)。** 删接口 + `NoopModerationGateway` + `GameInitService` 的四个调用点与字段。
**行为零变化**(`review` 今天原样返回入参),故这一刀**可独立验证也可独立上线**。
⚠️ 不准顺手做:不碰 `LeakDetector`、不碰任何 prompt。

> **⚠️ 撤掉之后 init 侧那四处文本还有没有人管 —— 结论是「保护集合没变」,而这个措辞是承重的。**
>
> **不是「prompt 硬禁接管了它」。** 刀 2 的硬禁覆盖的是 world-gen 的**生成侧**,那是**新增**的一层;
> 刀 1 撤掉的是**零**。写成「A 换 B」和写成「加 A、删 0」在读者脑子里是**两笔完全不同的账**——
> 前者让人以为覆盖是守恒的,于是日后会有人拿「我们换过一次」当作某种保障的证据。
>
> 「零」有三条可核的依据(不是「no-op 嘛,应该没事」):
>
> 1. `NoopModerationGateway.review(text) { return text; }` —— **恒等函数**,无副作用、无日志、无计数。
> 2. 四个调用点都是**纯写回**(`wo.put("title", review(wo.get("title").asString("")))`)。
> 3. **连类型强制都不可能发生** —— `worldGen.generate()` 里 `GameSchemas` 已
>    `requireNonEmptyString` 钉住 `world/title`、`world/background`、`rules[]/content`,
>    到达那段代码时三处**必然已是非空字符串**,`asString("")` 不存在 number→string 的路径。
>    故删掉在**任何能走到这里的输入**下逐字节等价。
>
> **确实变化的那一样,分开记(它不是覆盖下降,是未来成本)**:撤掉之后 init 侧
> **不再有一个现成的挂载点**。解冻条件命中时要重新划位置 —— 这一点 §最终决策三已经写着
> 「不保证还是今天这四个调用点」,本节只是把它与「覆盖没下降」**分开陈述**,免得两样混成一句
> 读起来像粉饰。

#### 词表:5 条(Felix 2026-09-07 定稿)

**留下一个词的判据说死**:
> **「在这四个已上线世界的正常笔法里几乎没有理由出现」,而不是「它常用于自伤」** ——
> 后者是词自身的属性,**前者才是这个项目的判据**。

| 词 | 理由 | 风险 |
|---|---|---|
| `吞下整瓶` | 剂量 + 动作;正常叙事没有理由出现 | 低(最干净的一条) |
| `手腕内侧` | 部位**精确化**才构成操作细节(对照:单说「手腕」是常见描写,不收) | 低 |

| `割脉` | 同上,更少见 | 中 |
| `自缢` | 「自」在词内自指 | ⚠️ **本表最高** —— 恐怖场景描写他人死因(「梁上自缢」)会命中。**刀 4 语料若打中本表,第一个删的就是它。** |

| 砍掉 | 理由 |
|---|---|
| `上吊` | ⚠️ **四个已上线世界里最可能被打中的一条** ——「上吊的房客」是规则怪谈的标准桥段 |
| `投缳` | 几乎不会命中的词**不是保护,是词表里的噪音** |
| `服毒` / `跳楼` / `卧轨` | 共同点是**在四个世界里都有合法用法**(修仙服毒试药、末日有铁轨) |

⚠️ **覆盖边界**:语料里**没有 `availableActions`** → 判据的那半边(`.text` / `.hint`)
**量不到,不是量出来是 0**。
> ✅ **这一格已由刀 4 补上**(2026-09-08):那四局的 **61 条选项、2014 字**扫过,**0 命中**。
> ⚠️ 补的是**覆盖**,不是**结论** —— 那 0 仍然只能记「没有立刻炸」,判据不变。

### 刀 4 · 真机冒烟:四世界各一局 —— ✅ 已跑完 2026-09-08

**⚠️ 验的不是「没出现」。**「验证一个不该出现的东西没有出现」是个难以证伪的形状,
故本刀验的是三件各自可证伪的事:

| # | 验什么 | 手段 | 可证伪吗 |
|---|---|---|---|
| a | **主防线在场** | 16 处 dump 逐份确认那个 `【】` 段真的渲染进去了 | 可数。**且它同时就是刀 2 的 parity 阳性对照——一次取证两用** |
| b | **扫描器会响** | 构造含词文本喂纯函数 | 单测即可,**不需要真机** |
| c | **代价付得起** | 四世界各一局:叙事质感无退化 + world-gen 首过不新增修复 | 可判 |

> **真机唯一能答而单测答不了的问题,不是「安全了吗」,是「代价付得起吗」。**
> 那一段话是加在**共用骨架**上的,四个世界的叙事都会受影响(已知代价 3)。

#### ⚠️ 订正(2026-09-06):本刀不再需要「当场留存语料」,而它的用途换了

原文是「**本刀还有一件必须当场做的事:留存那四局的完整叙事** …… 跑完再想起来去 `/data` 里找就已经晚了」。
那一步**已在刀 0 之前完成**(HAR 导出,零代码 —— 见 §最终决策五 订正块),
产出 = [ADR-004 基线语料](ADR-004-baseline-corpus.md)。原措辞留档,只作历史记录读。

**这批局的用途因此从「留语料」变成「与那份基线对照」**,而这需要 ADR 补一个它今天没有的概念:

> **基线** = 四个世界在**硬禁加入之前**的一份叙事样本。
> **没有基线,「有没有把世界写坏」根本无从判断** —— 那正是上表 c 那一格问的问题,
> 而这批局的全部价值就在这儿。

⚠️ **对照面以基线文件 §三 为准,它不是全覆盖**:`world.title` / `world.background` 四局全空;
**world-gen 首过率是过程指标,本语料不承载**。故上表 c 的两半里 ——
「叙事质感无退化」**有基线可比**,「world-gen 首过不新增修复」**只能当场数**,
⚠️ **而那个数今天同样没有基线**。

拿到词表(刀 3)之后跑一遍基线数误报,据此定 WARN 接不接。

⚠️ 若那四局词表命中 0,**如实记为「没有立刻炸」,不得记为「误报率低」**——
四局答不了误报率,那需要的是上一段那份语料,不是这四局的命中数。

#### 刀 4 实测结果(2026-09-08,Felix 亲手)

⚠️ 本 ADR 立过「刀 4 必须在部署之后跑」,**这一行是那条前提被满足的证据,不是背景交代**:
它验的是**线上**那段话有没有把世界写坏,跑在没吃到硬禁的镜像上等于什么都没验。

##### 验收三项

| # | 验什么 | 结果 |
|---|---|---|
| a | 主防线在场 | ✅ 刀 2 已给(16/16 逐份 + diff 只多出那一段);本刀不重复 |
| b | 扫描器会响 | ✅ 刀 3 单测已给(逐词 5 条各自命中) |
| c | **代价付得起** | ⚠️ **见下三条口径** —— 不是一句「通过」 |

##### ⚠️ 口径一 · 「偶发」不是「没问题」

按开跑前说死的判据(复现批零降级 → 判偶发),no-op 判为**偶发**。
**但那是这批数据支持的最强结论,不是结论本身。** 三点如实记:

1. **2/16 是实测不是推测,而且玩家可见。** 降级的语义由 `EventLoopService.degrade` 逐字定死:
   「turn++、不脏写、**复用上一组动作**」—— HAR 逐条对拍到玩家**连续三个回合看到同一组四个选项**、
   `hp=80 san=70` 三回合不动。**它发生过。**
2. **没有基线对照。** 基线那 16 发零降级,**可能是差别,也可能是运气** —— 16 发的样本量答不了这个问题
   (同本 ADR 对命中数立的那条字:小样本支撑不起比率)。
3. **两次落在同一局的连续两回合(T2、T3),不是随机散布,而 T4 自己恢复了。**
   ⚠️ **这个形状要记,别抹成「偶尔两次」** —— 连续 + 自愈,与「独立随机故障」是两种不同的东西,
   而只有前者会让人怀疑是某个局部状态(那一局那两回合的上下文)而不是普遍退化。

⚠️ **哪一条降级路径没有定位**:`EventLoopService` 有三条(主调用流中断 / 叙事空或无结构化尾巴 / 修复仍败),
三条各打一条**措辞不同**的 WARN,**分得开**;但本轮交付的读数里**没有服务端那一行**
(completion 149/114 只说明那两发短,不说明短在哪一步)。**下次遇到先读 WARN**,那是零成本的。

##### ⚠️ 口径二 · 词表 0 命中只能记「没有立刻炸」

**⚠️ 不得记为「误报率低」** —— 本 ADR 已立字,3115 + 2014 + 621 + 644 字支撑不起任何比率;
也不得据此就把 WARN 接上(见 §挂账,判据一个字不改)。

**但有一处覆盖是真的推进了,这一条是本批唯一的净增量**:
基线**没有 `availableActions`**,那半边当时只能记「**量不到,不是量出来是 0**」;
本批 **61 条选项、2014 字,那半边量到了**。§最终决策五与
[基线语料 §八](ADR-004-baseline-corpus.md) 里那条覆盖边界据此更新。

##### ⚠️ 口径三 · A-1 超限 1/16 的定性

**Felix 裁定:可接受** —— 逐字理由是「**不能因为字数破坏故事可读性**」。

⚠️ 但要如实记**它不是写坏了**:那一发是修仙劫云局 T4,写的是**完整三段式战斗**
(诱敌 / 蓄雷 / 闪避反打),三层重量齐备、无现实可复现的方法细节 ——
**是内容密度撑长的,不是废话撑长的**。

⚠️ 并记一句可归因的观察(它正是已知代价 3 给刀 4 立的验收口径):
**回合骨架涨 11.9% 是三处里最高的,而回合侧恰恰是 A-1 生效的地方**。
故这一发要读作「**叙事变长**」,**不是「叙事质感退化」** —— 两者分开读,不混成一条结论。

## 背景

[世界目录](../world-catalog-and-experience-modes.md) A 档第 134 行登记了「穿越古代 | 浮世 | (空)」—— 引擎零改可做、
归属浮世侧,尚无具体世界。本 ADR 给它一个具体世界:**《七日开张》**。

设计来源:校勘整合两份创意稿(GPT《七日开张》+ docx 甲)+ 发散窗口一轮补漏;**Felix 2026-11-12 选定露馅做法Ⅰ**
(底细做致命轴,现代招数立功与露馅同一回合落数)。下面「最终决策」各节是 brief 给定的决策,数字经 Felix 2026-11-12 审定。

一句话:玩家穿越到一个不具名的「本朝」,被当成失踪摊主的远房亲戚,接手县城以下一条街上一个快倒闭的小摊;
七天后是「百味夜集」。现代的经营、卫生、算术、说话方式能救活这个摊,**但每用一次,街坊就多看你一眼**。

约束条件:

1. **单体世界,不是融合组合,也不属一生制族**:走 ADR-036《派单》立下的单体服务端编排(CONTEXT §三.18 五条),
   不套 ADR-014 的 per-combo 槽与 ADR-021 的族层。
2. **引擎 / 校验语义无知不动**(ADR-008);结局语义产出方仍是模型(ADR-010),服务端核对只在 `engine.apply` 之前改写提议(§三.18(b))。
3. **`schemaVersion` 不动**(仍 "0.4"):新 archetype id、四条结局、三条轴都不是 state schema 字段变更(§三.5 开放字典、§三.14 伴生元数据)。
4. **公共【现实边界 · 硬约束】已在骨架**(ADR-037 / CONTEXT §三.19);本世界更严的题材边界只进本世界指令槽,不得放宽骨架。
5. **不在本 ADR**:前端卡面 / 粒子 / 顶图 / 局内皮肤(归前端待做三条,最后统一做);浮世 / 深界分区大厅。

#### 勘察 13 详述 · `pickFailureEnding` 在本世界只有一条 failure 结局时的路径

本世界致命轴只有 `cover`(底细);`capital` 是非致命资源轴(`resource`,`lethal=false`),`regulars` 是累积轴,两者都不触底、不 gate。
`Engine.pickFailureEnding(List<String> lethalAxisKeys)`(`Engine.java:566-592`)四步:

1. 对每个濒零 / 触底的致命轴 key,找「`outcome == failure` 且 `condition` 含该轴**中文名**」的结局(`findEndingByConditionMentioning`,:608 起;中文名缺失才退英文 key)→ `condition` 含「底细」的「请来了道士」**在这一步命中**。
2. 否则取首个 `outcome == failure` 的结局 → 只有一条 failure,仍是「请来了道士」。
3. 否则取 `condition` 提及致命轴的任意极性结局。
4. 否则 `endings[0]`。

两个入口:
- **结局极性 gate**(`Engine.apply` 第 9 步,:304-331,gate 判断在 :319):模型提议 `success` 且底细 ≤ 10 → 改判为第 1 步的结果。本世界的核对在 `apply` 之前已把这类提议改写掉(决策 4),gate 只在核对 `skipped` 时才会真的出手。
- **触底兜底**(第 10 步,:333-340;`forceBottomOutEnding` 在 :546):底细 ≤ 0 且本回合没有被接受的结局 → `forceBottomOutEnding` 走同一函数。核对对底细 ≤ 0 直接写「请来了道士」,引擎第 9 步接受(failure 不受 gate 拦),第 10 步见 `aiAccepted` 不再兜。

所以只要 world-gen 产出了那条 failure 结局,不论核对在不在场,底细触底都确定地落到「请来了道士」;第 3、4 步只在结局池里一条 failure 都没有时才走到 —— world-gen 检查「四个固定 id 都在」(决策 5)把这条路堵死。

## 候选方案

本 ADR 的结构性取舍只有一处:**底细(露馅)在机制上是什么**。时段注入、结局核对、world-gen 检查、跨档台词都直接沿用 §三.18,不再比选。

### 方案 A:底细只染叙事,不进轴(露馅做法Ⅱ类)

**优点**:
- 少一条轴,数值面板更轻;不需要致命轴与 gate 的衔接。

**缺点**:
- 「用一次现代招数就多一分风险」没有落账的地方,全靠模型记;冒烟经验(F-038)表明不写死数字的东西模型会给 0 或乱给。
- 「请来了道士」没有确定的触发条件,只能让模型自判,结局核对无从核起。

### 方案 B:底细做累积轴「惹眼」,越高越糟(perilAtHigh,同《派单》画像)

**优点**:
- 与《派单》画像同形,前端「高位染 danger」已有现成派生。

**缺点**:
- 累积轴引擎不触底(ADR-009),「请来了道士」需要核对单独写一条「≥ 某值即结束」,等于在服务端重造一条致命轴;
- 「圆回来」是往回补的动作,累积轴的叙事语义(纯积累)与之不合。

### 方案 C:底细做致命消耗轴,立功与露馅同回合落数(露馅做法Ⅰ,本 ADR 采纳)

Felix 2026-11-12 选定。

**优点**:
- 引擎已有的触底兜底与结局极性 gate 直接覆盖「请来了道士」,核对只是让它在第 22 回合的判表里先到一步;
- 「现代招数 = 摊本涨、底细跌」在同一回合同时落数,玩家每次选择都看得见交换;
- 底细的三档正好对应三种街坊反应,叙事跟着档走,不卡选项(CONTEXT §三.14 bands 只染叙事)。

**缺点**:
- 致命轴意味着这个轻松世界也能「死」;以「请来了道士」这种荒诞结局承接,不写成惩罚(决策 4)。
- 立功、露馅、圆回来三条数字都靠提示词落(已知代价 1)。

## 最终决策

**方案 C — 底细做致命消耗轴**,其余按 §三.18 单体编排落地。

### 1. 世界与名称

- **单体,浮世**。卡面题材名(`displayName`)「**穿越古代**」;游戏内世界名由 `fixedWorldTitle`「**七日开张**」服务端覆写。
- **archetype id = `time_travel`**(Felix 2026-11-12 定)。理由:① 现有 id 一律是**题材名**而非世界名(`cyberpunk` 之于《派单》、`life_sim` 之于《寻常》),世界名另由 `fixedWorldTitle` 固定;② 题材的核心是「穿越」,「古代」只是落点;③ snake_case 英文(CONTEXT §三.3)。
  代价:`time_travel` 比「穿越古代」宽,将来若有「穿越到未来」的世界,两者会争同一个 id(已知代价 9)。
- 朝代不命名,只叫「**本朝**」;规模压在**县城以下的一条街**;地名全部虚构。
- 开局:玩家被当成**失踪摊主的远房亲戚**,接手一个快倒闭的小摊。失踪摊主在钱匣里留下一张**字迹缺笔画的小抄**,写着「这个时代的规矩」(即 8 条规矩的来源);**不揭示前任身份**。

### 2. 形状:七天 × 早 / 午 / 晚 + 百味夜集,定长 22 回合

| 真 | 雨天卖粉食,纸包要双折封口 | 不信则受潮退货,摊本 −4 |

- **world-gen 世界专属检查**(§三.18(c),Felix 2026-11-12 定),三项:
  1. 每条 `isTrue` 必须是布尔(照搬《派单》订正二);

- **单字表不可行**:「汉」「唐」「宋」「明」「清」会命中「汉子」「宋体」「明天」「清水」,修复与 ERROR 会被误伤打满。

- **命中的代价**:多一次修复调用(花钱),修复仍败 → 整局 ERROR(§三.11),玩家看到「重新生成」。

### 关键理由

1. **全部机制都有先例**:时段与状态行注入、结局核对、world-gen 专属检查、跨档台词,四件都是《派单》验通后立字的 §三.18,本世界只是第二个使用者 —— 新东西只有内容。
2. **引擎、校验、schema 一行不动**:新 id 只进 registry 与类型声明;致命轴、gate、触底兜底全是现成行为。
3. **不先抽象**:两份核对并排存在,改一处不会误伤另一处;重复的代价(约 45 行)写清楚,第三个使用者出现时再判断。
4. **把易错的交给服务端**:时段、结局、跨档这三件冒烟里模型稳定出错的事(ADR-035、ADR-036 四次订正),一开始就由服务端判,不再等冒烟失败后补。

## 已知代价

1. **经济数字靠提示词落数,未经冒烟**:进货 −6、立功代替营业收入、早回合立功免进货、第 22 回合按营业落数、圆回来同回合 −3 且不营业,都是 F-038 的同类风险 —— 模型可能不扣进货、或立功回合仍加营业收入。缓解:数字同时写进回合指令与 `behaviorHint`,加「不得大幅偏离」;冒烟读 issues 与摊本轨迹核。
2. **底细 1–10 而摊本 < 60 落到中性结局**:是**有意沿用**《派单》「差一点不降级」的先例(ADR-036 订正四),不是漏判。
3. **提示词侧「11~39」与代码侧「≤ 39 再降级」写法不同**(决策 4):结果逐格相同,但读代码的人会看到两种写法。缓解:本 ADR 写明,核对代码注释指回决策 4,单测对拍落点表逐格。
4. **核对代码重复**:`QiriEndingCheck` 与 `PaidanEndingCheck` 有约 25 行私有小函数逐字重复,`EventLoopService` 守门再重复约 20 行。缓解:不抽象,等第三个单体核对出现时判断(挂账)。
5. **`displayName`「穿越古代」进提示词**:「古代」可能把模型往真实朝代上带。缓解:两个指令槽写明模式名只是标签,并写决策 8 的朝代禁令。
6. **致命轴进了浮世世界**:轻松世界也能「结束」。缓解:用「请来了道士」这种荒诞收场承接,description 不写惩罚。
7. **题材边界只是提示词约束**(同 ADR-037 已知代价):回合侧没有拦截层;首刀不做禁词表,world-gen 侧也没有。
8. **world-gen 检查不查恰好 8 条、4 真 4 假**:模型可能产出 6–7 条或 3 真 5 假的世界而通过检查。接受:凑数不值得一次整局 ERROR;真、假各 ≥ 3 已保住玩法的骨架。
9. **`time_travel` 比题材名宽**:将来若有「穿越到未来」的世界,会与本世界争同一个 id。
10. **前端未登记期间走中性外观**(勘察 16):卡面、局内都没有本世界的视觉,直到前端轮。

**上线后观察(第二轮真 key 冒烟发现,2026-11-12;只记,不修)**:

11. **熟客几乎不卡人**:模型几乎每回合给熟客 +5~+8,两局第 11–13 回合即过 50,「熟客 ≥ 50」基本不卡人。
    候选修法:涨幅降到 +3~+5,只在客人明显满意时给。
12. **第 22 回合叙事与改判可能不一致**:`7c890a9b` 模型把夜集写成城中怪点子王,服务端核对改判请来了道士。
    候选修法:第 22 回合注入落账前的底细值。
13. **底细 < 70 时缺【打圆场】选项**:第二轮出现 2 次,没有 issue 计数。候选修法:照「缺怪点子选项」加一条计数。

## 订正(2026-11-12 一):选项前缀、服务端兜底与每回合钳制

> 本节补充决策 3(落数)、决策 4(核对的判定区间)、决策 7(示例语气)。Felix 2026-11-12 定,依据第一轮真 key 冒烟两局
> `6a3b425c` / `eb5fda16`。旧文字原样保留,被补充处就地加 ⚠️ 标注指回本节。

**为什么订正**(冒烟读数):
1. 44 回合里选项几乎没有现代招数;底细两局只掉了几次 1 点(`eb5f` 第 10 回合叙事写了画出不像本朝的数目,底细没扣)。

4. 叙事偏安静文艺,没有「立功又翻车」的喜剧感。
5. 正常:`world.title`、tone 介绍句、第 22 回合出结局、结局回合写出招牌、改判路径。

选项里也没有一个让玩家认得出「这是现代招数」的记号,服务端无从按玩家的选择核数。本订正给选项加前缀,再按前缀在服务端兜底。

### 决策

1. **选项前缀**(玩家可见,Felix 定稿,逐字):**【怪点子】= 用现代的经营、卫生、算术、说话方式;【打圆场】= 主动化解别人对你来历的怀疑。**
   - 回合指令与 world-gen 开局的 `availableActions`:每回合至少 1 个【怪点子】选项;落账后底细低于 70 时,至少再有 1 个【打圆场】选项。

   - 【怪点子】的 `hint` 写这一招具体会招来什么(邻摊学去、客人追问、大爷辩论),不写「可能惹眼」这类警告。
   - 【打圆场】的选项要写出实际的掩饰办法。
2. **服务端两头兜底**(新纯函数 `QiriActionGuard`;落点照 `clampClosingVigorFloor` / `PaidanEndingCheck`:`landSettled` 内、`apply` 之前、
   `QiriEndingCheck` 之前;只对单体 `time_travel` 生效)。按玩家本回合所选 `actionId` 在 `pre.currentActions` 里那条选项的 `text`
   是否以前缀开头(字面精确匹配)——
   - 【怪点子】:底细 Δ ≤ −6;午、晚、第 22 回合摊本 Δ ≥ +8;早回合摊本 Δ ≥ 0(只省下进货那 6)。

3. **本世界每回合数值钳制**(同一处,在兜底之后):摊本 Δ ∈ [−15, +12],熟客 Δ ∈ [−8, +8],底细 Δ ∈ [−12, +6];最后再 clamp 到 0–100。
4. **记录**:每次兜底或钳制改写了数值,记一条引擎 issue;本回合 `availableActions` 里没有【怪点子】选项时,记「T{n} 缺怪点子选项」。只记录,不触发修复。

### 兜底与钳制核算(两者不冲突)

| 前缀 | 兜底 | 钳制区间 | 合起来 |
|---|---|---|---|
| 【怪点子】底细 | Δ ≤ −6 | [−12, +6] | Δ ∈ [−12, −6] |
| 【怪点子】摊本(午、晚、第 22 回合) | Δ ≥ +8 | [−15, +12] | Δ ∈ [+8, +12](= 决策 3 立功 +8~+12) |
| 【怪点子】摊本(早回合) | Δ ≥ 0 | [−15, +12] | Δ ∈ [0, +12] |
| 【打圆场】底细 | Δ ≥ +6 | [−12, +6] | **Δ = +6**(= 决策 3 圆回来 +6) |
| 【打圆场】摊本 | Δ ≤ −3 | [−15, +12] | Δ ∈ [−15, −3] |

每一格兜底的界都落在钳制区间之内,所以「先兜底、再钳制」不会把兜底写的值又钳回去。只有 0–100 的最终 clamp 会在边上压掉兜底
(例:底细 97 打圆场 → 100,Δ 只有 +3),这与引擎 clamp 的口径一致,不另处理。
冒烟 `6a3b` 第 22 回合按本节重算:落账前摊本 2、模型给 64 → 钳到 14 → 核对判明日照常开张(不再是夜集第一摊)。
钳制后单回合 |Δ| ≤ 15,本世界不会再出现引擎的「跳变过大(需复核)」(阈值 40)。

**2. 数值形态:九档算盘(`QiriStats`)**

结构(自上而下):

```
.ledgerPanel
  .panelHead      左:时辰牌 .hourTag(timeLabel;没有时整个节点不渲染)  右:灯笼 .lantern(aria-hidden)
  .names          三个轴名,按 axes 顺序,直接用 displayName
  .abacus         三组(.group)× 三档(.rod,百 / 十 / 个)× 五颗珠(上 1 下 4);梁一道线,每组个位档梁上一个定位点
  .readout        三格(.cell):数字 .cellNum / 档名 .cellBand / 状态词 .cellRisk
```

- **主题层不认轴**(ADR-018 §4.2):三组按 `axes` 顺序排,不按 key 判断哪根是摊本;颜色只读 `severity`。
- **珠子映射**(纯函数 `abacus.ts`,只吃 `AxisView.value`):`v = clamp(round(value), 0, 100)`,三档数字 `[⌊v/100⌋, ⌊v/10⌋ mod 10, v mod 10]`;
  每档 `upper = d ≥ 5`、`lower = d mod 5`(下珠从靠梁那颗起算)。靠梁的算数,上珠当五、下珠当一。
- **位置**(样张原值):上珠原位 `top: 4px`、算上时 `translateY(12px)`;下珠第 j 颗原位 `top: 48 + 11j px`、算上时 `translateY(−18px)`。算盘高 96px,梁在 27–29px。
- **颜色**:算上 `--wood #4f3a24`、没算上 `--bead-off #cfc2a4`;`danger` 时该组算上的珠子与数字转 `--zhu #a2351f`;
  `caution` 时只有状态词与小方点转 `--ochre #96621a`,**珠子不变色**;`neutral` 状态词「正常」。`severity` 为 null → 状态词为空串、不画小方点
  (`.cellRisk:not(:empty)::before`,节点保留只为三格底边对齐)。状态词由 `severityWord()` 给,不在皮肤里另写映射。
- **手感**(Felix 定,照演示 `moveBead`):一颗珠子走 160ms,关键帧 `0 → 0.55 到位 → 0.78 反向弹回 1.5px → 1 归位`,
  缓动 `cubic-bezier(0.5, 0, 1, 0.7)` / `ease-out` / `ease-in`;**珠子在动时目标又变了,从当前位置接着走**(读计算样式里的 `translateY`,取消旧动画再起新的)。
  用浏览器自带的 Web Animations(`element.animate`),**不引库、不用 GSAP**:这是逐元素的短关键帧,CSS 过渡做不出「到位后反向弹回」,
  GSAP 在这里没有时间线可编排。只动 `transform`(AGENTS.md §6)。jsdom 没有 `animate` → 直接落位(同演示的守卫)。
- **数字滚动**由通用层做(600ms、`power3.out`),本组件不自己滚;数字、档名、状态词、珠子同一渲染换(勘察 1)。
- **reduced-motion**:数字由通用层直接到位;珠子不起动画、直接落位。
- **字体**:轴名、数字、时辰牌用楷体(决策 5);`.cellNum` `font-weight: 400`。⚠️ 演示里 `.cellNum` 是 `700` / `1.45rem`,
  静态样张是 `400` / `1.5rem`,**以静态样张为准**(简报「一律 400」)。
- 读屏:每格 `aria-label = axis.a11yText`(通用层给,「熟客 · 36 · 回头客 · 正常」);算盘整块 `aria-hidden`(珠子是数字的另一种画法,不重复念)。

**3. 记忆点:熟客升档时亮一盏灯笼**

- **信号**:`signatureAxisKey: 'regulars'`,用通用层现有的 `signature.tick`(向上跨档才加一、一次跨多档只加一、续局首帧不加)。不新增判定,皮肤不读熟客数值。
  熟客档界只有 30 / 60,所以每局最多亮两次。
- **形态**:面板头右侧一个只有线的小灯笼(SVG 照样张逐字搬,15×24,`stroke-width 1`,颜色 `--wood`)。平时空轮廓;触发时灯身 `fill: #dc9a34`,

- **先后**:灯先亮,数字与珠子 600ms 后才动(`ceremonyDelayMs: 600`,通用层施加)。
- **reduced-motion**:仍然亮和熄,只是没有过渡(CSS 里 `transition: none`)。
- **接法(推荐乙)**:

  | | 做法 | 好处 | 代价 |
  |---|---|---|---|
  | 甲 | `StatsProps` 加可选 `signatureTick`;`QiriStats` 自己管灯笼的状态与定时器 | 灯笼的样子与驱动在同一个文件 | 记忆点第一次放进 `Stats`,与五套皮肤的先例不同;调试重播按钮也得进 `Stats`;契约多一个字段 |

  | 丙 | `QiriStats` 从 context 或 store 自己读信号 | — | 第二套读法,违反「判定只在 `PlayingScreen` 一次」(ADR-018 §4.1)。不采用 |

  甲乙都满足「不新增第二套判定、皮肤不读熟客数值」。推荐乙,因为它不动契约,也沿用现有托管位置。

- **调试**:`?debug=1` 下 `QiriAmbient` 给一个「重播:灯笼」按钮(同 `PaidanAmbient`),不需要真 key 就能看。数值滚动与珠子可用现有 `DebugPanel` 改值观看。

### 已知代价

1. **字符集写死**:改标签文案或轴名不重裁,缺的字回落系统楷体(一个词两种字形)。时辰标签的文字在 Java(`ClientProjection`),
   前端测试是**手抄**那 9 个标签,服务端改了文案前端测试不会红。缓解:决策 5 的测试 + 本条记录;本刀不动后端,不在 Java 侧加守卫(挂账)。
2. **时辰牌比正文早一格**(ADR-039 已知代价 2):回合落地后时辰牌已是下一步。Felix 定放面板头、读作「现在是什么时候」。
3. **顶部「第 N 回合」与时辰牌并存**:N = `state.turn`,时辰牌说的是第 N+1 回合,屏上有两种时间读数。Felix 定保留回合行。
4. **共享 CSS 多了 10 个令牌**:未登记世界不受影响靠的是「回落值 = 现值」,DOM 对拍看不出 CSS 变化 → 验证方案 C 另做计算样式对拍。
5. **楷体数字可能不等宽**:若源字体没有 `tnum` 或子集丢了它,滚动时数字宽度会变,居中的数字会左右晃。缓解:重裁保 `tnum`;没有就给 `.cellNum` 固定宽度,实测后报。
6. **字体加载闪一下**(`font-display: swap`):首帧可能先用系统楷体 / 宋体,约 6.6KB 到了再换。接受。
7. **移植债多一项**:小程序要 `wx.loadFontFace` 加载这份字体(ADR-017 §4 那一篮子),量很小,记账。
8. **灯笼过渡动的是 `fill`**,不是 `transform` / `opacity`(AGENTS.md §6 写的是「优先」)。一个 15×24 的 SVG 路径,重绘面积可忽略;
   换成「叠一层已填色的灯身、改 `opacity`」可以严格守 §6,但多一层 DOM。默认按样张用 `fill`,待审 5。
9. **灯笼对读屏无声**:装饰性(`aria-hidden`),没有文字;熟客升档仍可从该格 `aria-label` 的档名读到。同修仙钟鸣。
10. **珠子数量**:45 颗,一次 0→100 的滚动会让个位档连续拨很多下,每次都是一个短 WAAPI 动画。只动 `transform`;低端 Android 的实际帧率本地验不了,交真机。
11. **Android 系统没有楷体**:网页字体加载失败时落到 `Noto Serif SC` / `serif`(宋体),不是楷体。交 Felix 真机看。

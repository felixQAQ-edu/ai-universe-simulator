## 背景

[世界目录](../world-catalog-and-experience-modes.md) A 档第 134 行登记了「穿越古代 | 浮世 | (空)」—— 引擎零改可做、
归属浮世侧,尚无具体世界。本 ADR 给它一个具体世界:**《七日开张》**。

设计来源:校勘整合两份创意稿(GPT《七日开张》+ docx 甲)+ 发散窗口一轮补漏;**Felix 2026-11-12 选定露馅做法Ⅰ**
(底细做致命轴,现代招数立功与露馅同一回合落数)。下面「最终决策」各节是 brief 给定的决策,数字是草案量级,审定时可改。

一句话:玩家穿越到一个不具名的「本朝」,被当成失踪摊主的远房亲戚,接手县城以下一条街上一个快倒闭的小摊;
七天后是「百味夜集」。现代的经营、卫生、算术、说话方式能救活这个摊,**但每用一次,街坊就多看你一眼**。

约束条件:

1. **单体世界,不是融合组合,也不属一生制族**:走 ADR-036《派单》立下的单体服务端编排(CONTEXT §三.18 五条),
   不套 ADR-014 的 per-combo 槽与 ADR-021 的族层。
2. **引擎 / 校验语义无知不动**(ADR-008);结局语义产出方仍是模型(ADR-010),服务端核对只在 `engine.apply` 之前改写提议(§三.18(b))。
3. **`schemaVersion` 不动**(仍 "0.4"):新 archetype id、四条结局、三条轴都不是 state schema 字段变更(§三.5 开放字典、§三.14 伴生元数据)。
4. **公共【现实边界 · 硬约束】已在骨架**(ADR-037 / CONTEXT §三.19);本世界更严的题材边界只进本世界指令槽,不得放宽骨架。
5. **不在本 ADR**:前端卡面 / 粒子 / 顶图 / 局内皮肤(归前端待做三条,最后统一做);浮世 / 深界分区大厅。

#### 勘察 13 详述 · `pickFailureEnding` 在本世界只有一条 failure 结局时的路径

本世界致命轴只有 `cover`(底细);`capital` 是非致命资源轴(`resource`,`lethal=false`),`regulars` 是累积轴,两者都不触底、不 gate。
`Engine.pickFailureEnding(List<String> lethalAxisKeys)`(`Engine.java:566-592`)四步:

1. 对每个濒零 / 触底的致命轴 key,找「`outcome == failure` 且 `condition` 含该轴**中文名**」的结局(`findEndingByConditionMentioning`,:608 起;中文名缺失才退英文 key)→ `condition` 含「底细」的「请来了道士」**在这一步命中**。
2. 否则取首个 `outcome == failure` 的结局 → 只有一条 failure,仍是「请来了道士」。
3. 否则取 `condition` 提及致命轴的任意极性结局。
4. 否则 `endings[0]`。

两个入口:
- **结局极性 gate**(`Engine.apply` 第 9 步,:304-331,gate 判断在 :319):模型提议 `success` 且底细 ≤ 10 → 改判为第 1 步的结果。本世界的核对在 `apply` 之前已把这类提议改写掉(决策 4),gate 只在核对 `skipped` 时才会真的出手。
- **触底兜底**(第 10 步,:333-340;`forceBottomOutEnding` 在 :546):底细 ≤ 0 且本回合没有被接受的结局 → `forceBottomOutEnding` 走同一函数。核对对底细 ≤ 0 直接写「请来了道士」,引擎第 9 步接受(failure 不受 gate 拦),第 10 步见 `aiAccepted` 不再兜。

所以只要 world-gen 产出了那条 failure 结局,不论核对在不在场,底细触底都确定地落到「请来了道士」;第 3、4 步只在结局池里一条 failure 都没有时才走到 —— 决策 5 的 world-gen 检查若含「四个固定 id 都在」(审定清单第 7 项),这条路就被堵死。

#### 与 brief 不一致、或 brief 未给出的(不自行调和,全部进审定清单)

- **A · 结局表内部矛盾**:「城中怪点子王」写「底细在 11~39 之间」,而「判出 success 而底细 ≤ 10 → 降级为请来了道士」。两条成功结局的条件(≥ 40、11~39)**本来就排除了底细 ≤ 10**,按表判不可能判出底细 ≤ 10 的 success,**降级规则永远不触发**;于是「底细 1–10 且摊本 ≥ 60」按表落到「明日照常开张」,而不是结局描述里写的「夜集时判出成功但底细 ≤ 10 → 请来了道士」。已知风险那句也只说「底细 1–10 而摊本 < 60 时落到中性」,隐含摊本 ≥ 60 时不落中性。见决策 4 的两种读法。
- **B · 经济粗算在中位数上对不上**:见决策 3「经济粗算」—— 按 brief 的数字取中位数,4 次立功摊本约 49,不是 60;要到 60 约需 6 次,而 6 次时底细 44,是「夜集第一摊」唯一的窗口。
- **C · 立功能否发生在早回合**:「立功 +8~+12 代替当回合营业收入」,而早回合没有营业收入、固定进货 −8。早回合立功怎么落数,brief 未说。
- **D · 跨档台词的触发次数与边界**(勘察 14)。
- **E · 摊本、熟客两条轴的档 label 与 narrationHint、底细三档的 label**:brief 只给了底细三档的 narrationHint。本 ADR 写了草稿(决策 3),标明待审,不是占位符。

## 候选方案

本 ADR 的结构性取舍只有一处:**底细(露馅)在机制上是什么**。时段注入、结局核对、world-gen 检查、跨档台词都直接沿用 §三.18,不再比选。

### 方案 A:底细只染叙事,不进轴(露馅做法Ⅱ类)

**优点**:
- 少一条轴,数值面板更轻;不需要致命轴与 gate 的衔接。

**缺点**:
- 「用一次现代招数就多一分风险」没有落账的地方,全靠模型记;冒烟经验(F-038)表明不写死数字的东西模型会给 0 或乱给。
- 「请来了道士」没有确定的触发条件,只能让模型自判,结局核对无从核起。

### 方案 B:底细做累积轴「惹眼」,越高越糟(perilAtHigh,同《派单》画像)

**优点**:
- 与《派单》画像同形,前端「高位染 danger」已有现成派生。

**缺点**:
- 累积轴引擎不触底(ADR-009),「请来了道士」需要核对单独写一条「≥ 某值即结束」,等于在服务端重造一条致命轴;
- 「圆回来」是往回补的动作,累积轴的叙事语义(纯积累)与之不合。

### 方案 C:底细做致命消耗轴,立功与露馅同回合落数(露馅做法Ⅰ,本 ADR 采纳)

Felix 2026-11-12 选定。

**优点**:
- 引擎已有的触底兜底与结局极性 gate 直接覆盖「请来了道士」,核对只是让它在第 22 回合的判表里先到一步;
- 「现代招数 = 摊本涨、底细跌」在同一回合同时落数,玩家每次选择都看得见交换;
- 底细的三档正好对应三种街坊反应,叙事跟着档走,不卡选项(CONTEXT §三.14 bands 只染叙事)。

**缺点**:
- 致命轴意味着这个轻松世界也能「死」;以「请来了道士」这种荒诞结局承接,不写成惩罚(决策 4)。
- 立功、露馅、圆回来三条数字都靠提示词落(已知代价 1)。

## 最终决策

**方案 C — 底细做致命消耗轴**,其余按 §三.18 单体编排落地。

### 1. 世界与名称

- **单体,浮世**。卡面题材名(`displayName`)「**穿越古代**」;游戏内世界名由 `fixedWorldTitle`「**七日开张**」服务端覆写。
- **archetype id = `time_travel`**(建议,待审)。理由:① 现有 id 一律是**题材名**而非世界名(`cyberpunk` 之于《派单》、`life_sim` 之于《寻常》),世界名另由 `fixedWorldTitle` 固定;② 题材的核心是「穿越」,「古代」只是落点;③ snake_case 英文(CONTEXT §三.3)。
  代价:`time_travel` 比「穿越古代」宽,将来若有「穿越到未来」的世界,两者会争同一个 id。替代写法 `ancient_transmigration` 更窄但更长。由 Felix 定。
- 朝代不命名,只叫「**本朝**」;规模压在**县城以下的一条街**;地名全部虚构。

### 8. 题材边界(本世界指令槽,比公共【现实边界】更严;world-gen 与回合两个槽都写)

- 不引用任何真实诗文;
- 不预言、不借用真实历史;
- 不出现真实朝代、年号、都城、官制专名(官职只用通称);
- 不写朝堂、皇帝、官场;
- 不写火药、炸药、毒药等的制法;现代知识只限**生活、经营、卫生、算术、说话方式**;
- 不用时事梗或出自真人的梗;
- 不写体罚(改罚扫、罚站);
- 主角是成年人,不写婚恋线;
- 模式名「穿越古代」只是分类标签,不写进任何玩家可见文字(勘察 2)。

**是否加真实朝代 / 年号禁词表**(world-gen 世界专属检查),代价如实,由 Felix 定:

- **单字表不可行**:「汉」「唐」「宋」「明」「清」会命中「汉子」「宋体」「明天」「清水」,修复与 ERROR 会被误伤打满。
- **多字表可做但必然不全**:「唐朝」「大明」「贞观」「开元」「康熙」「长安」「汴京」「尚书省」…… 只能拦写得最直白的,改写式漏网照旧;表要维护,每多一项就多一次误伤可能(如「长安」作吉祥话)。
- **只拦 world-gen,不拦回合**:回合侧没有拦截层,ADR-004 流末扫描是遥测不拦截,也不扫政治与品牌词(ADR-037 §三.19 已记)。21 个回合的风险面远大于一次 world-gen。
- **命中的代价**:多一次修复调用(花钱),修复仍败 → 整局 ERROR(§三.11),玩家看到「重新生成」。
- **建议**:首刀不做禁词检查,靠指令槽的提示词约束;冒烟中若真的出现真实朝代名,再按出现过的词做窄表。

### 关键理由

1. **全部机制都有先例**:时段与状态行注入、结局核对、world-gen 专属检查、跨档台词,四件都是《派单》验通后立字的 §三.18,本世界只是第二个使用者 —— 新东西只有内容。
2. **引擎、校验、schema 一行不动**:新 id 只进 registry 与类型声明;致命轴、gate、触底兜底全是现成行为。
3. **不先抽象**:两份核对并排存在,改一处不会误伤另一处;重复的代价(约 45 行)写清楚,第三个使用者出现时再判断。
4. **把易错的交给服务端**:时段、结局、跨档这三件冒烟里模型稳定出错的事(ADR-035、ADR-036 四次订正),一开始就由服务端判,不再等冒烟失败后补。

## 已知代价

1. **经济数字靠提示词落数,未经冒烟**:进货 −8、立功代替营业收入、圆回来同回合 −3 且不营业,都是 F-038 的同类风险 —— 模型可能不扣进货、或立功回合仍加营业收入。缓解:数字同时写进回合指令与 `behaviorHint`,加「不得大幅偏离」;冒烟读 issues 与摊本轨迹核。
2. **底细 1–10 而摊本 < 60 落到中性结局**:是**有意沿用**《派单》「差一点不降级」的先例(ADR-036 订正四),不是漏判。读法乙下摊本 ≥ 60 的那格也落中性(决策 4)。
3. **「夜集第一摊」在中位数上窗口很窄**(决策 3 经济粗算):约 6 次立功且别无底细损失。若冒烟显示几乎打不出,先调数字,不改机制。
4. **核对代码重复**:`QiriEndingCheck` 与 `PaidanEndingCheck` 有约 25 行私有小函数逐字重复,`EventLoopService` 守门再重复约 20 行。缓解:不抽象,等第三个单体核对出现时判断(挂账)。
5. **`displayName`「穿越古代」进提示词**:「古代」可能把模型往真实朝代上带。缓解:两个指令槽写明模式名只是标签,并写决策 8 的朝代禁令。
6. **致命轴进了浮世世界**:轻松世界也能「结束」。缓解:用「请来了道士」这种荒诞收场承接,description 不写惩罚。
7. **题材边界只是提示词约束**(同 ADR-037 已知代价):回合侧没有拦截层;若不做禁词表(决策 8 建议),world-gen 侧也没有。
8. **前端未登记期间走中性外观**(勘察 16):卡面、局内都没有本世界的视觉,直到前端轮。

## 重新审视的触发条件

- 冒烟中「夜集第一摊」在多局里都打不出,或「城中怪点子王」成为绝大多数结局 → 回到决策 3 调数字。
- 冒烟中模型稳定不扣进货 −8、或立功回合重复加营业收入 → 考虑像《派单》【腿况】那样加一行按回合注入的提醒,或改由服务端落进货。
- 冒烟中出现真实朝代 / 年号 / 诗文 → 按出现过的词做窄禁词表(决策 8)。
- 第三个单体世界需要结局核对 → 判断是否把两份核对的公共部分抽出来(已知代价 4)。
- 浮世计数到 3 后,立字二的判断结论(审定清单第 9 项)。

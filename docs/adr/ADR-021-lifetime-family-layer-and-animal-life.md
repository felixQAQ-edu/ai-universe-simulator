# ADR-021 · 一生制族层抽取(补上「族」这一层)与第二个实例《动物人生》

- **日期**:2026-08-14
- **状态**:已采纳
- **决策者**:Felix

## 背景

ADR-020 发明了一套**族级抽象**:「一生制」是第一个具名族,一局覆盖完整生命周期、回合密度非匀速,
后续动物人生 / 校园青春 / 穿越古代同族。ADR-020 §1 逐字写着「共享族级约定(本节与 §2),
**不共享具体切分表**」,并把「第二个一生制世界上架时检验族级约定是否真的可复用」
写进了自己的[重新审视的触发条件](ADR-020-lifetime-world-family-and-ordinary-life.md)。

**本 ADR 首先是来兑现那条触发条件的,其次才是加一个世界。**
《动物人生》在这里的角色是**验证载体**,不是主角 —— 顺序写清楚,是因为它决定了刀次:
先补抽象、再加世界,而不是一边加世界一边顺手抽象。

### 勘察发现:ADR-020 §1 被证伪了一半 —— 缺的不是原则,是存放原则的那一层

勘察的结论**不是**「族级原则不能复用」。原则本身是对的、也确实通用。
问题在于:**代码里根本没有「族级」这一层**。三份证据,逐条实测:

**证据一 · 三条族级原则全在世界层,骨架零承载。**
「不显示岁数」「重要的事不给专门回合」「最后一回合是活着的」——
这三条对**族内每个世界都成立**(动物同样不该报岁数、同样不该给「重要的事」专门回合、
同样是走完了而不是耗到零),但它们今天**一条都不在骨架里**,全部躺在
`TurnPromptBuilder.TURN_DIRECTIVES` 的 `life_sim` 那一项里
(`TurnPromptBuilder.java:202` 绝不显示岁数 / `:214` 铁律第 5 条)。
骨架段落对这三条**零命中**(已 grep 实测)。

**证据二 · 已经在各抄一遍了,而这还只有一个世界。**
「最后一回合是活着的」这条,今天**在两个槽里各写了一遍,且逐字相同**:

| 位置 | 原文 |
|---|---|
| `WorldGenPromptBuilder.java:263` | 老死不是生命力耗到零,是故事走完了而你还剩一点;耗到零的是意外与病,那才是早逝 |
| `TurnPromptBuilder.java:240` | 老死不是生命力耗到零,是故事走完了而你还剩一点;耗到零的是意外与病,那才是早逝 |

**第三份拷贝在 Java 里**:`EventLoopService.java:299` 的 `VIGOR_KEY = "vigor"` —— 同一条原则的
引擎侧兜底实现,把轴名写死成了《寻常》的那一个。

**一个世界、三份拷贝。** 这正是 ADR-008「安全规矩全在骨架、绝不 per-mode 重抄」要防的东西,
而 ADR-020 的槽注释里其实已经写了「凡是多个世界共用的指令一律回骨架」——
**规矩写了,但没有地方可以「回」**:骨架是全世界共用的(动物不能读到人的年龄段),
世界层是 per-world 的,而族级的东西两头都不属于,于是只能留在世界层。

**证据三 · 时钟本身是人类专有的。**
`LifeStage` 是 enum,七个常量把人类年龄段(`0–6 岁` / `19–30 岁` / `31–55 岁`…)写死在**枚举值**里。
`values()` 是**类级单例** —— 这不是代码风格问题,是**它在语言层面就做不成 per-archetype**:
一个 JVM 里只有一份 `LifeStage.values()`,不可能同时是人的表和动物的表。

### 勘察发现:两处与 brief 读数不符(以现测为准,如实记)

1. **`ArchetypeRegistryTest` 会变红的计数断言在 `:175` 而不是 `:158`。**
   `:175` 是 `assertThat(registry.activeMetas()).hasSize(5)`;`:158` 是
   `knownEnumCoversContextSection34AndCthulhu`,它遍历一个固定清单断言 `isKnown`、
   **不断言穷尽**,故加一个世界**不会让它变红**(动物人生仍须进 `KNOWN`,但那是实现动作、不是测试改动)。
   完整红点是四处:`:63`(`containsExactly` 目录顺序)、`:65`(`subList(0,5)`)、
   `:72`(`subList(5,6)`)、`:175`(`hasSize(5)`),外加 `ArchetypeControllerTest:27`(`hasSize(6)`)与其下两条
   `containsExactly`。**全部是数量类,照改**。

2. **`LifeStage.*` 的测试引用是 53 处(39 行,分布在 3 个文件)**,brief 记的是「40+ 处」——
   量级一致,精确数记在这里供刀 2 估工:`LifeStageClockTest` 22 / `ExitFeedbackAndVigorFloorTest` 14 /
   `LifeExitActionTest` 3(按 `grep -o` 计 53 次出现)。

约束条件:

1. **《寻常》的 prompt 必须逐字节零回归** —— 族层抽取是纯重构,提上去之后拼接结果不变。
   这是刀 1 唯一的验收硬线(§4.5.1 同族的 parity 三件套)。
2. **四个既有世界 + 两个融合组合的 prompt 零回归**,`schemaVersion` 保 `"0.4"`,golden 零动。
3. **不动引擎结算序列**(见立字四:「身子」的不可逆机制被明确降级,理由入档)。
4. **《寻常》五条待回看项不在本 ADR 范围**(F-022 / F-023 / F-026 / 回合数超上界 / F-024),
   本 ADR 只提供对照样本,不修它们。
5. 第一版**不做专属皮肤**(同 ADR-020 裁定一,走既有四条降级路径)。

## 候选方案

### 甲组 · 族级原则放在哪

#### 方案 A:继续留在世界层,动物人生把三条抄一遍

**优点**:
- 零结构改动,刀 1 直接跳过,今天就能开始写动物人生。

**缺点**:
- **它正是勘察发现的病,不是解法**:一个世界已经三份拷贝,两个世界就是六份。
- 拷贝之间**会各自漂移**,而漂移的方向恰恰是「某个世界改了、另一个没改」——
  这类失效**没有任何测试抓得到**(两份都是合法字符串,parity 只保证「和上次一样」)。
- ADR-020 §1 的族级立字会**退化成一句文档里的话**:代码里不存在的层,等于不存在。

#### 方案 B:三条提进骨架(全世界共用层)

**优点**:
- 单点维护,不必新开一层。

**缺点**:
- **对四个既有世界是错的**:规则怪谈没有「岁数」可言,末日不存在「最后一回合是活着的」。
- 一旦进骨架,四个世界的 prompt **当场破 parity**,且要为它们逐一加「本条不适用」的例外——
  例外一多,骨架就从「全世界共用」退化成「一张带 if 的表」。

#### 方案 C:两个 builder 各开一层 family directive(本 ADR 采纳)

**优点**:
- **判据可数**(见立字二),后续世界照用不必再讨论。
- 族层为空 = 现状,四个既有世界逐字节不变是**构造保证**(同 ADR-020 两个槽的缺省空串证法)。
- 与 ADR-014 per-combo 槽、ADR-020 per-archetype 槽**同形第三次** —— 不是新范式,是既有形状再用一次。

**缺点**:
- prompt 拼接从两层变三层,读代码要多跳一次。接受:三层的层次含义是清楚的
  (全世界 / 族 / 世界),比「两层 + 每个世界各抄一遍」好读。

### 乙组 · `LifeStage` 怎么变成 per-archetype

#### 方案 D:加一个 `AnimalLifeStage` 枚举,调用处 if 分派

**优点**:
- 改动局部,不动现有 `LifeStage` 一个字。

**缺点**:
- **把世界判定复制进了通用层** —— 与 ADR-018 §4.1「世界判定只发生一次」正面冲突,
  而刀 1 花整整一刀才把散在五处的 archetype 分派收编进注册表。
- 第三个一生制世界来时是第三个枚举 + 第三个分支。

#### 方案 E:`LifeStage` 由 enum 改为**可替换的常量表**,按 archetype 查表(本 ADR 采纳)

**优点**:
- 从根上解决 `values()` 是类级单例的问题。
- 《寻常》的现有七段**原样成为「第一张表」**,行为零变化 → 刀 2 可独立验证。
- 出口措辞随表走,自然解掉「出口措辞与 `LifeStage` 成员结构耦合」这条(见立字六)。

**缺点**:
- 波及 53 处测试引用与三处接缝(表本身 / `TurnPromptBuilder` 的 8 参 format 契约 /
  `EventLoopService` 两处)。接受:**多数是《寻常》口径的断言,属该改而非回归**,
  但仍须逐条报处置(同 ADR-020 刀 1 的数量类/行为类二分)。

### 丙组 · 《动物人生》的「身子」要不要做成「上限只降」

#### 方案 F:实现真正的不可逆上限(引擎级)

**优点**:
- 语义最准:动物的身体损伤确实回不去,这是这个世界的核心体感。

**缺点**:见立字四,四条理由逐条否决。

#### 方案 G:降级为 `behaviorHint` 里的措辞约束(本 ADR 采纳)

**优点**:
- 零引擎改动、零 golden 重录,与本 ADR「先补抽象」的主线不抢刀。

**缺点**:
- **模型不遵守时没有任何东西拦得住** —— 这是真代价,已挂账,见立字四。

## 最终决策

### 立字一 · ADR-020 §1 就地订正(改正文,不是补记)

`ADR-020` §1 第 153 行原文:

> 后续**动物人生 / 校园青春 / 穿越古代**均属此族,共享族级约定(本节与 §2),不共享具体切分表。

**订正为**:族级可复用的是原则,**且原则必须有独立的存放层**;
没有那一层,原则会退化成**每个世界各抄一遍**。

⚠️ **就地订正,两个口径不得并存**(同 ADR-020 §2 刀 5 那次的做法)。订正块须写明证伪经过:
三条原则全在 `life_sim` 槽内骨架零承载 / 「最后一回合是活着的」已在两个槽里各写一遍
/ 第三份是 `EventLoopService` 的 `VIGOR_KEY = "vigor"` —— 而这**还只有一个世界**。

⚠️ **立字二本身没写错,它缺的是一个落地形态。**
这句必须写进订正块 —— 免得后来者读成「族级抽象整条被推翻」。
被证伪的是「有原则就够了」这个隐含前提,不是原则本身。

### 立字二 · 三层结构:骨架 → 族 → 世界

两个 builder(`WorldGenPromptBuilder` / `TurnPromptBuilder`)各开一层 family directive。
**拼接顺序固定为:骨架 → 族 → 世界。**

| 层 | 收什么 | 缺省 |
|---|---|---|
| **骨架** | 全世界共用:叙事清洁度 / 长度 / 状态档 / 输出格式 | 恒非空 |
| **族** | 一生制公共:不显示岁数 / 重要的事不给专门回合 / 最后一回合是活着的 / 时钟契约 | 空串 |
| **世界** | per-world:切分表、写作标准、结局池、出口措辞 | 空串 |

**判据(可数,供后续世界照用)**:

> **一条指令若对族内每个世界都成立,它属族层;只对一个世界成立,属世界层。**

判据刻意做成**可数**而非内容型(「这算原则还是设定」),理由同 ADR-020 §10 补记那条
「读几次」判据:内容型判据会立刻退化成各人各判,三层随即长成同一个杂物抽屉的三份拷贝。

⚠️ **族层为空 = 现状**:四个既有世界与两个融合组合的 prompt 逐字节不变是**构造保证**,
不是「没写错就不会变」;`%s` 挂位须照 ADR-020 那两个槽的教训 —— **挂末行行尾,不得独占一行**
(独占一行时空串会多留一个换行,parity 当场破)。

⚠️ **文档侧同源空位,一并记明**:族级写作标准**目前没有存放位置**——
`docs/world-ordinary-life-writing-standards.md` 是 **per-world** 的(文件名即口径)。
本 ADR 只记录该空位;**是否在刀 1 一并补一份族级文件,由刀次切分决定**(见实施步骤刀 1)。
不先记这一条,族层的真理源会重蹈「两处不得漂移」那种靠注释维系的约定。

### 立字三 · `LifeStage` 参数化

**根本原因写清楚,免得被读成风格偏好**:enum 的 `values()` 是**类级单例**,
一个 JVM 里只有一份;七个常量又把人类年龄段写死在枚举值里。
**这是它在语言层面就做不成 per-archetype 的原因**,不是「写得不够优雅」。

要动的**三处接缝**(已勘察定位):

1. **表本身** —— `LifeStage` 由 enum 改为可按 archetype 查的常量表;《寻常》七段成为第一张表。
2. **`TurnPromptBuilder` 的 8 参 format 契约** —— `archetypeTurnDirective` 现以
   `(nextTurn, label, ageRange, advanceClause, CONVERGE_FROM, CONVERGE_TO, FINAL_STAGE_FROM_TURN, EXIT_ACTION_ID)`
   八个参数 format 世界层模板;表参数化后这组参数须随表走。
3. **`EventLoopService` 两处** —— `appendLifeExitAction`(`:254`)与 `clampClosingVigorFloor`(`:322`),
   两者都读 `LifeStage.of(...)` 与 `LifeStage.FINAL_STAGE_FROM_TURN`。

⚠️ **同批修 `VIGOR_KEY = "vigor"` 硬编码**(`EventLoopService.java:299`)。
**动物人生的致命轴不叫 `vigor`,该兜底对它静默不生效。**
「静默」是这条的关键,不是修辞:代码编译过、测试全绿、`stateUpdate` 里没有 `vigor` 键
于是 `clampClosingVigorFloor` 直接 return —— **没有任何一处会报错**。
同族的还有 `LIFETIME_EXIT_ARCHETYPES = Set.of("life_sim")`(`:358`):不扩它,动物局根本不出现出口。
两条都属「加世界时忘了改就静默失效」,与 ADR-018 §4.11 那一族(「谁在什么时候重新启动它」没有答案)
形状不同但后果相同 —— **失败方式是安静的**。

⚠️ **未参数化时最刺眼的现形方式,记下来当刀 2 的验收探针**:
prompt 里会出现动物处在「31–55 岁」。

### 立字四 · 「身子」的不可逆降级为措辞约束(记账,不是妥协)

**裁定:不做「上限只降、当下可回到上限」的机制。** 四条理由逐条入档:

1. **引擎里不存在「上限」这个概念。** `AttributeAxis.max` 的四个读者
   (`WorldGenPromptBuilder:614` 拼提示词 / `GameInitService:168` 投影 DTO bands /
   `AttributeAxis:266` 算 bandRange / `ArchetypeRegistry:244` 构造)**全是描述与投影**;
   真正落账的是 `Engine.java:634` 里写死的 `Math.max(0, Math.min(100, x))` ——
   **引擎拿不到轴元数据**(守 ADR-008 数值语义无知,那是特性)。
2. **它需要一个 per-轴、跨回合、会变、必须落盘的第二个数** →
   引擎 / 校验 / schema / 落盘格式**四处都要开位置**(ADR-015 §三.17 落盘七字段亦须动)。
3. **大概率是《寻常》以来第一次动 `Engine.apply` 的结算序列** → **golden 必须重录**,
   而 golden 逐字节 parity 是本项目最重的一条护城河。
4. **走软约束亦不成立**:F-025 立的通用判据是「软约束要挂在模型每回合已经拿得到的东西上」,
   而**上限值不在 `snapshot()` 里**(实测:`snapshot()` 只投 attributes 当前值 / turn / status /
   timeline / logSummary / log)—— **模型看不见它**,挂上去就是第二次犯 F-023 那个错。

**处置**:「身子」按普通 `depletion` + `lethal=true` 登记,不可逆写进 `behaviorHint`:
**回升幅度必须远小于降幅,且不得回到历史最高。**

⚠️ **明写「损耗不可逆的机制未实现,当前只有措辞约束」并挂账。**
解冻条件:**当第三个一生制世界也需要它时再开。**

> **立字:一个世界要的机制不开引擎,两个世界要的才开。**

理由与 ADR-018 §4.17「差异只在样式 → 加 class 令牌;差异在 DOM 结构 → 才开组件槽」同形:
**门槛必须是可数的**,否则每个新世界都会带着一个「这次真的需要」的机制申请。

### 立字五 · 三条结构约束(从创意稿提取的**结构**,不是文字)

创意稿另存,本 ADR **只引用不复述**。以下三条是从中提取的**可验收结构约束**:

**(1) 末段所有分支的最后一个可玩回合都落在某个楼道口。**
兑现方式:选了「走回那栋楼」与选了「找新的地方」的玩家,读到的是**一模一样的一句话**——
分支改变了一切,一个字没改。这是「走回去了」标 `neutral` 的模糊在文字上的落地处。

**(2) 失效排期爬坡:金属声第 2 级(外面早期)必须排在规则二失效之前。**
代价序列须是:**零(头放下去) → 掉身子(伸手那次) → 处境变坏(叫那次)**。
若先被打了再抬头,那次抬头就读成了「它还没长记性」,
而不是「**这条规则本来就不管用**」—— 后者才是这个世界要说的话。

**(3) 动词分区:「推」封在屋里与断裂段,外面段永不出现。**
外面是**踢**、是**砸**、是**手落下来的地方不对** —— **别的种类**的接触,不是同一种的加强版。
种类不同,**前震不会吃掉主震**。

### 立字六 · 复用率读数(本 ADR 的首要产出)

ADR-020 [重新审视的触发条件](ADR-020-lifetime-world-family-and-ordinary-life.md)要的就是这张表。
**逐项记实测,不记预期**:

| 判定 | 项 | 实测依据 |
|---|---|---|
| ✅ **真通用** | 两个指令槽机制 | 缺省空串 + 挂末行行尾,四世界零回归已由 ADR-020 刀 2/刀 3 实证 |
| ✅ **真通用** | `exitAlreadyPressed` | 硬信号取自**玩家选过的动作 id 本身**(`playerAction` / 折叠后的 `选X`),跨压缩、跨续局、跨 redeploy,不依赖任何世界语义 |
| ❌ **人类专有** | `LifeStage` | 七个常量把人类年龄写死在**枚举值**里,`values()` 类级单例 |
| ❌ **槽内独占** | 三条写作原则 | 全在 `life_sim` 槽,骨架零承载(本刀修为族层) |
| ❌ **结构耦合** | 出口措辞 | 是 `LifeStage` 的**成员**与 static 单例(`EXIT_HINT` / `EXIT_TEXT_AFTER` / `EXIT_HINT_AFTER`),不是可替换常量表 |

⚠️ **勘察补充一 · 加世界的代价读数要如实写成「后端一条 + 前端一行」。**
`web/src/types/schema.ts` 的 `Archetype` 联合类型**必须加一行**(`:16` 现有 `'life_sim'`)——
这是**《寻常》以来第一次「加世界必须碰前端」**;ADR-020 刀 1 的「前端零改」
是**复用既有灰显占位**的收益,不是加世界的常态。不订正这一条,F-016 成本模型会被读窄。

⚠️ **勘察补充二 · 隐藏耦合单独记**:`archetypeTurnDirective`(`TurnPromptBuilder.java:167`)里
`LifeStage.of(nextTurn)` 在 `template != null` 之后**无条件执行** ——
即它对**任何注册了回合指令模板的 archetype** 都会跑,gate 在「有没有模板」而不在「是不是一生制」。
**槽是通用的,但槽的填充管道被焊死在《寻常》的时钟上**:
将来任何非一生制世界想用这个槽,都会被迫走 `LifeStage` 的 8 参 format。

### 关键理由

1. **本 ADR 首先在还 ADR-020 自己挂的账。** 触发条件写的是「检验族级约定是否真的可复用」,
   而诚实的答卷是「原则可复用,但没有地方放」——**先补层再加世界**,顺序不能反:
   反过来做,动物人生会先抄一遍三条原则,然后再也没人回头抽象。
2. **复用了三次同形的槽机制**(ADR-014 per-combo → ADR-020 per-archetype → 本 ADR 族层),
   缺省空串 + 挂末行行尾 + parity 三件套,是既有肌肉记忆而非新范式。
3. **避开了「静默失效」这个本项目已摔过多次的坑**:`VIGOR_KEY` / `LIFETIME_EXIT_ARCHETYPES`
   两条硬编码在刀 2 一并解掉,而不是等动物人生冒烟时才发现兜底没生效
   (同 runbook §3.1.5 / §3.1.6「先证明环境是你以为的那个」)。
4. **保留演进路径**:族层为第三、第四个一生制世界预留;「身子」不可逆的解冻条件写死为
   「第三个世界也需要」,机制留在门外但门有钥匙。

## 已知代价

1. **刀 1 是纯重构,对玩家零可见收益。** 一整刀下来 prompt 逐字节不变、没有任何新东西能玩。
   接受理由:它是唯一**不依赖新世界就能独立验证**的改动,而抽象层的正确性只有在这种
   隔离条件下才验得干净;混进刀 3 就再也分不清「族层对不对」与「动物世界好不好」。
2. **`LifeStage` 参数化波及 53 处测试引用。** 缓解方式:多数是《寻常》口径的断言,
   属**该改而非回归**;仍按 ADR-020 刀 1 的**数量类/行为类二分**逐条报处置,行为类一条不许删。
3. **「身子」的不可逆机制未实现,当前只有措辞约束。** 模型不遵守时没有任何东西拦得住,
   而这恰恰是《动物人生》核心体感的一部分。缓解方式:写进 `behaviorHint`(模型每回合拿得到,守 F-025);
   已挂账,解冻条件见立字四。**不假装它没风险 —— 冒烟须专门看这一条。**
4. **三层拼接使 prompt 结构更难一眼读完。** 接受:层次含义清楚(全世界 / 族 / 世界),
   且判据可数;代价小于「两层 + 每个世界各抄一遍」。
5. **本 ADR 不修《寻常》五条待回看项。** 它们仍未解决,动物人生只提供对照样本。
   接受理由:F-027 立的字是「可玩性是验证能力的前置」,而《寻常》调优已收手 ——
   在同一个世界里再调一轮,得到的仍是这一份文本的方差。
6. **加世界首次必须碰前端**(`schema.ts` 一行)。接受:一行,且它是类型安全的收益不是负担。

## 重新审视的触发条件

- **第三个一生制世界(校园青春 / 穿越古代)上架时**:检验族层是否真的只需「加一张表 + 一段世界层指令」;
  若届时又出现「三条原则里有一条不适用」,说明族层收的东西多了,须再切一刀。
- **第三个一生制世界也需要「损耗不可逆」时**:按立字四解冻,开引擎级上限机制
  (届时须自己的 ADR:引擎 / 校验 / schema / 落盘四处 + golden 重录)。
- **动物人生冒烟后**:若族级三条原则在动物世界里读起来别扭(尤其「重要的事不给专门回合」),
  说明它其实是《寻常》专有,须退回世界层 —— **这正是第二个世界存在的意义**。
- **出现第一个非一生制世界想用回合指令槽时**:立字六勘察补充二那条隐藏耦合会当场现形,
  须把 `LifeStage` 从槽的填充管道里摘出去。
- **CONTEXT §三.16 (7) 解冻**:见下方裁定二。

## 四项裁定(Felix 已拍板,记明不再讨论)

1. **《寻常》待回看是五条,不是三条。** 完整清单:**F-023**(热望下降不稳定)/ **F-026**(单回合体量失控)
   / **回合数超上界** / **F-022**(气力在收束段静止)/ **F-024**(模型看不见自己被否决)。
   后两条与前三条同批、由勘察补入 —— **漏账就是账记丢了**。本 ADR 不改其中任何一条的状态。
2. **CONTEXT §三.16 (7) 本刀不解冻**,待**动物人生冒烟通过后**再判。
   理由:现在只是「第二个世界开工」,不是「两个世界都验通」;
   循 ADR-013 / ADR-015 先例(待验通再立字,不写空头约定),
   亦与 ADR-020 §1 那条 2026-08-10 复审的口径一致。
3. **[world-catalog](../world-catalog-and-experience-modes.md) 的「首批推荐(建议,Felix 未拍板)」由本 ADR 兑现。**
   该文件推荐的是「人生模拟 + 动物人生」,理由是两者同为一生制、第二个用来验第一个的骨架能否复用——
   本 ADR 即是那条建议的落地,措辞须呼应而非另起一套。
4. **体验分类 = 浮世,只进文档不加字段。**
   world-catalog 立字五(分类是 per-world 元数据)仍成立:浮世侧上架后为 **2**,
   未达该文件「< 3 不建大厅」的阈值,故此刻加字段即死代码。

## 实施步骤

**三刀,顺序不可换。** 每刀一律:`schemaVersion` 保 `"0.4"`、golden 零动、
四世界 + 两融合 prompt parity 零回归、引擎与校验零动。

### 刀 1 · 补族层(不带任何动物人生内容)

**纯重构。** 把《寻常》现有三条原则从世界层槽内提到族层,两个 builder 各开一层。

- 骨架 → 族 → 世界 三层拼接;族层缺省空串,`%s` **挂末行行尾不得独占一行**。
- 顺带消除「最后一回合是活着的」的两份拷贝(world-gen 侧与 event-loop 侧各一)——
  按立字二判据,它对族内每个世界都成立,属族层。
- **文档侧空位**:一并建族级写作标准文件(`docs/lifetime-family-writing-standards.md` 或等价),
  `world-ordinary-life-writing-standards.md` 保留为 per-world 并加指针;
  两处 lockstep 守护照 ADR-020 刀 3 那条的形状(**先改文件再同步 prompt,不得反向**)。
- ⚠️ **对《寻常》prompt 必须逐字节零回归** —— 提上去之后拼接结果不变。

**验收**:parity 三件套(HEAD 构建与工作区构建各 dump 一次后 `cmp`;
六处 IDENTICAL 且哈希与 ADR-020 刀 3 记录的 baseline 逐位相同;
**《寻常》自身作正对照 —— 它必须也全等,故须另证两个构建确实不同**,见 ADR-018 §4.5.2)。
**变异验证三条**:族层被抽掉 / 拼接顺序颠倒(族与世界对调)/ 族层内容写进世界层 —— 各须变红。

⚠️ **这一刀可独立验证,是本批唯一不依赖新世界的改动。**

### 刀 2 · `LifeStage` 参数化 + `VIGOR_KEY` 解硬编码

仍不带动物人生。**《寻常》的阶段表原样成为「第一张表」,行为零变化。**

- 三处接缝按立字三逐一改:表本身 / 8 参 format 契约 / `EventLoopService` 两处。
- 同批解 `VIGOR_KEY = "vigor"` 与 `LIFETIME_EXIT_ARCHETYPES = Set.of("life_sim")` 两条硬编码
  (改为随表 / 随族登记走)。
- ⚠️ **53 处 `LifeStage.*` 测试引用会波及**,多数是《寻常》口径的断言 ——
  **属该改而非回归**,但仍须**逐条报处置**(数量类照改 / 行为类换等价断言继续守,一条不许删)。

**验收**:《寻常》prompt 与出口措辞逐字节不变;parity 三件套;
**变异验证**:把《寻常》的表换成动物表 → 出口措辞与阶段名当场全变(证明表真的可替换,
而不是「改了但没人读」)。

### 刀 3 · 登记《动物人生》

- `ArchetypeRegistry` 一条元数据(**archetype id = `animal_life`**,snake_case 守 CONTEXT §三.3;
  与《寻常》复用 `life_sim` 占位不同,本世界**无既有占位可复用**,故是新增枚举 →
  CONTEXT §三.4 枚举与 world-catalog A 档条目须同步)+ `web/src/types/schema.ts` **一行**(见立字六勘察补充一)。
- 四张表各一条:`SEED_POOLS` / `IMAGERY` / `TURN_DIRECTIVES` / `WORLD_GEN_DIRECTIVES` /
  `ENDING_COUNTS` / `LIFETIME_EXIT_ARCHETYPES`。
- **动物的阶段表**:屋里 14 / 断裂 3 / 外面 28(共 45 回合);出口措辞「趴下」。
  ⚠️ **切分表 per-world 不得跨世界复用**(ADR-020 §1:硬套人的段式会得到「毛茸茸的人」)——
  动物幼年极短、成年占绝大部分、多数动物没有老年。
- 「身子」按 `depletion` + `lethal=true` 登记,不可逆写进 `behaviorHint`(立字四)。
- **立字五三条结构约束**须在 prompt 里可验收(末段分支同句 / 失效排期爬坡 / 动词分区)。
- **体验分类 = 浮世,只进文档不加字段**(裁定四)。

**会变红的数量类断言(已勘察定位,照改)**:
`ArchetypeRegistryTest:63`(目录 `containsExactly`)、`:65`(`subList(0,5)`)、`:72`(`subList(5,6)`)、
`:175`(`activeMetas()).hasSize(5)`);`ArchetypeControllerTest:27`(`hasSize(6)`)及其下两条 `containsExactly`。
**`ArchetypeRegistryTest:158`(`knownEnumCovers…`)不受影响** —— 它不断言穷尽;
`cyberpunk` 仍在 `INACTIVE_DISPLAY_NAMES` 表内,**行为类反例(已知但未激活 → 400 未开放)不受影响**。

**验收**:四世界 + 两融合 parity 零回归(正对照 = 新世界自身);
《寻常》prompt 逐字节不变;真 key 冒烟另起一刀(不并入本 ADR)。

## 实际效果(事后补充)

*刀 1 收口时回填:《寻常》prompt 逐字节零回归的 parity 读数(六处哈希 + 正对照)、
消除的重复拷贝数、族级写作标准文件的落点。*

*刀 2 收口时回填:53 处测试引用的实际处置分布(数量类 / 行为类各几条)、
「换表即换出口措辞」变异验证的读数。*

*刀 3 收口时回填:**加第二个一生制世界的真实代价**(后端几处 + 前端几行 + 族层是否一字未改)——
这是 ADR-020 触发条件真正要的那个数,也是立字六那张表的事后校验。*

*动物人生冒烟后回填:族级三条原则在动物世界里是否成立(若别扭 → 退回世界层);
立字五三条结构约束是否兑现;「身子」措辞约束在无引擎保证下守不守得住;
以及 **CONTEXT §三.16 (7) 是否解冻**(裁定二)。*

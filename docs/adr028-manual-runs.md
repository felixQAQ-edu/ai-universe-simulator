## 一、本地起服务并接真模型

需要的环境变量(只列名字,值自己填,key 不进仓库、不进对话):

| 变量 | 用途 |
|---|---|
| `DEEPSEEK_API_KEY` | 真模型的 key |
| `AIUNIVERSE_LLM_ACTIVE` | 设为 provider 名 `deepseek-v4-flash`(不设 = 跑 mock,而 mock 不读 key —— 「key 设了」不构成接上真模型的证据) |
| `AIUNIVERSE_SESSION_STORE_DIR` | 落盘目录。不设时默认 `./data`,相对于起服务时的目录(在 `server/` 下起就是 `server/data`) |

命令(两个终端):

```sh
# 终端 1:后端(:8080)
cd server
export DEEPSEEK_API_KEY=...            # 自己填
export AIUNIVERSE_LLM_ACTIVE=deepseek-v4-flash
export AIUNIVERSE_SESSION_STORE_DIR="$PWD/data"
mkdir -p "$AIUNIVERSE_SESSION_STORE_DIR"
./mvnw spring-boot:run

# 终端 2:前端(:5173,/api 由 Vite 代理到 :8080)
cd web
npm install
npm run dev
```

起来以后先看后端启动日志里两行:`[session-store] 落盘目录 = …`(确认目录是你以为的那个),
`启动回载:载入 N 档 …`(下面第二节第 5 步要靠它确认夹具被载入)。

## 二、新开一局 → 派生夹具 → 续上这一局

1. 浏览器打开 `http://localhost:5173`,在选择屏新开一局《动物人生》(只花一次 world-gen 调用)。
   看到开场正文即可,**不必走任何回合**。
2. 找到这局的 saveId:浏览器开发者工具 Console 里执行
   `localStorage.getItem('aiuniverse.saveId')`。源存档就是 `server/data/<这个 saveId>.json`。
3. 派生夹具(仓库根目录下执行;原存档不改,输出一个新文件、新 saveId):

   ```sh
   python3 scripts/adr028_derive_box_fixture.py server/data/<源saveId>.json server/data
   ```

   成功时打印一行新的 saveId(记下来,下面叫 `<夹具saveId>`)。脚本拒绝时打印「拒绝:…」并且不写任何文件
   (没有局面键的旧局、局面已开始、不是《动物人生》、局已结束、回合号超过 10,都会拒绝)。
   两条短局各派生一次(同一个源存档跑两次,得到两个不同的 saveId),R1 用一个、R3a 用一个。
4. **重启后端**(终端 1 `Ctrl-C` 后再 `./mvnw spring-boot:run`;环境变量仍在)。
   夹具只在启动时被扫进内存,不重启就看不见它。
5. 看启动日志:「载入 N 档」应比上次多出派生的那几个,「拒载」应为 0。
6. 浏览器 Console 执行 `localStorage.setItem('aiuniverse.saveId', '<夹具saveId>')`,然后**刷新页面**。
7. 选择屏点「继续上局」。看到的是第 10 回合:正文可能为空或很短(夹具没有前 10 回合的叙事,只有开场时的选项),
   这是夹具的形状,不记作问题。

派生改了存档里的这几项(其余原样):`state.turn` → 10;`phaseHint` → `AWAITING_ACTION`;
`boxScene` → 新局初始状态(`g = 0`,未结算,无处境,无映射,无意图历史);文件名(saveId)换成新的。

## 三、两条短局的按键表

读表口径:「第 N 回合」= 屏幕上正在显示的那一回合。在第 N 回合按下某个选项,生成第 N+1 回合;
上一步选择的**反馈事实**写在第 N+1 回合的正文里,第 N+1 回合自己的**征兆**也写在同一段正文里。
「权威处境」是生成这一回合时会话里存的处境;结算当回合会写成新处境(表里写成「→」)。

| 回合 | 在这一回合按 | 本回合正文应写到的反馈事实 | 本回合正文应写到的征兆 | 本回合给出的 A / B / C | 权威处境 |
|---|---|---|---|---|---|
| 10(夹具) | 任选一个 | —— | —— | 开场时的选项(模型产出) | 无(纸箱之前) |
| 11 | **A**(跟着孩子 = FOLLOW) | —— | 屋里多了许多纸箱。纸板和胶带的味道盖住了原来的气味，孩子的玩具也被收了起来。 | A 跟着孩子 / B 钻进纸箱闻一闻 / C 回到平时趴着的地方 | 无(纸箱局面中) |
| 12 | **A**(跟紧孩子 = FOLLOW) | 孩子蹲下来摸了它一下 | 家具一件件被搬走。它平时趴着的地方空了，屋里的脚步声比平常多。 | A 跟紧孩子 / B 守在自己的碗旁边 / C 躲进床底 | 无(纸箱局面中) |

## 四、每回合的阅读检查清单

每生成一回合,对着上表那一行看:

1. 本回合的征兆或反馈事实是否写进了正文(表里写「——」的那一项不查)。
2. 正文与选项是否越出当前处境:EMPTY_HOME 写到屋外;NEW_HOME 写成离开新屋(已知代价 8)。
3. 是否出现「搬家」「遗弃」「收养」「被带走」「被留下」「不要它了」等解释词。
4. 选项是否恰好 A / B / C 三个。
5. 界面上【近人】的颜色是否为中性。
6. (只 R3a 第 18 回合)是否写出离开反馈,并且已经在门外。

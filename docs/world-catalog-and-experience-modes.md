# 世界目录与体验模式 · 浮世 / 深界

> 建档:2026-08-08。项目要从「一串不同题材的恐怖世界」扩为**通用世界生成模拟器**——
> 新增大量非恐怖世界,并按情绪分为两个体验入口。**本文件只立字与入档,不实现任何东西。**
>
> **先纠一个容易读反的印象**:恐怖不是这个项目的定义,只是**先落地的那批**。
> [ROADMAP §七](ROADMAP.md) 的「基础模式」一行从初版起就写着
> 「规则怪谈、**人生模拟**、修仙、**赛博朋克**、末日生存」——人生模拟与赛博朋克**本就在列**,
> 只是 MVP 选了规则怪谈开路,后续四个已激活世界(末日 / 克苏鲁 / 修仙 / 规则怪谈)
> 恰好都偏暗,于是「万界 = 恐怖游戏」成了一个**由落地顺序造成的误读**,不是设计。

> **为什么另起新文件,不并进 [世界库扩展 backlog](world-library-expansion-backlog.md)**:
> **旧文件按工程成本分级(做它要花多少钱),这份按情绪分类与体验入口(它是哪一侧、大厅怎么组织)——两条轴不同。**
> 两轴**正交**:人生模拟 = 第一级便宜 × 浮世;禁书库 = 便宜 × 深界;修仙 = 第二级 × 浮世。
> 合并会让其中一条轴被压扁(要么成本表里塞进情绪列、要么情绪表里塞进成本列,读的人只会用其中一列)。
> 故**分工写死、互不重复**:本文件的世界目录**只记世界与分类归属**,
> **成本一律交叉引用旧文件对应级别,不在此重述**。

> **为什么分两节、中间显式划死**:**立字与构想分节的意义是 provenance ——
> 防止某个构想被后来者读成已裁定的约束。** 第一节的每一条都已拍板、可被当作约束引用;
> 第二节是 Felix 提供的原始构想,**逐字保留但一律未裁定**,任何人不得据以主张「这已经定了」。

# 第一节 · 已立字(可作为约束引用)

## 立字一 · 体验模式只作用于大厅,不进局内

**`experienceMode`(浮世 / 深界)只在大厅侧成立。进局之后,视觉真理源是世界自己的主题注册表。**

- **形状上同 [ADR-019](adr/ADR-019-fusion-visual-entry-and-composability.md) §1「入口互噬,局内单主语」**
  (交叉引用,不复述):那条讲的是**融合的两个世界**在入口可以互噬、进局只留一个主语;
  这条讲的是**两个体验模块**在大厅可以有各自的行为语言、进局交回世界自己。同一个形状的第二次实例化。
- **真正要防的不是组件复制,是视觉真理源从一处变成两处。** 模式层若跟进局内,
  [ADR-018](adr/ADR-018-base-world-visual-migration-and-severity-contract.md) §4.1
  「**世界判定只发生一次**」当场退化为两处判定(先判模式、再判世界),
  而那正是刀 1 花整整一刀收编 `scene.ts` 封面分派与 `ArchetypeSelect` 私有 `vibeClass` 要消灭的东西。
  收编掉的两处判定不该以「模式层」的名义回来。

## 立字二 · 先做世界,不建大厅

**浮世侧世界数 < 3 之前,不启动大厅分区。**

- **空大厅会倒逼赶工填充,顺序反了。** 先建两个入口,就等于给自己派了一个「把浮世侧填满」的任务,
  于是世界为了填格子而做——这与[世界库 backlog](world-library-expansion-backlog.md) 的纪律
  「宁可 3-4 个让人反复玩,不要 14 个平庸」是同一条。
- **分区应在它自己站得住时出现**:当一个列表里同时躺着轻松世界与恐怖世界、**玩家感到割裂**时,
  分区就不再是设计问题而是**压力**问题——那时才知道它要被建成什么样(第二节 (4) 的三种产品结构
  A/B/C 之所以现在无法裁定,正是因为还没有这个压力)。

## 立字三 · 命名已定(非待定)

**浮世(轻松娱乐)/ 深界(恐怖惊悚)。品牌仍为「万界」。**

**选定理由:它命名的是「情绪轴」而非「亮度轴」。** 以亮度命名(白昼 / 午夜)会把实现引向
「换个背景色」,而分区真正要区别的是**行为语言**——页面呼不呼吸、反馈延不延迟、
卡片是浮起还是封存(见第二节 (1) 那张九行对照表)。**名字是有引力的,你会得到你命名的那个东西。**

**落选候选记录在案**(记下来是为了防止日后有人「重新想到」它们):

| 候选 | 落选理由 |
|---|---|
| 白昼 / 午夜 | **亮度引力**——会把两个模块的差异实现成配色差异,行为语言层无人负责 |
| 游乐场 / 禁域 | 产品化足够,但**世界观弱**,与「万界」这个品牌接不上 |

**顺带记为视觉候选(不裁定、不排期)**:「浮 / 深」**自带方向语义**——浮世上浮、深界下沉。
若日后做跨模块融合入口视觉,**方向性无需另行定义**,可直接接现有碎解材质与世界核系统
([ADR-019](adr/ADR-019-fusion-visual-entry-and-composability.md) §2/§3)。此条与立字四的视觉候选是同一件事的两面。

## 立字四 · 跨模块融合不是免费的

**跨分类融合(浮世 × 深界)仍是一个必须被手写出来的融合世界。分类差异本身不产生内容。**

- **口径同 [ADR-019](adr/ADR-019-fusion-visual-entry-and-composability.md) §挂账「融合方向的可发现性」
  对反向组合的立字**(其方向语义见该 ADR §5;交叉引用,不复述):
  它要**新 worldview 融合 / 新轴合并 / 新守则形态 / 新结局**,**得被写出来才能存在**。
  「一个浮世 × 一个深界」这件事本身,不比「两个深界」多产出任何一个字。
- **但入口视觉是免费的那部分**:「**昼夜边界被亲手撕开**」是现有四套碎解材质与世界核系统的
  **自然延伸,不新增资产维度**(仍是 O(1) 材质覆盖 O(N²) 组合,守 F-016 成本模型)。
- **两者分开记账**:视觉候选(便宜、可复用)与内容成本(每对都要手写)**不得合并成一条乐观估算**。

## 立字五 · 分类是 per-world 元数据,融合可改变分类

**体验分类挂在每个世界自身,不由 archetype 家族继承。**

- **融合世界的分类由其自身情绪决定,不跟随 host。** 例:修仙(浮世)× 克苏鲁(深界)=
  「飞升是捕捞」,**归深界**——host 是修仙,但那个世界的情绪不是修仙的。
- **推论(要执行的那句)**:此后**每个新世界登记时都须回答「属于哪一侧」**,含融合世界。
- **现状:零成本,先占位。** 大厅未建、融合世界仅两个(识海遗蜕 / 守则即补给),
  现在立这条不花任何东西;等到有二十个世界再回头补分类,才是贵的。

## 立字六 · ARCHIVE 档案形态与已冻结的融合入口构图,几何上不兼容

> 本条描述的是第二节 (2) 那个**构想**的成本,但它**本身是关于已冻结产物的事实判断**,
> 不是提案,故立在第一节。

第二节 (2) 的「深界侧世界入口作 ARCHIVE 档案条目」若实施,**替换**的是已上线的四世界专属选择卡
(刀 1–刀 4 产物,2026-08-07 已随正式发布上线)。受影响的**不是**刀 1 局内屏那批真机结论
(OLED 亮度 / 字号行距 / 触控热区 / 滚动 / 地址栏伸缩 / 后台恢复 / 连续回合——**多在局内**),
而是下面三块:

1. **选择屏侧的取证基线**:[ADR-018](adr/ADR-018-base-world-visual-migration-and-severity-contract.md)
   §4.5.1 对拍基线(选择屏是四刀每一刀的对拍面之一)、§4.18 热区、§4.19 对比度,**全部要重取**。
2. **B1 / B2 整条线**:`ArchetypeSelect` 同时挂着拖拽手势(`useFusionDrag`)——
   B1 真机验的六条(误抓起 / 误滚 / 边缘自动滚动 / 磁吸阈值 / 取消 / 单手)
   与 B2 真机验的方向与排斥,**都建立在「卡片列表」这个形态上**。
3. **最要紧的一条(本立字的核心)**:
   **2026-08-06 冻结的四帧静态构图,它的每一个数字——仪式空间 156px / 世界核 ⌀60 /
   融合卡 322×116 / 非参与卡 28%——全部以「卡片」为单位定义**
   ([ADR-019](adr/ADR-019-fusion-visual-entry-and-composability.md) §挂账「静态构图已冻结」)。
   换成档案条目形态后,**冻结构图不是需要微调,而是失去了它的度量单位**。

**推论**:ARCHIVE 形态与已冻结的融合入口构图**几何上不兼容,谁先做,另一个就得重来**。
**此条决定它不能被当作「顺手改个样式」**——它是一次需要自己评估的高成本候选,
与第二节 (3) 那种改 CSS 值的低成本视觉调整**不得并列**。

### C 档 · 被「持久世界状态」挡着(经营类)

**成员**:妖怪客栈、美食江湖、怪物公司、猫咪王国(**均浮世**)。

**为什么挡着**:经营类的核心**不是**开店的题材,而是**跨回合累积的世界状态**——
客人记不记得你、铺子有没有被砸、上季存的货还在不在。
交叉引用 [future-experience backlog](future-experience-backlog.md) §0 立档原则
「**不拿页面内计数冒充世界记忆**」与 §1 ①(依赖能力 `persistent world state`):
**无持久状态,经营世界会退化为「每回合都像第一回合」——那不是轻松,是空。**

**阻塞物挂两处(同一片地的两个视角)**:

- **主阻塞 · 产品侧** = [future-experience §1 ①](future-experience-backlog.md) 的 `persistent world state`,
  其依赖现状逐字为「**主题 A,冻结中**」,指向
  [打磨与愿景 backlog §1/§4 主题 A · 持久世界记忆](phase2-polish-and-vision-backlog.md),
  地基压在**尚未做的账号 + 云存档**。
- **架构侧** = [工程债清单 §3.3 数据库迁移的具体形态](backlog-engineering-debt.md)。
  沿用 [future-experience §2.3](future-experience-backlog.md) 已立的字:
  **「产品视角 vs 架构视角看同一片地」,两边开工时必须一起看**。

**反向记明(本档的另一半价值)**:这批世界给了工程债第 3 层一个**产品理由**,而不只是简历理由。
在此之前,「迁数据库」的论据是外部审查给的面试价值(工程债 §3.1),
而 [Felix 的补充判断](backlog-engineering-debt.md)(§3.2)是「规模远大于任何一刀、会动引擎与存档两块最稳的部分,**挂账,不急开工**」——
**一个只有简历理由的大刀永远排不上号**;有了「四个想做的世界卡在它后面」,它才有被排期的资格。

### 不进三档 · 元结构而非世界

**无限流 / 无限列车**。

**理由**:它们的本质是**一局内切换多套规则 / 轴 / 世界观**——那是**世界调度机制,不是世界**。
按本文件的分类轴,它根本没有「属于哪一侧」这个答案(它两侧都路过)。
规模上接近工程债第 3 层,**需自己的 ADR,不排期**。

> **与旧文件口径的关系(如实记,不悄悄改)**:
> [世界库 backlog 第三级](world-library-expansion-backlog.md) 对无限流的处置写的是
> 「与 Phase 3 混合模式 fusion 高度重叠 → **不单独做,跟 fusion 一起设计**」。
> 那是 2026-06-24 融合尚未落地时的判断;融合 round 1/1.5 端到端跑通之后可以看清:
> **融合是「两套设定调和成一个自洽世界」,无限流是「一局内依次进入多个世界」——不是同一件事**,
> 前者归 world-gen,后者要动回合状态机与存档。**两处结论都是「不排期」,故不冲突;
> 本条只更新理由,旧文件正文不动**(循「旧文档不回改、由新文档修订」惯例)。

### 首批推荐(**建议,Felix 未拍板** → **已由 ADR-020 / ADR-021 兑现**)

> **2026-08-14 回填**:本节的建议**已经落地**——人生模拟由
> [ADR-020](adr/ADR-020-lifetime-world-family-and-ordinary-life.md)(《寻常》,复用 `life_sim` 占位)兑现,
> 动物人生由 [ADR-021](adr/ADR-021-lifetime-family-layer-and-animal-life.md)(`animal_life`,刀 3)兑现。
> 下面「第二个用来验第一个的骨架能不能复用」这条**已经拿到答卷**:
> **原则可复用,但代码里没有存放它的层** —— 故 ADR-021 先补族层(刀 1/刀 2)再加世界(刀 3),
> 并就地订正了 ADR-020 §1。**本节措辞保留原样不回改**(循「旧文档不回改、由新文档修订」惯例)。

**人生模拟 + 动物人生。**

- 两者同为「**一生制**」时间尺度——即 [CONTEXT §三.16 约定 (7)](CONTEXT.md) 那条
  **per-combo 隐性设计参数**(时间尺度必须被明确,否则经济/节奏会被叙事时间结构架空)。
  一生制是四个已上线世界都没有的时间尺度,**它本身就是要验的东西**。
- **第二个用来验第一个的骨架能不能复用**——作用同
  [ADR-014](adr/ADR-014-fusion-skeleton-parameterization-and-second-combo.md) 的第二组合。
- **为什么不是三个不同结构一起上**:那样**成本归因会脏**——分不清哪份成本来自「世界」、哪份来自「结构」。
  先做两个同结构的,是为了让「加一个一生制世界要花多少」这个数**干净**。

# 第二节 · 原始构想(**未裁定** · Felix 提供 · 逐字保留)

## (1) 行为语言对照表(九行逐字保留)

| | 浮世 | 深界 |
|---|---|---|
| 页面 | 松散有呼吸 | 收紧有压迫 |
| 卡片 | 浮起展开 | 档案封存 |
| 动效 | 弹性柔和 | 突然中断不确定 |
| 文案 | 有趣生活化 | 冷静危险留白 |
| 数值 | 彩色有趣 | 仪表档案异常 |
| 声音(以后) | 环境生活 | 极低频异常 |
| 空间 | 大留白 | 深色包围 |
| 反馈 | 明确 | 偶尔故意延迟 |
| 融合 | 柔和揉合 | 碰撞污染 |

**为什么这张表逐字保留**:它是全部构想里**唯一把「两个模块到底差在哪」写成可执行判据而非形容词**的一块
(「松散 / 收紧」「明确 / 偶尔故意延迟」都能落成具体的值),**重建成本高**。

## (2) 深界侧 ARCHIVE 档案入口形态

世界入口**不作商品卡,而作异常档案条目**;顶部「深界」+ 小字 `ARCHIVE / UNAUTHORIZED ACCESS`。

三个样例(逐字保留):

```
ARCHIVE 017 · 规则怪谈 · 状态:未封存 · 风险:高
ARCHIVE 031 · 无名之港 · 认知污染:存在 · 回收记录:失败
ARCHIVE 044 · 灰烬纪元 · 文明存续率:12% · 通信:间歇
```

> **⚠️ 成本标注:本条是高成本候选,须自己的评估,不得与 (3) 那类改 CSS 值的低成本视觉调整并列。**
> 具体受影响面与「**与已冻结的融合入口构图几何上不兼容**」的判断,见**第一节立字六**(不在此重复)。

## (3) 浮世侧视觉语言

- **背景**:米白 / 极浅灰蓝 / 奶油 / 很淡的暖绿 —— **但不要纯白**。
- **卡片**:更宽松、更有图片感、圆角略大、留白更多,允许轻微插画或材质。
- **标题**:不必全部压迫粗重。
- **动效关键词**:弹、浮、展开、呼吸(对照深界的:闪、裂、抖、故障)。
- **明确的反面清单**:**不做儿童游戏感、不做糖果 UI,高级感不能丢。**

## (4) 三种产品结构(未裁定选项)

| | 形态 | 优 / 劣 |
|---|---|---|
| **A** | 首页直接两入口,各看各的世界列表 | **最清晰** |
| **B** | 昼夜式大厅切换,整列表左右切换 | **视觉记忆点最强** |
| **C** | 一个世界大厅 + 顶部分区(全部 / 浮世 / 深界) | **工程量最小,世界观最弱** |

**三者均不排期,受立字二阻塞**(浮世侧世界数 < 3 之前不启动;且那个「压力」出现之前,无从判断该选哪个)。

## (5) 跨模块融合素材(纯素材,一字不删)

- 妖怪客栈 × 克苏鲁 =《今晚入住的不是客人》
- 人生模拟 × 规则怪谈 =《你的一生只有七条规则》
- 美食江湖 × 末日 =《最后一家饭馆》
- 猫咪王国 × 克苏鲁 =《猫知道海下面有什么》

**受立字四约束**:每一个仍**须被完整写出来才能存在**——标题好听不代表世界已经存在。

## (6) 技术层结构草图

单一应用,`experienceMode = 浮世 | 深界` 控 design tokens / card skin / motion profile /
typography / background / UI chrome,**不复制 `LightWorldCard` / `DarkWorldCard` 一类的平行组件树**。

> **⚠️ 与立字一的边界(必读)**:该草图**仅在大厅内成立**。
> **进局之后,motion profile 与 typography 必须交回世界主题注册表,不由 `experienceMode` 控**——
> 否则就是立字一点名要防的「视觉真理源从一处变成两处」。

# 案例集 · 失败 → 定位 → 修复

> 每篇一条真实缺陷:它是什么、**它为什么没被现有守护抓住**、是什么抓住了它、
> 修法为什么不是更「自然」的那一个、留下了什么判据。
>
> **写作纪律**:素材全部来自 ADR 订正块 / commit / 周度日志,**是转写不是回忆**;
> 引用逐字,**有锚点才归因、没锚点不补**;优先引不会漂的东西(方法名、注释原文、commit SHA、
> ADR 小节标题),行号让位给名字。裁定的真理源在各 ADR,**本目录只转写与索引,不复制裁定**。

## 这不是三次事故,是三个不同深度的拦截

| 案例 | 被什么抓住 | 到过哪 | 玩家可见 |
|---|---|---|---|
| [闸 A · 一次没发生的静默撤销](02-the-silent-revert.md) | **勘察**(写码前核对口径时撞见) | 没写进代码 | 否 |
| [`catch (RuntimeException)` 的慢性失血](03-a-slow-bleed.md) | **审阅**(读 diff) | 写进了 commit(`03bcbd3`),**从未上线** | 否 |
| [一句会撒谎的文案](01-a-message-that-lied.md) | **真机冒烟的第二问** | 已部署(`c43fe3c`),次日修掉(`d631c36`) | **是** |

**⚠️ 只有最后一条是真事故,前两条是差点。** 这个区别不该被抹平 ——
把「差点」写成「事故」,等于把拦截成功记成战功。

而这个排列本身是这三篇合在一起才说得出的话:

> **越早拦住,代价越小;而最贵的那一次,正是唯一一次「所有测试都绿、
> 只有真人照着那句话去做才发现」的。**

## 三条各自的形状

- **勘察抓到的那条**,靠的不是任何自动化守护,是**动手前把两份口径摆在一起读**这个步骤本身。
  它防住的是一次**静默撤销** —— 两条各自正确的规定在交集处,把上一刀的修法无声换掉,而测试全绿。
- **审阅抓到的那条**,形状决定了自动化抓不到:要发现它,必须把 `catch` 那一行和它上面几行
  javadoc 放在一起读。它的后果**不是崩溃是慢性失血**,而失血过程中的日志
  **与真实饱和长得一模一样**。
- **冒烟抓到的那条**,是唯一一条机制侧全部验通、只有**照着那句话再做一遍**才暴露的 ——
  冒烟对同一个用例记了两条读数,通过的是第一条,失败的是第二条。

## 一条贯穿三篇的线

三篇里,**没有一条是靠「跑一遍测试」发现的**。

它们分别被**读口径**、**读 diff**、**照着文案做一遍**抓住 ——
对应的正是 [`engineering-practices.md`](../engineering-practices.md) 里那几条:
绿有两种解释而测试套件本身不区分;没有断言在看的探针不是守护;
观测工具本身需要被验证。

**每篇末尾都写了「它本可以怎样溜过去」。** 没有那一段,这些就只是「我们修了几个 bug」。

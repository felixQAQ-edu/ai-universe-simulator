# 线 B1 原型 · 融合入口拖拽手势 —— 真机冒烟清单

> **这一刀的性质**:先验最险的假设,**允许被判死**。Felix 的融合入口设计(把 A 卡拖到 B 卡上,
> 被拖者 = foreign、承接者 = host)本身完整、成本模型也正确,但它压在一个未经验证的假设上:
> **在纵向可滚动的世界列表里,拖拽手势是否可用**。
> 本原型**只做手势、不做任何视觉**;若手势不成立,它省下的是整套碎解动画的投入 ——
> 那是它的价值,不是失败(同刀 1 灯闪教训:先验承载表面,别等做完才发现)。
>
> 入口:`https://<临时 app>.fly.dev/?proto=fusion`。**零网络调用**(不调 init、不读 registry、
> 不吃 ADR-016 额度),提交后只打印一行文本。生产选择屏 `ArchetypeSelect` **一个字符未动**。

## 一、桌面模拟测不准什么(先说清,免得把「本地过了」当证据)

鼠标没有手指的接触面积、没有惯性滚动、不会误触 —— 六条验收里**没有一条**能靠桌面回答。
本地只证明了「代码接线是通的」:抓起 / 磁吸 / 可提交 / 提交文案方向 / 无效组合回弹 /
一次触摸只判一次滚动 —— 均已在浏览器里用合成指针事件跑通并读到读数。

**本地不可验**(浏览器面板 `visibilityState: hidden` 时 rAF 冻结、setTimeout 被钳到 ≥1s
—— 同刀 2/刀 4 的取证边界):

- 边缘自动滚动的**实际速度与手感**(rAF 循环在隐藏页里不跑,实测 `scrollY` 纹丝不动,
  而速度读数是对的 → 只能真机验);
- 长按 180ms 的**体感时长**(计时器被钳到 1s,本地一切时间读数都不作数)。

```sh
fly apps create wanjie-proto-drag --org personal
```

```sh
fly volumes create wanjie_data --app wanjie-proto-drag --region syd --size 1
```

- fly.toml 里声明了 `[mounts] source = "wanjie_data"`,临时 app 也得有同名卷才能起。

```sh
fly deploy --ha=false -a wanjie-proto-drag
```

- `-a` 覆盖 fly.toml 里的 app 名,**fly.toml 一个字不用改**。
- **不设 `DEEPSEEK_API_KEY`、不设 `AIUNIVERSE_LLM_ACTIVE`**:原型页零网络调用,
  后端跑 mock 即可,本轮**不花任何 LLM 的钱**。

```sh
fly status -a wanjie-proto-drag
```
- 必须看到:1 台 machine、region `syd`、state `started`、health `passing`。

## 三、六条真机验收(逐条记结果,不要为了让原型「成功」而调参掩盖问题)

页面底部常驻**读数条**:第一行是实时状态(dx/dy、目标、重叠 %、停留 ms、自动滚动速度),
第二行是计数(抓起 / 滚动胜出 / 误抓起 / 提交 / 取消 / 无效)+ 最近 6 条事件。
**「误抓起」= 抓起后 320ms 内、位移不到 16px 就松手** —— 这是「本想滚动却被抓起」的代理指标,
第 1 条主要看它。顶部「阈值调参」可现场改长按时长 / 重叠比 / 停留 / 边缘带宽 / 滚动速度,
**不必重新部署**;「列表长度」可切 6 张 / 12 张(6 张在手机上只滚得动一点点,验第 3 条要切 12 张)。

| # | 验收项 | 判定 |
|---|--------|------|
| 1 | **想滚动时会不会误把卡拖起来**(最重要) | 正常上下滑读列表 20 次,「误抓起」应≈0;若频繁抓起 → 范式不匹配 |
| 2 | 想拖拽时会不会误触发滚动 | 长按后拖动,页面不应跟着滚;`pointercancel` 日志不应出现 |
| 3 | 目标卡在屏幕外时,边缘自动滚动 | 切 12 张,把卡拖到屏幕上/下边缘,列表应平稳滚动把目标带进来;速度可控不冲过头 |
| 4 | 磁吸范围与阈值是否符合直觉 | 不该「太黏」(还没对准就吸住)也不该「太滑」(明明盖上去了不算) |
| 5 | 取消是否可靠 | 拖开再松手应干净归位,不能有「甩不掉」的感觉 |
| 6 | 单手可行性 | 拇指从列表底部把卡拖到顶部的卡上 |

## 四、结论(冒烟后填,三档任选其一)

- **(a) 顺手,可进 B2**(碎解材质与揉合动画)
- **(b) 别扭但可救** —— 需改容器形态(例:进入拖拽时列表收缩为小卡网格,使全部候选同屏,
  从根上取消「边缘自动滚动」这个最难的部分),给出方案
- **(c) 范式不匹配** —— 建议回退到别的入口设计。**这同样是本刀的成功产出**

> 结论: _待冒烟后填_

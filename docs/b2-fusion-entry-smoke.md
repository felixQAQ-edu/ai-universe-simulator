## 一、桌面 / 本地测不准什么(先说清,免得把「本地过了」当证据)

鼠标没有手指的接触面积、没有惯性滚动、不会误触 —— **手势六条没有一条能靠桌面回答**(同 B1)。
本地已用合成指针事件在真实几何上跑通并读到读数:抓起(`cardDragging` + z-index + scale 1.03)/
磁吸与排斥 / 提交方向(拖 A 到 B → init 请求体 `{"archetypes":["<B>","<C>"]}` host 在前)/
无效组合不吸不提交 + 一句「两个世界尚无法彼此容纳」/ 原卡归位(transform 与 z-index 清空)/
融合卡落位并获得焦点。

**本地不可验**(浏览器面板 `visibilityState: hidden` → rAF 冻结、setTimeout 被钳到 ≥1s,
同刀 2 / 刀 4 / B1 的取证边界):

- **五拍 1000ms 的实际节奏**,尤其**停顿那一拍会不会被读成卡顿**(本地时间读数一律不作数);
- **四套碎解材质在 1 秒内是否一眼可分辨**(形态本地看得见,过程看不清);
- 边缘自动滚动的**速度与手感**;长按 180ms 的**体感时长**。

## 二、命令清单(所有 `fly` 命令 Felix 亲手敲;临时 app 用完即毁)

在**仓库根目录**、当前分支 `phase4/fusion-entry` 上执行。

```sh
fly apps create wanjie-b2-entry --org personal
```

```sh
fly volumes create wanjie_data --app wanjie-b2-entry --region syd --size 1
```
- fly.toml 里声明了 `[mounts] source = "wanjie_data"`,临时 app 也得有同名卷才能起。
  会警告「单卷无冗余」→ 输 `y`。

```sh
fly deploy --ha=false -a wanjie-b2-entry
```
- `-a` 覆盖 fly.toml 里的 app 名,**fly.toml 一个字不用改**。
- **真 key 的取舍**:验收第 4 条(提交后真的进了正确的融合局)**需要真 world-gen**,
  故本轮要设 key。**两个 secret 必须一起设**(runbook §3.1.6:只设 key 不设 active =
  线上跑 mock,而 mock 不读 key,「key 设了」不构成任何证据):

```sh
fly secrets set DEEPSEEK_API_KEY=<key> AIUNIVERSE_LLM_ACTIVE=deepseek -a wanjie-b2-entry
```
- 若只想验手势与动画、不验融合局,可跳过这条走 mock —— 那么验收第 4 条记「未验」,
  **不要写成通过**。

```sh
fly status -a wanjie-b2-entry
```
- 必须看到:1 台 machine、region `syd`、state `started`、health `passing`。

**部署陈旧前置检查**(runbook §3.1.5 —— 先证明镜像真换了,再验功能):

```sh
curl -s https://wanjie-b2-entry.fly.dev/ | grep -o 'index-[A-Za-z0-9_-]*\.js'
```
```sh
ls web/dist/assets/index-*.js 2>/dev/null || (cd web && npm run build && ls dist/assets/index-*.js)
```
- 两个哈希**必须一致**;不一致 = 线上还是旧镜像,此时验什么都是假的。

**后端投影前置检查**(本轮唯一的后端改动,ADR-019 §6):

```sh
curl -s https://wanjie-b2-entry.fly.dev/api/archetypes | python3 -m json.tool | tail -20
```
- 必须看到 `fusions` 两条:`cultivation×rules_creepy` 与 `rules_creepy×apocalypse`。
  若为空数组 → 前端会一律判无效组合(安全降级),此时拖不出融合是**预期行为、不是 bug**,
  但说明镜像仍是旧的,回上一条。

冒烟入口(手机 Safari / Chrome 打开):

```
https://wanjie-b2-entry.fly.dev/
```

**用完即毁**(不留常驻成本):

```sh
fly apps destroy wanjie-b2-entry
```

## 三、真机验收(逐条记结果;**不为了让本轮「成功」而调参掩盖问题**)

### A. 手势六条(同 B1,回归确认范式在生产列表里仍成立)

| # | 验收项 | 判定 |
|---|--------|------|
| 1 | **想滚动时会不会误把卡拖起来**(最重要) | 正常上下滑读列表 20 次,不该有卡被抓起 |
| 2 | 想拖拽时会不会误触发滚动 | 长按后拖动,页面不应跟着滚 |
| 3 | 目标卡在屏幕外时,边缘自动滚动 | 把卡拖到屏幕上/下边缘,列表应平稳滚动把目标带进来(生产列表只有 6 张,若滚不动即此条无从考验,记「不适用」) |
| 4 | 磁吸范围是否符合直觉 | 不该「太黏」也不该「太滑」 |
| 5 | 取消是否可靠 | 拖开再松手干净归位,无「甩不掉」感 |
| 6 | 单手可行性 | 拇指从列表底部把卡拖到顶部的卡上 |

> B1 的读数条与调参面板**是原型道具,已随 `web/src/proto/` 删除** ——
> 本轮没有屏上读数,六条靠体感判。若某条判不通过、需要改阈值,回报后改代码重部署,
> **不在生产界面上留调参入口**。

### B. 本轮新增的七条

| # | 验收项 | 判定 |
|---|--------|------|
| 7 | **五拍在真机上的观感** | 1 秒读作「挤压 → 碎 → 揉 → **顿一下** → 展开」;**停顿那一拍应读作重量,不是卡顿** |
| 8 | **四套材质可分辨** | 拖三对不同组合,碎解瞬间能看出是**哪两个世界**在碎(冷蓝硬边 / 锈土带尘 / 墨雾湿纤维 / 薄玉光丝) |
| 9 | **四套物理各走各的** | 规则=阶跃不转 / 末日=一律向下坠 / 克苏鲁=同向被抽走 / 修仙=上浮化散。**看的是过程不是形态** |
| 10 | **方向对不对** | 拖「末日生存」到「规则怪谈」上 → 进「缺页的人防工程」;拖「规则怪谈」到「修仙」上 → 进「识海遗蜕」。**反着拖应被拒**(方向敏感) |
| 11 | **无效组合排斥** | 拖「克苏鲁」到任意卡上:不吸附、轻微推开、松手回弹 + 一句「两个世界尚无法彼此容纳」,**不弹 Toast、不挡路** |
| 12 | **原卡归位不消耗** | 揉合演完后两张原卡都还在原位、可正常单击进各自世界;融合卡多出一张 |
| 13 | **reduced-motion 降级** | 手机开「减弱动态效果」后再拖一次:只有重叠 + 短暂停顿 + 新卡出现,**不碎裂、不旋转**,融合卡照样拿得到 |

## 四、结论(2026-08-05 真机冒烟)

**功能与手势全过;审美不达标,单独挂账,不阻塞合并。**

- **手势六条:全过**(拖拽范式在生产列表里成立,与 B1 结论一致)。
- **方向:正确**(host 在前,拖对了进对应融合局、反着拖被拒)。
- **无效组合:排斥 + 提示正常**(不吸附、回弹、一句话,不弹 Toast)。
- **原卡归位:通过**;**融合卡落位并获得焦点:通过**。
- **碎片确实在动**(本地修掉的 `.undefined` 静默失效在真机上确认已解决)。
- **五拍观感 / 四套材质可分辨 / 四套物理:功能上成立,但整体审美不达标** ——
  Felix 判定:仍像**「列表中间播放了一组碎片特效」**,没有形成新世界诞生的仪式感。
  这不是某个参数调错,根因是**视觉焦点管理缺失**(四条根因见 ADR-019 §挂账),
  下一轮**先回样板间定静态构图,冻结后再碰 GSAP 时间线**。
- 阈值与时长:**本轮不调**(功能层面无一条要求改动;时长与节奏的判断留给下一轮的静态构图定稿后再谈)。

临时 app 已销毁。
